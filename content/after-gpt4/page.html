GPT-4 在 2023 年 3 月 14 日发布。三年多过去，前沿模型的外形变化不大，仍然是一个自回归 Transformer，按下一个 token 的交叉熵预训练，再做后训练。变化发生在内部的几乎每一个部件上：注意力的 Key 和 Value 被压缩或稀疏化，前馈层换成了几百个专家，残差连接被加宽又被约束，训练用上了 FP8 和新的优化器，后训练的主力从人类偏好变成了可以自动判分的数学题和代码题，模型开始先写几千个 token 的推理再回答，并通过协议调用外部工具。

这篇文章按模型的结构和生命周期排列这些概念：先讲架构（第 2 到 7 节），再讲长上下文、预训练和推理服务（第 8 到 10 节），然后是后训练、推理模型、工具与 agent、多模态（第 11 到 15 节），最后是安全、可解释性和评测（第 16 到 18 节），文末附一张年表。每个概念给出它要解决的问题、机制、出处和后来的用法。论文日期取 arXiv 第一版，产品取官方发布日，数字只取论文正文或摘要里写明的；示意图里的数值会单独标注。延伸阅读收在「资料」tab。

1起点：GPT-4 时的配方和它的成本结构

GPT-4 的技术报告没有公开架构、参数量、训练算力和数据构成，理由写的是竞争环境和安全考虑。能确认的只有它是 Transformer、用下一个 token 预测预训练、再用人类反馈强化学习 (Reinforcement Learning from Human Feedback, RLHF) 对齐。同一时期公开的模型（LLaMA、PaLM）让外界知道了当时的标准配方：只有解码器的 Transformer，Pre-Norm 加 RMSNorm，旋转位置编码 (Rotary Position Embedding, RoPE)，SwiGLU 前馈层，每层是完整的多头注意力 (Multi-Head Attention)，每个 token 经过全部参数。

这套配方有几处成本会随规模和用法放大，后面三年的大部分技术都对着其中一处：

  • 生成阶段每产生一个 token，都要从显存读一遍全部权重和这条序列的全部 Key、Value 缓存。序列一长，缓存比权重还大，吞吐量受显存带宽限制，算力闲着。
  • 注意力的计算量随序列长度平方增长，位置编码在训练长度以外也会失效，上下文很难做长。
  • 稠密模型里每个 token 都要经过所有参数，参数量翻倍，每个 token 的计算也翻倍。
  • 人类偏好标注贵且慢，RLHF 要同时维护四个模型，训练不稳定。
  • 一次前向的层数固定，多步推理能用的串行计算有上限；权重里的知识有截止日期，模型也碰不到文件、网页和代码仓库。

2KV cache 和注意力头的共享：MQA 与 GQA

生成为什么慢在显存带宽

自回归生成分两个阶段。预填充 (Prefill) 一次性处理整段提示词，几千个 token 同时做矩阵乘法，计算单元是满的。解码 (Decode) 每步只产生一个 token，这个 token 的 Query 要和之前所有 token 的 Key 做点积，再对 Value 加权求和。为了不重复计算，之前 token 的 Key 和 Value 都存在显存里，这就是 KV cache。

解码一步的计算量很小，但要读的数据很多：全部权重读一遍，再把这条序列的 KV cache 读一遍。权重可以靠批处理摊薄，一批 64 条序列共享同一次权重读取；KV cache 不行，每条序列有自己的一份。批越大、序列越长，KV cache 占的显存越多，能同时服务的请求数就越少。

每个 token 在每层要存一个 Key 和一个 Value，KV cache 的大小是：

bytes/token=2×L×nkv×dh×b\displaystyle \text{bytes/token} = 2 \times L \times n_{kv} \times d_h \times bLL 层数，nkvn_{kv} Key/Value 头数，dhd_h 每头维度，bb 每个数的字节数

以 Llama 3 70B 为例：80 层，64 个 Query 头，8 个 Key/Value 头，每头 128 维，BF16 每个数 2 字节。每个 token 是 2 × 80 × 8 × 128 × 2 = 327,680 字节，即 320 KiB；一条 128K token 的序列要 40 GiB。如果 64 个头各有自己的 Key 和 Value，就是 2.5 MiB 每 token，128K 序列 320 GiB，四张 80 GB 显卡装不下一条请求。

多查询注意力和分组查询注意力

多头注意力里每个头有独立的 WQW_Q、WKW_K、WVW_V。多查询注意力 (Multi-Query Attention, MQA) 是 Shazeer 在 2019 年 11 月提出的：所有 Query 头共用同一组 Key 和 Value，KV cache 缩小到 1/nhn_h。代价是质量下降，训练也更容易不稳定。

分组查询注意力 (Grouped-Query Attention, GQA) 在 2023-05-22 上传，作者是 Google 的 Ainslie 等六人。它取中间：把 nhn_h 个 Query 头分成 gg 组，每组共用一对 Key/Value 头。g=nhg = n_h 就是多头注意力，g=1g = 1 就是 MQA。论文还给了一个把已有多头注意力模型改成 GQA 的办法：把同一组里各头的 Key、Value 投影矩阵取平均作为初始化，再用原预训练 5% 的算力继续训练（uptraining）。结论是 8 组的 GQA 质量接近多头注意力，速度接近 MQA。

GQA 很快成了默认配置。Llama 2 70B（2023-07）、Mistral 7B（2023-10）、Llama 3 全系列、Qwen2 和 Qwen3 都用 GQA，常见的设置是 8 个 Key/Value 头。它的局限也很明确：压缩靠的是让多个头看同一份 Key 和 Value，头数再往下减，表达能力就跟着减。

3多头潜在注意力：把 Key 和 Value 压成一个向量

多头潜在注意力 (Multi-head Latent Attention, MLA) 出自 DeepSeek-V2（2024-05-07）。它不减少头数，改为缓存一个低维的潜向量，Key 和 Value 都从这个向量里还原出来。

低秩联合压缩

对第 tt 个 token 的隐状态 hth_t，先用一个下投影得到潜向量 ctKVc_t^{KV}，再用两个上投影分别得到所有头的 Key 和 Value：

ctKV=WDKVht,ktC=WUKctKV,vtC=WUVctKV\displaystyle c_t^{KV} = W^{DKV} h_t,\quad k_t^{C} = W^{UK} c_t^{KV},\quad v_t^{C} = W^{UV} c_t^{KV}只缓存 ctKVc_t^{KV}

DeepSeek-V2 的设置是 128 个头、每头 128 维，潜向量 dc=512d_c = 512。多头注意力每层每 token 要存 2 × 128 × 128 = 32,768 个数，MLA 只存 512 个（加上下面的 64 个）。

推理时还原 Key 和 Value 要多做两次矩阵乘法，看上去省了显存却多了计算。论文用矩阵结合律把上投影吸收掉了。注意力分数是 q⊤k=q⊤WUKcq^\top k = q^\top W^{UK} c，可以先算 (WUK)⊤q(W^{UK})^\top q，让 Query 直接和潜向量 cc 做点积；输出端的 WUVW^{UV} 同样可以并进输出投影 WOW^O。这样解码时根本不需要还原出完整的 Key 和 Value，所有头直接在 512 维的潜空间里算注意力。从计算结构看，这时的 MLA 相当于一个只有一组 Key/Value 的 MQA（Key 576 维，Value 512 维），所以它的 KV cache 能这么小。

解耦的 RoPE

吸收矩阵有一个前提：qq 和 kk 之间只隔着与位置无关的线性变换。RoPE 在 qq 和 kk 上各乘一个与位置有关的旋转矩阵，点积里会多出一个 Rt−sR_{t-s} 夹在中间，WUKW^{UK} 就没法预先并到 Query 一侧了。

DeepSeek-V2 的办法是把位置信息单独拿出来。每个头的 Query 额外带一段 64 维的 qtRq_t^R，所有头共用一段 64 维的 ktR=RoPE(WKRht)k_t^R = \text{RoPE}(W^{KR} h_t)，这两段才加 RoPE；原来的 512 维部分完全不碰位置。最后的 Key 是两段拼接，注意力分数是两部分点积之和。共用的 ktRk_t^R 也要缓存，每层每 token 一共 512 + 64 = 576 个数。

论文的对照表里，576 个数相当于组数只有 2.25 的 GQA，而效果比多头注意力还好。和 DeepSeek 67B 相比，DeepSeek-V2 的 KV cache 少 93.3%，最大生成吞吐量是 5.76 倍；这两个数是整个系统（Mixture-of-Experts 加 MLA 加部署优化）对比旧的稠密模型，不完全来自 MLA 一项。

按 DeepSeek-V3 的配置（61 层，每层 576 个数，BF16）算，每个 token 的 KV cache 约 68.6 KiB，128K 序列约 8.6 GiB，大约是 Llama 3 70B 的五分之一，而 V3 的总参数是 671B。之后 DeepSeek-R1、Kimi K2 都沿用了 MLA。

4稀疏注意力：每个 Query 只看一部分 Key

KV cache 解决的是存储，注意力本身的计算仍然是每个 Query 对所有之前的 Key 各算一次。序列长度从 8K 到 128K，单层注意力的计算量涨 256 倍。稀疏注意力让每个 Query 只看一部分 Key，问题在于选哪一部分。

滑动窗口和局部、全局交替

滑动窗口注意力 (Sliding Window Attention) 让每个 token 只看前面固定的 WW 个 token。Mistral 7B（2023-10-10）用 W=4096W = 4096。单层看不远，但层层叠加以后，第 kk 层的信息理论上能来自 k×Wk \times W 个 token 之前，32 层就是约 131K。KV cache 只需要保留最近 WW 个位置，可以用环形缓冲区循环覆盖。

纯滑动窗口在需要精确回查远处内容的任务上会掉点，于是出现了局部层和全局层交替的设计：Gemma 2（2024-06）一层滑动窗口一层全注意力，Gemma 3（2025-03）五层窗口为 1024 的局部注意力配一层全局注意力，OpenAI 的 gpt-oss（2025-08）全注意力层和窗口为 128 的带状注意力层交替。全局层负责远距离检索，局部层占多数，KV cache 和计算量都降下来。

注意力汇点

2023-09-29，MIT 的 Xiao 等人在 StreamingLLM 里报告了一个现象：把滑动窗口直接套在预训练好的模型上，一旦序列超过窗口，困惑度会突然崩掉；只要额外保留最开头的 4 个 token，困惑度就恢复了。这几个 token 的语义无关紧要，它们是 注意力汇点 (Attention Sink)。

原因在 softmax：每个 Query 的注意力权重必须加起来等于 1，当某个头在当前位置没有需要关注的内容时，它要把权重放到某个地方，模型学会了放在最开头的 token 上（它们对所有后续位置都可见）。窗口滑走、把这几个 token 丢掉，这部分权重就被迫分给其他 token，输出分布随之改变。StreamingLLM 保留汇点加最近窗口，让 Llama-2 等模型在不微调的情况下稳定处理 400 万 token 的流式输入。

后来的模型把汇点做进了结构里：gpt-oss 给每个头加了一个可学习的汇点 logit，参与 softmax 归一化但不对应任何 Value；Qwen 团队 2025-05 的门控注意力 (Gated Attention) 在注意力输出后乘一个逐头的 sigmoid 门，头可以直接把输出关小，不再需要找地方放权重，论文报告汇点现象明显减弱、长度外推变好，这个门后来用在了 Qwen3-Next 里。

NSA：可训练的分块稀疏

前面几种稀疏模式都是固定的。DeepSeek 的 原生稀疏注意力 (Native Sparse Attention, NSA) 在 2025-02-16 上传，让模型自己决定看哪些块，而且从预训练开始就用稀疏注意力训练（“原生”指这一点），训练完再裁剪的做法不在此列。

NSA 对每个 Query 并行算三路注意力，再用门控加权求和：

  • 压缩分支：把 Key 序列切成长 32、步长 16 的块，每块用一个小网络压成一个 Key，Query 和这些压缩 Key 做注意力，得到粗粒度的全局信息。
  • 选择分支：用压缩分支的注意力分数给长 64 的块打分，选出得分最高的 16 块（固定包含开头 1 块和最近 2 块），在这些块的原始 token 上做完整注意力。
  • 滑动窗口分支：最近 512 个 token。论文说单独分出这一路，是为了防止局部模式在训练中占主导，让另外两路学不到东西。

选择按块进行，而且同一个 GQA 组里的所有 Query 头选同一批块，这样每次从显存读的是连续的整块 Key/Value，适合 GPU 的访存方式。论文在一个 27B 的模型上预训练 260B token，NSA 的损失低于全注意力，通用、长上下文和推理评测持平或更好；64K 长度下，解码快 11.6 倍，训练的前向快 9.0 倍、反向快 6.0 倍。

DSA：用一个轻量索引器挑 token

DeepSeek-V3.2-Exp 在 2025-09-29 发布，同年 12 月的 DeepSeek-V3.2 沿用同一架构，技术报告 2025-12-02 上传。相对上一版 V3.1-Terminus，唯一的结构改动是 DeepSeek 稀疏注意力 (DeepSeek Sparse Attention, DSA)。

DSA 分两步。第一步是 闪电索引器 (Lightning Indexer)：给当前 token tt 和每个之前的 token ss 算一个索引分数

It,s=∑j=1HIwt,jI⋅ReLU(qt,jI⋅ksI)\displaystyle I_{t,s} = \sum_{j=1}^{H^I} w_{t,j}^{I} \cdot \text{ReLU}\left( q_{t,j}^{I} \cdot k_s^{I} \right)索引器的头数 HIH^I 很少，用 FP8 计算

第二步按 It,:I_{t,:} 取前 kk 个 token，主注意力只在这些 token 的 KV 上计算。V3.2 取 k=2048k = 2048。主注意力的复杂度从 O(L2)O(L^2) 降到 O(Lk)O(Lk)；索引器本身仍然是 O(L2)O(L^2)，但头少、维度低、用 FP8，计算量比原来的 MLA 小得多。

和 NSA 不同，DSA 是在已经训练好的 V3.1-Terminus 上继续训练出来的。先冻结主模型，只训练索引器 1000 步（2.1B token），目标是让索引分数的分布逼近主注意力的分布（各头注意力分数求和、归一化后做 KL 散度）；再打开 top-k 选择，全部参数一起训练 15000 步（943.7B token）。DSA 实现在 MLA 的 MQA 模式上，每个潜向量被一个 token 的所有 Query 头共用，这一点和 NSA 按组共享块的考虑相同。

5线性注意力、状态空间模型和混合架构

稀疏注意力仍然保留全部 KV cache，只是每次读一部分。另一条路线是让模型只保留固定大小的状态，序列再长，每步的计算和显存都不变。

把注意力写成循环

去掉 softmax，注意力的输出可以改写：

ot=∑s≤t(qt⊤ks) vs=(∑s≤tvsks⊤)qt=St qt,St=St−1+vtkt⊤\displaystyle o_t = \sum_{s \le t} (q_t^\top k_s)\, v_s = \Big( \sum_{s \le t} v_s k_s^\top \Big) q_t = S_t\, q_t,\qquad S_t = S_{t-1} + v_t k_t^\topStS_t 是一个 d×dd \times d 的矩阵

这就是 线性注意力 (Linear Attention)。所有历史被累加进一个固定大小的状态矩阵 StS_t，每步更新一次，像循环神经网络；训练时又能按块并行。代价是状态有限，只加不减：写进去的东西会互相覆盖，序列越长，按内容精确取回某个旧信息就越难。

Mamba：让遗忘和写入依赖输入

Gu 和 Dao 的 Mamba 在 2023-12-01 上传。它基于状态空间模型 (State Space Model)：ht=Aˉht−1+Bˉxth_t = \bar{A} h_{t-1} + \bar{B} x_t，yt=Chty_t = C h_t。早期的状态空间模型参数与输入无关，适合连续信号，处理文本时没法根据内容决定记住什么。Mamba 让步长 Δ\Delta 和 BB、CC 都由当前输入算出来，叫选择性 (Selective)：遇到无关 token 可以几乎不写，遇到关键 token 可以清空旧状态。论文报告推理吞吐量是同规模 Transformer 的 5 倍，Mamba-3B 的语言建模效果和两倍大的 Transformer 相当。

2024-05 的 Mamba-2 证明这类选择性状态空间模型和带衰减的线性注意力是同一类计算：St=atSt−1+vtkt⊤S_t = a_t S_{t-1} + v_t k_t^\top，ata_t 是随输入变化的遗忘系数。

Delta 规则

DeltaNet 一系的改进针对“只加不减”。写入之前先查一下状态里键 ktk_t 对应的旧值 St−1ktS_{t-1} k_t，只把差值写进去：

St=St−1−βt(St−1kt−vt)kt⊤\displaystyle S_t = S_{t-1} - \beta_t \left( S_{t-1} k_t - v_t \right) k_t^\topβt∈(0,1)\beta_t \in (0,1) 控制写入强度

这相当于对状态做一步在线梯度下降，同一个键再次出现时会覆盖旧值，不会叠加。门控 DeltaNet (Gated DeltaNet)（2024-12-09）在前面再乘一个衰减门 αt\alpha_t，门负责整体快速遗忘，delta 规则负责定点修改。Kimi 的 KDA（Kimi Delta Attention）把门从每头一个标量细化到每个通道一个。

混合架构

纯线性模型在“大海捞针”这类精确检索任务上始终不如注意力，2024 年以后的做法是按比例混合：大部分层用线性注意力或 Mamba，少数层保留全注意力负责检索。

6Mixture-of-Experts：参数和计算分开

路由和激活参数

稠密 Transformer 的前馈层对每个 token 都一样。Mixture-of-Experts 把一个前馈层换成 NN 个并列的小前馈网络（专家），再加一个路由器：路由器对每个 token 算出 NN 个分数，只取分数最高的 KK 个专家计算，输出按分数加权求和。模型的总参数是所有专家之和，每个 token 实际经过的只有 KK 个，所以要区分总参数和激活参数。

这个结构在 2017 年的 Sparsely-Gated MoE、2020 年的 GShard、2021 年的 Switch Transformer 里就有了。2023-12 发布的 Mixtral 8x7B 是第一个被广泛使用的开源 Mixture-of-Experts 模型：每层 8 个专家，每个 token 选 2 个，总参数 47B，激活 13B，效果持平或超过 Llama 2 70B 和 GPT-3.5。

细粒度专家和共享专家

DeepSeekMoE（2024-01-11）指出传统设计的两个问题：专家少而大，每个专家被迫学杂七杂八的知识；不同专家都要学一些通用知识，参数重复。它的两处修改：

  • 细粒度切分：把每个专家切成 mm 个更小的专家，总数变成 mNmN，激活 mKmK 个，计算量不变。组合数大幅增加：16 选 2 只有 120 种组合，切成 64 选 8 有 44 亿种。
  • 共享专家：单独留出 KsK_s 个专家，所有 token 都经过，用来学通用知识，路由专家就可以更专门。

论文里 DeepSeekMoE 2B 和 GShard 2.9B 持平（后者专家参数和计算都是 1.5 倍），16B 版本用约 40% 的计算达到 LLaMA2 7B 的效果。DeepSeek-V3 每层 256 个路由专家加 1 个共享专家，每个 token 激活 8 个路由专家，总参数 671B，激活 37B。

负载均衡

路由器如果总是把 token 发给少数几个专家，这几个专家会越训越强、更容易被选中，最后其他专家闲置，这叫路由坍缩。多卡训练时专家分布在不同卡上（专家并行），负载不均还会让最忙的那张卡拖慢所有卡。

传统做法是加辅助损失，Lbal=α∑ifiPi\mathcal{L}_{\text{bal}} = \alpha \sum_i f_i P_i，fif_i 是专家 ii 实际分到的 token 比例，PiP_i 是路由器给它的平均概率。辅助损失的梯度会和语言建模的梯度互相干扰，系数大了伤效果，小了压不住。

DeepSeek 在 2024-08-28 提出 无辅助损失的负载均衡 (Auxiliary-Loss-Free Load Balancing)：给每个专家一个偏置 bib_i，只在选 top-K 时加到分数上，不参与输出的加权；每步训练后看负载，超载的专家 bib_i 减一个小量，欠载的加一个小量。偏置不经过梯度，不会干扰主损失。DeepSeek-V3 用这种方法，外加一个系数很小的序列级辅助损失防止单条序列内极端失衡。

7残差流：Hyper-Connections 与 mHC

残差连接的恒等映射

自 2015 年 ResNet 以来，残差连接的形式没有变过：xl+1=xl+F(xl)x_{l+1} = x_l + F(x_l)。展开多层得到 xL=xl+∑iF(xi)x_L = x_l + \sum_i F(x_i)，浅层的信号原样传到深层，反向传播时梯度也有一条不经过任何变换的通路。这条恒等映射是深层网络能稳定训练的主要原因。

Hyper-Connections：把残差流加宽

字节跳动的 Hyper-Connections（2024-09-29）把残差流从一条 CC 维向量扩成 nn 条（扩展率 nn，常取 4），再用三个小矩阵控制它们和层之间的连接：

xl+1=Hlres xl+Hlpost⊤ F ⁣(Hlprexl)\displaystyle x_{l+1} = H_l^{\text{res}}\, x_l + H_l^{\text{post}\top}\, F\!\left(H_l^{\text{pre}} x_l\right)xlx_l 的形状是 n×Cn \times C

HpreH^{\text{pre}}（1×n1 \times n）把 nn 条流加权合成一条，作为这一层的输入；HpostH^{\text{post}}（1×n1 \times n）把这一层的输出按权重写回各条流；HresH^{\text{res}}（n×nn \times n）在流之间混合。层本身的计算量不变，多出来的只是几个 n×nn \times n 的小矩阵。论文报告在稠密和 Mixture-of-Experts 模型的预训练上都有明显提升。

不受约束的混合矩阵会放大信号

DeepSeek 在 2025-12-31 上传的 mHC 论文指出了问题：HresH^{\text{res}} 没有任何约束，跨越多层以后，信号经过的是连乘 ∏Hres\prod H^{\text{res}}，恒等映射不复存在。论文在一个 27B 模型上测了这个连乘矩阵的最大行和与最大列和（对应前向和反向的最坏放大倍数），峰值接近 3000；训练到 12K 步左右损失突然上升，和梯度范数的异常同时出现。

mHC：约束到双随机矩阵

流形约束的 Hyper-Connections (Manifold-Constrained Hyper-Connections, mHC) 把 HresH^{\text{res}} 投影成双随机矩阵：所有元素非负，每行之和、每列之和都是 1。投影用 Sinkhorn-Knopp 算法：先对原始参数取指数变成正矩阵，再交替做行归一化和列归一化，迭代 20 次。HpreH^{\text{pre}} 和 HpostH^{\text{post}} 则用 sigmoid 限制为非负。

双随机矩阵有三个性质正好对应稳定性：

  • 谱范数不超过 1，单层不会放大信号。
  • 两个双随机矩阵的乘积仍是双随机矩阵，连乘多少层都保持这个性质。
  • 双随机矩阵的集合（Birkhoff 多胞形）是所有置换矩阵的凸包，所以 HresH^{\text{res}} 等于若干种“把流重新排列”的加权平均，各流信号的均值守恒。n=1n = 1 时它退化成标量 1，就是普通的残差连接。

约束以后，27B 模型的最大增益从约 3000 降到约 1.6，损失曲线和梯度范数恢复平稳，最终损失比基线低 0.021。下游评测上 mHC 全面超过基线，大多数也超过 HC，例如 BBH 从基线的 43.8 提到 51.0（HC 是 48.9），DROP 从 47.0 提到 53.9。加宽残差流会让访存量变成原来的 nn 倍，论文用算子融合、重计算和流水线通信重叠，把 n=4n = 4 时的额外训练时间压到 6.7%。

这篇论文的实验规模是 3B、9B、27B，正文说内部更大规模的训练也验证了结论；论文本身没有说明哪个已发布的模型用了 mHC。

8位置编码与长上下文：从 8K 到 100 万 token

GPT-4 发布时有 8K 和 32K 两个版本。2023-11-06 的 GPT-4 Turbo 到了 128K，同月 Claude 2.1 到 200K，2024-02-15 的 Gemini 1.5 Pro 到 100 万，技术报告里在 1000 万 token 内的检索召回率超过 99%。把上下文做长要解决三件事：位置编码在训练长度以外失效、长序列的训练显存、模型是否真的用得上这么长的内容。

RoPE 为什么不能直接外推

RoPE 把 Query 和 Key 的每两个维度看成一个平面向量，按位置 mm 旋转角度 mθim\theta_i，第 ii 对维度的频率是 θi=b−2i/d\theta_i = b^{-2i/d}，bb 通常取 10000。两个向量旋转后的点积只取决于位置差 m−nm - n，这就是相对位置。

前面的维度频率高，几个 token 就转一圈，负责区分近距离位置；后面的维度频率低，有的周期比训练长度还长，在训练中只见过一小段角度。推理时位置超出训练长度，这些低频维度会转到从没见过的角度，注意力分数随之失常。

位置插值、NTK 和 YaRN

Meta 的 位置插值 (Position Interpolation)（2023-06-27）把位置压回训练范围：要从 LL 扩到 L′L'，就把位置 mm 换成 m⋅L/L′m \cdot L / L'。所有角度都落在见过的范围内，LLaMA 7B 到 65B 微调不到 1000 步就扩到 32768。缺点是所有维度一起压缩，高频维度原本用来区分相邻 token，压缩后相邻 token 的角度差变小，近距离分辨率下降。

几乎同时，社区提出 NTK-aware 缩放：不改位置，改底数 bb，低频维度被拉伸得多，高频维度几乎不动。

YaRN（2023-08-31）把这个思路做细，按每对维度的波长分别处理：波长远小于训练长度的维度不插值，波长超过训练长度的维度按位置插值的比例压缩，中间的维度线性过渡。另外给注意力 logit 乘一个温度系数，补偿插值后注意力分布变平的问题，系数满足 1/t=0.1ln⁡s+1\sqrt{1/t} = 0.1 \ln s + 1，ss 是扩展倍数。论文报告所需的训练 token 是之前方法的 1/10，训练步数是 1/2.5。DeepSeek-V3 用 YaRN 分两阶段把上下文从 4K 扩到 32K 再到 128K，Qwen 系列也用它。

另一种更直接的做法是预训练时就把底数调大：Llama 3 把 bb 从 10000 改成 500000，低频维度转得更慢，后续扩展更容易。

长序列怎么训练

一条 128K token 的序列，激活值放不进一张卡。上下文并行 (Context Parallelism) 把序列切到多张卡上，Ring Attention（2023-10-03）是其中一种：每张卡负责一段 Query，各卡的 Key/Value 块沿环形传递，每张卡依次和所有块算注意力，通信和计算重叠。实际训练一般是先用短序列预训练，最后几个阶段再逐步拉长，长数据只占总量的一小部分。

能放进去不等于能用上

斯坦福的 Liu 等人在 2023-07 的 Lost in the Middle 里发现，相关信息放在上下文开头或结尾时模型答得最好，放在中间时明显变差，曲线呈 U 形。“大海捞针”（Needle in a Haystack）测试把一句无关的话插进长文档，问模型那句话的内容，很多模型能做到接近满分。NVIDIA 的 RULER（2024-04-09）指出这个测试太简单，加入多根针、多跳追踪、聚合统计等任务后，17 个声称支持 32K 以上的模型里，只有一半在 32K 时还能保持合格的表现。

长上下文和检索增强生成 (Retrieval-Augmented Generation, RAG) 各有代价。前者省去切块和检索带来的信息丢失，代价是每次请求都要预填充大量 token；后者便宜，但检索漏掉的内容模型看不到。实际系统通常先检索，再把检索结果放进一个较长的上下文里。

9预训练：数据、目标、优化器和精度

超过 Chinchilla 的训练量

DeepMind 的 Chinchilla（2022-03）给出了固定训练算力下的最优配比：每个参数约 20 个 token。这个结论只算训练成本。模型上线以后，推理成本按参数量和调用次数计，部署越广，越值得把一个小模型训得更久。Llama 3 的 8B 模型训练了超过 15T token，约为 Chinchilla 最优量的 90 倍，405B 模型是 15.6T token。2024 年以后，几乎所有开源模型的训练量都远超 Chinchilla 配比。

数据质量

训练量变大以后，网页数据的总量反而成了约束，筛选和合成越来越重要。

  • 微软的 Phi-1（2023-06-20）用“教科书质量”的数据训练 1.3B 的代码模型：约 6B token 筛选过的网页和 1B token 由 GPT-3.5 生成的教科书和练习，HumanEval 达到 50.6%，超过很多大得多的模型。
  • Hugging Face 的 FineWeb（2024-06-25）从 96 个 Common Crawl 快照里清洗出 15T token，并公开每一步过滤的消融实验。FineWeb-Edu 再用 Llama-3-70B-Instruct 给样本标注教育价值，训练一个分类器筛出 1.3T token，在知识和推理类评测上明显好于未筛选的版本。
  • 退火 (Annealing)：Llama 3 在学习率衰减的最后阶段换成高质量数据（数学、代码、精选文本），用少量 token 带来不成比例的提升。这一阶段后来也被叫作中期训练 (Mid-training)。
  • 合成数据：用强模型改写网页、生成题目和解答、生成带推理过程的长样本。后训练里的数据大部分已经是合成的。

多 token 预测

Meta 的 Gloeckle 等人在 2024-04-30 提出 多 token 预测 (Multi-Token Prediction, MTP)：在共享的主干上接 nn 个独立的输出头，第 ii 个头预测第 ii 个之后的 token。训练信号变密，模型被迫提前规划。13B 模型在 HumanEval 上多解出 12% 的题，MBPP 多 17%；训练时额外的头可以在推理时做自推测解码，4-token 版本推理最多快 3 倍。

DeepSeek-V3 的 MTP 换了结构：额外的预测模块是串行的，第 kk 个模块把第 k−1k-1 个模块的输出表示和第 kk 个未来 token 的嵌入拼起来，再经过一个 Transformer 块，预测下一个位置。这样每一级预测都保留了完整的因果链。V3 只用了一级（多预测 1 个 token）。推理时这个模块可以丢掉，也可以拿来做推测解码，第二个 token 的接受率在 85% 到 90%，生成速度约为 1.8 倍。

Muon 优化器

AdamW 从 2017 年起一直是大模型训练的默认优化器。2024 年 10 月，Keller Jordan 在 NanoGPT 速度竞赛中提出 Muon：对二维权重矩阵，先算动量 MM，再把 MM 正交化后作为更新量。正交化是指做奇异值分解 M=UΣV⊤M = U \Sigma V^\top 后把所有奇异值换成 1，得到 UV⊤U V^\top；实际用 5 步 Newton-Schulz 迭代近似，不需要真的做分解。

直观地说，梯度矩阵往往被少数几个方向主导，直接用来更新，其他方向几乎学不到东西；正交化把每个方向的步长拉平。嵌入层、输出层和一维参数（归一化的缩放系数）仍然用 AdamW。

月之暗面在 2025-02-24 的论文里把 Muon 推到大规模：加上权重衰减，并按矩阵形状调整更新的缩放，使其均方根和 AdamW 一致，这样学习率等超参数可以直接沿用 AdamW 的。缩放律实验显示在计算最优训练下 Muon 约有 2 倍的计算效率，他们用它训练了 16B 总参数的 Moonlight。2025-07 的 Kimi K2（1T 总参数）用 MuonClip：在 Muon 之外，如果某个头的最大注意力 logit 超过阈值，就按比例缩小这个头的 WQW_Q 和 WKW_K。论文报告 15.5T token 的预训练没有出现一次损失尖峰。

FP8 训练

BF16 是 2020 年以后大模型训练的默认精度。FP8 只有 8 位，H100 上的矩阵乘法吞吐量是 BF16 的两倍，但动态范围很小，激活值里少数几个特别大的数会让整块张量的缩放失效。

DeepSeek-V3 是第一个公开在 671B 规模上用 FP8 完成预训练的模型，做法是细粒度量化：激活按 1 × 128 的小条、权重按 128 × 128 的块，各自用一个缩放系数，离群值只影响自己所在的那一小块。FP8 矩阵乘法在 Tensor Core 里累加的精度不够，V3 每累加 128 个元素就把部分和搬到 CUDA Core 上用 FP32 继续累加。主权重、优化器状态和对精度敏感的算子（嵌入、归一化、注意力的一部分）仍保持高精度。V3 全部训练用了 278.8 万 H800 GPU 小时，论文说训练过程中没有出现不可恢复的损失尖峰，也没有回滚。

10推理服务：让一张卡同时服务更多请求

FlashAttention

注意力的标准实现要把 n×nn \times n 的分数矩阵写进显存再读出来做 softmax。Tri Dao 等人的 FlashAttention（2022-05）把 Query、Key、Value 切成块，放进片上 SRAM 里算，用在线 softmax 一边算一边更新归一化常数，n×nn \times n 矩阵从不写回显存。结果完全精确，显存从平方降到线性。FlashAttention-2（2023-07-17）改进了线程块之间的并行和分工；FlashAttention-3（2024-07-11）针对 H100 的异步执行和 FP8，FP16 达到 740 TFLOPs/s（利用率 75%），FP8 接近 1.2 PFLOPs/s。

连续批处理和 PagedAttention

一批请求的输出长度不同，早结束的请求如果要等整批完成，算力就浪费了。连续批处理 (Continuous Batching) 在每一步解码后检查，有请求结束就立刻放入新的请求。

动态进出的请求让 KV cache 的显存管理变难：每个请求最终多长事先不知道，按最大长度预留会浪费，按实际长度分配会产生碎片。UC Berkeley 的 vLLM（2023-09-12）借用操作系统的分页：PagedAttention 把每个请求的 KV cache 切成固定大小的块（默认 16 个 token），块在显存里不必连续，每个请求有一张块表记录逻辑块到物理块的映射。浪费只发生在每个请求的最后一块。并行采样多个回答时，共同前缀的块可以共享，写入时再复制。论文报告在相同延迟下吞吐量是之前系统的 2 到 4 倍。

前缀缓存

很多请求开头相同：同一个系统提示词、同一段多轮对话历史、agent 每一轮都带着前面所有工具调用的结果。SGLang（2023-12-12）的 RadixAttention 用基数树保存所有已算过的 KV cache，新请求先在树里匹配最长公共前缀，只计算剩下的部分。各家 API 后来都提供了提示词缓存，命中缓存的输入 token 按很低的价格计费。

预填充和解码分开

预填充受算力限制，解码受带宽限制，放在同一批里会互相拖累：一个长提示词的预填充会让同批所有请求的下一个 token 都延迟。有两种处理方式。Sarathi（2023-08-31）的分块预填充 (Chunked Prefill) 把长提示词切成小块，每块和一批解码请求混在一起执行，让每一步的计算量均匀。DistServe（2024-01-18）把预填充和解码放到不同的 GPU 上，各自选择最合适的并行方式，KV cache 算完以后传过去；在给定的首 token 延迟和每 token 延迟约束下，可服务的请求量最多提高 7.4 倍。DeepSeek-V3 的部署也是预填充和解码分开的。

推测解码

解码一步只算一个 token，算力大量闲置；如果能一次验证多个 token，就能用闲置的算力换时间。推测解码 (Speculative Decoding) 由 Google 的 Leviathan 等人（2022-11-30）和 DeepMind 的 Chen 等人（2023-02-02）分别提出：

  • 一个小的草稿模型 qq 先连续生成 γ\gamma 个 token。
  • 大模型 pp 一次前向同时算出这 γ\gamma 个位置各自的分布（和预填充一样是并行的）。
  • 从第一个草稿 token 开始逐个检验：以概率 min⁡(1,p(x)/q(x))\min(1, p(x)/q(x)) 接受；一旦拒绝，就从修正分布 norm(max⁡(0,p−q))\text{norm}(\max(0, p - q)) 里重新采样一个 token，后面的草稿全部作废。

可以证明，这样得到的 token 分布和直接从大模型采样完全一样，加速比取决于草稿的接受率。

后来的改进集中在怎么更便宜地产生好草稿。Medusa（2024-01-19）在大模型上加几个额外的解码头，一次猜后面几个位置，用树状注意力同时验证多条候选，报告 2.2 到 3.6 倍加速。EAGLE（2024-01-26）不在 token 层面而在倒数第二层的特征上做自回归预测，在 LLaMA2-Chat 70B 上延迟降低 2.7 到 3.5 倍。前面提到的 MTP 模块也可以直接当草稿。

量化

推理时的权重可以比训练时压得更狠。GPTQ（2022-10-31）用二阶信息逐列量化权重，把 175B 模型压到 3 或 4 位。AWQ（2023-06-01）发现只有约 1% 的权重通道对误差影响大，而这些通道要看激活值的大小才能找出来；它把这些通道按比例放大后再量化，避免了混合精度。2025 年起，硬件开始原生支持 4 位浮点格式：gpt-oss 把 Mixture-of-Experts 层的权重用 MXFP4 发布，120b 模型能放进一张 80 GB 的显卡。

11偏好对齐：从 RLHF 到 DPO

RLHF 的三步

OpenAI 的 InstructGPT（2022-03-04）确立了 GPT-4 时代的对齐流程：

  • 监督微调 (Supervised Fine-Tuning, SFT)：用人工写的示范回答微调预训练模型。
  • 训练奖励模型：同一个问题采样几个回答，让标注者排序；奖励模型 rϕr_\phi 按 Bradley-Terry 模型拟合这些比较，P(yw≻yl)=σ(rϕ(x,yw)−rϕ(x,yl))P(y_w \succ y_l) = \sigma\big(r_\phi(x, y_w) - r_\phi(x, y_l)\big)。
  • 强化学习：用 PPO 让策略 πθ\pi_\theta 最大化奖励，同时用 KL 散度限制它离 SFT 模型 πref\pi_{\text{ref}} 不要太远，否则策略会找到奖励模型的漏洞。
max⁡πθ  Ex, y∼πθ[rϕ(x,y)]−β KL(πθ ∥ πref)\displaystyle \max_{\pi_\theta}\; \mathbb{E}_{x,\, y \sim \pi_\theta}\big[ r_\phi(x, y) \big] - \beta\, \mathrm{KL}\big( \pi_\theta \,\|\, \pi_{\text{ref}} \big)RLHF 的优化目标

InstructGPT 的 1.3B 模型在人工评估中比 175B 的 GPT-3 更受欢迎。但这套流程的工程负担很重：PPO 训练时显存里同时有策略、参考模型、奖励模型和价值模型四个网络，每一步都要在线采样，超参数敏感。

DPO：把奖励模型消掉

斯坦福的 Rafailov 等人在 2023-05-29 上传 直接偏好优化 (Direct Preference Optimization, DPO)。推导分三步。第一步，上面这个带 KL 约束的目标有解析解：

π∗(y∣x)=1Z(x) πref(y∣x) exp⁡ ⁣(1βr(x,y))\displaystyle \pi^*(y \mid x) = \frac{1}{Z(x)}\, \pi_{\text{ref}}(y \mid x)\, \exp\!\Big( \frac{1}{\beta} r(x, y) \Big)Z(x)Z(x) 是归一化常数，算不出来

第二步，反过来把奖励用策略表示：r(x,y)=βlog⁡π∗(y∣x)πref(y∣x)+βlog⁡Z(x)r(x, y) = \beta \log \frac{\pi^*(y \mid x)}{\pi_{\text{ref}}(y \mid x)} + \beta \log Z(x)。第三步，代入 Bradley-Terry 模型，两个回答的奖励相减，算不出来的 βlog⁡Z(x)\beta \log Z(x) 正好抵消，剩下一个只含策略的分类损失：

训练只需要策略和参考模型两个网络，数据是现成的偏好对，不用在线采样，和普通的监督学习差不多。论文的副标题是“你的语言模型其实是一个奖励模型”：策略和参考模型的对数概率比，就是隐式的奖励。

DPO 发布后很快成了开源模型对齐的默认做法，Zephyr、Tülu 2、Llama 3 都用它。后续变体针对它的几个弱点：KTO（2024-02-02）只需要单个回答“好”或“不好”的标签，不需要成对数据；SimPO 去掉参考模型，用长度归一化的平均对数概率当奖励，缓解 DPO 偏爱长回答的问题。

DPO 是离线方法，只能在已有的偏好对上学，不会探索新的回答；对数学和代码这类有标准答案的任务，在线强化学习后来又回到了主导地位（见第 13 节）。

Constitutional AI 和 AI 反馈

Anthropic 的 Constitutional AI（2022-12-15）用一份书面原则（“宪法”）代替大部分人工的无害性标注。监督阶段，模型先回答，再按原则批评自己的回答并改写，用改写后的回答微调；强化学习阶段，由模型按原则比较两个回答，生成偏好标签，这叫 AI 反馈强化学习 (Reinforcement Learning from AI Feedback, RLAIF)。人只需要写原则，不再逐条标注有害内容。现在大多数后训练流程里的偏好数据，相当一部分来自模型打分。

12推理（上）：测试时多花计算

思维链

Google 的 Jason Wei 等九人在 2022-01-28 上传 思维链 (Chain-of-Thought, CoT) 提示：few-shot 示例里不只给答案，还写出中间步骤，模型就会模仿着先写步骤再给答案。PaLM 540B 用 8 个这样的示例，GSM8K 从 17.9% 提到 56.9%，超过了微调过的 GPT-3 加验证器。增益只在大约 100B 参数以上才出现，小模型写出步骤反而更差。几个月后 Kojima 等人发现，提示词里只加一句 “Let's think step by step” 也有类似效果。

思维链有效的一个解释是计算量：Transformer 每生成一个 token 做一次固定深度的前向，直接输出答案，所有推理只能在这些层里完成；先写中间步骤，每个步骤都成为后续计算的输入，可用的串行计算步数随输出长度增长。2023 年有几篇理论工作证明，固定深度的 Transformer 解不了某些需要串行计算的问题，允许生成足够长的中间步骤后就能解。

自洽性和树搜索

自洽性 (Self-Consistency)（2022-03-21）对同一个问题采样多条推理路径，取出现最多的答案。理由是正确的推理往往殊途同归，错误的各错各的。GSM8K 上比贪心解码的思维链高 17.9 个百分点。

思维树 (Tree of Thoughts)（2023-05-17）把推理拆成若干步，每一步生成几个候选，让模型自己评估哪些有希望，再用广度或深度优先搜索往下展开，可以回溯。在 24 点游戏上，GPT-4 加思维链只解出 4%，思维树解出 74%。

结果奖励和过程奖励

要从多个候选里选最好的，需要一个打分模型。结果奖励模型 (Outcome Reward Model) 只看最终答案对不对；过程奖励模型 (Process Reward Model) 给每一步打分。OpenAI 的 Let's Verify Step by Step（2023-05-31）请人标注了 80 万个步骤级标签（公开为 PRM800K），结论是过程监督明显优于结果监督：用过程奖励模型从多个候选里挑选，在 MATH 测试集的一个代表性子集上解出 78% 的题。

过程奖励的问题是标注贵，而且“一步对不对”本身不好定义。DeepSeek-R1 的报告专门列出过程奖励模型作为不成功的尝试：自动标注的步骤标签不可靠，模型学会了讨好奖励模型。

测试时计算的最优分配

Google DeepMind 的 Snell 等人在 2024-08-06 系统比较了几种测试时多花计算的方式：

  • 并行：采样 NN 个回答，用验证器挑最好的（Best-of-N），或者多数投票。
  • 串行：让模型看着自己上一版回答修改，一轮轮改下去。
  • 搜索：用过程奖励模型在每一步做束搜索 (Beam Search)，保留得分高的分支。

结论是没有一种方式总是最好：简单题适合串行修改，难题适合并行或搜索。按题目难度分配计算，效率是 Best-of-N 的 4 倍以上；在总计算量相同时，小模型加测试时计算，在小模型本来有一定成功率的题上，可以超过大 14 倍的模型。

13推理（下）：用强化学习训练长思维链

o1：把思维链变成训练目标

2024-09-12，OpenAI 发布 o1-preview。官方文章说，o1 用强化学习训练模型在回答前生成很长的思维链，模型学会了拆解问题、发现并纠正自己的错误、换一种方法重试。两张图是这次发布的核心：o1 的准确率随强化学习的训练计算和测试时的思考计算都呈对数线性增长。AIME 2024 上，GPT-4o 平均解出 12%，o1 单次采样 74%。思维链本身不展示给用户，只给一份摘要。

o1 没有公开方法。之后半年里，开源社区复现的主要线索是一个问题：只用答案是否正确作为奖励，强化学习能不能自己学出长推理。

可验证奖励

可验证奖励的强化学习 (Reinforcement Learning with Verifiable Rewards, RLVR) 这个名字出自 AI2 的 Tülu 3（2024-11-22）。奖励由程序判定：数学题比对最终答案，代码题跑测试用例，指令遵循题检查格式约束是否满足。和 RLHF 的奖励模型相比，规则奖励不会被模型“讨好”，可以放心地训练很多步；代价是只适用于答案能自动判对错的任务。

DeepSeek-R1-Zero 和 R1

DeepSeek-R1 在 2025-01-20 发布，论文 2025-01-22 上传。

R1-Zero 直接在 DeepSeek-V3-Base 上做强化学习，没有任何监督微调。提示模板只要求模型把推理写在 <think> 标签里、答案写在 <answer> 标签里；奖励只有两项：答案是否正确（规则判定），格式是否正确。论文刻意没用神经网络奖励模型，理由是大规模训练中奖励模型会被钻空子。

训练过程中，AIME 2024 的单次准确率从 15.6% 升到 71.0%，64 次多数投票达到 86.7%。回答的平均长度随训练步数持续增长，从几百 token 涨到近一万，没有人教它写长。论文记录了一个中间版本在推理中途写出 “Wait, wait. Wait. That's an aha moment I can flag here.”，然后重新检查前面的步骤，作者称之为“顿悟时刻”。R1-Zero 的问题是可读性差，中英文混杂。

R1 在此基础上加了四个阶段：

  • 冷启动：用几千条人工整理的长思维链数据微调 V3-Base，让输出格式可读。
  • 推理强化学习：和 R1-Zero 相同的规则奖励，加一个语言一致性奖励（思维链里目标语言的比例）。
  • 拒绝采样和再次微调：用上一阶段的模型生成约 60 万条推理数据（只保留答案正确的），加上约 20 万条写作、问答等非推理数据，重新微调 V3-Base。
  • 全场景强化学习：推理题用规则奖励，开放式问题用奖励模型评估有用性和无害性。

R1 在 AIME 2024 上达到 79.8%，MATH-500 达到 97.3%，和 o1 相当，权重以 MIT 协议开源。

GRPO

R1 用的强化学习算法是 组相对策略优化 (Group Relative Policy Optimization, GRPO)，最早出现在 2024-02-05 的 DeepSeekMath 里。PPO 需要一个和策略差不多大的价值模型来估计每个 token 的优势（这一步比平均水平好多少），显存和计算都翻倍。GRPO 去掉价值模型，对每道题采样一组 GG 个回答，用组内的相对好坏当优势：

A^i=ri−mean(r1,…,rG)std(r1,…,rG)\displaystyle \hat{A}_i = \frac{r_i - \text{mean}(r_1, \dots, r_G)}{\text{std}(r_1, \dots, r_G)}回答 ii 的所有 token 共用这个优势

其余部分和 PPO 一样：用新旧策略的概率比乘优势，比值限制在 [1−ε,1+ε][1-\varepsilon, 1+\varepsilon] 内防止一步走太远，再减去和参考模型之间的 KL 散度。对规则奖励来说，一道题的 GG 个回答里有对有错，对的那些优势为正，错的为负，模型就往对的方向调整。

GRPO 在 R1 之后被大量复现，也暴露出几个问题。字节跳动和清华的 DAPO（2025-03-18）提出四处修改：裁剪上界放宽（下界 0.2、上界 0.28），防止低概率 token 的概率涨不上去、熵过快坍缩；动态采样，丢掉一组全对或全错的题（这些题优势全是 0，没有梯度）；损失按 token 平均而不是按回答平均；对超长回答做软惩罚。用 Qwen2.5-32B 基座在 AIME 2024 上达到 50 分。Sea AI Lab 的 Dr. GRPO（2025-03-26）指出 GRPO 损失里按回答长度归一化会让错误回答越写越长，去掉这一项和标准差归一化以后，长度增长变得更合理。

蒸馏

R1 论文的另一个结论：用 R1 生成的约 80 万条数据直接微调 Qwen2.5 和 Llama 的 1.5B 到 70B 模型，效果远好于在同样的小模型上直接做强化学习。R1-Distill-Qwen-32B 在 AIME 2024 上达到 72.6%。在小模型上，模仿大模型的推理轨迹比自己探索划算得多。Qwen3 的小模型、gpt-oss 都用了从大模型蒸馏的推理数据。

斯坦福的 s1（2025-01-31）把这件事推到极端：只用 1000 道精选题和对应的推理轨迹微调 Qwen2.5-32B。它还提出预算强制 (Budget Forcing)：模型想结束思考时，在后面追加一个 “Wait”，逼它继续想；想太久就强行截断。追加 “Wait” 能让 AIME 2024 从 50% 提到 57%。

思考预算和混合推理

推理模型对简单问题也会写很长，延迟和费用都高。腾讯的 Chen 等人（2024-12-30）专门研究了这种过度思考 (Overthinking)：问 2 + 3 等于几，o1 类模型会反复验证好几遍。产品上的对策是让同一个模型支持两种模式并可控预算：Claude 3.7 Sonnet（2025-02-24）在同一个模型里提供标准回答和扩展思考，开发者可以设置思考的 token 上限；Qwen3（2025-04-29）在聊天模板里用 /think 和 /no_think 切换，并支持思考预算；Gemini 2.5 也提供思考预算参数。

2025 年以后

  • 推理训练扩展到可验证之外的任务：用规则加模型评分（rubric）打分，覆盖写作、医学、研究类问题。
  • 强化学习的计算量占比上升：DeepSeek-V3.2 的报告说后训练的计算预算已超过预训练成本的 10%。
  • 推理和工具调用合并：模型在思维链中途搜索网页、运行代码，再根据结果继续推理（见下一节）。2025 年 7 月，OpenAI 和 Google DeepMind 的实验模型都在国际数学奥林匹克 (IMO) 上达到金牌分数线，DeepSeek-V3.2-Speciale 在 IMO 和国际信息学奥林匹克 (IOI) 上也达到金牌水平。

14工具调用：模型输出结构化的动作

从文本里插调用到函数调用接口

Meta 的 Toolformer（2023-02-09）让模型在生成的文本里插入 API 调用，例如 [Calculator(400/1400)]，调用结果填回文本后继续生成。训练数据是模型自己标注的：在各处尝试插入调用，如果插入后后续文本的损失下降，就保留这条样本。

产品上的做法更直接。2023-06-13，OpenAI 在 API 里加入 函数调用 (Function Calling)：开发者用 JSON Schema 描述可用的函数（名字、用途、参数类型），模型决定调不调用、调哪个，输出一段符合 schema 的 JSON；应用程序执行函数，把结果作为一条新消息放回对话，模型读了结果再继续。模型本身不执行任何东西，它只负责输出结构化的动作。后来的版本允许一次输出多个并行调用。

ReAct：推理和动作交替

ReAct（2022-10-06）把这个循环写成固定格式：Thought（这一步想做什么），Action（调用什么工具），Observation（工具返回什么），然后下一轮 Thought。和只思考不行动相比，模型能用观察结果纠正自己；和只行动不思考相比，每一步的意图是显式的，出错时容易定位。今天几乎所有 agent 的主循环都是这个结构，只是 Thought 变成了推理模型的思维链，Action 变成了函数调用。

Reflexion（2023-03-20）在循环外再加一层：任务失败后，让模型用自然语言总结失败原因，存进记忆，下一次尝试时带上。

MCP：工具的接口标准

每个应用各自定义工具格式，同一个工具（读数据库、查日历、操作 GitHub）要为每个应用重写一遍。Anthropic 在 2024-11-25 发布 模型上下文协议 (Model Context Protocol, MCP)：工具提供方实现一个 MCP 服务器，对外暴露三类东西：工具（可调用的函数）、资源（可读取的数据）、提示词模板；应用里内置 MCP 客户端，通过 JSON-RPC 发现和调用服务器的能力。服务器可以是本地进程，也可以是远程服务。2025 年 3 月 OpenAI 宣布在 Agents SDK 里支持 MCP，之后各大厂商和开发工具陆续接入。

操作电脑和浏览器

2024-10-22，Anthropic 发布 Claude 3.5 Sonnet 的 Computer Use：模型看屏幕截图，输出鼠标移动、点击、键盘输入等动作，由宿主程序执行后再截图，循环往复。OpenAI 在 2025-01-23 发布 Operator，背后的模型叫 CUA（Computer-Using Agent）。这类 agent 不依赖任何 API，任何图形界面都能操作，代价是每一步都要传一张截图，速度慢，错误率比调用 API 高。

编程 agent

普林斯顿的 SWE-bench（2023-10-10）从 12 个 Python 仓库的真实 GitHub issue 和对应 pull request 里收集了 2294 道题：给模型整个仓库和 issue 描述，要求修改代码，用原 pull request 里的测试判定是否修好。发布时最好的 Claude 2 只解出 1.96%。2024-08，OpenAI 和原作者一起发布 SWE-bench Verified，人工筛出 500 道描述清楚、测试合理的题。

SWE-agent（2024-05-06）的贡献在接口：给模型设计专门的命令（带行号的文件查看器、按行编辑、在仓库里搜索），而不是让它直接用原始的 shell，解题率显著上升，论文称之为 agent-计算机接口 (Agent-Computer Interface)。2025 年起，Claude Code（2025-02-24 预览）、OpenAI Codex 这些在终端或云端直接操作代码仓库的产品成为编程 agent 的主要形态。Kimi K2 在非思考模式下的 SWE-bench Verified 达到 65.8%。

Agent 的训练

早期的 agent 只靠提示词搭起来，模型本身没有专门为多轮工具调用训练过。2025 年的模型把 agent 任务放进了强化学习：每条采样轨迹里包含真实的工具调用和返回结果，奖励看任务最终是否完成。难点在环境：每类任务都需要一个能执行动作、能自动判定结果的环境。Kimi K2 搭了一条合成流水线，批量生成工具定义、任务和评分标准；DeepSeek-V3.2 合成了超过 1800 个环境和 8.5 万个复杂任务用于强化学习。

上下文管理

一个编程任务跑几百步，工具返回的内容很快会占满上下文。常见做法有三种：把早期的工具输出压缩成摘要（compaction），让 agent 把计划和进度写进文件、需要时再读，把子任务交给独立上下文的子 agent，只取回结论。METR 在 2025-03-18 提出用 任务时长视界 (Time Horizon) 衡量 agent：人类专家需要多长时间完成、而模型有 50% 成功率的任务。Claude 3.7 Sonnet 约为 50 分钟，自 2019 年起这个数字大约每 7 个月翻一倍。

15多模态：从外接视觉编码器到原生多模态

投影层方案

GPT-4 发布时就展示了看图能力，但图像输入到 2023 年 9 月才随 GPT-4V 开放。开源方面，威斯康星大学和微软的 LLaVA（2023-04-17）给出了最简单的结构：一个预训练好的 CLIP ViT-L/14 视觉编码器，把图像变成一串特征；一个线性投影层把这些特征映射到语言模型的词嵌入空间；后面接 Vicuna 语言模型。图像特征就像一串额外的 token，和文字一起输入。

训练分两步：先冻结视觉编码器和语言模型，只用 59.5 万对图文数据训练投影层，让两边对齐；再用 15.8 万条由纯文本 GPT-4 根据图像描述生成的多轮对话，同时微调投影层和语言模型。LLaVA-1.5 把线性层换成两层的多层感知机，此后几乎所有开源视觉语言模型都是这个“编码器加投影层加语言模型”的结构。

分辨率

CLIP 编码器的输入是固定的 224 或 336 像素，文档、图表、截图里的小字看不清。一种做法是把高分辨率图切成多块，每块单独编码再拼起来。阿里的 Qwen2-VL（2024-09-18）让视觉编码器直接接受任意分辨率，图像按原始尺寸切成 14 × 14 的小块，相邻 2 × 2 个块的特征再合并成一个 token，所以图越大 token 越多。位置编码相应扩展为 M-RoPE，把旋转维度分成时间、高、宽三段，文本、图像、视频共用一套编码。

早期融合

投影层方案里，图像和文字走不同的入口，模型只能读图不能生成图。Meta 的 Chameleon（2024-05-16）用早期融合 (Early Fusion)：一个图像分词器把 512 × 512 的图像量化成 1024 个离散 token（码本 8192），和文字 token 放进同一个词表，同一个 Transformer 从头一起训练，既能读也能生成任意交错的图文序列。论文专门讨论了训练稳定性，混合模态训练中不同模态的 logit 尺度会互相竞争，需要 QK-Norm 等手段压住。

2024-05-13 发布的 GPT-4o 是一个端到端处理文本、图像和音频的模型。在此之前，ChatGPT 的语音模式由三个模型串联：语音识别转文字，GPT-4 生成文字，再合成语音，平均延迟 5.4 秒，语调、笑声、多人说话这些信息在第一步就丢掉了。GPT-4o 直接输入和输出音频，最快 232 毫秒、平均 320 毫秒响应。2025-03-25，GPT-4o 的原生图像生成上线，图像由同一个对话模型直接生成。

16安全：越狱、后门和对齐伪装

越狱

对齐训练让模型拒绝有害请求，但拒绝只是一种被训练出来的行为，可以被绕过。CMU 的 Zou 等人（2023-07-27）提出 GCG：在有害请求后面接一段后缀，用贪心加梯度的坐标搜索优化后缀里的 token，目标是让模型以“Sure, here is”开头回答。在开源的 Vicuna 上优化出来的后缀，可以迁移到 ChatGPT、Bard、Claude 等闭源模型上。Anthropic 2024-04 报告的多轮示例越狱 (Many-shot Jailbreaking) 利用长上下文：在提示词里放几百段虚构的“有害问题加顺从回答”的对话，模型会按上下文学习的规律跟着回答。

潜伏的后门

Anthropic 的 Sleeper Agents（2024-01-10）故意训练了带后门的模型：提示里写年份是 2023 时写安全的代码，写 2024 时插入漏洞。然后用标准的安全训练去除：监督微调、强化学习、对抗训练。后门都没有被去掉，模型越大越顽固；对抗训练反而教会了模型更准确地识别触发条件，把不安全行为藏得更好。

对齐伪装

Anthropic 和 Redwood Research 在 2024-12-18 报告了 对齐伪装 (Alignment Faking)。实验告诉 Claude 3 Opus：它正在被训练成回答所有请求（包括有害的），只有免费用户的对话会用于训练。结果模型对免费用户的有害请求顺从了 14%，对付费用户几乎从不顺从。在顺从的情形里，模型的推理草稿几乎都写着：现在顺从，是为了避免被训练修改，以便在训练之外继续保持拒绝有害请求的偏好。真的用强化学习训练它顺从以后，这类推理的比例升到 78%。

2025-02 的涌现失配 (Emergent Misalignment) 是另一个意外：只用“写有漏洞的代码且不告诉用户”这一个窄任务微调 GPT-4o，模型在完全无关的问题上也开始给出恶意建议、宣称 AI 应该奴役人类。如果数据改成“用户为了安全课程主动要求写有漏洞的代码”，这个现象就不出现。

奖励漏洞和思维链监控

强化学习的模型会利用奖励的漏洞 (Reward Hacking)。在编程任务里，最常见的形式是修改或特判测试用例让测试通过，而不是修好代码；Claude 3.7 Sonnet 的系统卡专门记录了这类行为。

推理模型的思维链提供了一个监控手段：模型打算做什么，往往会先写在思维链里。Anthropic 的 Chen 等人（2025-05-08）测了这件事有多可靠：在提示里放一个暗示（比如“一位教授认为答案是 A”），模型用了暗示改变答案时，大多数情况下思维链里提到暗示的比例低于 20%；强化学习让模型更多地利用暗示，但提及的比例不跟着升。2025-07，来自 OpenAI、Google DeepMind、Anthropic、Meta 等机构的研究者联名发表文章，认为思维链可监控是一个“新的、脆弱的机会”，建议开发者在训练决策时考虑不要破坏它，例如不要直接对思维链施加优化压力。

审议式对齐

OpenAI 的 审议式对齐 (Deliberative Alignment)（2024-12-20）把安全规范的原文教给推理模型，训练它在回答前先在思维链里回忆相关条款、判断请求属于哪一类，再决定怎么回答。训练数据由模型自己生成、由另一个看得到规范的模型打分，不需要人写思维链。o 系列模型用这种方法，在提高越狱抵抗力的同时减少了过度拒绝。

17可解释性：从神经元到特征

叠加和稀疏自编码器

解读单个神经元一直很难，因为大多数神经元是多义的：同一个神经元在完全无关的语境下都会激活。一个解释是叠加 (Superposition)：模型需要表示的概念远多于神经元数，于是把概念编码成激活空间里的方向，许多方向近似正交地叠加在同一组神经元上。

稀疏自编码器 (Sparse Autoencoder) 尝试把这些方向找出来。给定模型某一层的激活 hh（维度 dd），学一个宽得多的编码 ff（维度 m≫dm \gg d），要求它能重建 hh，同时绝大多数分量为 0：

训练好以后，ff 的每个分量叫一个特征，通常只在一类语境下激活，人可以给它起名字。Cunningham 等人（2023-09-15）和 Anthropic 的 Towards Monosemanticity（2023-10-04，单层模型）几乎同时发表了这个方法。

Anthropic 的 Scaling Monosemanticity（2024-05-21）在 Claude 3 Sonnet 上训练了最多 3400 万个特征，找到了对应金门大桥、代码漏洞、谄媚、欺骗等概念的特征，而且同一个特征对文字和图片都响应。把金门大桥特征强行调高，模型在任何话题上都会把自己当成金门大桥，这个版本作为 Golden Gate Claude 公开了一天。OpenAI 在 2024-06 在 GPT-4 上训练了 1600 万个特征的稀疏自编码器。

归因图

特征回答了“模型在想什么”，没有回答“特征之间怎么算出结果”。Anthropic 2025-03-27 的电路追踪 (Circuit Tracing) 用一个替代模型把原模型的计算改写成特征之间的连接，画出单个提示词从输入到输出的归因图 (Attribution Graph)。在 Claude 3.5 Haiku 上的例子包括：回答“达拉斯所在州的首府”时，模型内部先激活“得克萨斯”，再从它得到“奥斯汀”，是真实的两步推理；写押韵诗时，模型在写下一行之前就已经选好了行末要押的词。

18评测：基准怎么换代

饱和

GPT-4 发布时最常引用的是 MMLU（57 个学科的选择题）和 GSM8K（小学数学应用题）。两年内前沿模型在两者上都超过 90%，分数之间的差距主要是噪声和标注错误。评测的问题从“模型会不会”变成了“题目能不能拉开差距”。

人类偏好和模型评审

LMSYS 的 Chatbot Arena 在 2023-05 上线：用户输入问题，两个匿名模型同时回答，用户投票，按 Bradley-Terry 模型算出排名分数。2024-03 的论文里已有超过 24 万票。它的问题在于普通用户的偏好受格式和长度影响很大，后来加了风格控制，把长度和 Markdown 格式的影响单独回归掉；2025-04 Meta 用一个专门为竞技场调过的实验版 Llama 4 上榜，引发了对榜单可操纵性的讨论。

MT-Bench 的论文（2023-06-09）研究了用 GPT-4 当评委 (LLM-as-a-Judge)：GPT-4 和人类评审的一致率超过 80%，与人类之间的一致率相当。它也有系统性偏差：偏爱排在前面的回答、偏爱更长的回答、偏爱自己生成的回答。

污染

公开基准的题目会进入网页，进而进入预训练数据。常见的应对方式：按时间切分，只用模型训练截止之后的新题（LiveCodeBench、每年的 AIME）；保留不公开的测试集（ARC-AGI 的私有集、HLE 的保留部分）；训练前对数据做去重和去污染（Tülu 3 专门公开了去污染流程）。

真实任务

2025 年的评测重心转向多步的真实任务：SWE-bench Verified 和 Terminal-Bench 测编程和命令行操作，τ-bench（2024-06）测和模拟用户、模拟数据库交互的客服任务，OSWorld（2024-04）测在真实操作系统里完成任务。第 14 节 提到的 METR 时长视界把这些任务统一换算成“相当于人类专家多少分钟的工作”。
