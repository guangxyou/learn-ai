12–16 年：博士期间做 model scaling

张祥雨

我当时在读博的时候，那个时间也其实非常好，也是赶到 12 年——大家都知道这个 AlexNet。其实它的方法跟之前的深度学习框架没有任何差别，但它最大的差别就是它做了 scale。所以说呢，你可以看到，影响整个深度学习、就人工智能深度学习，它最大的一个动力其实就是要做 scale。

当时 AlexNet 非常成功，那为什么呢？因为它刚好达到了那个时间的一个最佳的历史契机。我们说 scaling，按今天的观点，你要同时 scale 模型、数据和这个算力——刚好在 12 年那会儿嘛。

我是从 CV 出身的。CV 的话，就是在 09 年，像李飞飞他们团队就提出了这个 ImageNet，就是搞了一个 120 多万的这个数据集，当时你能跑完就已经很不容易了。所以 data scaling 就认为在那个时候已经不是问题，有人给了一个非常大的 data。

这个算力呢，英伟达大家都知道，在那个零几年就提出了 CUDA，一开始都是为科学计算，但是到 12 年左右，CUDA 的那个性能已经非常好，就是也有一些算力的支持。所以呢，可以认为在算力的这个 scaling 上也已经解决了。

所以呢，到那个时间点，最重要的一点就是谁能最先把 model scale up 上去。AlexNet 它就成功了——之前我们做的那些神经网络也就是几兆，它一下子搞到了 700 多兆。就是因为这样的一个契机，所以 AlexNet 成功了。

刚好我在那个时候读博呢，也是延续了相同的路线。所以我整个博士阶段呢，就是 12 年到 16 年，我所做的事情其实也就是在做 model scaling，我想把模型做到更大。而把模型做到更大呢，无非就是更大的宽度、更大的深度，对视觉信号来说还有更大的分辨率。

然后这一块就是恺明老师和孙剑老师给我的指导是非常多的，然后我们也一起提出了很多种方法。比如在分辨率的 scale up 上、在宽度的 scaling 上，它会遇到相当于梯度的爆炸、或者是弥散这些问题，所以我们提出了一种初始化策略，就是 MSRA init，比较好地解决了这个宽度 scaling 的问题。

在深度方面，深度是最困难的。之前的一些模型基本上过了十几层以后，它那个效果就会迅速下降。我们刚好在那个时候就提出了这个 ResNet，也是现在影响力比较大的一个工作，可以把网络从十几层提到几十层、上百层，甚至你愿意上千层也是可以的。

当我们把这一系列做完以后，我认为 model scaling 这一块，至少在那个时间点已经基本上解决了。

16–19 年：到旷视做小模型，得出「架构不重要」

张祥雨

所以在我毕业以后到旷视，其实是做小模型。因为那个时候继续把模型做大，没有特别大的收益，因为这时候棒子重新交回到了数据和算力。

从我 16 年、17 年加入旷视以后，其实我做的反而是那种小模型。而且呢我也发现，就是说把模型从大做小，其实它的思路非常非常不一样。可能跟大家想象的不一样：大家觉得模型架构这些设计细节是非常关键，但实际上做过架构的同行可能都知道，很多时候我们发现架构是没有用的。就是架构设计，尤其是对于大模型，架构设计更多的是针对大方向——大方向只要对了，至于它里边那些层与层之间如何连接，其实差别是不大的，效果差别是不大的，关键还是那个大方向很重要。

但是一旦你把这个计算的规模变小，放到比如说放到端侧，这时候模型架构的那个细节设计就会变得非常重要。尤其是对于不同的硬件设备，它的执行效果、它的那个效率，都是有很大不同的。

所以呢，我在做 ShuffleNet 的时候也深刻地感受到，就是这件事非常困难。就是说你要在特定的硬件上，把一些特定任务的模型跑起来，要设计出效率最高、性能最高的这个模型，其实需要大量的经验设计。

所以一开始我们做了几个小模型的工作以后呢，我的研究主要转向就是：怎么通用或者自动化地把这些很复杂的小模型设计出来。所以在 17、18 年的时候就立了一个项目，就是搞那个神经网络架构搜索，就是 NAS，是利用自动化的手段，帮我自动化地设计出能够在特定硬件上高效跑起来的这样的模型。

19 年提的那个叫 SPOS（Single Path One-Shot）这个工作，它可以用非常小的代价，在特定硬件上、就针对给定的硬件，我去搜索一个在目标数据集上效果最好的这样一个模型，就可以很大程度上解放这个人工。

19 年：难点从 model scaling 换成了 data scaling

张祥雨

所以到 19 年底的时候，我们的目光重新要做大模型。但到 19 年这会儿，把模型做大和当时 16 年它的难点已经很不一样了。

16 年之前，主线的故事都是怎么把模型做大，就是 model scaling。但是到 19 年，它最大的难点在于 data scaling。因为大家知道，CV 发展那么多年，虽然半监督、或者是自监督、或者就是这种 label efficient 的方法其实层出不穷，但是一直以来就缺少一个就像 NLP 里面所谓的「GPT 时刻」或者「BERT 时刻」这样一个东西。

其实在 19 年的时候，NLP 那边进展非常大。很多人以为这个进展是架构带来的，但其实并不是。我前面也说了，架构在这里面不起主要作用，起主要作用的是优化方法。之前 NLP 其实跟 CV 是一样的：我来一批数据，我需要标一大批 label。但是只要你还是依赖人工标注，那么你是永远 scale up 不起来的。

但是 NLP 它就是——他们很幸运的呢，就是发现了，我通过一些特定的这种训练方式，比如 BERT 就是利用这种类似完形填空这样的方法。他看起来这个 task 跟我的下游要做的千千万万个 task 可能没有关系，但是呢，他通过这样的一个上游的 task，首先他不需要 label，可以无限扩展；其次他发现，我数据越多，通过上游这个 task 我神经网络就可以学到更强的表征，那我在下游任务上就做得更好。

而 GPT 这种 decoder-only、就是 predict next token 这种方式呢，就更进一步。就是说我不仅不需要 label，并且呢它还可以泛化、还可以统一——通过 in-context 建模的方式，还可以统一很多这个下游的 task。

当然这里很多的 insight 是在 GPT-3 出来之后才有的，20 年 GPT-3 出来之后，至少 NLP 这条路是完全打通了。

但在 19 年，至少 19 年 CV 其实还没有经历过这个时刻。

19 年的时候，尤其上半年，Google 有很多在那个半监督领域的一些突破，比如像 UDA 这些。这些东西其实它走向了一个看起来不错的一个方法，叫我们叫对比学习、Contrastive Learning。

然后呢，到 19 年底，像 MoCo、像 SimCLR 这类工作出来，让大家重新看到了希望：我通过对比学习——对比学习是不是就是类似 NLP 里的这个 BERT、GPT 这个时刻？

因为大家尤其是看到它在很多指标上，通过完全的这种自监督，它在下游任务上的效果已经开始逼近——当时还有一定差距，但是已经在快速逼近——像我们用 ImageNet 这种全标注的数据训出来的模型。这就是给人很大的鼓舞。

但是整个业界包括我们也是花了很多精力在研究，结果发现呢，很多这些方法它其实只在小模型上管用，仍然没有 scale up 的特性，一旦 scale up 到很大，然后就发现效果就快速平掉了。

CV 向 NLP 学习的那几年

张祥雨

然后呢，到了 20 年，其实 CV 里面还有一个大事，就是说有人把这个 Transformer、就是纯 Transformer 架构在 CV 上彻底做 work 了——就是 ViT 那个系列，就一直用到今天。

那当时搞学术的人大家就自然想：那这太好了啊，我可以把那个 NLP 的方法都搬到这个 CV 这里面来试试。所以产生了很多类似的方法：比如说现在 NLP 里叫做 GPT，但是这个 CV 里面它就叫 iGPT；在 NLP 里叫 BERT，在 CV 里叫 BEiT。毕竟也有一系列从 NLP 借鉴过来的方法。

一开始的效果非常好，甚至尤其是像何恺明提出这个 MAE 之后，我们可以看到它在自监督方面的性能，尤其是对于泛化后的这个下游 task，已经不输、甚至略有超过对应的带全监督信号的这样的模型。这就再次又让这个 CV 社区又火起来了。

但是其实我对此一直谨慎乐观。因为确实我做了很多事情都是在小模型上，这些方法都是在小模型上；一放到大的上面，你会发现它完全不像 NLP 那样有这个 scale up 的特性。

然后到大概到 21 年底的时候，我仔细分析了为什么早期大家做 contrastive 不 work——就是放到大模型不 work，MIM（Masked Image Modeling）可能效果好一些，但是我依然不看好。我当时大概想明白了是为什么。

为什么自监督在 CV 上 scale 不起来：不变性是手工的

张祥雨

原因是：不管是 Contrastive Learning 还是 MIM，它 somehow 都在学某种不变性。

确实，不变性对于 CV、尤其是视觉的这个表征来说是非常非常关键的。但是问题是，这两种方法它所学到的不变性，它并不是 data-driven 的，而是完全 hand-crafted 的。

因为我们知道，对于 Contrastive Learning 来说，它非常非常依赖那个 augmentation，就是你怎么样构造。它实际上是在鼓励——就它的负样本部分，你可以认为它是一个正则项，它在鼓励一个最大熵，就防止信息坍缩；而它的那个分子部分，其实是在学习一种不变性。但这个不变性不是数据赋予的，而是你通过那个人工设计的 augmentation 赋予的。

但是这其实又走到了更早我们之前就是说人工设计的这个老路上。你看那个 NLP 为啥这么 work？它是真正做到了 learn from data：我有越高质量的语料，我这个模型就可以学习这个语料中的关联性，然后建模它的联合分布，通过压缩学习到更多的知识。

但 CV 这个不行。你设计了一个什么样的不变性？比如说对于旋转、比如说颜色变换或者 multi-crop 这样的不变性，它最后学到的特征就是满足你所设计的那几个不变性。那它当然没有 scale up 的效果，因为你只需要少量的 data，我就可以让这个模型学会，然后你就没有信息增量了。

当时呢，MIM 还是有非常多人一拥而上去搞，其实就是 BERT 那一类的方法。但是我也是很早就看到这个方法的上限，也就是说它学到的是遮挡不变性。遮挡不变性确实很重要，比如说我们人类认识这样一瓶水，我把这个水给挡住，它露一个头，但对于一个人类来说，我仍然能猜到这后面是什么——它只要看到一个局部就好，这就是人类认知的遮挡不变性。

但是呢，拥有遮挡不变性的特征，它只是一个必要条件，它不是充分条件。你做 MIM 这类方法，就是你在数据量很小的时候，通过这样它的这种算法的设计，可以让你学出拥有这种不变性的特征，这个非常好，这个特征非常有用。但是即使你的数据量再扩大，你学习的仍然只是这一种不变性，它并没有从数据中激发出更多的不变性——这就是它不 work 的原因。

所以当时在 22 年初，我发了一篇那个观点性的文章，我就认为 MIM 其实是没有用的，没有明显的那个 Scaling Law。而且也受到了圈内不少人批评。但现在看来，确实这条路线走的人也很少，确实不是那么的有效。

其中最主要的原因就是，其实你看到它的本质，大概就可以意识到是这样的一个问题。

22 年：对纯视觉能不能学出智能变得悲观

张祥雨

所以其实到 22 年开始，我对单纯依靠视觉、尤其是依靠这个静态图像，可以学出智能、学出 CV 领域的「GPT 时刻」这件事，我是比较悲观的。

一个是，也是大家研究了这么多年，搞出了各种各样的自监督的方法，但是始终都没有取得像 NLP 领域这样这么容易的 scaling 的特性。

尤其是当时我看了两篇 paper 以后——这两篇刚好都是 Jason Wei 的：一篇就是关于思维链的发现，另一篇就是关于这个涌现性。这两篇文章我当时大受震撼。因为我感觉我研究了这么多年，都还停留在表征这个层面，但是像做 NLP 的同行们已经开始在研究推理了，在研究更高级别的这个智能特性。

我越来越觉得，纯视觉这个东西可能是有问题的。虽然它很重要，但是它会很有问题。

纯视觉的问题：生成、理解、对齐三者割裂

张祥雨

有什么问题呢？比如说我们就从三个角度来看这个自然语言数据和静态图片——视频例外，视频可能蕴含更丰富的信息。

但是至少从自然语言角度，它的生成、理解和跟人类的这个对齐，这三件事它是合三为一的。也就是说，当我做出了一个像类似 GPT 这样的一个生成模型，你建模了它的联合概率——你只要建模了联合概率，你就同时拥有了生成、理解和人类对齐。

这是为什么呢？比如说像 GPT 这样的架构，它是个自闭环的。它的前文，你给定了这个前文，当你在输出关于前文的这个条件概率的时候，前文一定会影响后文的条件概率、改变了这个分布，那后面这个分布它就可以输出跟前文所匹配的这些文字——这其实就是一种理解。

因为你可以在中间要求他，通过一些 prompt 去约束他，让他回答前文中的问题，你可以任意对前文进行提问。他在这个联合概率建模的过程中，针对这个后文的条件概率进行采样，这就可以回答前文的问题。

我们可以认为这就是一种生成，那当然也是肯定的，因为它本身就是——就像 GPT 的话，它本身就是一个生成模型，那我当然可以对它进行做生成。

那么它所预训练的、它训练的语料呢，都是来自于人类的、就是自然的语料，那你建模了它的分布，那你当然就完成了跟人类的这个对齐。

然后呢我们再反过来再看这张图片，仍然从这三个维度：一个是生成、理解和人类对齐。然后你发现图像、尤其是静态图像这个领域，它不是自闭环的。

也就是说为什么呢？我给你一张图像，或者给你一个图像数据集，大家想想，你能拿到的最多的信息、能够最充分利用这个数据信息的模型是什么？那肯定是生成模型。也就是说，我完全可以做一个模型，把你这个图像数据集的这个联合概率分布都给做出来。当我做出了这样的一个模型以后，我认为我已经拿到这个数据的全部信息。

但是大家想一想，这个模型当然可以做生成，但它能够做理解吗？

这个显然是不可以的。因为这个数据集你建模的是这个数据的所有图像、它的每一个 pixel 之间的联合分布，而这个联合分布的建模可以有无数种方式，但是呢没有什么东西限制、要求它这个建模的方式就刚好符合人类对这个图像的理解方式。

因为图像是客观存在的，它是来自于大自然，但是它跟人类如何理解，这个信息并不蕴含在这张图上。可能有少量的图，比如说带文字的图，你可以认为它拥有人类对它的理解。但是 in general，大家都知道图像是大自然创造的，它不管你人类对它怎么理解，它就在那里。所以这张图像它不必然包括人类对它的理解，它其实缺少这类信息。

大家想，为什么我们说的 MIM、或者像那个 contrastive learning，它 somehow 能 work 到一定的程度？说白了还是注入了人类的理解。对，比如说我这张图摆在这里，如果我不注入「我这张图的特征需要有某种不变性」这样的一个东西，那么这张图它自己是不可能拥有这样的不变性的，因为它不知道。

对人类来说，我理解这个杯子，它需要一个遮挡的不变性，意思是我遮挡住一部分，我还知道它是杯子。但是如果是一个动物、或者是一个外星生物、或者是一个机器人，他需不需要用人这种方式来理解这张图？当然是不必备的。也就是说，这种不变性这件事，它并不蕴含在这张图里。

所以呢，你会发现这个理解和生成，至少在静态图像这个维度就产生了割裂。

当然很多人问，那视频能不能补偿这些？因为视频我可能有不同角度拍摄，它自然就有了这种不变性。我只能说有可能，这可能是下一个方向，但是视频数据的有效利用实际上是要比静态图像难很多，它的信息密度也是低很多。

那最后一点就是人类对齐，那自然更不必说了。我们语言模型的语料是人类生成的，你在上面训练一个生成模型，你的分布跟人类所产生的这个分布自然是对齐的。但这个图像它来自于大自然，它未必是对齐的，或者说它一定不是对齐的。

这就是对静态图像来说，它的理解、生成，还有人类对齐这三点是割裂的。也就是说，你在静态图像上你做再多的东西，我认为你都很难形成人类所谓意义上的那种智能。

转向：用图文交错的数据借语言的对齐

张祥雨

所以在 22 年那会儿，我基本上就停止了对静态图像和表征这一块的研究。

我认为，要在视觉领域——首先一个真正的 AGI 系统、智能系统，视觉肯定是必不可少的这样的一个模块，但是肯定不是按现在我们做 contrastive learning、做 MIM 这样的一个方式，就可以真正通向视觉领域的智能。

所以我当时大致构思了一个方向：短期内，我可以利用视觉和语言的对齐关系。因为我们知道在互联网上我们有大量的这种图文交错类的数据，不管是网页，还是像论文、期刊杂志、公众号，往往都组织成这种图文交错混排的形式。

图像自己是很难表达很多东西的，但是如果我让图像嵌入在文字流里面，我利用文字的这个自闭环——我刚刚说的理解、生成和人类对齐这个自闭环的性质——是不是这个图像也可以借由这种对齐，让我这个智能系统里拥有智能能力？这是短期内最容易想到的方法。

但是长期来看，这一类语料它的 bias 是特别显著，而且局限性也很大。比如说它很少包含非常细节的视觉的过程，尤其是物理运动的这种过程，这种数据更多的还是在视频里面。所以从长期来看，我们还是要通过视频、甚至像这种具身系统，从这里面来挖掘视觉智能的可能性。

但是当时到 22 年的时候，想到这里，这个框架我觉得就已经比较显然了：做这个视觉多模态大模型，我有一个比较短期的目标，还有一个比较长期的目标。

但是呢，也聊了一些人，大家都不相信。因为刚好 22 年那个时间点比较尴尬：当时在 21 年的时候，尤其是国内，就出过一波那个大模型的热潮。就在 GPT-3 出来以后，相当多的人都跳出来说我做了一个多少亿参数、甚至真的有万亿的都有这样的大模型，但是最后都没有取得非常好的效果。所以大部分人是不信这个故事的。

插一句：21 年那波大模型为什么效果不好

张祥雨

当然这里就要插一句，就是为什么那个时候的大模型其实效果不好。其实我认为主要可能还是两个原因。

第一个就是老生常谈了，就是那些 base model，它在没有 instruct tuning 的时候，它确实是很不好用，而且能做的事情也很少，效果也不好。

但是当时更重要的一个原因，我认为是大家远远低估了 Scaling Law 里数据这部分所占的比例。尤其是像 GPT-3 出的时候，GPT-3 刚出的那回，它用了千亿的参数，但只配了几百 B 的数据。按今天的观点来看，这就相当于完全倒置了——像这么大的一个模型，我不配一个十几 T、甚至几十 T 的数据，肯定是对不起这个参数量的。所以当时模型都是一个训练严重不足的状态。

也是因为这两个原因，其实导致了整个 21 年大家在复现 GPT-3 这件事上，其实没有做出特别好的效果。但是很快呢，到 22 年底那个 ChatGPT 出来，就一下子打动了很多人：说原来这个东西可以做得这么有用。给人感觉是非常 promising，感觉这个智能时代就一下来了。

李广密

因为过去主要是叫视觉类数据，今天是文本类数据，大家都想更好地结合起来。从我的理解上，今天视觉类的很多数据其实还没有跟文本关联起来，其实关联起来也是一个很难的。我不知道做这个过程中会遇到哪些难的地方，不管说数据上，包括架构上，包括做实验的过程当中？

Part 2 · 生成与理解为什么融不到一起

第一代方案：图文混排预训练 + 外挂 Diffusion

张祥雨

其实我觉得就是做多模态模型的机构、团队，都会跟我有类似的想法，就觉得语言模型、尤其是 GPT，在 GPT 成功之后，因为它是个纯语言模型，就觉得多模态应该可以复刻同样的路线。包括我创业的时候当然也这样想的。当时从现在来看，也是大大低估了这件事的难度。

我当时想法其实非常简单：无论是互联网还是书籍，我们都有大量的这种图文混排、交错的数据。

那既然语言 next token prediction 这条路我们验证是 work 的，那么我图像进来，我就很简单——我想办法把这个图像首先对齐到跟语言同样的一个空间。那么我也用跟这个语言相同的方式来处理这种多模态的交错式的数据：比如说遇到文字，就处理这个文字；遇到图像，就处理这个图像。这样不就成功了？

所以我们当时在 23 年做我们的第一代模型、就 Step-1 的时候，就完全走了这样一条路线。我们当时没有做一个纯的语言模型，而是从我们的预训练最开始，我就把我所有的数据都把它组织成这个图文混排的一个形式。

然后遇到图像呢，我就把图像编码进去；遇到文字，我就把文字编码进去。文字的话是 token 化，图像也是 token 化。只有一点是跟文字略有区别，就是在生成图像的那个地方——因为 auto-regressive、至少在那个时间点，直接用 auto-regressive 生成图像效果还是会差一些，所以呢我外挂了一个已经预训练好的 Diffusion 模块来做这个图像的生成。

这就是我们当时做的第一版的这个多模态模型，就 Step-1V。

结果：图像理解极好，生成几乎没用

李广密

这个模型出来效果怎么样？

张祥雨

首先文字部分跟直接训练文字相比差不多，效果也是挺好。而它的图像理解效果尤其的好。

经过这种图文混排训练——因为当时尤其学术界流行的方法，是先训完语言模型之后，我再把其他的模态通过后训练对齐的方法给它对到这个语言模型，它并没有在预训练最开始就把这个多模态数据加进去。而我们这个方法呢，其实在预训练最开始就把这数据加进去以后，就发现它其实图像和文字对齐得非常好。

它主要是体现在这个图像理解上，它能力很强。而且你会发现这个图像和文字它的相容性非常好——也就是说，比如说你把字写到图像上，你针对这些字问问题，和把这个字用 OCR 做出来来问问题，它的效果几乎是差不多的。也就是说对于这个模型来说，它已经完全能够自由地利用文字和图像这两个模态的信息进行思考，在它看起来没有什么障碍。

但是唯独有一点，就是生成的效果特别差。

我们虽然是在上面挂了一个 Diffusion 单元，这个 Diffusion 单元也是经过预训练的，它是可以生成图像的。但是呢，我们发现就简单地这样做的一个多模态系统，你的理解部分、也就是说你的语言部分，对那个视觉部分它的控制能力是非常非常差的。

同时呢，更有意思的是，我后来还做了个试验：我在训练的某个阶段，我把这个生成部分给去掉，后来发现呢，完全没有影响我的理解部分的进展。说白了，就是我的这个生成部分可能就是没有用的。

这个其实对我们也是一个很大的一个打击。本来设计这个系统就是想做所谓的生成理解一体化，就是从架构上仿佛实现了——既能生图也能理解图，既能生成文字也能理解文字——但是最后效果其实没有。

同时期我们也注意到，海外一些比较有名的工作，他也号称是端到端训练，然后最后我看他也没有做到理解和生成的一体化，他也是通过外挂 Diffusion 这种方式。

这就让我意识到这件事情其实可能没有那么简单。就是说，你看起来是强行把这样的一个生成和理解做到了一个系统里面，但是从它实际的效果来看，它其实完全没有达到语言那种生成和理解完全融合到一起的特性。就是生成和理解在那个时间点看起来还是分开的。

但是至于为什么导致了这个图像的生成和理解如此难以融合，其实在那个时间点我们是没有太好的 idea 的。所以呢，当时就做了很多这种假设：可能认为是数据质量的问题，可能我图文高度相关的这种数据量、或者数据密度还是太少——因为我知道从互联网扒的有很多看起来相关、其实图文无关的这样的内容，这个很有可能干扰了这个训练。

24 年：生成和理解还是分开做

张祥雨

所以整个在 24 年，我们的生成和理解其实是分开做的。因为我观察到像海外的一些大厂，OpenAI 也是的：他的理解这条线，尤其是 4o 之后，把语言、把声音，还有视觉理解，甚至后面还有视频理解，都融合到一个模型；但是生成这部分一直单独做，走的是 DALL·E 到 Sora 这条路线。Gemini 也是的。

所以到 24 年的时候呢，我们也是在走这条路线，但是我们在不断地在找这中间有没有机会能把它融到一起。

因为对于一个生成模型来说，它需要构造这个文本和视觉信号的配对。我完全可以用我最新版的理解模型给它打标，我就可以做到一个更好的生成模型；再把这个生成模型外挂到这个理解模型里面，我去继续训练我的理解模型，这样我的生成模型它可以提供梯度，这个梯度是可以指导我这个理解模型的。

这样的话，经过这样一轮迭代，我就认为生成和理解这中间的 gap 又缩小了一截。我再利用这个理解模型给生成模型打标，训练下一代的生成模型，再反过来再给理解模型……我在想，是不是到中间某一个时刻，这两者的 gap 就会越来越小，最后在某一个时刻我就可以把它放在一块进行训练——我有一个这样好的、已经充分对齐的这样一个初始的系统，我把它放在一块，我就可以把整个链路给跑起来了。

做了大半年：1 + 1 没有大于 2

张祥雨

但是呢，其实我做了大半年，这件事都没有成功。

我得到了一个越来越强的理解模型和一个越来越强的生成模型，但是把它放到一块——不是说不 work，你永远可以放到一块——但是它没有 1+1 大于 2 的效果。我放到一块以后，它的表现还是两个模型。也就是说我随便把它摘掉一个，另一个的效果不受影响，既不会变强也不会变弱。那我还要把它两个放在一块干嘛？也就是说它完全没有起到叠加的这样的一个效果。

这是生成对理解。那理解对生成就更为糟糕：虽然我打了这么多数据，我还联合训了蛮久，但是我生成分支的可控性仍然是非常的差。

比如说它经常会生成一些像比如说有肢体畸变、有那个违反几何约束的，尤其是我做视频生成的时候，是大量的违反这个物理约束的这样的视频信号被生成出来。

而我把这样的一个信号直接送给理解模型，它能够准确地告诉我，这个东西是不符合常识的。 它自己都知道，但是它自己无法控制住自己，不生成出这些显著违反物理常识、或者违反空间透视关系的这样的图像。

所以这件事呢就一直卡在这里，我当时一直是没有想清楚这件事要怎么做。所以生成理解一体化，当时我做了大半年以后，其实是一个很迷茫的状态。

但是这个转机呢，其实出现在那个语言模型的 o 系列之后，就是 o1。其实 o1 这个东西非常了不起。

回退一下：Step-2 那个万亿参数模型

张祥雨

我可能还要再把时间回退一下。其实在 24 年的时候，我们语言模型也走了一个很大的一个弯路，直到 o 系列出现，我才把所有这些事情想清楚。

时间回到 23 年底。其实到 23 年底，我们不是把那个 Step-1V 给做完了——它其实就是我刚刚主要介绍的那个多模态、图文混排这样训练出来的模型，它参数大概是 100 多 B，就一个千亿参数。

那很自然就想：我现在数据量也够了，我的算力可能也够了，那我是不是要挑战一下更大的？所以在 24 年初的时候，我们又上马了一个更大的模型，就是 Step-2，它这个万亿参数。尤其是它跟今天的这些万亿参数还不一样，它激活非常大，激活有 200 多 B，是一个非常巨无霸。

但是一旦这个模型开训以后，我们发现它这个投入就简直是一个无底洞。一方面，一开始大大低估了训练这么大的模型所需要的数据量——在数据不足的情况下，你光把这个模型 scale 到非常大，其实效果是很差的。

而还需要巨大的数据。大家都知道，算力需求跟你的卡数是正比关系；随着数据的增长，跟你的算力也是个正比关系。所以你同时扩大模型的参数和数据量，那你对算力需求就是个平方关系。所以我们这个模型是非常非常吃力的，这个 project 前后做了 9 个多月，总算训到一个我们认为比较满意的一个状态。

Part 3 · 训练大模型发现的怪事

模型越大，数学反而越差

张祥雨

但是当时发生了一件事，让我们百思不得其解。

一般我们认为，随着这个数据扩大、这个模型扩大，这个模型的能力应该是全方位增长的。但是呢，我们就发现这个模型的性质很奇怪：它在文科上非常非常强，文科类、还包括写作类，它上面非常强；但是它在理科类、尤其是数学上，表现得还不如一个 7B 的模型。而且是很困难——你想通过常规的方式把它的数学或者逻辑能力做上去，这是一个非常困难的事情。

就说这件事其实是非同寻常的。因为当时整个业界大家都认为，模型越大，各方面应该越好。因为一开始觉得我们数据质量不行，或者是没有训够时间等等。

但是后来做了一系列非常严谨的测试，我们在一些模型上，比如从 1B 到 7B、再到 30B、再到 70B，这样一路撕上去，我们训了一系列这个项目，我们发现：确实是模型的通用对话能力、尤其是情商这一块，还有知识量，确实是越大越强；但模型的推理能力、尤其是数学这种比较局部的推理能力，它其实是表现为一个先上升，然后再平，再扩大的时候反而是个下降。

李广密

这个是不是还是一个业界的非共识，很多人还没怎么认？

张祥雨

到今天已经有很多人意识到了，但在去年那个时间点，其实还很少有人做到这么大，把这个增长曲线的后半段给画下来。

蛛丝马迹：大模型倾向跳步

张祥雨

就它其实是个下降，这件事其实让我们比较诧异。但仔细一想，其实我们看到就是说，为什么更大的模型它做这些理科问题效果就变差？

然后是发现了一些蛛丝马迹，就比如说更大的模型，它在做一些数学题的时候，它更倾向于跳步。

它不会像一些相对比较小的模型——它虽然能力很弱，但它处理一些长列的算式，不管它再简单，它都会老老实实地一步步计算。而你一个较大的模型，它总是比如说写了三个数、这三个数相加，它经常就放弃一步步推导，它直接一口就报出这个最后的结果。

虽然从整体的这个思维链来看，它是从前写到后面的，但它中间的某些细节步骤，它总是倾向于跳步。

一跳步呢，其实大部分情况都是对的，但是就有那么少量的情况是错的。那数学题大家都知道，你错一步，那最后的结果就完全错误。

这件事其实当时就引起了我注意。我就很好奇：实际上我们在训练的语料，因为很多是来自互联网，但也包括很多合成数据。合成数据我是可以保证它跳步的情况是很少的；但是对于那个互联网数据，因为人类的数据很多省略了中间过程，那个跳步应该是非常多的。这种情况跳步是非常多，所以这很容易理解为什么这些大模型会跳步。

但是那些相对比较小的模型，为什么我训练完以后它反而不会跳步？

最后我经过分析，我认为这其实就是 next token prediction 它的一个本质的缺陷。

归因：更大的压缩率未必对应更高的计算精度

张祥雨

next token prediction 大家都知道，其实就是 GPT 的核心范式，也是支撑这一代大模型起飞的、最基础的一个算法。

它本质是联合概率的建模。也就是说，模型会在优化过程中尽可能调整它的输出，使它的输出越来越接近你输入数据的这个分布，就是我模型输出的分布和数据的分布越接近越好。

它还有一种理解，就是做压缩。因为大家知道，学过信息论大家都知道，对一个压缩器来说，你联合概率估得越准，那么你对这个数据做无损压缩的时候，你的码率可以做到越小。

就是它其实是通过对数据的压缩、通过这种归纳的方式获得了一定的这种智能——这其实是 next token prediction 的主要的原理。

但是呢，到了数学这样的问题，你会发现这两件事之间存在一个非常本质的冲突，就是说：更大的压缩率其实未必对应更高的计算精度。

一个思想实验：特征坍缩

张祥雨

我们举一个思想实验。现在假设这个数据集里面，它有很多的操作都在做比如十几个数字相加这样的一个操作：

可能有 50% 的数据，它来自于互联网正常的语料，它是没有给出计算过程的，它就直接十几个数字相加，最后一个等号得到了最后的结果。还有一些数据呢，可能是你精心清洗的、或者专门找了有过程的数据，它会非常老老实实地一步一步算，这十几个数字一步步相加，最后得到这个最终的结果。

我现在让一个模型去拟合这样的分布。大家想想，当你达到最优的这种情况下、就最大压缩率的情况下，那个模型就应该是以 50% 的概率直接输出结果，还有 50% 的概率按右边那样一个一个词这样输出结果——这是理论的最优值。

但是当我们拿一个小模型去训练的时候，你会发现，左边那个峰、就是直接一口爆出结果，因为它模型参数量有限，它处理不了这么复杂的函数，所以它几乎会出现拟合不上这样的一个问题。所以最后它能够学会的其实只有右边那个峰。

这其实就是非常经典的，在生成模型里面叫特征坍缩现象。就像我们做一个比如说 diffusion model 去生成图像，你会发现它总是先建模那些比较简单的图；当你这个模型能力更强或者训练时间更久以后，它才会逐渐把完整的这个分布刻画出来。如果你训练不足或者模型能力有限，它只会建模——就每次输出你会发现基本上都一样。我们把这个现象叫做特征坍缩。

那大模型就不一样了。大模型会尝试，比如我们尝试过 Step-2，它的激活有 200 多亿，它真的可以十几个两位数相加，它直接一口爆出最后那个答案，而且那个答案大概率是对的，可能有个 99% 的概率是对的。

当然它也有概率一步一步输出。但现在问题来了：如果你以压缩率论英雄，那当然是这个大模型压缩率更高，因为它跟原来的分布更接近；你这小模型直接少了一个峰，那肯定是压缩率不足。

但数学要的是算对

张祥雨

但是呢，对于数学题，我们首要的要求是你得算对，而不是你的分布离那个预训练语料更为接近。这就产生问题了。

不管小模型大模型，只要它是一步步算，因为都是一些比较简单的数字运算，它几乎是不会错的，它肯定是对的。

但大模型它总有倾向，它觉得它行了，它确实就一步直接报出了答案。

整体你想，对于一个比较复杂的数学题，它可能有很多很多的步骤。然后中间任何一步，只要它觉得它很行，它不用一步步计算、开始偷懒，就一步报出答案，可能 90% 都是对的，但它就错那 10%，那 10% 它就要命——只要错一步，尤其是很长的链路，它最终的错误率就会非常的高。

所以你会发现，它做那些常见的这种 CoT 数学是这样，很多那种推理模型也是一样：它总是在中间跳过了一些必要的步骤，然后直接输出一个它自认为很对的答案。很多时候确实是对的，但是一旦我这个逻辑推理越复杂、步骤越多，这种小的错误可能性的累积，就使得你整个的这个错误率反而就大幅增加，就很多时候还远远不如那些小模型走得好。

这个现象非常糟糕。而且它可能直接指向了我们做 next token prediction 这样的一个本质的缺陷。

其实 next token prediction，大家在理解上对它的批评也很多了。因为它本质是个 behavior cloning，就天生容易 OOD（Out-of-Distribution，分布外：自己生成的内容偏离了训练数据的分布），容易在中间出现分叉，就是 OOD 以后它容易陷入一个它没见过的环境，很多幻觉也是这样产生的。

这个都是老生常谈了。但是我刚发现的这个现象，可能在业界里讨论的还不多，这还是一个比较有趣的一个问题。

解法方向：直接优化目标本身

张祥雨

当然这个解决方案大家也比较自然。因为你刚刚说了嘛，next token prediction 本质上还是基于信息论、是压缩率，是最大化这个压缩率的。

但是如果你的这个问题本身跟最大化压缩率这两个优化目标存在 gap，那你还不如直接优化我关心的那个任务本身——那其实就是 RL 所提出的这个问题的依据。

所以像大家用这一波 o1 出现以后，包括像 DeepSeek-R1 这些非常优秀的这些工作，其实大家都用了这个 rule-based 这套方案。但实际上这套方案真正在大模型里面大规模使用的时间是非常早的。

其实基本上在 24 年初，就有非常非常多的人都试过把这个 rule-based RL 接进来，很大的原因也是为了克服大家所说的这个 behavior cloning、或者说 next token prediction 这套范式的缺陷。

但是呢，从效果上来说，大家发现这个收益是非常有限的。就看起来 RL 我的目标非常对——它其实就相当于跳出了之前叫拟合分布这样的一个范畴，我就是直达目标，我不管你中间怎么做，你把目标做对就行。

那你会发现这种情况下，大模型和小模型就一视同仁了。大模型不是喜欢跳步嘛，但是它只要跳步，它就会降低它遇到正确答案的这个概率。所以呢，一旦我上了这个 RL，那么大模型容易跳步这个缺陷其实就得到了很大程度的缓解，因为它自己会找到一种最可靠的、最有可能达到这个目标的这样的一些路径。

但是这种方法有收益，尤其是大模型收益会更大，因为它其实是起点更低的、它的 base 更低；小模型也会有收益，对它稳定思维链很有用。但是总体来说这个收益还是非常小的，我们发现很多的问题，它该做不对的它还是做不对。

但是直到 o1 出现以后，这个情况得到了非常大的一个改观。

Part 4 · o1 为什么不一样：pattern is all you need

关键不在 RL 算法

张祥雨

我觉得把 o1 时刻也当成某种意义上的 GPT-4 时刻，我觉得一点都不为过。

o1 同样是 RL，那 o1 跟之前用的这些范式有什么不同呢？

其实这个核心点，很多人可能都觉得是这些 RL 算法、或者是一些数据上的研究，但其实都不是。算法还是那个算法，还是 rule-based 这样的一个算法。 其中最核心的原因就是它的思维链。

我们做这行的时候，很多人都说：做 o1、或者做思考模型，我信本质就是 pattern is all you need。

就是所谓的你要找到这样的一个最佳的思维链的组织方式，再有这个 RL 算法的解法就可以了。但这个 RL 算法至于选什么其实都不关键——你看业界用得比较多的像 PPO，这当然可以，但如果你不想用，你用 REINFORCE，或者其他可能更简单的、甚至是最原始的这个 policy gradient 类似的一些方法，其实都是可以的，没有什么本质差别。

真正使得这个 o1-like 的范式和之前的范式产生差别的最主要原因，还是那个思维链。

为什么语言上的 RL 和传统 RL 世界观完全不同

张祥雨

这就不得不说一下，为什么 o 这套范式——它虽然用了 RL 这个方法，但是说实话在这个 community 里，很多人都认为、尤其是搞 RL 的都认为这不是 RL，它只是借用了 RL 的一些名词和方法论，但它的世界观是完全不一样的。

比如说我们传统做打游戏的、或者做控制的这些算法，它遇到的问题其实很多时候都是那个奖励回报过于稀疏，而且难以估计这样的一个问题。

比如说你像打游戏，你真想达到一个非常高的分，你纯粹让游戏中的人物在原地随机胡乱地操作，是非常非常困难的。你需要写非常多的规则，或者是你要用各种各样的技巧去鼓励他的探索性，让他真的能走到一个能够达到高分的这样的一个点。

尤其像那个棋牌类，棋牌类你想——当然很多棋牌类它是一个左右互搏式的训练，假如说我不是让你左右互搏，而是我上来让你挑战某一个已经训好的这个人工智能体，大家可以想象一下，你想获得正的 reward 的难度有多大？它基本是不可能的。

而且呢，关于这个回报的估计也经常会有很多的问题。比如说在一个序列的早期，你想获得精准的回报，这是不太可能的。而且那个决策空间也非常不光滑，我可能需要用 MCTS 搜到非常后期的一些分支，筛选出一些高质量的、把它一路 propagate 给到前面，我才能拿到比较 high quality 的训练 sample，那我这个 RL 路径才可以继续。

但是在大家做 o1 的时候，大家很多人都发现，我上一个 MCTS 似乎完全没有什么用。我搞一个 PRM 呢，不能说完全没用，但是至少在目前大家研究的这些问题上，可能也许是问题过于简单、也许是因为其他原因，但是种种现象都发现，在 RL 里面流行的那些方法论其实在语言模型里是不一样的。

这里我认为最核心的原因还是在于语言是有预训练的。而且这个预训练它非常的重，跟我们做其他一些打游戏那些场景——很多时候它完全没有预训练、或者仅仅是一个很轻量级的预训练——它是完全不同的。

预训练把动作空间压缩到只剩几个 critical decision

张祥雨

大家想象一下，比如说我解一个数学题，往往需要有上千或者上万个 token。如果从动作序列的角度来说，就相当于我有一个成千上万的这样一个动作序列，而每个动作的 action space 是整个词表。

这是一个非常大的一个搜索空间。如果是这种情况下，那我可以认为目前所有的 AI 算法可能都是无能为力的。

但是不是啊——实际上在有预训练之后，我们发现，因为预训练你见过非常多种，以数学为例，它见过各种不同难度的题目，可能全天下的题目它都见过，就使得它的动作空间得到了极大的压缩。

你看起来是一个长度是几万的一个 token 序列，它真正会让它的解法产生本质区别的分叉点就那么几个。我做了一些统计：对于一个比如四五千长度的这个思维链，可能只有不超过 10 个，我们叫做关键的 decision，它会影响最终的结果。

它一旦进入到某个分支，你看起来那些 token 这么多，但基本都是自动的、几乎确定的形式，后面全部都是顺着写下去。也就是说那些 token 其实根本不在 search space 里面、就 RL 要解决的 search space 里面。RL 实际要解决的，其实就是那些 critical 的分叉，就那些 critical token，它数量很少。

也就是说，看起来语言模型我们解决一个困难问题的时候，它的决策序列是很长的，但是跟传统的游戏、做控制相比，因为存在预训练，它实际的动作空间实际上是非常小的。你只要想办法把那几个关键 token 给搜对，就结束了。

这也就可以解释为什么我们今天用 rule-based RL 来训练一个语言模型，在刚开始训的时候、我都还没有训练，你会发现即便对于一个很难的题目，我都有不低的概率、即便是随机 roll 就可以把它 roll 对。

这在我们做那个传统 RL 里是不可想象的——你不可能在原地随便走走，我这个游戏突然通关了，我就可以找到、我就学习了，进一步学习「哦我原来这样走就可以通关」。

但是呢，在预训练语言模型这里面，你就会发现，如果你把把问题解对定义为通关，那我这个通关率也太高了。几乎——如果题目不太难，甚至有一半以上，你什么都没有做，你发现它刚开始训练的时候它都是做对的。就算题目很难，我比如说我 roll 个 100 次，我可能也会有几次是完全对的，中间我没有做任何过程监督，我仅仅是 random 地跑。

这就使得你在语言模型上做，跟我们传统在游戏上做，遇到的问题是完全不一样的。

所以 RL 在这里面它起到的作用，其本质是什么呢？它其实就是要决定这些 critical token 要怎么走。

因为我们发现，虽然这个模型你如果多次 roll 它经常能 roll 对，但它并不能稳定地对——可能这次是对的，那次是错的。

所以呢，在大家的想象中，我使用这个 RL，我就是要想办法让这个模型 focus 在那些关键的 token，把它给做对、选择正确的分支。如果做对了，你根本就不需要考虑那些已经被预训练压缩掉的部分。

但一个 token 之内决定不了：critical decision

张祥雨

但是问题又来了：这跟我刚刚说的 pattern is all you need 有什么关系？如果就是这么简单，那么之前大家做 rule-based 为什么不 work？就是说我为什么做了半天，那些关键的 token 它还是不能稳定做对？

这里面就涉及到另一个问题：当这个模型走到某一步的时候，摆在它眼前其实有两个分支，它到底是走左边还是右边——这件事可不可以通过一个 token 之内解决？ 我认为对于很多问题，这是不可能的。

举个最简单的例子，比如说我们做乘法。众所周知，当你位数很多的时候，你让现在的语言模型用一口报的方式去做一个大数乘法，是几乎不可能做对的。这里面其实核心原因是复杂度：我们知道你要做一个大数的乘法，你至少得是个 N 的平方吧——要抬杠的话是 N log N，反正是大于 O(N)。

但是我们知道 Transformer 单步做那个推理的结果，它复杂度也是 O(N)。也就是说，如果你做一件事它的复杂度超过 O(N)，那么它就大概率不大可能通过一个 token 来解决。

现在问题就出现了：搜索空间已经非常小，我告诉你可能只有 10 个 critical token 是你要搜索的，你 RL 算法要帮我决定——你到了某一个关键的 token 的地方，你要走左边这个分支，还是右边分支，还是中间这个分支，才能最大概率地通向正确答案。

但是问题是，当这个问题足够复杂，尤其很多数学的问题，它是无法根据这个题目以及前面一些浅显的推导，就立刻决定我在中间某一步需要用一个怎么样的构造、或者怎么样的一个算法的。

也就是说，它的那个 decision 的 complexity 已经远超了单个 token 所能干的事情的上限。

你想人类是怎么处理的？很多数学问题它其实都依赖一些巧妙的构造。比如说算到最后一步，刚好我设的某一个未知数消掉了，这道题就可解，就可以用这种方法解，否则的话我可能要用另一个方法解。又比如说一些不等式问题，它非常依赖一些巧妙的构造，你想不到那个构造它就解不出来，或者你构造错了，你也解不出来。

但是在你做这种构造的那一刻，你只能凭感觉，你在算完之前你根本不知道这件事可不可以。

所以那你指望——如果人都不可以，原因是太过复杂、我要做提前的判断过于复杂，那对于 Transformer 这样一种单步计算量限定在 O(N) 这样的一个系统，它凭什么又可以？

它当然不可以。所以我们就观察到，在 o1 这个范式出现之前，虽然我们要做 rule-based RL、虽然我也能观察到 reward 的上涨，但你发现它涨到一定程度就涨不上去了。

我的那些题目永远就出现——你很生气：他明明我做 10 遍，可能有 6 遍是对的，但就有 4 遍永远是错的。

那其实就是在还有一些关键的、我们叫做 critical decision 那个地方，它其实没有充分的依据能够在这么短的时间内、在一个 token 之内选择正确的路径。

比如说你很生气，就是说我看到他这个题都做到这一步了，前面都是对的，做到这一步他总是有 60% 的概率走到正确的分支、40% 的概率走到了错误的分支。那他为什么就不能学会，我就 100% 的概率走到正确分支？

那你可以这样想：也许你的数据集里还有另一道题，跟它长得非常像，当走到这个点的时候，但那个题就有几个数字不一样——对于那个题来说，它那 40% 的概率走的那个分支，它才是对的。

因为有这两种数据同时存在，所以模型根本无法——他如果选择全走 60% 那个分支，那么剩下那一类题他就做错了，就不利于他最大化这个正确率的这个目标。所以它永远到不了 100%。

引入反思：允许两条分支都走

张祥雨

其实想到这一步，解决方法也就非常显而易见了：如果我允许它按两条分支都走，那不就解决了？

那其实就是引入反思。这是引入反思的最大的一个动机，这也是 o 系列最了不起的一点：它真的把反思补充到这个计算过程中。

那这里就要插一句，那为什么 RL 自己不能产生、激发出反思呢？

其实是可以的。从实验上来看，你跑得足够久的话，你不人工注入反思，它自己也是会产生反思的，但是概率非常低，也特别耗时，并且效果也不是很好。

为什么会产生这样？那其实也是因为预训练。我们知道前面预训练对于 RL 这套范式非常关键，因为它起到了动作空间裁剪的效果，就大幅压缩了这个动作空间。

但是呢，这个动作空间在反思这件事上，它其实是过度压缩了。

因为我们人类的语料中，反思类数据是非常少的。因为人类基本上只会给出正确的——比如对于解题来说，人类只会给出正确的解题过程，它在绝大多数时候是没有写下来那些错误的、或者他走过的那些弯路的过程的，你看到的永远都是一条路走到底。

所以在模型充分压缩之后，它认为所有题目都应该非常顺畅地从第一步直接 CoT 到底，它是没有所谓的反思这样的过程了。那你动作空间虽然我有反思那样的一个 token，但是它的概率非常低，因为我经过预训练把它过度压缩掉了。

所以我们用 RL 过程是不容易把这些反思激发出来的，这也就可以解释为什么之前那些 rule-based 的效果其实没有那么好。

而 o 这个方式呢，我可以利用其他的一些方式，比如说就是通过 cold start 的 pattern 注入方式，把这些反思 pattern 给它重新做回来，相对我就扩展了这个动作空间。我在这个扩展的动作空间搜索，刚好就可以解决刚刚说的那个问题：你不是有一个 critical、你不知道从左走还是从右走吗？没关系，你自己随便选一个，选到底，你意识到不对，你可以反悔——我有一条反向边，你可以连回去，我可以从之前那儿再进一步搜索。

所以 o1 的本质是 Meta-CoT

张祥雨

所以我觉得，o1 你可以认为它其实是一种 Meta 的问题。

我们知道语言模型在最早的时候，大家的用法其实跟我们早期大家对 AI 系统的用法是一样的，都是希望我输入一个问题，然后直接输出答案。

但 CoT 发现以后，大家突然发现它对于一类复杂的问题可以大幅提升正确率。其中它背后的主要依据其实就是：很多问题的复杂度其实超过了你这个模型单步推理的最大复杂度，所以呢我要把步骤拆开，一步一步地，才能更好地把这个问题给回答正确——我保证我拆开的每一个单步都不超过这个模型复杂度的上限。

但是紧接着我们又遇到了：你为什么用这种 CoT 而不是用那种 CoT？所以这就涉及到一个叫 CoT 选择的问题。对于更复杂的问题，你根本无法一眼看出来接下来我这个 CoT 的路径要怎么走。

所以 o1 这种通过引入反思 pattern 这样的一种方式，我们可以认为它本质是一种 Meta-CoT，也就是说它是用 CoT 的 CoT。它就使得这个模型可以在多种 CoT pattern 之间自由地切换、进行排列组合，然后把更复杂的这种网状的问题能够解掉。

这是我理解的 o1 这个方式为什么成功的这个因素。

Part 5 · 回看视觉：生成为什么不可控

想通 o1 之后，回到最初那个问题

张祥雨

那么把 o1 复现这个过程全部想明白以后、也全部做完一遍以后，再回到最初的那个视觉生成理解一体化这种情况，那我觉得为什么我们的生成可控性这么差，其实问题就有了一个眉目了。

其实根本的原因就是还是一个所谓的复杂度问题，因为生成要考虑的因素太多。

我不管你用 auto-regressive——auto-regressive 是最显然的，auto-regressive 最大特点叫落子无悔，就一旦你把那个区域画上了，你就不能再改变它。也就是说神经网络需要在单步推理的过程中，就要把那块怎么画这件事给做出来。

那么这件事的复杂度有多高呢？有没有超过这个 Transformer 的单步复杂度上限？这个是不清楚的。但是我可以做一些思想实验，那绝对是超过的：

比如说我让它画一个黑板，在黑板上写一个鸡兔同笼问题的完整求解和解答。它看起来是个画图，但它背后隐藏的其实是一个数学题，这个数学题又包含了很多步骤，它的很多步骤明显超过了 Transformer 的单步复杂度。当你要求它做这件事的时候，我现在都不管你画图画得怎么样，你光是把这个问题解对，就不是你现在这些 token、就是或者叫一口爆可以爆出来的。

Diffusion 可能好一些，因为它是一个多步的过程。它是一个 SDE，如果你不 mention 的话，它其实是一个 ODE，所以它其实是个多步过程。

但这个多步过程，你要说它蕴含了什么推理，那我肯定是不信的。尤其是那些降噪的过程——那些降噪的过程，它其实是在构造一个随机过程，就更方便让这个系统去用一个已知的分布来拟合一个未知的分布。

但是降噪这个过程很明显跟人类生成图像的过程是明显不一样的。人类生成图像，比如一个画家，他往往是要先打草稿，然后再描绘轮廓，然后再描绘里面的关键，再上色，最后再渲染，这样的过程。他不是用橡皮一点点把噪声给擦掉、把每一个局部给还原出来这样的过程。

我们对比这两个过程，你会发现人类在画的时候，他是严格遵守人类对这个场景的语义理解的，它是强语义的。比如说它会从一个 object 到另一个 object，从轮廓再到它的细节，按照这样的一个过程。

而不像降噪这个过程，你很难说哪一步是在做语义、哪一步是在做物体，在它看来都是一堆噪声然后生成。

所以它跟 auto-regressive 我认为就是差别不大。基本上你可以把整个 diffusion 这个过程看成一个整体，它其实就是一步生成，语义可能在它 diffusion 的某一步就已经完全确定了，剩下的都是在补细节而已。

也就是说，不管是你用 auto-regressive 还是 diffusion，在我看来，你都还处于语言模型的最原始的形态，就是一口爆的时代——就是说我给定一个问题，我要求你在一步之内直接把这个图像生成出来。那当然你生成的结果是非常差的，因为你的复杂度根本达不到完成这个任务所需要的要求。

也就是说，生成这边我认为它最大的问题还是在于它缺少类似语言模型的这个 CoT。甚至于呢，它被语言模型现在已经甩了两代了——它不只是没有我刚说的所谓的 Meta-CoT，它连 CoT 都没有，它还是在之前那个一口爆那样的一个时代。

然后这样就想得很美：这样我们就可以做真视觉空间推理，就不依赖文本，我还可以在图上做圈点批注这样的东西。

当你要在恰当的地方把某一个图像生成出来的时候，其实这个控制信号本身是有非常丰富的语义的——它必须要能完全理解前面这一段话的内容，它上下文窗口、甚至是更远处的一张图像，它要对这个多模态有完全的理解，所以它才能非常可控地把这个图像给生成出来。

但是很遗憾的是，就像我刚刚说的，你生成这张图像，现有的所有这些方法，因为种种原因、其实最主要是复杂度的原因，它无法有充足的算力和信息把这张图完整地生成出来。那么这就导致生成这张图它产生的这个梯度，本身就噪声巨大，也没有什么信息量。

比如说 Diffusion 最简单——Diffusion 如果你跟文字同时训练，那么它一次怎么生成？它一次只能做一次的 denoising step，你要 sample 某一个 t。那你其实对于大部分的 t 来说，它的那个 diffusion 过程都是没有语义的，因为语义都已经确定了，它都在补细节。补细节那个东西产生的这个 loss，它反传到前面语言的部分，其实对于语言的语义提升没有任何作用，反而有可能把它搞坏。

这也是为什么后来有人说，如果用 auto-regressive 会好一些。但也没有本质的好。

好一些的原因是因为，好歹 auto-regressive 在训练的时候的行为和推理时候的行为是基本一致的。他在训练的时候他不是只做一步，他好歹是我生成一个 patch，patch 就出来了，他不是只生成图像的一次 denoise 的结果。所以他的梯度会相对而言更清晰一些、更有语义一些。

但也没有好太多，因为我前面说了图像过于复杂，你 auto-regressive 你还是个落子无悔的模式，你不大可能有非常非常清晰的信号。

类比：往预训练里灌只有答案没有过程的题

张祥雨

所以这种语料灌多了，你会发现模型又会出现两个极端：

一些比较强的模型，它会强行记住这个关联关系，下次遇到这个题，我不管三七二十一我就选个 C——这就表现为一个 overfit；而比较弱的模型，他会在想「哦，这个 C 的这个答案比较长，我是不是选 C 的原因就是因为它比较长，所以我应该选 C」，所以他找到了这些错误的规律。

就会导致——你像我们早期做了一些非常小的模型，像这种一口爆的数据做多了以后，你会发现它会学到一些很奇怪的 bias，比如说遇到一些比较难的题，一律选最长的。

如果语言这一块大家能够理解这种训练是有害的，那么自然就能理解：在图像上，你这种图文交错的训练，如果你不解决这个 CoT 或者这个 complexity 的问题，它也是有害的。

就是你 auto-regressive，就算你的监督信号是生成，但是因为它一步实际上 get 不到这一点，所以它产生的梯度很多是错乱的。所以最好的结果就是没有效果；如果你稍微再差一些，你甚至可以做得非常糟糕。

与人类记忆机制的对比

张祥雨

大家可以设想一下：对于一个人类，这个 context 可以类比——如果你把这个 context 类比成人的这个记忆系统，你会发现这个很有问题。

首先 context 大小，对于 Transformer 来说，它的 context 大小是随着数据的增长以同等的比例在增长的。也就是说它不会做任何的压缩，它不会对一个信息进行裁剪。

他跟人类非常不一样。比如说一场会开完，大部分人都会记录一下这个会议上最重要的、或者印象最深的一些细节。你看电影也是，也会看到这些细节，但是你绝对不会把「在第多少分钟上桌上有多少个水杯」这样的一个问题牢牢记下来。

也就是说，人类的记忆机制其实是个分层的：

短期记忆一般认为叫 working memory，我们认为它的时长也就是 2 到 4 秒，非常短。比如说你抄写一个电话号码，它是可以保证无损、或者说是精确的，但是它维持时间非常短——你抄完这个电话号码，如果这个电话对你来说不重要，你就不会再记得。

人真正厉害的是人的中期记忆，中期记忆能从几秒钟到星期级别不等。这套机制其实人类现在也叫海马体记忆。这是人类进行记忆和学习工作的一个非常重要的一个机制。

它的最大特点就是说：第一它是有延续性的；然后呢它是会遗忘的；它抓重点的能力非常强——它根据未来最有可能能用上的信息，它才会记住；并且这种记忆会通过反复刺激来增强。

最典型的就比如你写代码。人在写代码的时候根本不需要把整个仓库所有的这些东西都记住，人只要知道一个大概，他就可以开始工作。在工作的这段时间内，他可以保证第二天起床上班，他跟前一天工作是可以完美地接续在一起的。他不用像我们现在语言模型一样，每一个 task 都要把前面所有的代码全看一遍，他肯定是不需要的。

但是呢，这件事也看时间。比如说他出去休假了几个星期再回来，他可能就啥都忘了，他又得重新再 review 一遍。

然后最后，人是有长期记忆的：有些东西经过反复的刺激、然后印象深刻以后，它会形成一辈子都忘不了的那些记忆，用神经网络的话说，就可能就固化进参数了。

人是有这种分层记忆机制的。但是我们反观我们的网络、就是传统的 Transformer 的架构，如果按刚刚人类的这几个记忆机制来类比的话，它似乎只有短期记忆这一块，但是短期记忆的话它又太长了。

这太长了。比如说我之前曾经算过，按照一定的码率来估计的话，光是这个视觉信号可能 2 到 4 秒就占 30 万个 token 就差不多了；但是我们今天说的 long context 动不动就是 10 万、甚至百万，还有做千万这种级别了。

三个具体问题

张祥雨

这个 long context 就产生一个大家也都发现的一个问题：就是 context 变长，它很多时候只解决了「我把这个信息装下」这个问题，但是它没有解决一个问题，就是说我能从这个信息里获得什么。

似乎我们只能做一个最简单的 retrieve，稍微复杂一些的推理问题它其实做不了，它并没有解决怎么把这些信息用好这样的问题。

更麻烦的一件事：目前主流的架构、尤其是相对较小的模型，我们发现随着这个 context 增长，这个模型的性能都下降了。

这其中一个很大的一个原因就是因为 context 干扰。

比如说你让模型做一张数学卷：如果你让它一题一题做，一题做完清空，然后再做一题清空，你可以得到一个性能。如果让它连续做题，从第一题做到最后一题，可能开始的时候效果跟它差不多，但假如我题很多，比如说有 100 题、200 题，你会发现越往后面那个模型性能是急剧下降的。

其实你分析他的 attention 就可以看出来，就是他后面明显遇到了这个注意力涣散这个问题：因为有太多相似的 context 在他这个上下文窗口没有清空，他在看后面的题的时候，他不断地会 attend 到前面，然后模型要花很多的精力来避免这些干扰。

而且，就不说老生常谈嘛，大家说那个注意力机制是平方的，这个从 complexity 角度——但 complexity 不是我最主要关心的，我主要关心的是智能本身的建模模式。就是你光是这个问题，你就使得这个方式是不对的。

而且呢，我们经常说压缩才能产生智能。你这个信息如果你不经过加工来压缩它，不管是无损压缩、有损压缩，道理是一样的，就是用一个更精炼的表示——你要想办法提炼信息里边一个更精炼的表示，它才能产生智能。

但我们知道，在你用 Transformer 的那个 context 来建模的时候，它的 memory 容量是随信息增加同步增大的，所以它并没有任何压力或者动力、也没有什么 loss 来让它做压缩。

尤其是如果你关心的 task 还包括很多 retrieval task，这个模型就会更学到一个 bias：就是说我一点都不能忘，我必须得牢牢记住。因为我的训练器老是考我这个 retrieval 问题，比如说考我大海捞针问题，那我就一点都不能忘。

但其实这就是——这不是一种智能的表现，反而是一种智能倒退。本来可能存在智能的东西，正因为这种不遗忘、或者片面追求无损，它其实是阻碍这个智能进展的。

张祥雨

然后呢，实际中也取得一定的效果，但是用的据我所知还比较少吧。

但我是有这样的看法：这些架构都很好，但是现在关于建模 long context 的核心难点或者关键点根本就不在这里。

甚至于今年的 benchmark 有很多误区。比如说很多人会把 linear 的方法和普通 attention 混用，理由就是如果你不混用，retrieval 任务就没法做，比如说大海捞针过不了、就很难通过。

但问题是你想想这件事真的重要吗？这个 benchmark 真的重要吗？

替代方案：多模型协作

张祥雨

其实在今天这个 function call 的时代，long context 完全可以利用多模型——就 retrieval 这个 task 是可以通过多模型协作来解决的。

你想想，我给你一本书，人看完以后，假如他要对这个书写总结，但是很多细节，比如他要摘抄一些金句，这些细节他都忘了，那些句子是什么样他都是不知道的。

人并不是直接从他的记忆里背诵出这句金句——这个很容易出幻觉，因为记忆是有限的，人会忘。

而是人会翻书，逐章去翻。他虽然已经读过原书了，但他还是会一页页地去翻：我就根据我的印象，可能在哪附近是有一个我觉得比较好的情节，我想从那个情节里再抄一些好的内容。

那怎么建模翻书这个动作？你可以理解成这是一种 function call，但是在我看来，它可能会更复杂一些，它其实涉及到一个注意力、就是 context 转移：也就是说，我从一个全局的注意力转移到了一个局部，而这个局部呢是靠这个全局来导引实现的。

所以呢，具体建模我完全可以建模成两个 LM：

我每一个 LM 我都是只使用相对较短的这个普通 attention，混合上无限上下文的另一个来构建。我就不再像现在流行的架构那样，直接用一个全尺寸的 attention 加一个全尺寸的东西去搞——那样的话你等于只是取了个巧，然后你的 memory size 其实还是会变得非常大，就我前面说的所有问题都还在。

但实际上大可不必。我就故意用一个 context 非常小的普通 attention 来建模前面说的短期记忆，然后再用一个无限长序列的、比如说 linear attention 或者其他的，来建模这个全局的信息。

我有了整体感知，然后我想打开哪一页，我就触发一个动作——就是我印象中可能这个书 20% 的地方有一个东西我很看重。

然后呢，对于另一个 LM，我也可以用同样的架构，他就只看了那 20%，我看看他有没有我想要的这个东西。如果有了，他直接反馈给我的主程序、就下面那个无限序列的那个；如果没有，他没发现好东西，那我再换一个位置再看看。

哎，这样一搞，其实他还是一样——我用扩充思维链的方式，就比较巧妙地把它解决了。自始至终我都没有哪一个东西把整本书完整地存下来。

而相反，我通过扩充思维链，并且呢我这个思维链还带工具。但这个工具是广义的工具，它不只是指 retrieval 那种工具，它还包括调用另一个 AI。

这其实也是我认为为什么人类的脑区会学到这种比较精细的分工，而不是一个脑区就搞定所有模态、所有 task——这可能是更节省上下文的一种方式。

李广密

未来像大脑分区一样。

张祥雨

用这套思路推演 o3 的超长推理

张祥雨

比如说我们讨论一下，当时 o3 刚出来的时候，他是说他们可以做六天六夜不停的推理，然后有上千万个 token。那么，我肯定不知道他真正是怎么做的，那我可以简单思考一下，如果让你做你要怎么做。

最简单粗暴的方法就是：我设计一个架构，硬扛几千万个 token。这个第一很难也很慢，而且听起来成本也不太划算。

但是我现在告诉你，我现在手里只有比如 128K 的上下文，我要怎么做到这么长？

其实有一种非常简单的方法：我搞两个模型，一个模型做 plan，另一个模型来做具体的求解。

plan 模型呢，我是每一次我搜索到一条分支，我进入到这条分支以后，后面就是一个具体的演算和执行了，我把这个演算过程交给第二个那个模型来做。

这个模型它只有有限的上下文，它的上下文是经过那个 plan 模型摘要之后产生的。他给出一个结果，可能是已经找到答案了，或者是没有找到、但是他反馈了一些思路，然后他把这个结果汇报给我那个起到控制作用的模型。

然后这个模型再 plan，根据他这个反馈，我再 plan 第二条路径。然后这第二条路径我再发给那个刚刚负责执行任务的那个模型。注意这条路径其实已经跟刚刚的路径无关了，所以第二个负责计算和推导的那个模型，它根本不需要保留刚刚那一步的什么东西，它只需要有你这个起到控制作用的这个 agent 发给他的必要的信息，他只用这些信息就可以了。

这跟人类也一样：你做第二题的时候，你为什么还要对第一题念念不忘？ 比如说你做第一道题，你已经探索了路径、此路不通，然后你再算，那你为什么还要对刚刚那个路径念念不忘？这是一个道理。

就是说第二个模型就相当于它是人的注意力转移中的一个情景转移，它已经从一个 context 上切换成了另一个 context。

人是有很强的情景隔离的。 比如我现在跟你说话，其实我刚刚在办公室那边有很多问题，但是在这一刻我是不会想的，它就不在我的 context 里。

你就通过这样的方式，你会发现：假如说你的搜索层级是一个二叉树状展开的，那原来你需要把整个二叉树每条 path 全部拉直，你的 CoT 可能要上千万；但你现在只需要从顶层节点到底层节点这么一条路径。

也就是说，我负责 plan 的那个模型，他只要知道 high level 的架构——哪些路径搜过了、之前得到什么样的结果，也是 high level 信息；而我负责执行和演算的那个模型，他只需要负责他关心的那部分，他历史上的计算完全可以不存储。这样其实思维链长度就大幅减少了。

「这不就是拼 pipeline 吗？」

张祥雨

那最关键的是，这件事很多人看不起这个角度，说这不就是拼 pipeline 吗？而且在今天这个时代，很多人说讲拼 pipeline 的肯定永远比不过端到端了，对不对？

但是我今天可以告诉你：现在这套系统发展到今天以后，有了 RL 这套范式，这一套系统也是可以端到端训起来的。

为什么呢？我现在就给你一个 retrieval task，我甚至也可以用 rule-based 这种方案去搞。然后呢，我限制你这两个模型的 context 长度，你永远不能超过这个程度；但是呢，你们可以互相之间 communicate，可以不断地清空你的上下文。 反正最终的优化目标就是：我要最大化我回答对答案的概率。

这时候你会发现，这两个系统它如何协作，它不是你自己拼出来的。你可能需要一个简单的启动，但是经过 RL 的训练，他完全会 adapt 到他自己的那种 communication 方式。

所以它也是端到端的，而且比你直接塞到一个上下文里要强大得多。 而且它避免了那种上下文干扰问题，甚至于他会主动避免上下文变长，因为上下文变长一定会产生干扰。

李广密

那如果是沿着大脑分区的，那未来可能更多个模型有更多的不同的分工，通过 RL 的方式可以训得一体化更好。

张祥雨

是这样的，就我还一直强调一个观点：架构不重要，架构是服务算法和系统的。

你有什么样的算法，你就能做那样的架构。包括我说 linear Transformer，我为什么认为它一点都不本质呢？

那因为我们今天的算法是 auto-regressive 的 NTP。 如果你不用这个算法，比如说 Hinton 的那个 forward only 的那一套方法、就是无反传算法，你根本就不需要——你就一个任何一个普通的 RNN 都可以，因为它不反传历史。

甚至于这个算法如果最后 work 了，那么在线学习也就可以直接搞了，我就不需要有所谓的 training 和 inference 这个阶段，training 也是一种 inference。

Part 10 · 下一个 GPT-4 时刻：自主学习 / 在线学习

两根轴：算法与模态的螺旋上升

李广密

你刚才也提到了在线学习、或者叫模型的自主学习这块，能不能展开讲一讲为什么这个重要，以及这可能是实现 ASI 最重要的一个路径？

张祥雨

其实从今天大模型的演进来说，你会很明显地发现，真正的核心的驱动力是两根轴：

横轴是底层算法，其实就是叫优化方法；纵轴是模态。

优化算法的起点，或者叫从 0 到 1 的那个代表性的事件，是 next token prediction 的发现；按模态那个的起点是语言、翻译。

然后呢，我们的发展趋势其实都是在不断地——它是呈现一个螺旋上升的。

正因为 next token prediction 很 work、在文本上很 work，所以沿着多模态走，又有越来越多的人去研究怎么把类似的范式迁移到更多的模态。但迁移过程中可能会反复碰壁，碰壁多了，人们就会怀疑你这个范式、你这个训练到底 work 不 work。

还有一群人呢，他可能焦点主要是 focus 在语言本身，他在研究语言推理问题、尤其数学这些问题，他也发现了 next token prediction 的问题。

所以呢，大家一致结论这个不行，就基于这个压缩这个不行，我们得搞 RL。RL 就相当于直接面向目标优化，就不走那种间接的优化模式。

面向目标优化呢，发现一下子盘活了很多思路：首先语言模型推理能力强了一大块；然后多模态，之前大家多模态都无解的、甚至理解一体化这些问题，突然就因为有了推理模型，很多事情就变得都想通了，我们就可以继续再走了。

然后今天我们仍然是处于这个——大家还在挖掘 RL 这个训练算法的上限，但是已经越来越多的人也是开始发现，这套算法看起来也不是那么的完美。

只有 rule-based 和逆强化学习是 work 的

张祥雨

比如说纯搞语言的人，他觉得这件事最不 make sense 的一点在于什么呢？

就是目前只有 rule-based、还有以及一些那个像逆强化学习这样的方案，它是 work 的。

但是呢，这件事跟人类的学习其实差别非常大，而且呢局限性也特别大。比如最典型的就是 rule-based：你是无法处理那些没有明确评价标准的东西的。这些没有明确评价标准的东西呢，你可以通过模型来建模，但这些模型的行为又很容易被 hack。

以及对于人类来说，关于自我价值的认知以及正确性的判断，这个更多是靠人脑自己，而并不总是——就像经常开的玩笑，人不是做每件事都是服务于 KPI 的，他是要有自我意识，他有一个自驱力在驱动这件事。

也就是说，这个评价的这个模块，很大概率上它不应该是个外界的。我们现在是 rule-based，它都是外界；你训的那个模型、就 reward model，它也是外界，这就是逆强化学习嘛——你蒸馏了外界的偏好，然后来监督他自己。他都是来自外界，但是我们缺少一个真正的内生原动力。

可能很多人说这个不重要，现在的方法已经够了。

environment scaling：新的墙

张祥雨

但是你在工程实践上你会发现，如果你一直沿着 rule-based 现在这套方法走下去，你又会重新遇到 scaling 问题。这个 scaling 不再是我们之前说的 model scaling、data scaling，现在叫 environment scaling。

就是说，比如说你要解编程问题，你要搭环境嘛，你要做到 rule-based 你就得搭环境。结果一个 project 你得搭一个环境，把整个那一套 docker、那个输入输出，还有测试数据都给配起来——结果你产生了一条数据。

这个效率太低了。但大厂现在很多，据我所知就这样干了，就找了很多工程师一个一个写 project。这也是很多厂、尤其是主打编程的厂，他可能比较擅长做这件事。

但是终究这件事跟人类不一样。 人类不是通过给他无数的环境、外界手搭好；人类是自驱的，他会自己看文章、自己搭环境，从环境反馈中获得学习，并且这个学习绝对不是一个 0/1 这种要素的一个学习。

一个很小但还没解决的问题：从自然语言中拿反馈

张祥雨

我就说一个非常小的、这个大闭环里面非常小的问题：就是说如何从人类自然语言中拿到反馈？ 因为发现即便是这么小的一个问题，目前都是很难实现的。

举个例子：我写了篇作文，我的老师跟我说——啊你第一段写得不错；然后第二段稍微修辞用得有点过；然后第三段的话就是跟上下文衔接不太行；然后第四段有些错别字；然后整体读起来就感觉略显干巴，而且长度太短了。

这个老师从非常多不同维度对我这篇作文做出了评价。

但是我们今天的 RL 是怎么做呢？ 把每条评价都单独加了个权，这个算了 0.1 分，这个加了 0.5 分，最后说我这个回答得了 3 分。完全丢失了这里面非常丰富的评价的维度。

所以看起来——这也是现在大家做 general RM 的一个困境：就是说你确实是可以从多维度评价一个回答的好坏，但是怎么利用这些维度，现在是没有什么好方法的，最后都是把它加权成一个干巴巴的数字。

对于模型来说，它根本不知道这个数字怎么算出来的，他只能猜，他通过大量的样本去猜你的打分规则、你是靠什么算出来这个数字。以及他不仅要猜你的打分规则，他还得猜你的每一块的打分的要素——你是根据我第一段打的分，还是第二段呢，还是整体风格，还是整体的这个叙事逻辑？这些不同的维度，这信息完全丢失了。我根本无法从这一句话中获得反馈。

就现在连这一步，我们都还没有比较完美的解法。虽然说论文很多，这块的论文现在已经比较多了，但还没有一个在工业界上大家比较认可、做得比较好的。

其实这也是我现在重点研究的一个领域。就是要真正实现自主学习，它的前置技术链还是非常长的。我认为其中最需要解决的就是跟环境沟通，而跟环境沟通很多是那个自然语言，你得解决从自然语言中获得反馈这个能力。

就跟领导批评你，你这做得错了，你得知道你要向哪个方向去改 —— 这个才是基础。

自主学习需要的两个技术细节

张祥雨

那我刚刚说的就是当前这一代 RL、rule-based RL，它面临的最大问题其实还是环境，环境不可 scale up，你需要非常多的人去做标注。

而且这个跟人类是完全不一样的。人类它应该具有在那个空间里面自主探索，就是跟环境沟通中不断地 improve 他自己这样的一个能力。

这里面又涉及两个技术细节：

一个就是无限长上下文的建模，其实就跟刚刚那个 long context 就建立关系了。在无限长——因为真实的环境它就是一个无限长序列，而且是个动态的，就没有稳态的这样的一个界面。

第二个就是学习算法。 学习算法中尤其关键的就是刚刚说的：如何从这个自然语言、或者非结构化反馈中来提炼；以及你要如何设计你的内生奖励——内生奖励就是说驱使这个模型如何更新你自己的权重参数来适应这个事。

这个其实就是下一代自主学习要解决的问题。

我们经常说这个自主学习跟在线学习经常是绑定到一起的。因为像我刚刚说的这个模式，如果你能搞定自主，那为什么不把它放到真实环境中玩一玩呢？ 那其实他就是一个在线模式。所以这两件事是绑定的。这个也是我们下一步就是要重点投入的一个方向。

所以未来两年，可能我们还能再看到至少两个 GPT-4 时刻：一个是多模态的推理，一个是这个自主学习或在线学习。一个还会有更多的机器人时刻。

张祥雨

剩下的就不好预估了。

Part 11 · 澄清一些有关 Agent 的观点

李广密

现在那个 Google 还有一个就是 Agent，可能在未来一两年大规模地做有经济价值的任务，他们觉得这个可能是一个方向。

张祥雨

这个我想澄清一下：现在的 Agent 呢，和 OpenAI 提的很可能不是一件事。

OpenAI 的那个叫做智能度的五级分类法，它其实是非常有逻辑的。你看它第一级是 chatbot，第二级是 reasoning，第三级是那个 agent。我想说的就是，它这个 agent 跟我们今天说的 agent 应用差别挺大。

它这个五级分级，其实它背后的潜台词是：每一代这个升级，它都得有一个全新的算法的产生。

比如说 chatbot 的这个时代，它本质就是 next token prediction。

他之所以要 reasoning 呢，他要把他的 o 系列拿出来，因为他把长思维链 RL 做出来了，而且 RL 会往后越来越 scaling。所以以 RL 主导的这个时代，他们叫做 reasoning。

那 agent 这一级你自然就可以想，那是什么？我认为就是自主、在线学习。

因为 agent 这个东西，它定义上特别强调自主性：就是说我不需要人工设计这么多环境、我不需要人工给它定义这么多规则。

就相当于现在的这个 RL 的系统，就感觉还是一个 KPI 驱动：第一是它训练结束它就不能再继续 improve 了；第二它的训练过程完全依赖人工给他定了目标。

但比那个 NTP 要好一些的是：NTP 你不仅要给目标，你还要把路径达到这个目标的路径也背下来 ——「就这条路，你给我背下来」；现在是我给你个目标，你去实现去吧。

但是在自主学习，他相当于把这个目标这块也要放开 ——所以你得自己去找目标、自己探索、自己学习自己的价值。

这个是 agent 的时代，因为它定义为它能够独立工作。你要能独立工作、自我进化，你必须得有这样一套体系，所以它是要有新的算法的。

呃，今天我们说的 agent 更多的应用，它其实是把一个复杂 pipeline 搭到一块；或者是借由今天这个 reasoning 的模型、这一代的这个 RL 机制——你看现在大家普遍在推叫工具、function call，其实就意思是让 function call 这件事变得更加智能，就按需调用。

它其实这一代 agent 更多的还是 reasoning 这个时代的想法：就是说把一系列系统给它串起来，然后我有个统一的 KPI，你们随便输出，最后你要让我那个 KPI 最大化就结束了。这还是 reasoning 这个时代的思路。

但是它比 LangChain 那个东西它又进一步了。

LangChain 那个时代好像也有人说那个 agent 就是完全是自主——这就是那个 hand-crafted 的 pipeline，那个时候讲的 agent 本质上还是 next token prediction 这个时代的产物，大家通过 prompt engineering 把几个流程给它糊起来。

那个是属于那个时代的东西。现在这个时代我们讲究的是叫模型主动调工具。

但不是调就完了。这个调不是靠 prompt 激发调的，它是因为它扩展了这个调的动作空间，它靠 RL 自主激发：就是说以 RL 的那个优化目标最大为原则，它认为调了会更好，它就会调；如果它发现调了还不如不调，它就不会调。就相当于模型学出了这种能力。

Part 12 · 世界模型与机器人抢跑

李广密

我说他有关注过那个飞飞提的那个世界模型了没有？包括 LeCun 也在提嘛，我感觉最后可能就是祥雨说的这一套。

张祥雨

最后是殊途同归的。 他核心想解决的也是那个自主学习，但是说他的设计方法论还是有很大区别。

比如说他不提生成一体化，我觉得也是非常有道理的。

生成真不是必须的。 我为什么这边提生成？是因为从语料获取便利性角度，生成是最好的那种一种监督、或者自监督的一种模式。

但是 LeCun 说的是完全正确的：人身上没有视觉生成器官，人可以想象未来，但未必要画，他可以在脑中想象。 这件事非常正确。

我认为甚至于这个方向才是我们说再下一步——再到下一步，是我们进行更复杂的空间推理，我需要结合世界模型。这个结合了世界模型的说法，它可能更为本质。

但世界模型要怎么训练？从目前来看，还是得靠生成式学习。

所以这里又回到一个：就是叫做人虽然是没有生成器官，但人是有世界模型的，他能从脑中想象未来。但这个世界模型怎么学习更为方便？对人来说可能非生成式更方便；但对于我们现在这一步来说，可能做生成式方案会更多。

李广密

未来机器人的大脑，跟今天的多模态未来这个融合之后的模型，包括甚至自动驾驶的模型，这几个未来会是殊途同归吗？

张祥雨

对。实际上这几个领域目前其实是在抢跑的。

我们的智能水平远远没有到聊到这一块，就是说现在大家还在为视觉这一块在挣扎中。 而那个机器控制，它实际上是先抢跑、先起跑的。

因为它研究的 domain 一般要么是问题比较局限，要么是它控制的那个场景比较局限。

比如自动驾驶，它的控制维度其实比较低的，然后它跑的场景也是比较受限的，相对于那种通用计算来说是受限的。所以这就给了它一些机会，就是它可以提前用一些 rule-based 方法、以及分拆模块的方法，先把这个系统先 run 起来再说。

但你看现在自驾的趋势，它也是走向端到端。

当所有这些事情走向彻底的端到端，并且你还需要整合这个识别推理或者动态推理，就会发现跟 AGI 这个主线的形态是一样的。

那机器人当然更是——现在的事情做不好，你只能做个叠个被子、或者跑跑步、像跑马拉松，然后再做个小脑这些东西。那还是因为技术还没到这，但是并不妨碍这些东西已经可以做一些应用，应用很重要。

所以它其实是提前抢跑。他的路线也未必是按照我刚刚说的 AGI 主线这块来的，但是终究他会在某一个时刻汇合。
