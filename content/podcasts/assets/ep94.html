张小珺

DeepSeek、Kimi、MiniMax 这三篇注意力机制的改进策略，是共性更大还是差异更大？

杨松琳

我觉得 Kimi 和 DeepSeek 这两篇共性更多一点，它们都是动态稀疏注意力。「动态」是说，它们的稀疏性质不是事先预定好的。

之前很多工作叫静态稀疏注意力（static sparse attention），稀疏模式是事先给好的。比方说谷歌之前有一篇工作叫 BigBird，它有一些固定的模式，比如平移的、跳跃的稀疏注意力，或者其他事先给好的 pattern。

而动态稀疏注意力是说，稀疏性由 query 动态决定：对每个 token 而言，它的 query 不同，它想要 attend 到的 key 和 value 就可能不一样。这就是动态稀疏注意力的核心思想。Kimi 和 DeepSeek 都想把这种动态稀疏注意力用在训练上面，所以它们非常相似，我们之后也会讲到。

MiniMax 则是另外一套思路——用的是线性注意力。线性注意力可以被写成 RNN 的形式，推理的时候是常数的空间复杂度，每一步也是常数的时间复杂度，总体加起来就是线性的推理复杂度。

张小珺

我理解今天的节目很大一部分都会围绕注意力机制展开。能不能先在节目开始给大家介绍一下：注意力机制是什么？为什么 attention 对于大语言模型这么重要？

杨松琳

注意力机制的起源有很多说法。一般公认的可能是之前有一篇 paper，在 LSTM 的 hidden state 上面做了一个 attention，把这个东西叫做注意力机制，大概是 2015 年的一篇工作。之后注意力机制由谷歌发扬光大，就是那篇非常知名的文章——Attention Is All You Need。他们用这一个架构完全取代了之前非常风靡的 LSTM。

因为这个架构训练起来并行度很高，所以在 GPU 上非常高效。这样它就具备了 scalability，很容易堆参数上去、训得更大。后面的 BERT、GPT 乃至现在的各种模型，都是基于 Transformer 这种架构。

注意力简单来说是这样：对于每两个 token，它们之间有一个 score，就是这两个 token 交互的分数。每一个 token 都要对所有其他 token 算出一个 score，这个 score 通常就叫注意力分数（attention score）。在自回归建模当中，我们一般会有一个 causal mask，防止这些 token 去 attend 到后面的 token，保证它只能看到前面的 token。

具体这个注意力分数怎么算呢？每一个 token 会有三个向量：Query（查询）、Key（键）、Value（值）。在自回归里面，每个 token 会用它的 Query 去跟之前所有的 Key 做点积，得到一个标量（scalar value）的注意力分数，再做一次 Softmax 操作，得到归一化的注意力分数。最后再由这个注意力分数，对之前那些位置的 Value 向量做一个线性组合，得到输出。这大概就是注意力机制的核心思想。

张小珺

可以怎么更简单地理解 attention？

杨松琳

更简单地理解 attention——我觉得 attention 就是每两个 token 之间建模一种交互。这样一个过程其实我觉得都能叫 attention，它是一个 pairwise 的建模过程，可以去建模这个序列里面每两个位置的交互程度。

Part 1 · DeepSeek：Native Sparse Attention（NSA）

1. 「Native」是什么意思

杨松琳

好，现在我们来看一下 Native Sparse Attention 这篇文章。

先说这个名字里的 native。它的意思是：要做一种在硬件上能够原生可训练的 sparse attention。它可以说是现在这些工作里面，第一个把动态稀疏注意力拿来做预训练的模型。

为什么之前的动态稀疏注意力不能做预训练呢？后面会讲到，它训练的时候会遇到各种各样的困难，主要是它跟当前的硬件不是非常 align、不是非常对齐的。所以当前主要的这些 dynamic 工作，都是用来加速 inference，而不是从头开始预训练。

DeepSeek 这篇文章我觉得是开创性的——第一次拿动态稀疏性做非常大规模的预训练。

它用到的机制，主要是基于 Quest。Quest 是 ICML 2024 的一篇文章，由 MIT 韩松老师组出品。Quest 的核心思想是：对于每一个 token，它应该动态地决定要注意到的 Key 和 Value 的 block 在什么地方。这个也很好理解，因为每个 token 需要的信息就是不一样的。

Quest 具体是怎么做的呢？为了跟硬件更亲和，它对每一个 query 会往前面找一个 Key/Value 的 block，而那个 block 是连续的（continuous）一段，里面有很多个 token，它们在位置上连续。这样在硬件上就可以做连续读取，避免一些额外的开销。

Kimi 和 DeepSeek 这两篇文章，其实都可以当成是 Quest 的 follow-up——把 Quest 拿来做预训练。

接下来我们会看到，这篇文章针对 Quest 这种 sparse attention 机制，是如何做 hardware-aware 的设计的：也就是在算法设计层面上，让算法更加硬件亲和，这样训练就能更高效。

这一篇的卖点，我觉得是他们想把这个东西在 modern hardware 上直接端到端地训，而且训得很好。最后他们发现，从头开始预训练，效果甚至能比 Full Attention 还要好——达到一个既快又好的目的。他们野心非常大，既要还要。

3. 三个分支：压缩、选择、滑窗

杨松琳

我们可以看图 2，这是他们架构的核心思想。

之前提到，它想让每一个 query（每一个查询的 token）去 attend 到不同的 Key/Value block，这是 Quest 这篇工作的思想。所以首先会把 Key 和 Value 分成不同的、连续的 block——这里可以看到它分成了四个 block，这是打个比方。

第一个分支：压缩（Compression）。 对于每一个 block，会有一个 compression 操作，把这个 block 里面所有的 token 压缩到一个低维表示里去。之后每一个 block 都有一个表示，query 就能够跟这些 block 的表示做一次 attention，得到 attention score。这里它是先把 Key 压缩成一个表示，同理也把 Value 压缩成一个表示。

这样我们会得到：给定一个 query，它对每一个 block 的一个 attention score。然后再 apply causal mask，再对每个 block 的 value 做线性组合，得到一个 output。

这个 output 会再过一个门控——图里写的是 gated output。它这里有三个分支，每个分支都会有一个门控，来决定它们对整体 output 的贡献程度。门控是模型自己学出来的：把 input 的 representation 过一个 projection 得到一个值，这个值由该 token 的表示决定。这是一个经典的门控机制。

所以第一个分支是比较粗粒度的：对每个 block 得到一个 block representation，做的其实类似于 block level 的 attention。

第二个分支：选择（Selection）。 粗粒度的 attention 做完之后，他们会想做一些更细粒度的 attention。但如果所有细粒度的都要做，就退化回平方复杂度的 Full Attention 了——所以这里就是 sparse attention 的来源：我们不想对所有 block 都做 attention，只想对 Top-n 做 attention。

比方说这个图里 n = 2，我们会在这四个 block 里选出 attention 分数最高的两个，来做更细粒度的 attention。这里我们选到第二个和第四个 block，然后把这两个 block 里所有的 token 拿过来，query 再对这些 token 算出 attention score，再对它们对应位置的 value 做加权求和，得到第二个分支的 output。同样，这个 output 也会有一个门控机制来决定它对整体 output 的贡献。

第三个分支：滑动窗口（Sliding Window）。 最后是一个 sliding window attention、也就是滑窗注意力的分支。这个分支主要是考虑到 language modeling 有一个 inductive bias：临近的 token 往往更重要。

如果你把一个训好的 Softmax Attention 模型的 attention map 做可视化，会发现很多注意力会集中在滑动窗口上，以及最开始的几个 token 上。后面这个现象一般被叫做 Attention Sink，是在 StreamingLLM 里面提出来的。

这里就直接利用了这个 inductive bias，默认就去 attend 滑动窗口的部分，得到一个 output，同理再做一次 gating。

最后我们对三个分支分别做 gating，把它们相加，得到最后的 output。这就是 Native Sparse Attention 的整体思路。

张小珺

在这张图里面，它是如何平衡全局和局部信息的？比如说压缩、selected 和 sliding window 这三个分支是怎么协同工作的？

杨松琳

我觉得这是让模型自己学出来的。

因为模型有一个门控机制，门控是一个经典的自调节机制。模型可以通过自己的 representation——每个 query 位置对应的那个表示——自反馈地学出「我每一个分支应该配多少注意力」。所以这里就没有那些人为的 inductive bias。因为很难定义每一个分支具体要选多少，所以我们不妨把这个选择直接交给模型，模型可以自己学出它需要 focus 在哪一个分支上。

这就是整体的核心架构。

第二个分支其实跟 Quest 很像——Quest 也是需要把每一个 block 得到一个 representation，再通过 query 去跟这个 block 做 attention，然后算 Top-k 来做 block selection。

所以这一篇工作的 novelty 并不在于这些机制。后面我会讲到，这一篇主要是集中在如何解决效率问题。其他这些机制，比方说 sliding window attention、粗粒度和细粒度的 attention，应该在已有的 literature 里都是有的，他们的主要贡献更多集中在如何让它变得更高效上面。

4. 关键分歧：MHA 可以各选各的，GQA 不行

杨松琳

这篇工作也提到了 Quest，但 Quest 其实是有一个问题的——这篇文章说它不能很好地跟更现代的 attention 机制兼容。

为什么呢？在 Quest 里面，每个 token 要去选不同的 KV cache，而且每一个 attention head 都要去选它自己的那个 KV cache 子集。

我们可以先简单回顾一下什么叫 Grouped Query Attention。我打开这张图，比较好理解：

  • MHA（Multi-Head Attention）：每一个 head 有自己的 Key、Value 和 Query。
  • MQA（Multi-Query Attention）：所有 head 的 Value 和 Key 都是共享的，所以只有一份 K 和 V。这样在 inference 的时候，整体 KV cache 的大小就从原来那么多缩小到只有一个 copy，KV cache 的大小会极大缩小——这就是为什么 MQA 在 inference 的时候高效很多。但因为缩减得有点太多了，所有 head 都共享同一份 Key/Value 表示，可能会带来最后 performance 上的一些 degradation。
  • GQA（Grouped Query Attention）：为了缓解这个问题，我们折中一下，不做这么激进的 sharing，做一些稍微温和一点的 sharing。比方说每两个 head 之间共享一份 Key 和 Value——这就叫 grouped query，所以叫 Grouped Query Attention，缩写就是 GQA。

回到 Quest。在 MHA 的情况下，每一个注意力头的 Key 和 Value 都不一样，那对每个 head 来说反正都要去读不同的 KV cache。所以你让每一个 head 去选不同的 KV block，整体的读写量是相同的——在 MHA 下你可以尽情地让不同的 head 去选不同的 KV block，因为整体 KV cache 的读取量是恒定的。而且如果能让不同的 head 读不同的 KV block，diversity 和灵活程度都更强，更有利于模型学到一个更好的 model。

但这只对 MHA 成立。 回到 GQA：一个 group 里面是共享 Key 和 Value 的。如果这个 group 里不同的 head 去 attend 不同的 KV block，因为你只有一份 Key/Value 的 copy，所以每次都要读不同的 KV cache 进来；反过来，如果这个 group 里不同的头选择同样的 KV block，那就只需要读一份共享的 KV cache，能带来 KV cache 读取开销的缩减。

也就是说，在 GQA 的情况下，如果一个 group 下面不同的 head 去选相同的 KV block，读取量会少一点，有可能带来 inference 上的加速。

这个地方我们之后会反复强调，它会成为 NSA 与 Quest、以及 Kimi 的 MoBA 之间的核心不同：Kimi 和 Quest 都是每一个注意力头能去选不同的 KV 子集；而 NSA 为了减少「在 GQA 下每个头 access 不同 KV block」带来的开销，会强行限制不同的注意力头去注意同样的 KV block。这就是为什么 NSA 在 decoding 的时候能带来额外的加速。

具体怎么保证不同的头选的是同样的 KV cache 呢？在做 block selection 的时候，它有一个求和操作：把一个 group 里面所有 head 对不同 block 的 score 加起来，每一个 group 就得到一个唯一的 selection score，再用它来做 Top-k——以此保证这个 group 下面所有 head 行为的一致性。

中间还有一小段处理 corner case 的内容我就不细讲了：它的 selection block size、sliding window 的 block size、以及 compression 的 block size 其实是可以灵活设置、不一定相同的。当它们相同的时候比较好做，直接通过前面说的块间注意力就能选出来；不相同的时候就比较麻烦，需要一些额外的处理机制。这部分稍微有点复杂，但完全不影响 high-level idea。

5. 回顾 FlashAttention：为什么要分块

杨松琳

前面讲的是这个设计对 inference time 有好处，下面说它对训练同样有好处。为此我先带大家简单回顾一下 FlashAttention-2 的 kernel。

它这里说：如果我们用 FlashAttention-2 那种 strategy，把一个连续的 query block 载入 SRAM，那么 memory access 是不高效的。因为同一个 block 里的 query 可能会注意到不同的 KV block，那么对这个 query block 来说，它需要从全局显存里读进来的 KV block，就是所有 token 所需 block 的并集。可以想象在最坏情况下，这个 query block 里所有 token 想要注意到的 KV block 都不相同，那我们就需要把整体的并集全部读进来，这就造成了 inefficiency。

我们简单再回顾一下 FlashAttention。它有一张图，DeepSeek 也画了一张类似的图。

FlashAttention 是这样：query 以块状的形式读进来，我读一个 block；Key 则从头开始，有一个 loop——比方说这里 query 是第四个 block，我会把第一个、第二个、第三个、第四个 block 按顺序 load 进来。假设 block size 是 b，我每次会 load 一个 b×d 的小矩阵进来。为方便起见，假设 KV 的 block size 和 Q 的 block size 相同，都为 b。

这样两边都是 b×d，我们可以做一个矩阵乘法——一个 b×d 乘一个 d×b，得到一个 b×b 的注意力子矩阵，也就是完整 self-attention matrix 里的一个 sub-block。然后再把对应的 Value（b×d）load 进来，先做一次 online softmax，再做一次矩阵乘法，就得到一个 output。这就是 FlashAttention 分块（blocking）的核心思想。

为什么要分块做呢？因为这样一来我们可以利用 Tensor Core 加速，同时又可以避免把 attention score 写回 HBM。

这里可以简单讲一下 memory hierarchy——FlashAttention 那篇 paper 里就有一张图：SRAM 是共享内存，容量比较小，但带宽非常大；HBM 就是普通 GPU 的显存，比方说 A100 有 80GB 显存，指的就是 HBM 的大小（这张图上可能是 A100 40GB 的版本），它的带宽显著比 SRAM 低很多。所以这些硬件高效的算法，都尽可能想把计算保留在 SRAM 里面，减少 SRAM 和 HBM 之间的通信。

回到 NSA。因为 FlashAttention 面对的是 Full Attention，对每一个 query block 来说，它之前所有的 Key/Value block 反正都要扫一遍，不会有什么浪费。但对于 Sparse Attention，不同的 query 所需要的 KV block 是不相同的——如果我们还是这样连续地读 query block，那我就需要 load 每一个 query 对应 KV block 的并集，这会带来 memory access 上的低效。

6. NSA 的解法：把并行维度从「序列」换成「注意力头」

杨松琳

这一篇就利用到了 GQA 的一个特性。

MQA 或 GQA 在 inference 的时候有一个技巧：它可以靠 number of head（注意力头的数量）这一个维度来凑出矩阵乘法的形式。在解码的时候这有点像 batchify——只不过因为它有一个共享的 Key 和 Value，所以就存在一个可以 batchify 的空间。这句话可能有点难理解，我们下面就来讲它是怎么 batchify 的。

回到 FlashAttention：它是一个 b×d 的 block 进去，算出来也是一个 block 的 output。b 一般会取到 128，所以它会并行地算 128 个位置。

但回到 DeepSeek 这个模型：为了避免 query block 带来的读取浪费，这里干脆让每一个 token 独立地算自己的 output，不把它们捆绑在一起算。

FlashAttention 之所以要捆绑，是因为它需要凑一个矩阵乘法——它需要 query 的 block size 这个维度来当矩阵乘法的一维，要不然就没法用矩阵乘法算了。而在 GPU 里面我们非常喜欢矩阵乘法，因为半精度的矩阵乘法可以调用 Tensor Core。Tensor Core 是 GPU 上一种特定的计算单元，能非常高效地计算半精度矩阵乘法。

打个比方：在 A100 上，给定相同数量的 FLOPs，用半精度矩阵乘法来算，要比用其他计算单元（比如 ALU）来算快大概 16 倍。而在 H100 这些硬件上，Tensor Core 越来越快，以至于矩阵乘法太快了，反而是 memory 的 loading 成为瓶颈——这就是大家常提的访存瓶颈（memory bound）。

有点扯远了，我们回到这里。我们不想在 block 维度上把 query 捆到一起读（那样会引入很多不必要的读取），但我们又想凑成一个矩阵乘法，那怎么办呢？前面提到 GQA 存在一个 batchify 的方式——那这里就来了。

对于 query 来说，它是 multi-query 的：对于相同的一份 Key 和 Value cache，query 是有多份的，这里是 h 份。而我们前面又强迫这 h 个头去共享它们所选择的 KV cache 子集——也就是说这些 block 对它们来说是共享的。所以我们干脆把这 h 个头打包到一起同时计算，这里就存在一个 batchify 操作：h 可以想象成一个 batch 维度。

这样我们就又可以用矩阵乘法了，只不过这次矩阵乘法的另一个维度不是 QKV 的 block size，而是 QKV 的 number of head 这个维度。

7. 一个副作用：被硬件逼出来的 64 个头

杨松琳

另外值得一提的是：Tensor Core 并不是所有矩阵乘法都能优化的，它有一些限制，比方说最小尺寸是有要求的。在这个 case 里，比方说在 Triton 里，它要求 H、D_k、B_k 这些维度都至少是 16。而 NSA 是用 Triton 写的，所以就要求 h 至少是 16。

但这个要求其实是非常强的。因为我们平常每一个 query group 下面的 head 数量是不会有 16 个的。同时我们又想让它有 4 个 group——为什么呢？因为每一个 token 想选择的 KV cache 子集，其实是靠 number of group 来决定的：我们已经把每个 group 下面不同 head 的行为绑定了（它们会选相同的 KV block），但我们又想保证不同头之间还是有一些差异度，这个差异度就只能靠 number of group 来凑。一般 GQA 都会用到 4 个 query group，比方说 Llama 我记得就是 4 个 query group。这里也强行把它拉到 4 个。

两个约束都想满足，他们就干脆把整体的 head 数量增大了。我们可以看到，这里 d_k 是 192，head 数是 64，相乘就已经将近 12,000 左右；而 hidden dimension 其实只有 2,560。这说明这里有一个非常大的向上投影过程。一般是不会这么干的——一般可能就是 2,560 投影到 2,560，然后再切分成各个头。这里完全是因为想强行把 head 数量拉上去，同时又想要更多的 group 数量，来保证每个 token 不同 head 之间选择 KV block 的 diversity。

这个做法我觉得非常有 DeepSeek 的特色。像 DeepSeek-V3 里面的 MLA 也是类似的做法：搞很多很多的 attention head，也会有一个非常大的向上投影过程。

DeepSeek 的考虑可能是：反正我是从头开始训练的，所以只要最后 inference time 和训练 time 这两个阶段都是硬件高效的、都足够 efficient，那这个 up projection 也无所谓。因为在 MoE 阶段反正有非常多的参数，所以也不会造成 attention 参数和 MLP 参数不成比例的问题。所以在 MoE 这个框架下面，DeepSeek 这么选择还是挺合理的。

这里用到的 MoE 是他们之前那个 MoE，跟这篇文章基本没什么关系，我就不讲了。

8. 结果：为什么「原生训练」才能超过 Full Attention

杨松琳

接下来我们看训练的 loss，可以看到它跟 Full Attention 相比，基本上全程都比 Full Attention 要好一点。

张小珺

他俩挨着。

杨松琳

对，但还是一直在它下面的。

表 1 是一些 benchmark 结果，NSA 甚至都会比 Full Attention 要好。这就证明了预训练的重要性。因为如果你只是在 inference 的时候做一些改动——他们后面会有一个消融实验——在 Full Attention 的基础上再套 sparse attention（比方说套 Quest），其实是会掉点的。但你把这种 sparse attention 机制直接拿来做预训练，就可能得到比 Full Attention 更好的结果。

刚刚提到的那些方法，是先训一个 Full Attention，再在 inference 阶段用不同的 sparse attention technique 尽可能增加效率。可以发现，这些模型因为不是从头开始训练的，所以它们需要去贴近 Full Attention 原本学出的那个注意力分布——这是一个逼近的过程，所以肯定会有损失。比方说 Quest 跟 Full Attention 相比就会更差。

他们甚至还做了一个 exact top-k：直接把 attention score 矩阵完整算出来，然后直接求 top-k。这是所有 top-k 方法的上限。我们发现这个上限其实没有多高，因为它始终是对 Full Attention 的一个逼近——再怎么逼近，还是有个天花板，那个天花板就是 Full Attention 本身。

而 Quest 跟 exact top-k 相比肯定还是更受限的，因为 Quest 要保证 KV 的选择是以 block 为单位的，这样在 decoding 的时候才可以一块一块地 load、尽可能加快效率。得到了效率，就失去了一些灵活度，所以 Quest 比 exact top-k 效果更差，这也非常 make sense。

所以，如果我们想让 sparse attention 甚至比 Full Attention 还要好，那只有一个出路，就是 from scratch 从头训。这个地方非常惊喜，我觉得这是 DeepSeek 这篇给我们指的路——DeepSeek 可能就是想告诉大家：你们不要在 Full Attention 的基础上再做 sparse attention 了，不如干脆去设计一些在训练时就表现得很好的 sparse attention 机制，这样就有可能直接跳过 Full Attention 的性能上限，解锁一些新的能力，或者说比 Full Attention 更好。

这一个 benchmark，可能是 long-context 的 benchmark，在长文本能力上，sparse attention 比 Full Attention 都要来得好。

对于这个现象有一些解释。首先，Quest 和 NSA 这类方法是不丢 KV cache 的。有一些模型，像 H2O，其实是会丢 KV cache 的。近一年有一些工作说明了：只要这个机制会丢 KV cache，那它对 performance 的影响就会很大——因为你指不定这个 KV cache 在之后的 query 又会被用到呢。这大概是一个 intuition，解释了为什么不丢 KV cache（比方说 Quest）的效果会比丢 KV cache 的更好。

其次，不丢 KV cache 之后，sparse attention 还有另一个作用：帮助注意力更集中。Full Attention 其实是一个非常冗余的机制——因为注意力自己学出来就是 highly sparse 的，有很强的稀疏 pattern 在里面。大家可以把训好的模型的 attention map 取出来，很容易发现里面有很多很多冗余。

直接用 sparse attention 来训，我的一个直觉理解是：它在训练的时候就已经去除了一些冗余，能够帮助注意力更加集中，这样效果就有可能更好，它不会被一些无关紧要的 token distract 到。

最后这里有一个大海捞针（Needle in a Haystack）测试，我们可以看到是绿油油一片，说明它的检索能力还是在线的。这个也很好理解，因为它没有丢 KV cache，靠模型动态选就行了。

最后这一点也很神奇：它不仅能增强长文本能力，甚至还能提高 chain-of-thought reasoning 的表现，这一点非常有意思。DeepSeek 用他们自己的 recipe 在 SFT 数据上做了微调，结果发现 NSA 的推理版本甚至比 Full Attention 的推理版本还要好一些——说明动态稀疏确实非常有潜力。

9. 速度实测与消融

杨松琳

图 6 把 Triton 实现的 NSA kernel 和 Triton 实现的 FlashAttention kernel 做了对比。因为想公平比较，所以 Triton 对 Triton——他们可能也没有时间来写 CUDA kernel，而一般 CUDA kernel 还是比 Triton kernel 要快一点的。

公平较量之后我们发现，NSA 在比较短的长度上就已经比 Full Attention 要好了；序列长度越长，加速比越多。比方说在 64K 上，来到了将近 10 倍的加速。

最后这里是 decoding 的 expected speedup。为什么测的是一个期望值呢？因为 decoding 是一个 memory bound 的过程，那么整体效率基本上就跟你需要读取的 KV cache 的量相关。前面提到 NSA 对 GQA 更有好处，因为它限制了每一个 group 下面的 head 都要 attend 到同样的 KV cache，减少了很多读取。

所以它不但相较于 Full Attention 会快，相较于 Quest、或者相较于 Kimi 的 MoBA，它在 decoding 上都有天然的优势。

这也是我非常喜欢 NSA 的一点：他们发现「让一个 group 里的 query 共享选择」能带来的提升很多，虽然会有一些局限性，但他们就进行了一些比较激进的修改——比方说增大 head 的数量——来保证模型的 performance 也在线。这样我们既能达到 performance 不掉甚至更好，又同时在 inference time 非常非常高效。这一点我觉得非常难能可贵。跟别的地方相比，DeepSeek 真的很敢去改架构。

最后我们看这个 ablation study，看的是它选 block 的机制。

前面提到 block selection 有一个压缩分支——那个分支会基于每一个 block 压缩过的 Key/Value 算出一个 output。这个分支在训练的时候是有梯度传回去的，模型就能通过端到端的训练知道哪些 block 比较重要。这个机制还是蛮巧妙的。

如果没有这个压缩分支的话，其实中间有一个不可导的过程。我们再回到那张图会更好看：如果我们没有 compressed attention 这一步，那就没有训练信号传回来；而这里做 Top-k selection 又是一个不可导的过程。所以如果这里有梯度传回去，整个 block selection 的过程就会更加 informative。

他们的消融是跟另外一些机制比的。比方说又是我们的老朋友 Quest——Quest 用的是一种启发式的（heuristic）importance score 计算，论文里写的是 "following the strategy of Quest"，具体是什么机制欢迎大家去看 Quest 原文。可以看到这个机制 loss 不是很好，可能是因为它选 block 的机制太 heuristic 了，所以选到的 block 不是很好——这也说明 block selection 还是蛮关键的，同时证明了 compressed attention 那个 output 的重要性。

另外它还试了一个「辅助 loss 做 selection」的方案，这个地方也不行。所以这篇工作把市面上常见的替代方案全部拉来做了一遍，来证明他们的方案是最优的，这样大家就能更加信服——比方说为什么会有第一个分支，也更加 make sense 了。所以他们会强调，他们是一个可反向传播的 selection 机制，就是因为有那个压缩分支在里面，可以把梯度反传回去。

好的，NSA 这一篇我觉得值得讲的部分就带大家过了一遍。

Part 2 · Kimi：MoBA（Mixture of Block Attention）

1. 中门对狙

我们来看第二篇工作，这篇是由 Kimi 做的。Kimi 最近也非常往开源的方向走：MoBA 已经开源了，今天早些时候他们还开源了一个基于 Muon 的新型优化器方案，code base 和微调都开源了，非常值得称赞。

2. 把三个分支砍到只剩一个

杨松琳

MoBA 这个工作，前面提到过，跟 DeepSeek 那篇非常像——它们都是在 Quest 的 framework 下面（Quest 就是 query-aware 的 sparse attention），做的不仅仅是 inference 加速，而且还有预训练。

MoBA 非常简单。其实我们之前把 Quest 和 NSA 讲完了，MoBA 就能在非常短的时间里讲完。

首先在 Quest 这个框架下，每一个 Key 的 block 需要算出一个表示，然后 query 跟这个 block 的 K 表示算出 attention score。而在这里，这个表示直接用了一个 Mean Pooling（把一个 Key Block 的多个 Key 平均成一个低成本代表）。这一点跟 DeepSeek 很不一样——DeepSeek 用了一个 MLP 来做 projection，而这里干脆用 mean pooling，完全没有引入任何多余的参数。

另外，DeepSeek 有三个分支，而 Kimi 把 compressed attention 分支砍了，也把 sliding window 分支砍了，只保留中间那个 selection 分支。这样整体模型的简约性比 DeepSeek 那个要简单很多，所以从这方面来说，很多人会觉得 MoBA 比 DeepSeek 的方案更加优雅。

他们的团队说他们相信 SGD（Stochastic Gradient Descent，随机梯度下降）的力量——不需要这些额外的 loss，也可以通过 SGD 选到很好的 Top-k block。但我觉得这可能跟 DeepSeek 那个 ablation study 是有出入的，所以具体哪一种好，我觉得还有待进一步的研究。

这两篇工作都是很好的，都打开了一个新世界的大门：原来这种动态稀疏也是可以做预训练的。我觉得之后可能会有很多研究更多地 focus 在动态稀疏的预训练上面，而不仅仅在于 inference。

整体架构基本上没什么可讲的，因为它非常非常简单。它跟 Quest 一样，每一个 head 可以有自己的自由度去选择想要 attend 到的 KV block。

3. 简约的代价（一）：kernel 里的 indexing 开销

杨松琳

这样一来，他们的痛点就变到了 implementation 上。

之前 NSA 可以利用它「共享」的那一点，做到每一步读取都不浪费一点东西。但在 MoBA 里，既然每个 query 会选不同的 block，那要么你会浪费东西，要么就得反过来做：对于每一个 KV block，找到所有选中它的 query token。而这些 query token 可能是不连续的——如果你还是一块一块地读，就会读到多余的东西。所以他们干脆事先把这些不连续的 query token 提出来，用一个连续的张量存起来，之后直接去调 FlashAttention 的 kernel 来算。

所以看他们的 code base，主要做的就是各种眼花缭乱的 indexing 和 reindexing 操作。

但这个地方是有 overhead 的，这个东西不是 for free 的。当 KV block 的数量足够多的时候，这一步可能会成为一个 bottleneck。

这也是为什么 Kimi 用了一个 512 的 block size。我们可以返回来看 DeepSeek 用的参数：DeepSeek 每一个 block size 是 64，Top-k 选 Top-16；而 Kimi 是 512 的 block size，选 Top-3。它们整体的 token 数加起来可能是差不多的。

但因为 MoBA 这一边不能像 NSA 一样写出那样一个 kernel，所以它必须对每一个 KV block 把选中它的那些 query 全部提出来。这个操作如果 block size 比较小，就会引入非常多的 overhead——比方说在这个 case 里把它设成 64 的话，那可能就是一个无法接受的局面。

所以大家虽然看到了 MoBA 表面上的简约，但也应该注意到一些隐藏的问题：第一个就是这个 KV block size 没有办法开得特别小。

这其实也是一种局限性。因为你能选的 token 就这么多，block size 如果太大，粒度就太粗了；你只选 Top-3，稍微一不小心就可能把一些重要的东西漏掉。而 DeepSeek 那边粒度非常小——64 的 block size、选 16 个 block——它在选 block 上更加细粒度，容错率也更大：选 3 个容易错，选 16 个错的概率就会小一点。

这是我觉得 Kimi 简约背后付出的代价之一：block size 开不了太小，没法太细粒度地选 KV block。

4. 简约的代价（二）：加速比与训练曲线

杨松琳

其次我们可以关注它的加速比，这个也值得对比一下。

我们可以看到，MoBA 在 128K 的时候其实都没有什么优势。但对于 DeepSeek 这个模型来说，在很短的长度上——比方说 8K、16K——加速比就已经肉眼可见了。这也是 NSA 更加硬件亲和的一个结果。

5. 简约的代价（三）：SFT 时的梯度稀疏

杨松琳

Kimi 因为相信 SGD 的力量，把 DeepSeek 那个 compressed output 分支砍掉了，但这同样带来了一个问题：SFT 的时候会遇到训练信号稀疏。他们自己也 highlight 了这一点，说 MoBA 在 SFT 的时候会有一些 suboptimal performance。

这是为什么呢？因为 SFT 的时候有一个很长的 prompt，那个 prefix 是不进入 loss 计算的，只考虑后面那部分 token 的 loss。而这又是一个 sparse attention——如果后面那少部分 token 的 loss 没有覆盖到某些 block，那对于那些 block 来说就没有任何梯度信息。这就造成了训练信号的稀疏性，梯度不是很好反传。

为了解决这个问题，他们搞了一个 hybrid 的 approach：把最后三层 switch 到 Full Attention。这样最上面的三层用 full attention，就有非常稠密的梯度信息——对每一个 token 都有梯度，保证了训练信号不稀疏，SFT 的 performance 也会增加很多。

他们在知乎的 blog 上也很有意思，把他们的思考过程都写出来了：这个 idea 具体的心路历程，我记得他们好像写了很多个 episode，讲不同阶段遇到的各种难题、怎么解决。这可能是之后训练「会做研究的 AI」非常优质的数据——如果有人想训一个做 research 的 AI 模型，一定要把他们那个博客拿来做训练数据。

而 NSA 应该是没有这个问题的。因为它有一个 compressed attention 分支，是直接参与 output 计算的，output 就会把梯度反传给前面所有的 token。这样 NSA 就不存在梯度稀疏的问题——这是 Kimi 特有的问题。我觉得是因为它砍掉了 compressed attention：他们相信 SGD 能找到正确的 block，但 SGD 在 SFT 的时候信号不是很足，所以就没办法找到正确的 block 了。

但好在，他们这个设计非常简约，没有引入其他东西，是一个极简设计。这一点也非常优雅，而且恰恰给他们解决这个问题带来了可能性：他们可以把最后三层直接换成 global attention，这是没有任何问题的——因为之前他们用的是 mean pooling，是一个不需要参数的方法，所以整个过程极简、没有引入任何参数。也就是说，Full Attention 和 sparse attention 的参数是完全一样的，只是计算路径不一样，那我完全可以在两者之间自由切换。

他们在 SFT 里就用到了这个自由切换的特性。我记得他们在预训练的时候好像也用到了这个性质：90% 的 token 用 sparse attention 训，后面切换到 Full Attention 来训剩下 10%——等一下，这只是一个 ablation study，sorry，看走眼了。我看看他们的 ablation study……对，他们确实发现这种 hybrid 的训法能提高 performance，绿线就是 MoBA 与 Full Attention 混合的那条。这说明这种自由切换不但能在 SFT 上带来好处，可能在预训练的时候也会带来好处。

这就是他们极简设计的有利有弊。

2. 线性注意力：把 Softmax 去掉

杨松琳

什么是线性注意力呢？

之前我们都管 attention 叫 Softmax Attention，因为这个地方有一个 Softmax 算子。而线性注意力，就是把 Softmax 这个操作去掉，非常非常简单。

我们看递归（iterative）形式。这里的 attention score 是一个标量，我们把标量移到后面，再把这两项的顺序调一下——因为调一下结果是相同的。最后我们发现这些都是线性操作，于是用结合律把它结合成这个样子。

然后我们发现这个地方其实是外积（outer product）的累加，它是一个恒定大小的矩阵，是一个 d×d 的矩阵。

如果我们把这个矩阵看成一个 RNN 的 hidden state，那么线性注意力整体的过程就是一个 linear recurrent 的过程。而这个 linear recurrent 其实就是一个累加：每次把当前时刻 KV 的外积加到这个记忆里面来。

在线性注意力里我们经常会提到一个词，叫 matrix-valued hidden state（矩阵形式的隐状态）——因为这个 hidden state 的大小是一个二维矩阵，所以我们管它叫矩阵形式的隐状态。这是用来区别于那些传统的 RNN：比方说 LSTM，它的 hidden state 就是一个一维向量，容量大概就是 d 这个量级。而线性注意力实际上实现了一个增维的过程——从 d 维变成了 d×d 维。可以看出这个 hidden state 是非常非常大的，跟传统 RNN 相比大很多。

它变大之后有一个好处。线性注意力——更准确地说是所有 RNN——都是只依赖这一个 hidden state 来对所有历史信息做 encoding 的。也就是说，hidden state 的大小直接跟这个 RNN 模型的记忆容量相关。那也就难怪线性注意力会比传统 RNN 表现要好，因为它有一个 state expansion 的过程。

State expansion 也是 Mamba 这个大家耳熟能详的工作反复强调的东西。而我在这里想强调的是：线性注意力有着最硬件高效的 state expansion 操作，因为这里是一个外积，外积是最硬件高效的。

我们前面在第一个 part 讲到了硬件高效的 Native Sparse Attention，在线性注意力里我们又一次讲到硬件高效——这足以证明，在这个年代设计算法，最好还是能怎么硬件高效怎么来。像 Mamba-2 为了解决 Mamba-1 硬件不高效的问题，就对它做了一些改写，后面可以看到，改写之后就变得非常像线性注意力了。

3. 线性注意力难在哪：怎么凑出矩阵乘法

杨松琳

这里讲一下线性注意力训练的困难在哪里。

如果我们用类似 self-attention 的并行形式来训，可以看到它跟整体长度还是平方关系的，那么在很长的序列下，这个架构在训练上是没有什么好处的。

而如果我们用循环形式来做：第一，循环着算就没有并行度，会很慢，就像传统的 LSTM 一样；第二，这个操作里面没有任何矩阵乘法——这里是一个外积，这个地方是一个矩阵—向量乘法来做 memory readout。

前面在 NSA 那里我们也讲到了，它用很暴力的方式来凑矩阵乘法。这些原则都是相通的：在线性注意力里我们也想凑矩阵乘法。但在循环形式里凑不出来，怎么办呢？那我们就想办法把一个 chunk 打包起来，把 chunk size 这个维度凑成矩阵乘法的一个维度。

这些操作大家可能听起来有点耳熟了——之前 Native Sparse Attention 就是强行把 head 那个维度拉进来凑了一个矩阵乘法。如果大家在设计算法的时候关心硬件，就会发现很多时候大家都在想：怎么去凑这个矩阵乘法？

比方说有一篇工作叫 FlashFFTConv。FFT（快速傅里叶变换）是一个非常经典的算法，但它在当前硬件上不是非常快，因为它没有矩阵乘法这种 operation——这一点跟线性注意力的循环形式很像。在这篇文章里，为了在硬件上加速，它对算法做了改写，把 FFT 写成一个等价的矩阵乘法表达形式，从而能够利用 Tensor Core 来加速。可以看到这种加速在硬件上是非常大的。

短期来看，我们还是要尽可能把算法写成矩阵乘法，这样效果立竿见影，可以直接在当前的硬件下优化——你不需要等到未来某些架构、比方说什么量子计算机之类的硬件，那个我不知道要等到什么时候。那为什么不直接去榨一下当前的硬件呢？而且前面也提到，很多 principle 对不同硬件都是相通的，比方说写成矩阵乘法、比方说做一些分块（block）的操作。

4. 分块（chunkwise）算法：既精确又并行

杨松琳

回到 Lightning Attention。它也提到了一个分块（chunkwise）算法，用来做高效训练。

分块算法是说：我不像循环形式那样一个 token 一个 token 地算 output，而是先把序列分成若干个 chunk，对每一个 chunk 只算一个 last hidden state。算 output 的时候，我们把两种算法结合起来：算历史 context 的贡献时用循环模式，算本地 chunk 内部的贡献时用并行模式。

需要强调一点：分块形式当 chunk size 设成其他值时，可以还原出循环形式和 self-attention 的并行形式。所以分块形式是一种数学上等价的变换，它不是一种 approximation。

这里简单讲一下分块——我在其他平台应该也介绍过，这里再回顾一下。

图里有两个灰色的 hidden state，代表这个地方直接被跳过了：我们不算中间的，直接跳到最后一个 hidden state。

我们把这个窗口里的三个 token 打包，一次性算出中间的 hidden state update——因为前面说到外积的相加可以写成矩阵乘法的形式，所以这里可以写成一个矩阵乘法。

然后在 output computation 之前，我们要用 query 去 attend 这个 hidden state 来算出 output。对于整个 chunk 来说，我们发现它所有的 query 都要去 attend 同一个 memory。这就又有点像 batchify 操作了——因为这就有点像一个 weight matrix，而这三个 token 就像一个 batch 里的三个 sample。也正因为此，chunk 这个维度就有点像 batch 维度，在这里我们就可以凑一个矩阵乘法出来，算出历史 context 对整体的贡献。

我们再回顾一下：这个 hidden state 其实已经 encode 了它这个位置之前所有的历史信息，所以我们可以用循环形式直接把整体历史都考虑进去。这也是为什么分块形式是精确的——就是因为有这个东西把整体信息都考虑进去了。其次，我们有一个 local chunk 的部分，类似于一个 local chunk attention，把 output 直接算出来，这里面也是一些矩阵乘法操作。

它整体的复杂度是这样：d 是 hidden dimension，L 是 sequence length，C 是 chunk size。一般 chunk size 我们设到一个比较居中的量，这样它不随 L 增大而增大。所以结果是：整体训练复杂度是次平方（subquadratic）的，不是平方关系。

这也就意味着，我们有可能把线性注意力用在非常非常长的预训练上面。比方说一个很好的应用场景是 video generation——它可以被 formulate 成一个序列建模问题，而几分钟的 video，序列长度非常大，可以很轻松地来到百万级别。所以用这种次平方的模型来做 video modeling，可能会有一些先天优势。

5. 线性注意力的现代进展

杨松琳

这个分块算法其实是非常 general 的，它可以用在 linear attention with decay、甚至 linear attention with delta rule 上。delta rule 也是一个很有意思的东西，它跟最近非常火的 test-time training、以及谷歌新出的 Titans 都有很多关联。

最近这些现代的线性注意力模型，比方说 Mamba-2、GLA、Gated DeltaNet 之类的；Lightning Attention 就是 MiniMax 用到的那个；还包括 mLSTM——那是 LSTM 作者团队的工作，叫 xLSTM，作者就是 LSTM 的一作。他打造出了一个现代的、可以并行的版本，而 mLSTM 可以看成一个线性注意力。

另外我们还要做一些 IO 上的优化，就有点像 FlashAttention。我们有一个开源库叫 flash-linear-attention，里面写了很多硬件高效的 linear attention 实现，支持非常非常多的模型。

简单做一个广告：大家如果想训这些现代的线性注意力模型，欢迎来用我们的库。我们提供「客服服务」——遇到问题尽管问，包解决一切问题，可以在 GitHub issue 上提，我们一般都回得比较快。

之前 linear attention 其实有个问题：它的 language modeling performance 太差了，导致大家有一个印象——linear attention 不 work。但实际上，从前两年开始到现在，进展是非常非常快的。大家对 linear attention 的印象可能还停留在四五年前，那个时候线性注意力的 performance 确实差，但现在已经上来了。大家可能要 update 一下自己的 prior knowledge 了。

它主要的改进呢，很简单，就是加 decay（衰减）。像 RetNet 就是一个比较经典的 work，出自 MSRA，在当时也挺火的。而 Lightning Attention——就是 MiniMax-01 用到的那个——它这个遗忘率在每个位置都是相同的。这样会有一个问题：它没有各个位置的选择性。

像 Mamba 里面就强调了 selectivity，LSTM 里其实也强调了 selectivity。在我看来，Mamba 的 selectivity 其实就是 LSTM 那个 gating mechanism 的新瓶装旧酒——本质 idea 是一样的，只不过在新时代又重新被挖出来发光发热了。

像 Mamba 其实就可以写成这样一个形式：跟之前的 Lightning Attention 相比，它把伽马变成了一个 data-dependent 的 decay，每个位置可以自己算自己的 decay。

前面提到线性注意力有三种形式，同样也可以 apply 到 linear attention with decay 上。举个简单的例子：这里我们有一个 γ_t，之前这个地方是一个 causal mask，但在这里我们需要 encode 两个位置之间 decay term 的累乘。

这两者的等价性，在 Mamba-2 那篇 paper 里被叫做 state space duality（SSD）——他们是从矩阵分解的角度 motivate 的，有一种叫 semiseparable 的矩阵，他们是从那个矩阵的角度出发。但其实这两个是等价的。大家看 Mamba-2 可能会觉得数学太多、比较难理解，但从线性注意力的角度出发，这些东西我觉得是更好理解的。

他们也有一个 chunkwise form，其实跟 Mamba-2 的 block decomposition 分块训练方法也是等价的。所以从这些角度看，Mamba-2 完全可以说是一个 linear attention 模型，只不过它有一个 data-dependent 的 decay。

6. 混合架构为什么有效：翻书 vs 大脑

杨松琳

回到 MiniMax 这一篇，它也有一个 chunkwise form，有一个 chunk 级 IO 高效的训法。

后面他们有一个 scaling law，发现这种 hybrid 架构的 scaling behavior 要比纯 Softmax attention 更好。我觉得这也挺容易想到的：很多时候大家都能看到 attention 和 RNN 结合能够利用它们各自的好处，softmax attention 和 RNN 的好处是比较 complementary（互补）的。

RNN 有一个 fixed hidden state，这就强迫模型去学出一些可以压缩的 pattern——因为它只有有限的 hidden state，所以必须学会压缩。而学习压缩的过程，可能就跟「压缩即智能」这个 concept 有一些联系。

反观 softmax attention，它其实没有压缩的概念，因为它会把所有 KV cache 都保存下来。但保存下来之后，它能起到一个非常好的检索作用。RNN 经常被诟病的一点就是不能很好地做检索类任务（retrieval），这也很容易理解：RNN 只有一个固定大小的 state，那它总不可能记住所有历史信息吧，要不然物理学就不成立了。而 attention 非常有利于做检索类任务，因为它自己就有包含所有历史信息的 KV cache。

经常会有一些比较形象的比喻：attention 有点像翻书，RNN 有点像人的大脑——因为人的大脑那个脑容量也是固定的。人在需要的时候会去翻书，但一般时候靠着固定大小的脑容量其实已经够用了。

下面是一些 performance 对比。可以看到，纯线性注意力在那些检索能力要求比较强的任务上——比方说这个 Needle in a Haystack，非常考验模型的检索能力——这种任务就是线性注意力的短板。但如果把 attention 和 RNN 结合起来，反而可能会更好。

值得一提的是，在这些 hybrid 架构里，RNN 还可以起到位置编码的作用。所以很多 hybrid 架构都不使用 positional encoding——干脆用一个 RNN，因为 RNN 自带位置信息，而且是可学的位置信息。这样就不存在 RoPE 会遇到的外推问题了。所以在外推长度之外做检索问题时，这种 hybrid 架构可能会有些优势。

看 speed：softmax attention 在 8K 之后会越来越慢；hybrid 虽然也会变慢（因为它还是有一些 attention 层），但因为 attention 层比较少——像 MiniMax-01 是每 7 层 linear attention 才有 1 层 softmax attention——linear attention 做了很多工作，softmax attention 只占很少，跟原来相比计算量会减少很多。

这篇工作在各种各样的 benchmark 上证明了 hybrid 架构的有效性。我觉得它非常惊艳的一点是：第一次把这种 hybrid 架构 scale up 到这个尺寸，并且让它有 GPT-4o 这个 level 的 performance，所以大家还是挺惊艳的。

7. 能 scale up，靠的是工程

杨松琳

它能 scale up 到这么大，当然也离不开硬件上的优化。比方说之前提到的分块算法——如果时间搁在三四年前、没有这个算法的时候，大家想 scale up 线性注意力也不行。之前大家对 linear attention 的印象就是：它只是理论上看起来快，但实际上跑起来很慢。我想纠正一下大家的印象——linear attention 这两年确实发展得很快，无论是 performance 还是 efficiency。

我们可以看到 MiniMax 这篇文章做了非常非常多的工程优化，他们应该有一个很扎实的 Infra 团队。这里有一些并行策略，比方说 MoE 里非常常见的专家并行，还有流水线并行。至于线性注意力的部分，他们做了一些分布式的、chunkwise 的线性注意力扩展，比方说 Linear Attention Sequence Parallelism——那是 Lightning Attention 那个团队做出来的工程优化。可以看出这些工程优化的细节还是挺多的，也可以看出他们的工程优化非常扎实。这也是为什么他们能把这种 hybrid attention model scale up 到这么大，这跟工程优化是密切相关的。

这也说明：如果一个算法硬件不高效，它其实是很难 scale up 到这么大尺寸的；而如果 scale 不到这么大的尺寸，是很难引起别人关心的。因为现在大家都是 The Bitter Lesson 的信徒——如果一个东西它不 scalable，那大家对它的兴趣可能就会大减。而线性注意力，我们最近做了很多工作，就是要说明它是能够硬件高效地训的。

另外我觉得，这种 hybrid 架构并不是空穴来风，不是 MiniMax 单独发现它能 work，还是需要提到一些其他工作的。比方说英伟达去年发的一个工作，我们可以看到 Tri Dao 和 Mamba 的作者 Albert Gu 也在 author list 上面。他们做到了一些结果，但没有做到像 MiniMax 这么大，所以掀起来的水花没有 MiniMax 这么大。

这也说明：这个年代想让一个工作吸引到足够多的注意力，还是要 scale up 到一个非常大的 scale，用最后的结果来说话。而在他们那种 scale 下面——在学术界看来已经是非常大的 scale 了，但在业界看来就是一个小模型——这篇也说明 hybrid 架构是不输其他架构的。

尤其是，我记得他们还有一些 ablation study，来看 attention 层到底需要占多少比例，大概得出 10%～20% 这个比例范围是比较正常的。这也跟 MiniMax-01 不谋而合，因为 MiniMax 的 attention 配比大概也在这个区间。

社区还有别的工作，比方说英伟达还有一个叫 Hymba 的工作，里面有各种各样的 hybrid 思路。各种各样的 hybrid 模型里，window attention 也是经常能见到的。这个应该是在一个 3B 的模型上做的。

所以之前的这种混合架构，我觉得大家其实都知道它是有效的，只不过缺少一个团队把它 scale 到一个非常大的 scale，比方说像 MiniMax 这样。有些技术要出圈，还是需要把它 scale 到非常大、能 work，才能引起足够多的关注。

所以我们做线性注意力的还要感谢 MiniMax——因为它说明了这种 hybrid 架构的有效性，所以我们做线性注意力的关注度，感觉最近会比之前高一点。

8. 问答：谁承担的风险最大

张小珺

为什么 MiniMax 没有选择像 Kimi、DeepSeek 那样的稀疏注意力机制？

杨松琳

我觉得可能是 sparse attention 更容易一点吧，因为它的技术路线其实没有那么高风险。

比方说 sparse attention 还是把所有 KV cache 都保留了；而 attention 学出来的分布是 sparse 的，这大家都知道。所以大家可以很直觉地想到：如果我预训练一个 sparse attention，同时又保证一些特性、比方说不丢 KV cache，那这个模型的下限是有保证的。所以这个风险我感觉是比较小的。

而在长文本上面，线性注意力确实还是有非常非常多的质疑的——对任何这种 RNN 类的模型，大家都感觉它在长文本上是不放心的，所以不太敢去做这方面的研究。而 hybrid 架构，其实就是对这种质疑的一种 compromise、一种妥协。

有一些线性注意力的研究者，比方说 RWKV 他们就不往这方面妥协，他们很有自信，相信这条路只需要 RNN 就够了。但其他一些更实际一点的、更 care 长文本能力的，还是会做一些妥协，比方说加一些 attention 层进来。

张小珺

我们说 DeepSeek 在改架构上动刀子非常激进。这么说的话，MiniMax 是不是更激进？

杨松琳

我觉得 MiniMax 有它激进的部分，比方说选用这个方案。但这个方案从某种程度上，熟悉这个领域的人都觉得是非常 safe 的，因为它在（主要是美国的）工业界已经大概验证了一年。

比方说去年年初有一个工作叫 Jamba，它其实也是一个 hybrid 架构，去年年初就已经放出来了。后面还有英伟达的那两个模型。还有比方说 Bamba，好像是 IBM 做的，是一个 9B 的模型。这些东西我感觉已经被反复验证是能 work 的。还有比方说 Samba，它也是一个 hybrid 架构——Mamba 加上一个 sliding window attention，这个是微软做的。

还有很多很多的混合架构。所以我觉得，如果大家相信这些 7B 规模的结果能够 transfer 到更大的 scale，那从这个观点上来说，MiniMax 其实也没有 take 很多 risk。

张小珺

所以他们三个谁 take 的 risk 最大？

杨松琳

我觉得可能还是 MiniMax 吧。

因为客观来讲，sparse attention、尤其是 dynamic sparse attention，它只省计算，不省显存。大家看到「OK，你这个方法把 KV cache 全部保存下来了」，心里就有个底了：这东西首先大海捞针肯定能做——大家都发现那个全绿了——各种长文本看起来也没什么问题，那就可以大胆地上了。

张小珺

那 MiniMax 的优化目标和前两个是一样的吗？

杨松琳

我觉得都是一样的。这些高效注意力主要就是两个分支：一种是 sparse attention，一种是 linear attention。它们的目标都是一样的——一方面是长文本的训练，另一方面是推理时的复杂度。

张小珺

理解。如果目标一致，从结果来看谁的结果最好呢？

杨松琳

大模型比较难比，除非它们是在同一个环境下训出来的。要不然 data 不一样、七七八八都不一样，大家也不知道是架构带来的原因还是模型本身的问题。所以这是一个很难说的问题，还是需要业界投入更多资源来更广泛地验证一下。

张小珺

现在数据遇到了瓶颈，所以他们其实不约而同都在改架构，都在试图通过架构的优化带来更好的结果。

杨松琳

对。去年那个大家都知道的演讲就说，training time 的 scaling 可能到头了〔按：指 Ilya Sutskever 在 NeurIPS 2024 的演讲〕，然后我们会发现最近 test-time scaling 这个概念很火。

用这些高效注意力的架构，一方面确实更 efficient，可以提高 test-time scaling 的空间；如果它的 performance 能够跟之前的 attention 持平，那么多出来的推理效率就能直接转换成 test-time scaling 的好处。另一方面，在 training 的 Scaling Law 上，靠堆 data 这条路可能走不通了，那确实需要一些更底层的架构创新。

像 DeepSeek 就是比较少见的、非常坚持自己做架构创新的公司，这一点非常可贵。因为很多公司我感觉都是排斥做架构创新的——他们可能觉得堆数据就行了，我们为什么要冒险做架构创新这件事？但我觉得做架构创新是风险与机遇并存的。比方说 MLA 的成功，还有肉眼可以预见到的 NSA 的成功——他们在 paper 里也看到了，它甚至可能比 Full Attention 更好。

所以我觉得，大家在 data scaling 走完之后，可能会花更多精力来研究架构了——因为你堆不了 data 了，那可能就想通过提升架构来提高整体的 performance。

杨松琳
