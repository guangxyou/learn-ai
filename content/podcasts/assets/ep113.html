一座无限的山

杨植麟

哈喽，大家好。

张小珺

在你创业第一年结束的时候，2024 年，我们访谈报道的标题是「向延绵而未知的雪山前进」。现在又过了一年，站在 2025 年 7 月此刻，你最新的感受是什么样的？

杨植麟

你刚刚提到这个词，感觉都好像过了很久，已经一年多了。AI 一天，人间一年，所以 AI 的一年不知道在人间是多少天。确实很多东西发生了很多变化，但你刚说的那种雪山的感觉倒是差不太多——往山顶的过程我们又走了一段距离。

张小珺

多远？现在行进到哪里了？

杨植麟

你现在想，模型的进步确实挺大的：两年前写一篇文章都写不太明白，现在它不光可以写很好的文章，还能够连续工作几个小时，帮你完成一个很复杂的代码任务。这个在两年前是很难想象的。所以可能就在一个爬雪山的过程中，你解锁了一些新的场景，大概知道中间这条路是什么样的；但同时在往上的过程中，你观察到的还是差不多的景象——接下来的路仍然会有很多未知的技术问题需要解决。

张小珺

更清晰了还是更迷茫了？在这个四下都是雪的地方。

杨植麟

肯定会有很多东西变得更清楚。比如两年之前，各种强化学习的范式怎么去做、怎么让模型有更强的推理能力或者更强的 agent 能力，在当时可能没有那么清楚——当时更多的是说预训练怎么能做得更好，可能还有 RLHF 这样的技术能让对话体验做得更好。但现在有一些新的问题得到了答案，同时这些答案又展开、产生了一些新的别的问题。

比如今天你看到虽然可以做这些强化学习，但强化学习最终还是依赖于一个很好的评估或者很好的验证。你让它做一道数学题，或者有 test case 的编程，可能做得比较好；但如果让它做一个更复杂的端到端的任务，有时候你并不容易找到评估或衡量的方式。

所以这个系统会产生一些新的问题。有点像我最近在看的一本书，叫 The Beginning of Infinity，我看了好几遍。它里面讲的最重要的一个事情是：有两句话要刻在石头上，一句叫「问题是不可避免的」，第二句是「问题是可以解决的」。你可以认为在启蒙运动之前，社会是静态的，大家并不追求创新，你会用很多神奇的方式去解释观察到的现象——天上打雷你会觉得有雷公，冬天下雪你觉得是某个神心情不好。这些都不是好的解释，所以整个社会是个静态的结构，只有非常少数的人在做真正的科学研究、知识的创造。

但启蒙运动之后，社会变成动态的：有很多新的知识被创造出来，而创造的过程中，你产生了一个知识、解决了一个问题，又会产生新的问题——你的知识边界在拓展，就会遇到很多新的问题。研发 AI 恰好就是这样一个过程：你解决了强化学习的很多问题，又面临评估、衡量、验证这些新问题，它们需要新的答案。这也是非常有意思的一点：你一直会有新的问题可以解决，每解决一个问题，技术就会再往上攀登几百米。

也许这个雪山有可能没有尽头，我不知道，但我希望它一直没有尽头，因为这就是所谓的 Beginning of Infinity——它可能是一座无限的山。你一直在往上爬，甚至爬到一段时间之后，不一定是自己在爬，而可能是用 AI 来爬。比如我们现在也会用 K2 这个模型去做很多模型训练、数据处理相关的工作——这些以前都要人工写代码，有些同学不一定会写代码就做不了，但现在很多数据处理、模型分析，甚至包括模型的一些训练，慢慢都可以用模型来做。你可以把它作为一个放大器，去更好地攀登这座山。问题是会持续产生的，你就持续去解决，然后发现新的问题。

张小珺

如果雪山是无尽的，你追求的是什么呢？

杨植麟

追求就是这个攀登的过程，你能一直越爬越高。原来在山底下，往上提升一点，看到的景色会不一样。它是一个动态进化的过程，我们想追求的就是越爬越高。

张小珺

以前我们会固化地认为终点就是 AGI，今天的终点已经不是 AGI 了？那 AGI 是什么？

杨植麟

AGI 可能是个方向，它不是某一级台阶——你爬到了这级台阶就突然一夜之间达到 AGI。它是一个方向。今天在很多领域你可能已经可以认为它是 AGI 了，比如翻译，它可能比 99% 的人类做得更好；包括很多数学题、编程竞赛题，按照现在的提升速度，可以预想很快有很多问题就可以被充分解决。

但很难说某一个时间点突然就可以喊一个口号说「此时此刻我们实现了 AGI」。虽然我们用了登月来命名公司，但它跟登月有一个区别：登月是你站上月球那一刻就达到了。这里面我觉得有两个层面：一方面是技术一直在提升；另一方面，技术对人类社会的影响可能是更长周期的事情——你也可以认为它是 AGI 的一部分。像你产生了蒸汽机之后，整个社会的变化需要花几十、几百年的时间去消化：有一些工作可能不再必要，但你会产生新的工作、新的方式，每个人可能成为超人，可以做更多的事情，社会的工作方式和运行效率都会发生很大的变化。

过去一年的范式变化：两种 test-time scaling

张小珺

回望过去一年，全球大模型在你脑海中最重要的几件事情是什么？有哪些范式级的变化？

杨植麟

我觉得有几个重要的。一个是长思考的推理模型，基于长思考的强化学习，o1 是第一个做出来的代表。本质上它是通过让模型在这个过程中做很多的尝试和反思——反思可能是这里面的重点。反思本质上是两种能力：一是提出一个新的猜想，模型在解决问题的过程中会不断提出新的猜想；二是这个猜想的自我验证——猜想提出来之后，它对还是错？它需要具备一定的验证能力，虽然不是显式地训练一个验证模型，但在推理过程中隐式地做了验证。你可以理解成它把这个问题做了很多次，每次猜想-验证、猜想-验证，最后得到一个答案。

这个东西会很大程度提升模型的能力，因为你本来只能做一次——直接给出一个答案，可能对可能错。但现在可以不断提出猜想去验证，等于你等价地尝试了好几次，可以把 pass@k 变成 pass@1。这跟人类做科研或解题的过程也很像：不断提出新的猜想，然后去验证。

张小珺

它是一个自由探索的过程，不是线性的？

杨植麟

它有效的工作方式实际上很多时候还是比较线性的。如果不考虑并行采样，只做串行采样，它是有线性体现的：每次提出新的猜想，这个猜想基于你之前已经否定过的猜想，再提出新的猜想，它会接近线性的过程。只是现在也可以把这个线性的过程搭配一些并行的策略，比如同时采样很多个，结合并行和串行两种方式。最近也有一些 paper 讲串行的上限会更高，这跟我们的一些实验结论相关。

这是一种范式，但它还是一个「缸中之脑」——想象一个鱼缸，你把一个脑子放在里面，它跟外界没有联系，只是在自己大脑里面想，不需要跟外界产生任何交互，就能解一道题。但有另外一个很重要的范式：基于多轮 agent 的强化学习，训练出 agentic 的模型。它的特点是会跟外界做很多交互：边思考边做一些操作，做很多轮——一会调用搜索，一会使用浏览器，一会写几行代码，通过多轮的方式解决一个问题。它就不再是缸中之脑，它跟外界有交互，下一步行为跟通过交互得到的外界反馈、新的状态更新是有关系的。

这两个东西都指向同一个东西：test-time scaling——在测试或者推理的时候做更好的规模化。之前做 chat、做对话的时候，更多是单轮输出一个结果：让你写篇文章就写篇文章，让你润色一下你又输出几百个 token，token 数量很少。但不管是基于长思考的强化学习，还是 agent 的强化学习，本质上都是一种规模化预测时 token 的方式：不管是把轮数打得更多，还是在每一轮里有更多的思考 token，它都是规模化 token 的方式，使你能完成更复杂的任务。这也伴随着完成时间会更长——现在可能会花几个小时去做一件很复杂的事情，过程中不需要人工参与：比如把一个代码仓库克隆下来，翻译成另外一种新的语言，调试、测试，把所有的 bug 都修了，让它能正常运行。这样的工作可以端到端直接完成，就得益于测试时的规模化——这两个都是 test-time scaling 的表现方式。

模型公司做「一方产品」：正向设计取代逆向工程

杨植麟

还有一个很有意思的趋势：现在会有更多模型公司去做一方产品——一方的 agent 产品。一开始，如果看半年前或者去年，很多产品是基于基础模型，在上面做一些脚手架，或者设计一些工具让模型更好地使用，来搭建一个产品。

张小珺

享受模型溢出的能力。

杨植麟

对。它本质上在做的一件事情是逆向工程这个模型的训练过程——因为模型训练过程也是通过各种 in-house 的环境和工具训练出来的，比如 Anthropic 的脚手架训练出来的模型，它没有直接开放给你，你就想逆向出来，更接近地去拟合它的分布：到底用什么工具效果好、什么样的 system prompt 效果好、什么样的 context engineering 效果好。这是一个逆向的过程。

但如果模型公司去做一方产品，逻辑完全不一样：你不再需要逆向的过程，它更多的是一个正向的做法——我先把这些工具设计好、context engineering 的方法设计好，然后就在这个环境里面去训练模型，你的模型天然在你的环境里就会表现得更好。这是两种不同的思路，第二种的上限也许会更高：你可以更好地整合工具和模型，模型有解决不好的地方，你可以调整工具的设计，同时又可以端到端地训练。这可能是开发方式上一个比较大的变量。

张小珺

让大家好理解：你刚才说的第一种脚手架方式就像 Manus，第二种就是你们这样的模型公司？

杨植麟

对。当然我们现在在一方产品上的投入还不算特别多，主要还是以模型为主线。但你可以看到像 Claude Code、ChatGPT Agent 这样的东西其实就是一方的产品，我觉得会是一个很大的趋势。后面就是看这两种东西怎么配合，在生态里面的边界分别在哪里。

L1 到 L5：不一定是串行关系

张小珺

说到主线，OpenAI 设置了 L1 到 L5：L1 是 Chatbot，第二是 Reasoner，第三是 Agent，然后是 Innovator 和 Organizer。我一直很好奇这里面的逻辑：为什么有了 Chatbot 和 Reasoner 之后才有 Agent，后面又是创新者和组织者？在模型能力上它的变化是什么？

杨植麟

它是能力一步一步的依赖。但实际看起来，Agent 的上限确实取决于你有很强的 reasoning 能力，但好像并不是说必须先有 reasoning——如果把技术发展顺序换一下，假设你先做出 agent 能力，再去做现在狭义上的 reasoning（long CoT 的 reasoning），可能也是成立的。你可以认为 Claude 的路线就是 bet 在这一点上：它在 reasoning 上做的并不是那么多，但在 Agent 上做得非常好——因为它背后对应的其实是两种不同的 test-time scaling 的范式：一种 scale 的是多轮的方式，你需要跟外界交互、使用很多次工具，scale 这个轮次；另一种 scale 的是你并没有什么交互、只是一直在思考的纯粹思考。这是两种不同的 scaling 维度。

你看 Claude 很多模型，reasoning 的 performance 并不是非常高，但 Agent 上的 performance 很高。这两个东西并不一定是依赖关系。但有一点：如果你想做最好的 Agent、解决最复杂的任务，最终可能还是需要 reasoning 能力也很强。所以在研发上它不是必然的顺序，但要达到一个东西的最好，你需要把另一个也做到最好。

当你有了 agent 之后，对应的接下来就是 innovation：最关键的一点是模型到底什么时候能参与到模型的开发。比如我们希望 K2 能够参与到 K3 的开发里面——如果没有 agent 能力，你很难做到这个事情。但当你有 agent 能力之后，它就可以去提出一些新的想法、做对应的实验、分析实验结果、得到结论、迭代下一版想法，或者优化某一个 infra 的性能。这需要很强的 agentic 能力才能做对。innovation 最大会产生在——至少一个很关键的点是——看模型什么时候能参与到模型本身的研发里面去做迭代。

但它跟 organization 也不一定是完全线性的关系，有的东西是并行的。比如现在你能看到很多趋势：当你有一个 agent，就可以把它拓展成一个 multi-agent 系统——从一个 agent fork 出很多个不同的 agent 做不同的事情，可以串行、并行、合并，分成几个不同的 task，有的写测试，有的写文档，有的设计整体软件框架，可以有不同的分工。所以 organization 可能就是它会是一个 multi-agent 的系统，现在也有很多雏形。当然，multi-agent 系统怎么很好地端到端训练、不要过拟合到某几种 agent 类型、让它有更好的泛化性，我觉得是有挑战的。

张小珺

Organization 是雪山的封顶吗？

杨植麟

我觉得也不是，可能它真的没有顶。这几个能力随着时间发展都会持续变得更好。包括推理能力，上限到底在哪里？今天也不好说——虽然它看起来是 L2，但真正做到很强很强的推理，今天也还是有很大的空间。

张小珺

你怎么看 L1 到 L5 的分解，把它当做一个什么样的刻度？

杨植麟

我觉得它是几个重要的技术 milestone，但并不一定完全是串行的关系——不是说有一个东西马上被解决掉、再解决下一个，它们可能同时都在提升。比如 reasoning，你要真正解决一些开放的问题、做很好的创新、提出新的模型架构，推理能力可能又需要有更高的要求。所以这几个能力要持续地提升。

K2 是乔戈里峰

张小珺

复盘一下：2023 到 2024 年你们的关键决策是 2 月决定创业、融资、组建团队，下半年 Kimi 上线、bet 长文本。那 2024 到 2025 年这一年，你关键的几个重要决策是什么？

杨植麟

技术上很重要的一个：从以预训练和 SFT 为重点的研发范式，转变成以预训练和强化学习为重点。这就需要做很多储备，不管是人才还是研发方式的改变。还有一个是从对话到 Agent，这是一个重要的范式改变，会很影响我们实际的工作方式。这两个是比较重要的方向上的变化。

张小珺

过去半年你们推出了 K1.5 和 K2，这分别对 Kimi 意味着什么？

杨植麟

K1.5 更多的是强化学习技术的验证。我们也比较早在这个技术路线上投入，得到了一些结果，看背后的技术到底怎么做——比如当时发现可能不太需要太多的 process reward 或者 value function，这些在训练过程中甚至还有一些副作用：直接用端到端的 reward，就可以把训练做得非常好。这在早期其实并不是非常明确。在这个过程中，我们积累了一些强化学习的基建和算法的 know-how。

K2 的重点有几个。第一，我们希望它是一个非常好的基础模型。想要一个更好的 base model，就要看整个领域预训练的瓶颈在哪里：高质量数据的增长确实很缓慢，多模态的数据又没有办法很好地提升文本本身的智商——可以认为高质量数据有点接近是一个常数。所以我们希望把每一份数据最大化地使用，就是所谓的 token efficiency：同样吃下一样多的数据，你脑子长得更多，得到更多的智能。

这跟之前的一些思路不太一样。比如在训练系统里做很多性能优化让它训得更快——这很有价值，但训得更快本身并不能提升智能的上限，因为 token 只有这么多，训得更快只是用更短时间完成训练，模型效果并不一定会更好。这是训练效率、compute efficiency 上的优化，之前有一些人在做。我们现在更多是希望提升 token efficiency，把一份数据当成好几份来用。

所以我们很关注 Muon 优化器。这个东西很有意思，它对 token efficiency 的提升比较大。你可以认为像 Adam 这样的优化器已经用了十年，大家一直在用，大部分模型都用 Adam 训练，但它的 token efficiency 并不够好——它没有把每个元素独立考虑，比如一个矩阵的参数之间的 dependency。考虑这个之后，你可以有更好的学习效率：学同样一份数据，得到更多的智能。在我们早期的实验里，compute optimal 的情况下基本上会有两倍的提升——学一份数据等于别人用 Adam 学两份数据。假设你有 30T 的高质量 token，等价于你现在有 60T。

张小珺

但它还是那么多数据啊。

杨植麟

对，但它学了之后脑子会长得更快，因为学习效率更高——优化器更好，吸收得更快。喂一样多的数据，它吸收得更好，压缩率涨得更快、loss 降得更快。

张小珺

这是你们原创吗？

杨植麟

Muon 优化器是 Keller Jordan 提出来的，我们在上面做了很多优化，让它能够在很大规模的语言模型上适配和训练。我们之前有一个 Moonlight 的工作，让它第一次能在有一定规模的语言模型下训练。后来进一步规模化的过程中发现了很多新的坑：比如发现它的 max logits 会有爆炸的问题——这个在小规模实验上很难遇到，但在大规模实验上会遇到。我们就提出来一些新的 clipping 的方式去解它，让它在非常大规模的情况下仍然能很好地训练（就是 MuonClip）。因为你的 token 数量有限，希望每一份 token 能产生更大的价值。

包括对数据做很多 rephrase（改写）的操作。高质量数据——比如你有 30T token，但里面高质量的可能更少，可能几百 B——你希望它能很好地被使用，就对这些数据做改写的操作，让它能更好地被模型吸收、有更好的泛化。

张小珺

我读了你们的技术报告，你们尝试用已有模型改写现有数据、生成新的语料。具体的改写过程和策略是什么样的？报告里没有提。

杨植麟

如果同一份数据学很多次，它可能泛化不一定那么好，会有一些过拟合的问题。所以我们希望通过改写让它有一定程度的泛化，这是主要的思想。具体改写的方式有非常多种，我们找到一种在实验里效果比较好的，但这个空间很大，有非常多的研究机会。

张小珺

你怎么看一种观点：改写其实没用，能写出来知识说明知识本身就在里面，没有新知识，除非改写的时候用到其他方法？

杨植麟

这是个很好的问题，确实跟改写方式有关系——理论上要看你有没有新的熵的输入。所以它是对改写的方式有一些要求。我们今天的方式也不一定是最好的，这里面还有很多可以探索的空间。

回到 K2 这个模型：一方面希望它成为一个好的 base model，所以很希望提升 token efficiency，这些是对应的设计——包括通过更大的稀疏度去加更多的参数，token efficiency 也会更高，参数多了之后虽然学一样多的数据但吸收得更好，实验可以验证确实有更好的 token efficiency。第二个是希望它有好的 agentic 能力：强化学习，以及对工具和环境的模拟，让它有比较好的泛化性。

Agentic 模型最大的挑战是泛化

杨植麟

对于一个 agentic 模型来讲，现在最大的挑战其实是模型的泛化。现在 RL 技术的局限性在于：训练任务和评价指标很多时候都是单点的——比如你就训 SWE-bench，它要提升 SWE-bench，这是一个基本上很确定的东西。但指标提升上去之后，并不意味着模型的泛化会变得更好。我们也尝试去解决一部分泛化的问题：不希望它过拟合到某一些工具、某一些环境、某一些具体的任务上——这些任务可能是很好的观测，但我们不希望去过拟合它。这个问题在 agent 的训练里比之前的对话模型更加严重。

张小珺

为什么不在 pre-training 里面去（解决）？

杨植麟

这也是接下来我们想探索的：有可能会有更多 agentic 能力是可以在预训练阶段去做的。

张小珺

这能提高泛化性吗？

杨植麟

取决于做法——比如数据分布是不是足够广泛，以及有没有很好的方法去评估。我认为现在整体的评估还是一个瓶颈，是阻碍 Agent 模型变得更加泛化的一个很重要的瓶颈。你会慢慢观察到，Agent 能用的 benchmark 不是非常多，你在那些 benchmark 上观察到一个分数，它很多时候并不是对能力的反应，比较片面。这是大家可能要去想办法解决的问题。这里面可能有一种潜在的思路：用更 AI native 的方式去训练 AI——我们希望让模型参与到更多的训练过程里面。如果你的 AI 能够做很好的 alignment research、很好的对齐研究，理论上它可能会有更好的泛化，你就不仅仅只是在优化一些单点的任务。我觉得这是下一步可能非常重要的一个点：Agent 今天可能还不像对话一样有这么好的泛化性，这可能是接下来雪山上的几百个台阶。

张小珺

听起来 K1.5 是在跟着 OpenAI 跑，K2 是在抢跑？

杨植麟

整体上肯定我们还是借鉴了很多技术上的方向，但在这里面也希望能有一些自己的创新。比如至少我们可能是公开资料里第一个使用非 Adam 的、基于矩阵正交化的优化器在这么大规模的模型上训练的，我觉得这是一个创新的地方；包括我们一些 agent 数据的做法，至少在公开可查的资料里面也是比较早去做的。这个空间越来越大——很有意思，当你越往上爬，你的空间在变大：token 在变多，完成同一个任务的 token 在变多，问题的复杂度变得更复杂。就像刚刚讲的，问题不可避免，但问题总可以被解决——不可避免的问题看起来会比之前更多，所以研究空间可能会更大。

张小珺

K2 立项筹备了多长时间？什么时候开始？

杨植麟

筹备可能比较长时间了，很多涉及的技术从去年就开始研究。比如 MuonClip 这样的技术需要经过比较长的周期：一开始做一些非常早期的实验，发现这个想法有一些潜力，再做小的实验验证潜力到底有多好。有了这个想法之后，到最后能把它放到一个万亿模型里面去训练，要经过很长的周期——你要通过不同的 scaling 实验去验证有效性，有些问题只有当你 scale 到一定规模之后才会发现。所以整个周期比较长。当然如果只看模型本身，从按下训练按钮到结束，时间倒没有那么长——是整体研发需要更前置，做很多事情才能保证训练是一个比较顺利的过程。

张小珺

整体的 bet 是什么时候开始的？

杨植麟

要做很多的积累。不同时间点的做法不太一样：一开始可能并不一定非常端到端地做，但积累一些环境和数据，到后面可以端到端地做强化学习。中间需要很多基建和数据的积累，很难说你一两个月做得非常好，需要时间。大模型或者相关的技术挺需要时间积累的——要做时间的朋友，不断积累，技术的曲线还是有点陡峭的，不是今天想做就能做出来。

张小珺

所以什么时候立的项？

杨植麟

技术可能是一年前开始积累。但 K2 这个东西，是最近几个月我们决定要训一个这样的模型，然后把哪些技术用上——大概是这样一个决策。不是说我今天想训这个模型，再从零去搞很多东西，那就不是两三个月能解决的问题。

张小珺

为什么立这个项？

杨植麟

很正常，我们就一直训练下一代模型，无非就是决策下一代模型到底要加入哪些技术、期待它是一个什么样的模型。就跟现在我们也会考虑 K2 之后下一代模型长什么样，这是持续要思考的决策问题。每次看你工具箱里面又多了很多新的东西，把哪些拿出来用，有这样一个过程。

张小珺

做研究和做训练的团队是分开的吗？一年前就开始研究这些技术，到正式训练，是一个团队在做吗？

杨植麟

是一个团队在做。这些东西很难分开——你在实际训练过程中会遇到问题，如果你之前都不了解，没有办法去解决它，所以这两个并不会分开。

张小珺

K2 过程中有遇到什么挑战吗？

杨植麟

我们遇到的就是 Muon 你去训的时候它就会炸。我们 paper 里面画了一些图：max logits 会长得非常高。我们认为这个东西对训练的稳定性有影响——训久了，很多内部指标不正常的话，其实对模型的上限是有害的。所以我们又回过头去 revisit、重新看这个问题，然后去修复它。这个东西在小规模实验上没有办法预测，小规模上没法复现这个结果——小规模就是不会有这个爆炸的问题。其他的基本还好，因为其他我们都在小规模上做了很多实验，基本上可以迁移。唯一这个是小规模上验证不了，需要在 scale 过程中再临时解决。

张小珺

你在 K2 训练过程中最重要的几个 know-how 是什么？

杨植麟

这个我就写在 paper 里了，主要的东西都写在 paper 里面，我们还是想跟社区更多地分享。

Agent 的定义：多轮 + 工具

张小珺

我很好奇你会怎么定义 Agent，怎么对 Agent 进行分类？

杨植麟

像我刚说的，它可能是从一个缸中之脑变成可以跟世界交互。所谓 Agent，最重要的特征是可以多轮地使用工具——两个点：一个是多轮，一个是工具。多轮就是你能做很多次，这是一种 test-time scaling 的方式；工具其实是连接这个脑跟外部世界的方式：比如你用搜索引擎，就把模型跟整个互联网连接起来；你可以写代码，就把这个脑跟数字世界连接起来——数字世界基本所有自动化都可以用代码描述，它就可以拥有自动化的能力。这两个是我想象中 agent 的特征。

接下来会有越来越多的工具，是一个长尾的分布：模型如果泛化得好，就不只是使用一些常见的工具，它可能可以使用非常个性化的工具。比如你想让模型能够访问公司内部的一些数据库、你个人的文档，甚至访问一些定制的 API，让它完成某一些业务操作——退票、下订单——它应该能够泛化到没有见过的工具上。所以我觉得 Agent 现在最缺的其实是这种泛化的能力。如果你有更好的泛化，之前大家在讨论的各种垂直 agent 就不一定非常需要了：当通用的 agent 能泛化到长尾的工具上，很多领域专有的问题可以直接用这些工具解决——你只是每次给它加不同的工具，定制的数据库、定制的 API、定制的文档接口，就可以完成一个非常垂直的 agent。普适性会强很多。

多轮主要是可以做 test-time scaling：可以做很复杂的任务，不只是输出一轮。就跟人一样——人每天的工作其实就是一个多轮使用工具的序列，你本质上是希望把人的这个序列拟合进去；但你又收集不到这样的数字化数据，那就可以用强化学习来构造。

张小珺

它本质上是在模拟人的行为？

杨植麟

也不能说叫模拟人，它是一个通用的东西。

张小珺

什么叫它是通用的？人也很通用啊。

杨植麟

对，人也是一个所谓的 universal constructor（万能构造器）。它的主要目的不是去模拟人，主要目的是通用——这个形式化的定义本身是通用的，可以完成几乎所有的任务。跟人的做法相似，只是一个刚好的结果，并不是设计这个系统的目的。

张小珺

就是设计飞机是为了当交通工具，并不是为了像鸟一样飞？

杨植麟

对。我们有这个 Agent 系统，它更多的是 general purpose 的智能，你是跟这个目标对齐的，刚好跟人是相似的。

张小珺

怎么提高通用性？有探索到什么方法吗？

杨植麟

这是一个很难的问题。今天 agent 的泛化有一个风险是会陷入到一些 benchmark 的过拟合里面，但现在又可能缺少很好的 benchmark，这会是接下来的挑战。我觉得可能有一些解法：如果能用更多的 AI 去训练 AI，可以一定程度上缓解这个问题。

张小珺

什么时候能做到用 AI 训练 AI？现在的瓶颈是什么？

杨植麟

现在已经有一部分可以这样做，但你希望更多这样去做，现在很多还是要靠人的设计。

张小珺

这就到 innovator 那个阶段了。

杨植麟

所以很有意思：它其实有可能不是线性的——你要用一些 innovation 的方式去解决你的 Agent 问题。因为今天你的 Agent 泛化不够，所以你要用 L4 的技术去解决一个 L3 的问题。L1 到 L5 这个定义有可能真的不是线性的。如果没有很好的 innovation、没有用 AI 去训练或对齐 AI 的方式，Agent 可能很难做到特别好的泛化。今天你发现，人工定义了一些 task，然后 fit 那个 task，但在别的看不见的 task 上它可能表现得没有那么好——你只刷那几个 task 的分，在更 OOD 的场景里体感就是没有那么好。这个领域确实面临 benchmark 不够用、benchmark 失效，agent 的泛化有问题这样的一个阶段。

张小珺

为什么数学代码是相对容易泛化的领域？

杨植麟

其实也没有。做强化学习，对于这些任务会有一样的问题。当然强化学习本身的泛化性要比 SFT 好：因为过程中有更多的 on-policy 的 sample——从模型本身去 sample，学出来的东西现在看起来泛化更好，而且你有负梯度。这两个东西会导致从证据上看它的泛化更好，但还是有限度的。比如你在某一种类型的数学竞赛上做到 99 分，别的数学问题可能会提升 5 个点，但很难直接也做到 99 分——如果不做对应的 RL 任务进去就很难。我觉得仍然有一样的问题：它是被分布所制约的，所谓种瓜得瓜、种豆得豆。但我们希望整体的 RL 或者 post-training 还是有更多的 AI 来让它摆脱这种种瓜得瓜的情况。

张小珺

会不会摆脱不了？就是提高不了泛化性？

杨植麟

还是回到刚说的：问题是不可避免的，但问题是可以被解决。你每次往前推进，泛化就会变得更好——它不一定有尽头，你只会有更好的泛化。

张小珺

对于 agent 来说，任务和环境非常重要。怎么定义好的任务、好的环境？

杨植麟

回到刚讲的：一种方式是给定一个模型，去设计一些环境逆向拟合这个模型；现在如果你做一方产品，可以正向地设计工具环境，让模型在这个环境里面提升。很重要的还是让这个设计有更好的通用性，能做很多的任务——不应该是为了某一些任务去专门设计这个工具环境。当你的设计足够通用，让模型在过程中去学，而不是反过来去拟合这个模型，我觉得可能是更好的做法。

张小珺

一般大家觉得在任务设计上，你设计一个足够有挑战的任务，这个任务可能会做出本质的新方法。但你们 K2 用的是一些中等难度的任务，这是有什么思考？会带来通用性吗？

杨植麟

它也是一个爬山的过程：不能一上来就让它去证明一个还没有人证明过的数学问题，那样 sample efficiency 会非常非常低。现在感觉比较好的方式是：强化学习如果搭配好的 sample 策略，本质上是一个隐式的课程学习机制——curriculum learning，希望它从合适的难度开始学，学完逐渐提升难度，而不是一上来就学非常难的，那样采样效率很低，基本学不到什么东西，算力都会被浪费掉。但这个挑战还是说，今天的很多任务还是来自人类存量的数据、人去设计的一些任务，AI native 的部分还比较少，所以会带来刚说的泛化性的问题。

Coding 是 Agent 的一个子集

张小珺

Coding agent 和通用 agent 是什么关系？

杨植麟

Coding 是一个比较垂直的，或者说是一个子集。你只要把几个工具用得足够好，就能做大部分的事情。最后还是希望能够不光只做 coding——包括现在我们训练这个模型，也不是说让它只能做 coding，它还是会有一些局限性。

张小珺

Coding 相当于一个环境、相当于人类的手？

杨植麟

它是任务的一个子集，但是很重要的一个子集。它对 Agent 来说是相对容易的任务，因为比较好验证，所以比较好学习，但还是会有一样的挑战，比如泛化性的问题，即便是 coding agent 也会面临。Coding 很重要的一个子集在于：它代表了数字世界的自动化。今天很多 agent 的工具集合是固定的，如果你想创建一个新的工具，本质上是写一段或者一大段代码来实现；或者你想做更好的上下文管理，所谓的 context engineering，背后对应的也是一个工具，这个工具也用代码来实现。代码在这里面有独特的位置、独特的作用。

但并不是说做了 coding agent 就足够。今天很多不是程序员的人会用 Claude Code 做很多任务——律师、产品经理、设计师也会用，是因为模型在一定程度上有一些泛化，它不只是会写代码。

张小珺

所以你们是要做通用 agent 的模型，不是做一个 coding 的模型。

杨植麟

我们还是希望能做通用的模型。

张小珺

从写代码到操控整个数字世界，你觉得 Agent 还缺乏什么能力？

杨植麟

首先现在这些高频的工具使用也还不够好，能力上还有很大空间。另一方面，现在缺少一些更好的 benchmark 来观测：SWE-bench 可能马上会饱和，有很多 benchmark 不够好、不够真实地反映实际的用户体验。高频工具本身会有空间，然后长尾的工具——在一些你没有见过、完全 OOD 的（场景）——怎么有更好的泛化，也是很重要的需要解决的问题。

张小珺

你自己最看重能提升 Agentic 能力的是哪几个关键能力？长期来看让它能力提升。

杨植麟

希望能用 innovation 这一层的一些技术去提升 Agent 这一层的能力，这可能是很重要的一个方向。

张小珺

Long context、long-term memory 重要吗？

杨植麟

Long context 也很重要。很多任务你 128K、256K 的 context 完全解决不了，需要百万级别甚至更多——但你又需要在这个级别下脑子还非常好用，智商还得非常高。这对模型训练的挑战很大：希望压缩率足够高，模型可能要足够大，同时又希望它也比较强，这两个东西天然存在一些冲突，需要更好的架构。但有一些架构你发现它在更长的 context 下效果有提升，短的 context 又不一定有提升、甚至会下降，会有很多架构上的平衡问题。这些问题接下来会逐渐被解决，它是有一些解法的。这是 architecture 上的一个支持。

还有就是现在的 RL 训练方式肯定也有很大提升空间。比如当你要训练一个很复杂的 multi-agent 系统，只用端到端的 reward 可能不太够——中间的 reward 怎么产生、是不是能摆脱一些人工的设计，也会是很有意思的挑战。

既简单又复杂的系统

张小珺

我回看了我们去年的对话，有一个问题非常想问你：你去年说开源会落后于闭源，因为开源的方式跟以前不一样——以前所有人都可以贡献到开源，开源的贡献很多没有经过算力验证；而开源本身是中心化的，必然有人才聚集和资本密集，是一个对市场的整合，所以领先者不会开源，只有落后者才会这么做。但你今天开源了呀。

杨植麟

对，因为我们还不是绝对的、完全的领先。有一些判断基本上还是这样：模型出来之后，社区确实能贡献一些东西——比如在推理侧可以做很多事情，让这个模型有更多人免费给你 serve、有更多人去用。但要贡献到模型本身、把模型本身变得更好，好像还只能是原厂自己来做。当然，如果你看 base model 是这样，但基于这个开源模型去做很多 post-training——特别是 agentic 的 post-training——有可能产生出来一些新的机会。比如你想做一个法律相关的 Agent，你是一个创业公司，完全可以基于 K2 在你定制的工具集合下训出一个 specialized 的 agent，在你关注的场景下表现得非常好。我觉得存在这样的机会，但它更多是去赋能下游的应用——你很难说把这些东西再变成 base model 的提升，这个目前还是很难。这个问题可以动态地观察。

张小珺

你们会长期选择开源吗？

杨植麟

我觉得这是一个我们希望长期去做的事情，但不一定是只做开源。我们希望能够跟社区分享，像你刚说的技术的 know-how。我觉得这个可以加速我们把技术再往下提升——大家可以不完全只是竞争，也可以有一些合作；甚至说所有开源的公司会形成一个生态，能更好地把这个技术往下推进，雪山可以爬得更好。也不一定所有东西都开源：比如我们现在跟某些公司有一些合作，不一定所有东西都要开出来，但我们希望能持续地开放一些好的技术。

张小珺

所以这是一个技术体系的信仰，还是一个市场博弈的策略？

杨植麟

客观地说都有，而且可能都有好处。但最终我们是希望通过这个东西，让技术更安全、更快地达到一个更好的水平。

张小珺

开闭源的生态会怎么演进？最终开源和闭源全球会剩下几家？

杨植麟

我觉得不会很多，但几家肯定还是会有的。整体来说，你去看过去两年，这个趋势还是比较明确：市场会逐渐更集中、收敛——一开始有几百个，到几十个，到几个，我觉得「几个」可能是最终比较稳定的数，现在看起来是一个大概率的事情。

张小珺

你们属于开源那一边的，还是闭源这一边的？

杨植麟

像我们刚说，我们可能会持续地去开，但并不是所有东西一定都会完全地开。

张小珺

选择性地开。

杨植麟

对，这个很多要动态地去观察，但我们肯定是希望能够长期去分享更多的技术。

张小珺

为什么中国公司都开源了——也不是都，字节就没开。

杨植麟

客观地说还是像我刚讲的，可能有市场博弈的因素。这对社区来说是一个好事：开源的可以互相借鉴，可以去加速做到登顶，我觉得是一个很好的方式。

张小珺

去年你提到一个很多的词是「有概率的非共识」，你今天的有概率的非共识是什么？

杨植麟

像我刚讲的几个接下来比较重要的技术点：比如怎么去提升 Agent 的泛化，我觉得还是非常重要的问题，我们希望看能否在技术上有一些新的东西。包括我们做优化器这些东西——至少在我们做出来之前，应该没有人在做这个东西，所以它也是一个非共识：之前所有人都会使用 Adam。它对 token efficiency 提升确实很大，使得我们现在可以有一个比较好的 base model，后面就可以有更多的 post-training 把它所有的性能去压榨出来。

模型即产品

张小珺

你怎么看 AI 时代的产品？你以前就很喜欢说「模型即产品」。做 AI 时代的产品跟做移动互联网产品会不一样吗？

杨植麟

我只能说说 AI 的产品，移动互联网没有做过。但「模型即产品」这个现在还是没有变化。比如你做一个 Agent 产品，做的时候需要把模型跟工具和 context 结合起来——但你发现在训练模型的时候，基本上已经要把这一套全部搭好，才有办法训练这个模型。所以当你模型训完之后，产品已经做完了：在上面做一些交互的东西当然也肯定有很大的价值，但它是最后的锦上添花的一步——模型的性能已经在这个过程中打磨好了，跟工具和环境已经有非常好的适配。它是在训练之中完成的：你训练好了之后，产品就基本上已经做得差不多。

张小珺

你去年说，现在的开发方式演变成要做一个巨大的系统，像 21 世纪初 Google 做的信息检索系统。你今天对于 AI 时代这个巨大的系统，有没有更多的想象？搜索引擎系统和推荐引擎系统都适配不同的时代。

杨植麟

现在系统的复杂性在于，你想让这个模型变得通用，通用会带来很多复杂性。但它一方面变简单了、一方面又变复杂：简单在于你只要把所有东西都放在同一个模型里，不需要维护那么多模型、不需要搞一堆 routing 的策略，从概念上、从一些工程实现上是变简单的。但另一方面也会变得复杂：你希望它很通用，那它在各种场景下都可以工作——比如做 agent 的模型，你不希望它只在你的工具集下能工作，希望别人用你这个模型在别的工具集下、在你没有见过的工具、不同的定义和实现方式下都能工作，这个要求很高。

比如 agent 里面有几种不同类型的任务——coding agent、search agent、还是一些其他的——你把它放在同一个通用模型里面，可能会有一些打架的问题：也许你的工具定义不一样，或者你的数据的 pattern 不一样。把它做成一个通用模型的过程有很多技术挑战。但你不做成通用的模型，泛化性又没那么好，只能做一件事情。特别是现在 agent 需要很多步完成任务：即便程序员也不仅只是写代码，写代码也不仅只是做 SWE-bench。你要做很通用的、真正可用的东西，随着步数变多，对通用性的要求会更高。

我觉得它的系统复杂性主要体现在：你在训练这个模型的过程中，需要让它足够通用，而不是拟合到某一些单点的能力上——拟合到单点能力上，benchmark 分数看起来很好，但通用性可能不够。

还包括一个例子：你想往这个模型里面加多模态的能力，就需要让多模态能力不要损伤它的脑子。

张小珺

只是能够不损伤，是吗？

杨植麟

对，能不损伤已经很好了。你希望在多模态的模式下跟文本模式下能共用一个脑子——它能在多模态的模式下也能把文本的智商激发出来，而不是进入另外一部分参数，那可能就完全丢掉了原来文本里面学习的部分。所以做一个通用的模型会面临这样的挑战：各种模态、各种任务类型，还有 agent、reasoning、chat 这些东西，全部合到一起。而且你现在不光是 SFT，要做 RL——RL 的时候这个挑战会进一步加重。相比之下，通用的 pre-training 相对比较好做，你把所有文本放在一起，基本不会有太多问题；但越到 post-training、越到 RL，这个问题会更加严重。这是它的系统复杂性。

张小珺

搜索引擎系统构建在 PC 互联网之上，推荐引擎系统构建在移动互联网上。这个 AI 时代，新的节点在哪里？超级节点在哪里？

杨植麟

新的系统肯定会跑在很多数据中心里——所谓 Jensen（黄仁勋）经常说的 AI factory。但肯定还会有很多终端，终端可能有些可以复用现在的，有些会有新的。

张小珺

可能会诞生新的交互方式。

杨植麟

肯定会。Chat 是一种：两年前看它，它是一种新的交互方式，之前没有人跟机器这种对话。但现在 Agent 也有很多新的交互方式：你让它异步执行一个任务，又可以看中间的结果。接下来还会有更多——当你有一个 multi-agent system，它的交互方式会怎么样？可能会随着能力的边界去变化。比如 coding：一开始有 Copilot，Copilot 之后有 Cursor，Cursor 之后有 Claude Code——每一代交互都会发生变化。你发现这个交互其实是随着模型的变化而变化：当你有新的一代模型、能力提升了很多，你的交互就可以改了——你不再需要单个人去点要不要 accept 一个修改，而是可以多步地执行一个 agentic coding 的任务。今天 Claude Code 的交互也不是终极形态，因为模型还会提升，提升之后交互就会持续变化。

张小珺

今天 Scaling Law 你觉得还没有放缓？

杨植麟

Scaling Law 是有数据墙了，这肯定是一个客观的事实。突破这个数据墙，就要提高 token efficiency——这是为什么我们会去做提高 token efficiency 的事情。同时你要 scale 更多的 compute 到 RL 上、各种各样的 RL 任务上。我们现在观察是：模型变好的速度并没有在减少，我觉得甚至是在加速。

为什么 AI 产品还没有数据飞轮

张小珺

为什么 AI 产品都还没有形成数据飞轮？

杨植麟

因为基于算力的 Scaling Law 太强大了。一方面，你先 scale pre-training，然后又 scale RL——RL 的 scaling 效率又比 pre-training 高很多，因为它是 on-policy、带负梯度的训练，scaling 的效果、效率更高。当你有很高的 scaling 效率的时候，你直接 scale compute、scale FLOPs 带来的提升非常非常大，显得其他带来的提升很小。

另一方面，所谓的数据飞轮很依赖于外界环境的 feedback，而这个 feedback 我们不希望有太多噪声——现在可能还没有把这个问题做得非常好，因为大模型的学习对噪声是比较敏感的，跟传统的推荐系统有点不太一样，它对噪声很敏感。现在看起来还是基于 FLOPs 的 scaling 是更有效的。当然这个平衡什么时候会产生变化，有可能就是你通过新的交互让你收集到的信号的噪声能够减少。

张小珺

真的需要创造一种新交互。

杨植麟

对，但你这个交互要适配模型能力的发展——交互不能超越模型能力，应该在当前模型能力的范围内去设计一个好的交互。我觉得这个值得尝试，只是今天我会觉得，去 scale FLOPs 那个维度、提升学习效率，还是确定性更高、看起来更有效的方法。

张小珺

那如果说像闫俊杰说的「用户数据无法提供模型的智能」，好像今天就没有必要做 to C 产品了，一门心思提升智能就好了？

杨植麟

这个东西要看怎么看。你可能没有办法直接去使用用户反馈直接拿去训练，但你有一定用户量的好处在于：你知道整体的需求分布是什么样，大概知道哪些可能是用户用得好、哪些用得不好，再把这个东西抽象成一些 evaluation，去优化模型。如果模型完全没有人用，你可能都不知道往哪里去优化。另外也要看用户的商业价值：现在其实又到了一个新的分水岭，你的用户其实是有可能产生商业价值的。看 OpenAI，C 端用户产生的商业价值很大，可能占了营收比较大的比例。特别是现在有很多 agent 的产品能端到端地产生很多价值——也要看你是什么用户：如果普通闲聊问天气，不一定有那么大商业价值；但很多 agent 的专业用户，本身就是很好的生产力价值，这个事情就不完全一样了。

张小珺

你的产品有什么新的想法吗？

杨植麟

我觉得更多还是想模型怎么做。像我刚讲的：模型训好了，产品就已经做得差不多了。

张小珺

模型即产品。

杨植麟

对，我觉得它今天还是成立的，我们还是会沿着这个方式一直在做。

商业模式与生态边界

张小珺

有人会说，Kimi 从做「中国的 OpenAI」是不是要变成想做「中国的 Anthropic」？有这样一个转换吗？

杨植麟

很难这样定义，中美不太一样，而且今天我们更多还是得站在全球的视角去思考这个问题。「做中国的什么什么」可能本身就不一定非常成立。简单一点说：我们希望还是继续爬山，做时间的朋友，跟 community 一起去加速技术的推进，这是我们想做的事情。

张小珺

聊聊商业模式。API 是好生意吗？

杨植麟

我觉得现在明确的商业模式，一个是 API，一个是说一方产品，这两个可能我们也都会去做一些尝试。当然今天最主要的优先级还是继续把模型做得更好，这个是首要目标。但在把模型做得更好的过程中，比如你在某些方面领先了，确实会有商业化的空间——今天整体的市场规模涨得很快，头部的公司有几十亿、上百亿美元的营收，而且在快速增长，可能每一两个季度就能翻个两三倍。我们会动态地观察，做一些尝试。但如果你的模型真的能做到比如 Opus 的水平、甚至做得更好，空间可能更大，所以我们会花更多时间把效果做得更好。

张小珺

你们的用户说他们很喜欢 Kimi，但很担心 Kimi 赚不到钱。怎么办？你们能赚到钱吗？

杨植麟

还是先投资。能不能赚到钱取决于你的模型效果做得怎么样——我觉得市场是一个已经一定程度上被验证、也在快速增长的市场。所以还是专注把技术做得更好，剩下的东西确定性反而可能是更高的。

张小珺

K2 火了之后，你心情有什么变化吗？

杨植麟

也没有，还好。这是一个漫长的旅程，反正要持续做下一代的模型——还是回到刻在石头上那两句话：你会产生新的问题，然后你就去解决它。这个可能是最有意思的部分。

张小珺

这个创业旅程有什么是完全意料之外的？

杨植麟

还好，基本上所有的困难我们也有预料到。最有意思的点是你永远不知道会产生什么新的技术问题，然后这些新的技术问题会怎么样被解决——这个基本上很难预测，如果能预测它就不是那么创新。你会永远遇到新的问题。

张小珺

你现在生活是什么样子？时间主要投入在模型训练上？

杨植麟

现在可能睡得比较晚，每天不太一样，但也还好，花很多时间去看怎么把模型训练更好。模型训练是个很抽象的概念——我觉得里面很重要的一个是技术战略，这可能是公司战略里最重要的一部分：下一步到底是哪些要做、哪些不要做，技术空间很大，你总要选一些东西去重点做。

张小珺

去年选择的是什么？

杨植麟

我觉得我们在很多东西上的 bet 还是有效、而且比较早的：比如做 long CoT，我们反应比较快；然后用新的优化器；做更大规模的 training；做可能是第一个开源的 agent 的模型。这些是一些技术的 bet、技术的决策。这个东西基本上会至少决定五六成的公司的走向。但要做很好的决策还是需要很多证据支撑——我们还得做很多实验，你得了解很多具体的实验结果，到底这个东西是什么样、接下来可能会怎么发展。不能拍脑袋，还是得知道更多的信息，这也花很多时间。

张小珺

这些决策里面哪一个是花时间最长思考的？

杨植麟

最重要的就是你接下来要做什么、不做什么。但还好——这个东西关键是一个收集数据的过程：你做实验，看实验是不是扎实，结合你对技术的理解去判断。很多时候只要数据足够充分，判断也是比较显然的。接下来我们也在想、在做一些实验，还是有很多东西可以做。至少现在 K2 的性能潜力其实还没有被完全压榨出来——我们之前放的更接近是一个 base model 这样的东西，接下来可以加更多的 post-training 的 FLOPs，上限应该会比现在还会高很多。然后肯定还会做下一代的模型，base model 应该可以有更多的提升。这些具体怎么做，我们会通过一些实验来决策。

张小珺

也会加多模态吧。

杨植麟

对，多模态肯定是比较确定的。

张小珺

你刚才一直说多模态只要不干扰智能就已经很好了，是吗？

杨植麟

对。多模态的能力本身要做好也不容易，里面有很多工作——你怎么让它能够去借鉴文本的脑子，而不是自己单开一个脑子。比如 MoE 里面你有 20 个 expert，他专门在做多模态，你可能不希望这种情况出现，否则你学出来的多模态是个「傻的多模态」。我们希望它是个「聪明的多模态」。

张小珺

下面有什么重要的里程碑？泛化性 maybe 是一个？

杨植麟

对，agentic 的泛化性可能是最重要的——今天是一个没有完全被解决的问题。

张小珺

你们解决了一部分了没？什么 know-how？

杨植麟

解决了一些，know-how 我们写在 paper 里了。还是尽可能避免你通过强化学习只拟合到几个任务上——因为 benchmark 现在比较局限，优化 benchmark 会导致你的 RL 任务坍缩到几个单点上，这个是我们不希望的：在你没有观测的东西上，它可能就掉得非常多。我们现在也在想更多的办法去解决。这个会很重要。然后像刚说的 long context 的支持也会继续看怎么做：在智商很高的情况下还能有更长的 context。现在很多 long context 的架构还是会影响智商——比如纯粹的 linear attention 可能就是会影响智商，因为这个架构会有一些 bias，这个 bias 在一些场景下效果没有那么好，但这个一定程度上也可以被解决。

基座模型公司和 Agent 产品公司的边界

张小珺

模型公司和做 Agent 产品的公司，长期来看关系和边界在哪里？

杨植麟

这个问题我也没有明确的答案。今天看起来，一方产品有个好处是可以做垂直的整合：我可以把模型放在这里面训练，所以我的模型跟工具是融为一体的，不是分开来做、再去逆向工程。但因为有非常多的 Agent 的空间，我感觉一方产品不一定做得过来。所以有可能是，如果能找到一些空间——比如你的工具实现需要非常多的领域 know-how，或者你的 evaluation 是一方产品根本不会考虑、考虑不过来的东西——那我觉得是有机会的。有 K2 这样的开源模型，大家可以在上面去微调，更容易产生出一些 specialized agent、垂直 agent 的可能性，这个可能性还是一定程度上存在的。

张小珺

那要看你通用模型能通用到多大程度了。

杨植麟

对。但不管你多通用，总还是有一些工具你要做。你也不一定是要去做那个模型，而是把工具做得非常好。但如果这个工具你做得太通用，可能就会跟一方产品 overlap 比较大——那还是做垂直整合优势更大。但如果你这个工具是专门针对一个东西去做的，甚至这个工具是别人做不了的——比如我今天掌握了一些线下服务的入口，下订单或者成交这个工具是别人根本做不出来的——那你也有可能产生一些独特的价值。

当然也存在另外一种可能性：当你这个一方产品、或者说通用的 Agentic 的流量和商业模式足够成熟之后，很多专有的、本来垄断的工具也会愿意接入进来，因为它整体的商业化效率会更高。但商业化效率的提升需要一些时间，在这个时间窗口内，专有的 Agent 也会有空间。最终通用之所以能工作，是因为它整体的商业化效率更高。包括很多内容平台，你最终有可能把内容接到通用 Agent 里面，商业化效率会比今天更高——有可能，但要花很长时间。

张小珺

像 Manus 这种公司，会是你的客户还是竞争对手？

杨植麟

在生态上来说还很早期，很难判断，产品本身也会演进。短期内可能更多是合作的关系，大于竞争。但未来确实会演进——有点像 Claude 和 Cursor 的关系：Cursor 可能也要动态地变化，在产品策略上有些动态的调整——一方面是能不能有一些模型的能力（技术研发的曲线还是很陡峭），另一方面是能不能有一些别人做不到的工具或者环境。这些现在没有办法直接回答，只能说现在看起来一方的整合优势是存在的。

张小珺

你形容 K2 是哪个山峰？

杨植麟

K2 本来就是世界上最难攀登的山峰，刚好这个名字有点重合。

张小珺

这是你故意选的这个名字吗？

杨植麟

对，当然它刚好也是 K2。我们也希望它首先不是终点——它不是最高的山峰；它可能是最难的，因为现在有很多范式的转变：从对话到 Agent，base model 的 scale 也进一步变大，本身肯定存在难度。刚好有点关联。

张小珺

结果超出你预期吗？会有 aha moment 吗？

杨植麟

差不多。基本上模型训得怎么样，在过程中就已经知道了，并不会有什么惊喜或者惊讶。很多东西是可以被预测的——我觉得更重要的是这个预测的能力：你训一次模型，一是需要周期，二是需要有成本，所以我们希望在早期尽可能多地把所有能预测的都预测到。唯一没有预测到的就是刚说的 max logits 的问题，但那个确实没办法，小规模预测不了。其他的都是我们希望尽可能预测好——在验证清楚的情况下再 scale，scale 的成功率是比较高的。

在自己的故事里面

张小珺

你怎么看张祥雨说的 next token prediction 的本质缺陷？他的意思是说，随着模型规模扩大，对话能力、知识量和情商都在变强，但是推理能力尤其数学的表现是先上升后平缓，再扩大反而下降——用更大的模型做数学问题倾向于跳步、不老实，他觉得这是 next token prediction 的本质缺陷。

杨植麟

所以要搭配强化学习的 scaling。确实如果你今天不做强化学习，模型很难说很聪明——像数学题这种不一定做得非常好。但更大的 base model，强化学习的上限还是会更高，因为它知识更多：本质上是去激活推理，让它能把那个知识解锁出来。上限会更高，但你要搭配一个 RL 去激活它。

张小珺

世界模型怎么看？一种说法说做世界模型是造世界，做 agent 是造人。

杨植麟

最后就像我刚说的「用 AI 训练 AI」，有点这个意思：你有一个很好的世界模型，就去模拟这些东西——它就是用 AI 训练 AI 的方式，泛化就会好很多。我觉得这个有可能是通往更好的泛化的一种可能性。

张小珺

你的一个投资人说，第一次见你的时候你就开始讲 GPT-10 可能长什么样——你说的不是 GPT-4、GPT-5 长什么样子，你说的是 GPT-10。你现在觉得 GPT-10 长什么样？还会有 GPT-10 吗？

杨植麟

我觉得我们今天其实已经实现了之前预想的很多东西——比如真的能完成几个小时的这种任务，发展还是很快的。但整体就是逐渐建更多的 evaluation，然后去突破这个泛化的过程。相对来说还是比较明确的。

张小珺

在 evaluation 上面你们有获得什么认知？

杨植麟

我们也在探索。你刚说的世界模型可以认为是这里面的一部分，但怎么实现，我觉得还需要更多的实验。

用 RL 的方式去管理，而不是 SFT

张小珺

过去一年，你对组织有新的思考吗？

杨植麟

最近在想一个事情：有几个东西好像有点联系在一起。你看我们去做科研、创造新知识的过程，很像一个强化学习的过程。有一种理论叫经验主义，说新的知识是从经验来的；但后来有很多观点认为不是这样——人类在地球上已经存在非常非常多年，可能三四千年之前没有任何人说地球是个球，你一直在这个经验里，但你不知道事实是什么样，所以经验并不能直接给你知识。而是你提出了猜想：你观察到一些东西，提出猜想说「我认为这个球可能是圆的」，然后想各种办法去验证它。

包括现在训练神经网络，你可能观察到几十万个内部指标，发现有一些不太对——直接观测并不能给你新的知识，你只是提出一个猜想它为什么会这样，然后设计一些实验去验证它。这是现在可能我们觉得比较好的方式，当然可能所有好的科研的方式都是这样。

这几个东西好像是相通的：管理一个团队也是这样的方法——要用 RL 的方式去管理。这个是 Tim（周昕宇）天天跟我讲的：要用 RL 的方式去管理，而不是用 SFT。当然现在好的技术是，你做 RL 的时候其实也希望加一部分 SFT，因为 SFT 是很好的先验——所谓的 PTX loss——你不希望这个模型飞太远。但你又要管住自己的手：不能 SFT 太多，SFT 太多，这些同学就会失去主观能动性，就没有办法创新了。

这个点我现在也在做一些实践，好像看起来有一些效果，但核心是掌握 SFT 和 RL 的平衡。SFT 就是你直接告诉他这个东西应该这样这样做；RL 就是给他一个奖励——从上而下，如果做成这样就是好的，更多时候它反映在目标上。这两个东西需要一些平衡：可能以 RL 为主，通过一部分的 SFT 去防止它飞太远，你还是要有一些先验去控制，或者防止它遗忘掉一些东西。

这些好像某种程度都是连接在一起：RL 好像是一个很本质的东西，你的组织在做创新，本质上也是一个 RL。但在 RL 过程中，你定这个奖励或者定这个指标，并不是非常简单的事情。比如你只是最后说要把所有的 benchmark 做得很高，那可能就会出现很多 overfitting 的问题——因为所有人都会不择手段地把那个分弄上去，但弄完之后你发现模型好像并没有变好。所以这个奖励的定义很重要，也需要你很了解具体的细节是怎么运作的，不然的话就会出现 reward hacking。

张小珺

怎么定 reward？有什么想法没？

杨植麟

还是建立更多观测指标，尽可能不要去（单点）拟合。这样你才有更好的泛化，不会被 hack。用 RL 管理团队，最大问题就是你容易被 hack：你 have 那个 reward，大家看起来各种结果都很好，但实际上并没有达到你最终想要的。这是它的风险；而你用 SFT 管理团队的风险就是大家失去创造力。所以最后这几个东西要有一定程度的 balance——我也在学习，今天肯定不是说做到很完美的情况，但可能要逐渐去学习和理解这个事情。

张小珺

你过去有很低落的时刻吗？

杨植麟

我觉得还好。有些东西会 work，有些东西不 work；会解决一些问题，又会有新的问题产生，像刚说的。只要觉得这个东西是有意思的，你就一直想继续做下去。

张小珺

你对 CEO 这个身份有没有新的理解？

杨植麟

我现在最新的理解是：怎么去把握 RL、SFT 还有 hacking 之间的平衡，这个可能很重要。

张小珺

过去一年 Kimi 也是波峰波谷来回震荡，你在其中的心态是什么样的？需要平衡自己的心态吗？

杨植麟

心态就是，做时间的朋友吧。

张小珺

真实人的心态不会这么简单的。

杨植麟

你会有高点和低点，像你说的。可能很重要的是你还是喜欢做这个事情，想把它做好——你也不用想别的东西，就想怎么把它做好。好像也比较简单，没有什么特别复杂。很多复杂性都是人为强行加上去的，实际上并没有那么复杂。

张小珺

那你对人性有多的理解呢？

杨植麟

这个东西也还是需要时间的打磨，不敢说有那么深入。只能说是在自己的这个故事里面，不断感受自己到底是什么样的一个人，然后你为什么要做这个事情。可能是不断去思考这些问题。

张小珺

你是一个什么样的人，为什么要做这样的事情？

杨植麟

就是觉得有意思。

张小珺

是什么有意思？做实验有意思？做科研有意思？

杨植麟

寻找真相的过程，不断发现新的问题、解决它的这个过程。

张小珺

那你也可以解决别的问题啊，为什么解决这个问题？哪个问题很重要？

杨植麟

我觉得 AI 很重要。因为这个问题我也问过 Kimi，他跟我说这个东西是「人类文明的放大器」，我觉得很有道理。又回到 The Beginning of Infinity：你从启蒙运动到现在，人类一直在找到新的方法去突破知识的边界，但可能下一个突破边界确实得靠 AI，因为它是一个巨大的杠杆。你今天在任何一个前沿学科，要花几十年——二三十年——才能学到最前沿的知识，但 AI 可能一夜之间就能学会，那你就往下去做新的突破。AI 会成为一个 science 的母机（mother of sciences），我觉得这是很重要的，人类文明的放大器。

张小珺

它有可能摧毁人类文明吗？

杨植麟

首先这个风险你不能说它不存在，但我们可以有很多事情去做——不管是更安全的对齐，还是更好的社会机制。比如当它可以做很多事情的时候，很有可能会创造出来一些新的工作，我们需要有一些方法去完成这个过渡。我其实 exactly 问过 Kimi 这个问题，他说：虽然有这样的风险，但我们可能不能放弃这个事情——因为你如果放弃，就等于放弃了人类文明的上限，你不知道它上限能做到什么样，有一点因噎废食的感觉。但我承认我们得做很多的事情——特别是你今天看到很多 AI 能力，我觉得是有点震惊的，半年前你都想不到现在能做到这样的程度。

同时我认为人的独特价值在这个过程中还是会持续存在——人的体验、人的情感这些东西是没有办法被 AI 替代的。所以可能会有不同的活法，但希望能活得更好。

张小珺

什么样不同的活法？

杨植麟

我之前觉得人的一生可能有几个不同的意义：创造、体验和爱——当然每个人不一样，这是对我来说。创造里面的很大一部分，也许有可能 AI 是可以做的——我还是很享受这个过程，但你不得不承认，有一天你可能会有很多的创造性的工作只是 AI 去做。但后两条，我觉得还是会以人为中心的。

张小珺

但如果它把创造拿走了的话？

杨植麟

它其实把生产力拿走了。这无所谓，因为人可以享受生产的结果——如果我们有一个好的机制的话。

张小珺

需要改变社会的机制。

杨植麟

对，但它也是一个缓慢的过程，不是你一两年做完的，可能要一二十年逐渐地去调整。

张小珺

你会频繁地跟 Kimi 聊天吗？

杨植麟

当然，我要测试模型。

张小珺

你会跟他聊一些很深刻的话题、很自我的话题吗？比如会聊什么？

杨植麟

杨植麟

张小珺

你觉得过去你有没有走弯路？

杨植麟

肯定有。你在这个过程中会有很多很多决策，有一些是技术决策，有一些是业务决策。很重要的是一个公司在这个过程中逐渐调整的能力。就像知识创造也是这样的一个过程：你不可能创造出来的知识所有东西都是对的，你会发现有的东西它也是错的——但它在一定时间内可能是对的；当它是错的之后，你要去做调整。比如牛顿做的很多东西，在他当时是最好的理论，但他不是完美的，也有错误——万有引力在一些场景下需要别的解释，需要相对论的解释、通过时空的扭曲去解释。我觉得是一样的：组织的进化、一个公司的发展是一个动态的过程，任何的中间点在某些时间是对的，有一些时间可能是错的。

这个也是 Kimi 告诉我的：任何中间状态都有可能成为被批评的对象。你总是会有时代的局限性。更重要的是你怎么在这个过程中：一是投入一些一定不变的东西，比如人才和技术的积累；二是在这个过程中去适应和调整——能够针对反馈信号或者环境的状态变化去做一些决策调整。这两个东西很重要。

张小珺

做 AI 时代产品是不是跟互联网产品完全不一样？互联网产品通过投流去扩大 DAU、扩大市场规模，但 AI 产品很不一样——模型能力提高了那个 bar 以后，它自然就会获客，而获了客也不知道用来干嘛，这个怎么平衡？

杨植麟

它有时候也不一定那么自然，取决于两个变量哪个大。但如果你是在技术快速发展的阶段，很难说通过投流的方式去赢得这个战争，我觉得是很难的——它更多的是一个辅助的手段。辅助手段跟主要手段之间到底什么样的配比，可能需要动态调整，也取决于你现在的（商业化）进展、你的 PMF 到底有多强——不同时间点有不同的策略，甚至这个策略也许再过一两年你发现又是一个好的策略，不一定。我们是用更 open 的心态去看这个东西。但每个时间点最重要的是看哪个是最大的变量，我觉得这个挺重要。

今天最大的变量依然是智能？还是爬山？

杨植麟

对，还是爬山。
