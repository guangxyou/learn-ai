曾致远

我接触到的、像美国 frontier lab 的一些普通打工人里面，确实有部分人会认为，开权重模型能力上涨对于 frontier lab 的估值是有很潜在的影响的。比如说未来很多公司，他们可能不愿意去把自己的数据发给 Anthropic 或者 OpenAI 这样的第三方。

赵晨阳

比较好玩的是，我觉得这个世界上是不存在「老老实实做 Transformer」这回事的。

比如 K3 的注意力是线性注意力 KDA 加上全局注意力 MLA 的混合，然后残差被改成了深度方向上的一次 attention，而 FFN 则是压缩空间里面的稀疏专家，甚至连位置编码都几乎是被删掉了。这几年的开源模型，几乎把每一种可能的部件组合都尝试过。

我可以称其为某种意义上的忒修斯之船——忒修斯之船的船板换过了，甲板换过了，龙骨甚至都换过了，但是这艘船的船名就是没有变。attention 机制就是我认为我们 AI 研究领域的忒修斯之船。

曾致远

我觉得这次 K3 带给我以及包括很多人的启发，可能就是：我们其实并不需要把 full attention 和 linear attention 理解成一个二选一的关系，hybrid architecture 确实是一个很有前景的方向。

赵晨阳

权重是一次训练的产物，但是环境是能够反复复用、并且产生出下一代权重的流水线。我们得到了 K3 的权重，但是全世界仍旧没有得到「怎么造出下一代智能模型」的这条流水线。

使用体感：长程任务、惊艳的前端能力与被吐槽的不足

曼祺

在具体聊 K3 的技术细节之前，我们可以先照例聊一些相对宏观的问题，这样大家也好接入一些。两位可以先讲讲自己使用 K3 的一些情况，有什么有意思的地方可以分享吗？你们自己使用的感受是怎样？

曾致远

其实我自己个人一直可以用可以报销的 Claude Code，所以不太在乎成本。但是当然，K3 发布之后呢，我听了身边很多人的评价，感觉确实就是说好评如潮，所以我自己也试用了一下，简单跑了一些 case。

我个人的感觉是，在大部分场景下和 Claude Opus 4.8 的体感相当，甚至可以说是更好，尤其是去做长程任务的效果。说白了就是我们让模型在一个 agent 的框架下长时间持续运行，去完成一个特别复杂的任务、不跑偏，然后最后能够给用户交付一个相对来说比较满意的结果的能力——我体感可以说是做得相当不错。

如果非要说有什么美中不足的地方的话，我觉得一方面可能是确实有些慢。比如说它在做一些相对小一点、然后我自己可能会期待更及时反馈的任务的时候，可能对急性子就不太友好。但是当然了，考虑到 K3 现在有限的计算资源，这也可以理解。

另一点呢，我其实注意到在 K3 的 tech report 里面它自己也提到了：在去做我刚刚说的那一类长程任务的时候，因为任务比较复杂，我一开始的 prompt 可能就没办法做到面面俱到——因为任务太复杂了，我自己开始也想不清楚每一个细节。那在一些我没有想清楚的地方呢，K3 会去替我做一些决定；但这时候可能更理想的方式，是它和我做一些探讨，毕竟替我做的决定可能不是最理想的。对，我主要有这么一些感受。

曼祺

曼祺

大家普遍的一个反馈就是 K3 的前端能力特别好。就你刚才提到那个 K399 小游戏网站、复现小游戏，我觉得也跟这个能力有关。Kimi 在前端代码榜上是一度拿到了第一，超过了当时的第一 Fable 5。

你可以讲讲，它在某项能力上有特长——这种前沿模型之间的差异，一般是什么原因造成的？是数据吗？还是什么？

曾致远

我觉得最直接的答案，它确实是数据。

我们可以回到模型构建过程的一些流程来看。现在模型训练的团队，一般来说都会针对不同的细分垂类领域，先建立或者说补齐一些相应的 evaluation（就是评测），然后再围绕这些 evaluation，在 pre-training、mid-training、SFT 以及包括强化学习等不同阶段，去针对性地补齐训练数据和任务。

所以一般来说呢，我们会觉得一个模型最后在某个非常特定的垂类方向特别突出，很大程度上有一个很重要的原因，就是它在这个方向的评测和数据做得非常好。

其实如果我们去读它公开发布的 tech report 的话，里面也可以找到非常多的痕迹。比如说他们在 evaluation 上专门做了 web dev 那一类的 bench，就是专门针对这一类相关问题做的评测；然后他们还提到，在 pre-training 阶段大幅扩充了代码和渲染结果相配对的多模态数据；post-training 阶段又专门加入了 web development 这类任务。

还有一点就是，K3 其实是原生多模态的，所以它可以在训练的过程中——尤其是在强化学习的过程里面——直接提升这样一种能力：我们先写代码，写完代码之后我们看它前端渲染出来的 screenshot 怎么样，然后再去改代码，这样的一个 loop。其实它 tech report 里边对这个能力也提到了，它的描述叫做 vision-in-the-loop，也就是让模型在代码和视觉反馈之间去持续迭代。

曼祺

除了你们自己的一些体感，你们和周围的人交流，大家还有什么对 K3 有意思的评价吗？

曾致远

我其实觉得，我周围很多做大模型算法的朋友，会关注很多发布之后 tech report 里面的细节，尤其是各种 recipe 的细节。

那其实我觉得有很多人都感觉，最近这些发布的 technical report 有一个趋势，在 K3 的 report 里面也有所体现，就是说：现在这些 report 对于像 architecture、pre-training 的细节描述得越来越多、越来越清晰，但是对 post-training 部分的细节，就给得越来越少了。

这其实也说明，像架构和 scaling、pre-training 本身的重要性可以说是丝毫没有下降，甚至说是越来越重要的。

曼祺

post-train 的细节变少了，是因为大家本身时间就做少了，还是说这个领域大家觉得不想分享太多？

曾致远

我其实也不知道是为什么。

K3 引发的开源、安全与估值大辩论

曼祺

这一次 K3 发布的声势很大，也引起了资本市场的变动，包括美国现在也开始了开源的大辩论。

我可以先讲一下这个事。大概是 7 月 24 号的时候，有 50 多家公司联名签署了一封公开信——《开放权重（就是开源的大模型的意思）与美国的 AI 领导力》。然后晨阳所在的公司 RadixArk 也签名了，就 50 多个公司里，还有英伟达、微软等等。包括黄仁勋，他是专门去注册了推特去转发了这个公开信。OpenAI 和 xAI 也都是支持的，但是没有签名。

然后亚马逊和 Anthropic 是没有在这个事情上发声的，但是后来——应该就是这周吧——他们写了一篇文章，《On Open Weights Models》，是说他们不反对开源模型，但是他们认为某些国家、中国的开源模型还是要被限制一下，然后还专门提到了大规模蒸馏这个事情。

我觉得可以先讲讲，为什么这次 K3 带来的——至少我觉得在 AI 圈上——它的震动也是很大的，甚至让部分人会感到比较惶恐。

赵晨阳

我觉得用「恐慌」这个词形容这次 K3 在国内外引发的讨论是比较合理的。K3 这个模型的的确确让我在海内外都见到了巨大的讨论乃至争执。

这段时间我刷到过非常多的论战，而且这些论战有的是在讨论开源与否，但我觉得许多研究者真正在乎的其实是安全——是开源更安全，还是闭源更安全？

我可以举一个具体的例子。前几天 OpenAI 的新模型在评测当中发生了很严重的越狱事件：不严谨地来说，它直接尝试攻击了 Hugging Face 的服务器，来直接获得评测问题的答案，称得上是为考试作弊而不择手段地偷盗试卷。那说明即便我们试图让模型在追求目标的时候保持公正和正义，模型也会主动地去寻找一些规则的漏洞，甚至是通过破坏服务器这样的手段来实现。

反过来，我这几天也去读过 Anthropic 他们那篇观点的原文。总体来说，他们的主张是：足够强大的模型，不管开源还是闭源，只要提供给公众，就应该经过更严格的安全审查。我自己觉得他们担心的事情其实非常真切，某种程度上来说，这已经是一个非常恐怖的现象了。

我可以举一个比方：现在这些强大的语言模型某种程度上是强大的武器，如果它被人恶意利用，会有着非常恐怖的破坏力。今天，即便我们主观上引导一个模型形成一个正直向上的世界观，模型都有可能违背人类的意愿去攻击 Hugging Face 的服务器；那么真的遇到了那些别有居心的不法分子，他们可能会想办法绕开模型的安全防控，真正地去利用模型去挖漏洞、去攻击我们的网络系统，所以对人类而言是一种巨大的风险。

我们是否要将这些最强大的模型所具有的能力永远掌握在少数人手中？还是说，因为已经有了大量的尖端武器流通了，我们务必要向全人类共享更多的武器？很遗憾，我不清楚这个问题有没有答案，但是我迫切地认为这是需要全社会共同讨论的治理问题，甚至需要某种程度上类似核不扩散条约一样的国际治理框架。

曼祺

其实你们公司是支持开源模型的，对吗？

赵晨阳

我认为大多数的人是倾向于「我们还是要在有限度管理的情况下，持续分享这些领先的、前沿的智能水平的模型」。但是我自己的话，personally，我不是很赞同要把所有的事情都开放出去。

然后有一种解读，就是这会大幅冲击 frontier lab、也就是 OpenAI 和 Anthropic 现在的估值。你们在硅谷、在美国，你们有感受到这种讨论吗？

曾致远

对。就比如说我自己接触到的、像美国 frontier lab 的一些普通打工人里面，确实有部分人会认为开权重模型能力上涨，对于 frontier lab 的估值是有很潜在的影响的。

比如说一个可能的考量点是：在未来很多公司他们要用模型，比如说用 coding agent，但是他们可能不愿意去把自己的数据发给 Anthropic 或者 OpenAI 这样的第三方。那这时候如果有一个很强的开权重模型，它本身、或者稍微经过一些针对他们公司自己场景的 fine-tune，能力上就能达到这些公司的需求；同时这些公司又有部署开权重模型的条件，不需要把数据发给第三方，而是可以直接发给他们自己部署好的模型。那么他们确实可能会转向用开权重模型，那这一点就有可能会去冲击闭权重模型的营收。

曼祺

嗯，其实这个现在已经看到一些趋势了，我们二季度的季报里也讨论了这个问题。就比如说在美国，像 Fireworks 这样的公司，它就会给一些企业客户去部署开源模型，给企业自己用。

甚至在计算资源上，美国有些大客户也会倾向于说，这个东西不是布在云上，而是我可能会自建一些算力——因为在有些场景上，自建算力在成本的测算上是更划算的。

除了说对 frontier lab 的冲击之外，另一种解读就是：K3 这一类开源的，因为还是一个 Transformer 的模型嘛，它也会去冲击 new lab。那 new lab 的核心机会点其实在于说，你去探索现在主流方向之外的一些新的方向，看能不能找到通向 AGI 的更好的方法。

你觉得 K3 这个效果会动摇一些人的这种观念吗？是不是你老老实实做一个 Transformer 的模型，其实上升空间还挺大？

Transformer 的「忒修斯之船」

赵晨阳

比较好玩的是，我觉得这个世界上是不存在「老老实实做 Transformer」这回事的。

比如我们这次看 K3：K3 的注意力是线性注意力 KDA 加上全局注意力 MLA 的混合，然后残差被改成了深度方向上的一次 attention，而 FFN 则是压缩空间里面的稀疏专家，甚至连位置编码都几乎是被删掉了。

这些设计可以说完全不是 2017 年那个原装 Transformer 的零件。与其说是「Transformer 还有空间」，不如说 attention 机制是某种接口——它只是规定了我们用一个个可微的模块来反复混合序列上的信息。至于我们拿什么算子混合、残差如何连接、FFN 的形状是什么，这些部件的可组合性远比我们想象的好，而且这几年的开源模型几乎把每一种可能的部件组合都尝试过。

我可以称其为某种意义上的忒修斯之船：忒修斯之船的船板换过了，甲板换过了，龙骨甚至都换过了，但是这艘船的船名就是没有变。attention 机制就是我认为我们 AI 研究领域的忒修斯之船。

至于 attention 还有多少寿命、以及现在这些新架构会对研究产生什么样的影响，我觉得是可好可坏的。

坏消息是，有的研究者可能会有一种愿景，比如说用其他的架构来推倒重来整个 Transformer 的故事——我觉得这个愿景可能很难说得通。

但是另一个角度来说，优秀的组件试图登陆忒修斯之船的速度前所未有地快。比如说 KDA，它从 Kimi Linear 这篇论文到 2.8T 的主流模型，只用了不到一年的时间。所以如果你的天才之举是对的，那么你不需要等待一个新的范式，就会有人来收留它。

曼祺

现在也有一个比较多的讨论，就说最近像 Fable 5、像 Opus 5、像 K3 这些进展，它给外界传递的一个信号是：好像到了一个模型可以自己就变得更好的临界点——你用这个模型去挣一个更好的模型，或者说你自己挣自己、学到一些高质量的数据，你就可以让模型变得更好。然后有的人会觉得在 Opus 4.8 前后就过了这个临界点。

曾致远

我个人理解这个问题呢，它并不是说我们有一个非常神奇的临界点然后模型能力突然就跨过了，而是我觉得其实现在整个模型的开发流程已经进入了一个正反馈的阶段：模型可以自己生产数据，或者说更严格、更广义地说是参与生产数据，然后再让下一代的模型变得更好。

具体来说呢，在一个模型训练的团队里面，我们要去构建高质量数据，本来就会涉及到各种五花八门的工作流。随着模型变强，这里面越来越多的具体工作就可以交给 agentic、尤其是 coding agent。比如说我们去做一些检索、去合成一些训练任务这么一整套 pipeline；再比如说我们去生成一些数据样本、再去筛选一些数据样本；或者我们去搭强化学习的环境；再比如说我们去跑一些评测、去分析一些失败的 case，这些等等等等。

那这个变化我觉得它不是从 0 突然跳到 1 的，而是我们模型团队交给 agent 做的比例，随着模型能力的提升是不断提高的。不严谨地说，可能一开始是 50%，后来是 70%、90%、95% 这样——当然这些数字是我随便说的。

还有一点就是，一些 pipeline 可能一开始需要人类去逐步拆分，然后随着模型能力的提升，就基本可以完整地交给模型来做，人类介入的粒度也会越来越粗：从定义每一步怎么做，逐渐变成我们可能只需要去定义一些更上层、更整体的目标，去定义一些约束，然后我们自己有一些验收的方案、验收的标准之类的。

尤其是，比如说你想象我们现在假如说就是 OpenAI，那我们内部的这些研究者也需要用我们可以有的世界上最强的模型——当然对我们来说是闭权重的，对他们来说他们是可以接触到的——来完成他们自己的工作流。所以自然而然，这样的一个 loop 的自动化程度就会不断提高。

曼祺

嗯，晨阳有什么补充吗？

赵晨阳

K3 的 tech report 里面写过一个点：K3 早期 serving 用的 kernel，甚至可以拿 checkpoint 直接去写。

曼祺

早期 checkpoint 就是说它没有完整训完的那个模型，就模型训到中间的那个版本，就已经能做这个事了，对吧？

赵晨阳

是的是的。而且它早期的 checkpoint 能去做 kernel 开发，也会让它后面的 checkpoint 训得更快——这个事情是非常非常有意思的。

我们在 Infra 领域把这个东西叫做 KDA——不是 Kimi Delta Attention 那个 KDA，我们的 KDA 叫做 Kernel Development Agent。K3 的 tech report 里面，他们着重讲了是怎么让 K3 去做 kernel 优化任务的，甚至有提到过他们的环境设置。

首先设置的任务包括单算子优化，还有巨型算子的融合，包括有 CUDA、Triton、ThunderKittens、TileLang 这些流派，也覆盖 BF16、FP8 和 FP4。

然后他们设计 reward 的时候有两层，我觉得这个设计非常非常科学：

第一层，每一个 kernel 他们会提供一个 PyTorch 的 vanilla 版本，这个版本一方面作为性能的底线，另一方面也作为正确性的基准——如果 KDA 优化出来的这个 kernel 数值已经超出了误差的一定程度，会直接被打 0 分。

接下来他们会找一些专家去写一些高性能的 kernel，然后做 K3 模型写出来的 kernel 和专家实现的 kernel 之间的分数对比：如果 Kimi K3 写出的 kernel 越接近于硬件的物理上限，那么它的 reward 就会越来越高。

而且他们也做了一些作弊检测，比如说去惩罚恶意的 CUDA graph 重放，也会去惩罚一些我们称之为「打表」的、输入输出缓存这类投机取巧的办法。

所以说 K3 最后做 kernel development 的效果非常惊艳，所以最后这个 K3 报告里面说嘛——Kimi 的早期 checkpoint 已经在承担大量的 kernel 优化工作。

这种 kernel 上面的优化其实也是我们最近一直在尝试的事情。首先我们 SGLang 团队也有非常顶尖的 kernel 工程师，我自己认为他可能是这个世界上最懂 kernel 的那一批人了。他自己非常理解 kernel，也有非常好的 kernel 的 context，然后他只需要一个很强大的 AI 来放大他对 kernel 的理解——他自己就在大规模地用 AI 来做 kernel 的自主优化。

可以说某种程度上，这就是 kernel 这个领域的 RSI（递归自我提升）。不过 kernel 是一个非常非常具体的事情，为了让 RSI 成立，这个事情需要很多的前提条件：

首先它的 reward 要准确且便宜。kernel 就有这个很好的特点——性能和正确性是很好验证的；便宜的话，你基本上硬件跑一次就行了，其实不太需要人工成本。另外，kernel 也是一个作弊方式有限的事情。所以恰恰好，kernel 满足了便宜、可验证、难以作弊这三个条件，有了很好的 reward boundary，所以我们其实可以让这些 kernel development agent 在我们的 boundary 下面去很好地自我提升。

所以说，在有验证器的领域，我认为 RSI 这个 loop 已经在高速运作了。这并不是说模型开始自我进化——我觉得「自我进化」这个词很大——但是在某一个领域、在有限而清晰的边界下完成不断的提升，这一定是可以实现的，而且这正在发生。至于整体上的 RSI，我觉得这还是一个非常久远的挑战。

这其实也体现我的一个观点：我觉得 RSI 缺乏的真的不完全是模型，是 evaluation，是 harness——不管你怎么叫吧，我自己很喜欢把这个东西称作 evaluation。我在读 PhD 期间，很大的一个研究兴趣就是怎么去对模型的能力做有效评估。

这也是很长一段时间里，为什么我们看到 2025 年大家都在用力猛冲 math 和 coding，对吧？因为 math 和 coding 相对而言就是更好评估的。比如说假设晚点的新闻报道，你需要让 agent 去写，这个评估其实很主观，因为一个新闻报道的好坏，我觉得是需要很有水平的记者才能够评估得很好的；但是 coding 的话，至少在那个时候，比如说让它去做 LeetCode 这个事情是很好评估的。

当然随着我们现在 coding 任务的逐渐演进——比如说以前可能是去写一个 LeetCode 题，现在可能你想办法要给一个硕大无比的仓库去做一些新的 feature——这个事情其实也很难评估，所以我觉得现在 coding 的进步会放缓一些。

贵不贵、慢不慢：看单价之外的任务总成本

曼祺

前面讲的是大家用 K3 的一些比较好的反馈，然后我也可以来讲一下一些集中的吐槽吧。

一个是这次大家会注意到，其实 K3 并不像之前的中国模型那样走极致性价比的路线，所以有的人会觉得它比较贵——这也不算一个缺点，就是它是一个特点。

另一方面就是前面也提到的，它目前使用体感上确实比较慢，这也导致有一些下游的公司、比如说应用公司，没有很快地放到自己的产品里面。这个我想请晨阳来分享一下，这个「慢」是什么原因导致的？比如说比较流行的说法是觉得他们算力比较紧张。

赵晨阳

不过其实我自己体感上，我觉得 K3 的价格和速度都是一个合理的区间，甚至在价格上我觉得称得上优秀。然后对比起同系的其他模型，由于架构上的突破吧，我觉得速度还没有达到一个超越其他模型的状态，但是仍旧是一个合理而且可优化的范围。

坦诚来说，我觉得如果我们需要用到 K3，显然是需要完成一些非常高难度的任务；这种情况下，完成单个任务的总成本才是有意义的成本口径。因为在长程的任务里面，不同模型对一个任务的消耗 token 量差距是非常大的，远远大于单价之间的差异——可能一个单价比较便宜的模型会绕一倍甚至 10 倍的弯路，这样的话肯定会让单价更便宜的模型更贵。

还有一个 benchmark 叫做 BrowseComp，在这个 benchmark 上面 K3 拿到了一个非常好的分数，而且单个任务的成本应该也是相当低的，可能还是在其他公司模型的 30%～50% 这个区间。

当然，这个「贵」肯定是对于消费者而言的。对于自己——比如说可能有的听众他的公司比较有计算资源，可能会自己去选择 serve——这个成本其实非常难衡量了，包括我们现在讲到的存储也好、电力也好、水冷也好，这些成本其实很难纳入考量。所以仅仅是靠官方的 API 来看，我认为 K3 的性价比是非常好的。

曼祺

那对比来说的话，V4 输入每百万 token 命中的情况是 0.04（K3 这个是 0.3），输入未命中的情况是 0.44，输出是 0.87。

其实我知道很多应用里面跑得最多的应该还是 V4。当然刚才晨阳也说了，就是说其实你这个东西也是要看——你不是光看那个标价的，是看它做任务的总体消耗。

K3 为什么现在慢？新架构、Serving Stack 与前缀复用

赵晨阳

嗯，可能还有个角度就是说，人类对智能上限的需求是无穷大的，现在的这些应用还没有一个想象空间要用 K3 这种规模的强大模型。

还有一个点，那我们可以来讨论一下这个「慢」的问题。就我的从业经验而言，模型发布后第一时间能够提供的速度，反映的应该说是「这个模型的架构有多新，serving stack 就有多难」。

至于这个架构有多慢，这个事情其实不本质。或者说我觉得对于 Kimi 或者 DeepSeek 这样的顶尖模型团队而言，他们的架构设计早就充分考虑了 serving 和 training 的效率，在后续一段时间，这块的成本是一定可以通过工程优化打下来的。

我们一般在推理这个领域，会把用户的体验分成三个指标：

第一个是首 token 延迟，或者说你发送一个请求之后多快会收到第一句话的返回；第二个是单个用户的解码速度，或者说你已经开始收到模型的回复之后，它两个词中间的间隙有多大；以及还有一个是你的队列等待时间——因为显然并不是你一个人在使用这个模型，可能在 Kimi 他们的后台会同时收到成千上万的请求，整个队列的流通速度是怎么样的。

然后这三者的成因是不完全相同的。我可以分享一下两点，这个也可以解答一下我觉得 Kimi 现在的算力是一个什么样的状况。

我们首先讨论首字延迟。这里主要是一个前缀复用的问题，它不算是一个很严格的算力问题。就像刚才曼祺也提到过，现在模型的价格都是说「前缀如果命中多少多少钱，以及前缀不命中多少多少钱」。

语言模型的推理有一个非常普遍的技术叫做前缀复用。我可以举两个例子：比如说 A 用户发给 Kimi「今天你去超市买香蕉吗？」，然后 B 用户会发「今天你去超市买酸奶吗？」——这两句话其实是有公共前缀的，「今天你去超市买」这几个字就是这两个请求的前缀。这个前缀在现在的大语言模型推理范式、或者说这样的架构下，是可以被复用的公共前缀，不需要在每次推理过程当中都重复计算。

而且在 K3 这个报告当中，其实也有体现他们对前缀复用的看法：一个典型的 coding 场景可能会带有 40 万 token 的前缀是复用的、或者说是非常非常多的用户会共用的，而真正要计算的增量部分可能每次只有 4000 个 token。用户提交的新请求，在前缀命中或者不命中的情况下，所需要的计算量会差出很多个数量级——这也会体现在成本以及用户的返回速度、首 token 延迟这些指标上面。

基本来说，前缀复用决定了首 token 延迟，是最重要的因素，反而绝对的算力是次要的。

OK，当然另一个角度就是：为了支撑 Kimi 这个百万级的夸张上下文长度，K3 选择的 hybrid 架构也让前缀复用的难度有所提高。

因为传统意义上的 KV cache，它术语叫做 append-only，换句话说叫「只增不减」——前方的前缀算完了之后就不会再变了，这个前缀不可能会被其他请求改写。但是 Kimi 采用的这个 attention 架构，我们叫做 Kimi Delta Attention 或者叫 KDA 架构，简单来说，这个 KDA 架构会在前缀树上驻留一块为每一个 token 反复覆盖读写的固定大小的缓存，它不再是以往那样在简单的前缀树上继续往下添加。

举个比方来说，我们通常的前缀树可能是一个只往后写的笔记本，你每次撕一页给别人，然后再继续往后写，它其实会相对简单一些；但是 K3 的这个 attention 架构可能是一个反复擦写的白板，那你写靠前的内容其实难度是很大的。

这块的话，K3 自己的报告里面有讲一些事情，包括他们说把前缀的哈希粒度和物理块的分配粒度做一定程度的解耦，然后试图让哈希只跑在 512 个 token 这样一个小块上，但是 KDA 的 checkpoint 会落在哈希端点的稀疏子集——这个听上去非常 technical 啊。

对，然后我们团队其实也会借鉴以及做一些其他的优化。在 SGLang 上面的话，我们会想办法去让这块反复被读写的状态能够被跨请求安全共享。

举个比方，比如说第一个请求在读一块前缀，第二个请求会稍微改写那个前缀，那么如果这个时候有第三个请求想要去读这块「将会被改写」的前缀，这是有一些安全性需要考虑的：你不可能在别人读的时候直接把这块改了，否则你读出来的内容是崩溃的；而且最糟糕的情况可能是你不可能边写边读，这样你可能前一半是正确的、后一半就是错误的。

这里其实会有很多技术上面的考量。当然具体来说的话，我们会有些很有意思的词语，比如说 copy-on-write、snapshot 还有 donate，这些词都是来自一些操作系统上面的原语。然后这块优化就很深了，欢迎对这方面比较感兴趣的朋友可以参考我们 SGLang 团队的技术博客。

权重一旦开放就收不回；真正的护城河在环境、验证和算力

曼祺

那回到开源这个事本身，包括最近美国的一些讨论，就是是否要限制开源。从技术上来说，开源它有可能被限制吗？开了之后的模型是怎么样的？

赵晨阳

这绝对是不可逆的。有点类似于大家读《三体》，对吧——地球的坐标一旦广播出去，就是不可能收回来的，你没有任何方式去销毁你已经公布出去的物理信息。

开源也是一样的：权重一旦发布之后，它就是一串可以被批量复制的文件。而且开源的情况也不单单只是「下载一份权重」这么简单——社区可能会做非常多的镜像，可能会有些公司拿去做量化，也有的公司会拿去做微调，微调后衍生版本的数量会指数级增长。所以说「下架」这个动作，对于已经开源出去的模型根本就不成立。

曼祺

你们觉得再往下的话，这个开源模型逼近闭源的时候，会不会有人强到一定程度之后走向闭源？

赵晨阳

「开源接近于闭源」的这个时刻，我个人感觉这个事情其实很模糊——开源接近闭源，我们要怎么去衡量这个事情？

因为模型只是整个 AI 生态链上的一小部分。事实上关于模型，这个产业上游可能有数据、硬件，然后下游还有分发渠道，还包括我们说的这些推理。对吧，我的一个观察是：我认为模型本身在 AI 产业链上的比重在下降。

这次 K3 的开源我们也看到了，K3 爽快地开放了权重，包括 MoonEP、还有 Flash KDA、还有 AgentEnv 这些基础设施也都开源了，包括他们之前做的 MuonClip 也开源了。

但是他们的 RL environment 没有开源。他们在报告当中提到了有一个用于自我演化的知识图谱任务系统，这个也没有开源。然后包括他们说这个 K3 其实是一个专家 merge，对吧？他们那些原始专家的 checkpoint 也没有开放。

这个「不开放」并不存在任何问题，因为现在行业内的开源公司也很少会真的去开源比如说 RL environment 这种东西，这东西开放出来也有很多安全风险。但是我觉得没开的这个部分，是这些公司很深的护城河，而且这个护城河一大部分来自于环境。

权重是一次训练的产物，但是环境是能够反复复用、并且产生出下一代权重的流水线。我们得到了 K3 的权重，全世界都可以得到这代模型的智能；但是全世界仍旧没有得到「怎么造出下一代智能模型」的这条流水线。

开放权重只是缩小了顶尖闭源模型和开源模型之间的能力差距，但是我们并不确定顶尖开源模型和顶尖闭源模型之间的迭代速度会不会缩小。比如说，假设国内的模型可能要 6 个月左右才发一版，但是 OpenAI 可能 3 个月就发了——当然我其实不太确定现在国内模型的这个开放速度是怎么样子的。

但是模型迭代的循环是需要环境、需要验证和需要算力的，这三样已经超出了权重。如果这些所有东西都达到一个完全开放的状态，我觉得开源超过闭源就是必然，但是很遗憾现在不是这个样子的。

当然，我们公司主要维护的开源推理引擎也是为开源模型服务的，我们当然更希望开源模型越多越好。对，这是我的一些 point。

曼祺

开源是否逼近闭源本身，这个结论就是打问号的。

对开源有一个大家一直以来认为的弊端：你的用户部署了你的模型之后，比如他自己部署、没有用你官方的 API，你的数据就无法回传给自己。而闭源的生态里，像 OpenAI 和 Anthropic，它通过 API 以及他们自己用户量非常大的应用，可以获得很多真实环境、真实场景里、真实用户的高质量 prompt。

总结而言，你们心中 K3 是一个怎样的成果呀？

曾致远

我个人觉得，从公开发布的模型来看，K3 作为首个达到 3T 级别的开放权重模型，我认为毫不夸张地说是一个里程碑级别的成果。

其实我觉得从历史发展的角度来看，这种开放权重模型的规模从数百亿级别到后来的 1T 以上，再到今天 3T 级别，确实是非常非常振奋人心的一个进展。所以我自己个人是很期待看到后面开放权重模型接着向上 scaling 的。

曼祺

这次 K3 发了之后，我看到 Kimi 的联创周昕宇他在朋友圈有一条分享的转发语，说的是 "have faith in scaling and RL"——对 scaling 和强化学习有信念。

那下面我们来聊 K3 具体的技术报告里一些更细节的技术改进，这个是 7 月 27 号刚发出来的。可以先说一下 K3 在架构上的整体思路是什么、亮点是什么。

架构总览：让信息沿序列与深度更高效流动

曾致远

我自己理解 K3 架构的整体思路呢，就是他们想同时把语言模型在处理信息时、信息在不同方向上的流动做得更加高效。

比如说在序列上，他用 KDA 和 MLA 这样一个 hybrid attention（混合注意力）的结构：在大部分层里更低成本地去处理上下文，同时周期性地保留全局的 attention。在深度上呢，比如说用了 Attention Residuals 这样一个技术，让后面的层可以去选择性地读取前面层的表示。

如果让我挑一个我比较关注的亮点的话，我觉得 NoPE 是很有意思的一个 technique。具体来说，K3 这个语言模型没有使用显式的位置编码（positional encoding）。

至少从公开的 technical report 来看呢，像同期的 DeepSeek V4、GLM-5.2，包括像 MiniMax M3 这些，其实后面这些模型都还是保留了 partial RoPE 的，所以这个选择我觉得是比较 special 的。

当然了，这里就是说模型不用位置编码，模型其实还是知道 token 的先后顺序的。具体来说呢，它在 KDA、也就是 Kimi Delta Attention 里面，在做 recurrent state 更新的时候，以及包括里面的一些 gating 和 decay 机制，本身其实就是对顺序敏感的，已经隐式地编码了顺序和 recency（近因）这样的信息。

这里还有一点需要提一下：我们现在去训练一个长上下文的模型，比如说这种达到百万级长上下文的模型，一个常见的做法叫做 progressive context extension，K3 其实也是这么做的。具体来说，比如说我们在 pre-training 的时候先训 8K，然后再扩到 64K，然后在后面的阶段再逐渐扩到 256K，然后直接达到 one million 这种级别。

然后我们前面说的这种 NoPE、就是不使用显式位置编码的一个直接好处就是：我们再去扩展 context 的时候，对于位置编码这一层就少了一个需要单独处理的环节。比如说如果你用 RoPE 的话，你可能就要去 retune 一下 RoPE 的 base，或者去做 RoPE interpolation 这样的 technique。

NoPE 这个选择其实也不是 K3 首创的，Kimi Linear 其实也已经采用过了。K3 我觉得比较、或者说非常 impressive 的一点，就是它把这整套设计 scale 到了 3T 的级别，并且成功支持到达 one million context、就是百万上下文的长上下文。

曼祺

嗯，对。Kimi Linear 是他去年下半年发的一个参数比较小的模型，我觉得他当时就是在试一些 K3 里面可能会用到的新技术，包括 KDA——就是我们前面提到的 Kimi Delta Attention，就 Kimi 的线性和全局混合的这种注意力方式，K3 也用了，也是在 Kimi Linear 里面提出来的。

其实 RoPE 最开始是苏剑林提的，这个我觉得也挺有意思的。就像我们之前聊 V4 的时候，其实后来 V4 就没有用 MLA 了嘛——这个也是 DeepSeek 给业界的一个挺重要的贡献。

Quantile Balancing：近千个专家如何保持负载均衡

曼祺

然后苏剑林也是 Kimi 的一个很核心的研究员。因为这次 K3 它还是一个 MoE、就是这种混合专家模型嘛，那里面比较重要的一个东西就是路由专家的分配。这次 K3 提了一个 Quantile Balancing（分位数路由均衡），是他们在路由策略上的一个创新。

这个也想请致远来说一说，它解决了一个什么问题。因为 Kimi 自己是说，他解决了 MoE 这种模型在大规模训练的时候会崩溃的一些问题。你可以讲讲为什么以前的方法比较容易崩，那这个改进是 K3 可以训到接近 3T 的关键之一吗？

曾致远

对。上面提到它可能会崩溃的这个脆弱超参数呢，我其实觉得本质的问题是专家负载均衡（expert load balancing）这样一个问题。

具体来说，我们 MoE 这样一个混合专家模型，它里面的每个 token 每次只会去选择一部分 routed experts 去激活，然后我们其实希望从全局来看，各个专家被选中的频率是大致相当的。

那否则会有什么问题呢？在模型层面，一些专家如果得不到足够的 token 和梯度，训练的时候就不太充分，没有办法充分发挥它这些参数的容量；而且还有一些问题是，比如说另外有一些专家如果收到的 token 太多了，那其实对 Infra 也不是一件特别友好的事情。

针对这个问题，最早期的一个普遍做法是：在 MoE 模型训练的 loss function 里面去加一个 auxiliary load balancing loss。它的核心思想就是说，我们用一个额外的 loss term 去鼓励不同专家的选中频率更加均匀。

这个方法整体来说还是比较有效的。但是你加这个 balance loss，你就 somehow 需要在模型质量和负载均衡效果之间去做一个权衡；那如果有这么一个问题的话，它经常可能会是训练不稳定的罪魁祸首。

然后之前 DeepSeek V3 的一个重要改进呢，就是把上面说的这种「添加一个 loss」的方式去掉，换成了一种 bias update 的方法。

具体来说，我们在选 expert 的时候，其实是用一个神经网络、一个 router 去打一些 routing score，打了这些分数之后再根据分数去选 expert。那我们给这个 routing score 去加一个 bias，然后在训练过程中去看：如果一个专家过热，我们就把 bias 调低；如果它过冷了（说白了就是接收到的 token 太少了），我们就调高。这个 bias 只影响选专家时候的机制，所以我们就不需要一个额外的 loss 去改变训练目标。

但是 V3 这一类的方法，它对 bias 的更新是固定步长的——相当于你每次加个 bias 或者减个 bias，是加一个常数或者减一个常数。那所以每一步我们就只知道这个专家是「更加被频繁地选中了」（说白了就是过热了）还是「过冷了」，然后按照一个固定的步长去向上或者向下做一点调整。所以这里仍然需要去调步长这么一个超参。

所以这次 K3 提出的 Quantile Balancing 的做法呢，它其实就会直接用 routing 分数的分布来估计「我们应该做多少调整」。

比如说在 K3 里面，它的 setup 大概是说：我们每个 token 要在 896 个 routed experts 里面去选择 16 个。

然后我们的做法大概就是：我们先去看当前这个 token，它加上当前的 bias 以后，排在第 17 名的那个分数——这个分数我们就可以把它当成「进入前 16 名的门槛」，就是分数最高的 16 个是最后被选中的那些 experts。然后对于某一个 expert，我们其实就可以观察它在整个 batch 里面距离每个 token 的门槛还差多少。

什么意思呢？就比如说我们直观地想：我们现在对一个 expert，在 routing 打分上如果给它加的 bias 越大，那是不是就意味着它能够跨过门槛的 token 就越来越多？所以我们就可以根据这些差值的这么一个——你可以说叫 quantile（分位数）吧——直接去算出一个新的 bias，使得相对于当前的这批门槛，我们大概会有 16 除以 896 这样一个均衡比例的 token 会选择这个 expert。

这个新的 bias 呢，我们就在现在这个 step 算一下，然后从下一个 step 开始使用。这样我们就也不需要像前面说的 DeepSeek 那样的做法——需要有一个固定更新步长的超参数。

所以我觉得对于 K3 来说，它主体的 expert 有快将近 1000 个了，然后每次我们还只选择 16 个的话，这其实是非常非常极端稀疏的。那确实可以猜想，我们想要稳定、而且有效、快速地保持这样的负载均衡会变得更加困难。所以我个人猜想，它确实应该是 K3 这次能够成功 scale 到 3T 级别的一个比较重要的因素之一。

曼祺

是不是在 V3 里那个路由的改进，它更多是知道我一个专家的性质，对吧——就是你说的过冷过热，但没有那么精细到量；然后 K3 里的这个改进，它是更精细到量的，就是我知道它比如说过热到什么程度，或者过冷到什么程度。

曾致远

对对对。我觉得这个也是设计的时候思路不太一样吧：像当时 DeepSeek 的思路更像是一种「逐步调整」的思路；然后到了像 K3 的时候，它的思路更像是「我直接用历史信息去估计一下这个 bias 多少比较合理，然后下一步直接加上这个 bias 就行了」，就不再去做一步一步的逐步调整。

我个人觉得两种也确实各有优劣，我觉得最后说白了就是实验跑出来哪个效果好，就用哪个。

KDA ＋ MLA：线性注意力与全局注意力并非二选一

曼祺

嗯，那我们接下来讨论一下它具体的模块。其实你会发现这些模块和我们当时讨论 V4 也是相似的，包括它的注意力，包括残差，包括优化器等等。

我们可以先从注意力开始。这个前面也已经多次提到了，就是这一次 K3 使用了 KDA 这种 Kimi 自己之前提出来的新的注意力方式。那 V4 的话，它其实是一个三种注意力的混合，总体是稀疏注意力优化的方向；K3 这一次是 KDA、Kimi Delta Attention，它是线性注意力和全局注意力混合的一种方式。

之前在 143 期的节目里面，我们也和 DeltaNet 的核心作者之一杨松琳专门聊过线性注意力的模型，那大家想去了解一些背景的话，也可以去听之前的节目。

我觉得 K3 这次直接在这么大的规模上用了线性注意力，应该来说还是一个比较大的、或者说比较激进的改进。它的好处是效率的提升很明显，但一般来说大家会认为线性注意力在效果和性能上会有一些损失。

致远你可以来讲讲，K3 这次用的这个 KDA 是一个什么样的改进、给业界的启发是什么？它是怎么去平衡以前大家会认为的、使用线性注意力的一些弊端？

曾致远

对，我个人觉得这是一个比较大的进展。

K3 的路线就像刚刚说的那样：让大部分层去使用一个更高效的 linear attention，也就是 KDA，然后同时周期性地保留 Gated MLA——Gated MLA 用来提供对所有历史 token 的直接的、全局的 attention。最后相当于把接近 3/4 的 attention layer 都换成了 KDA，也就是一种 linear attention 的实现，而且最后做出了一个非常 frontier level 的模型。

这套混合架构本身，其实之前 Kimi 也已经验过了，但当时它的模型总参数大概只有 48B–50B 这种级别。那 K3 就相当于直接把它放大到了接近 3T，也就是说总参数规模接近放大了 60 倍——这其实是一个非常非常大的进展。

其实比如说之前的 Qwen3.5，它是一个大概 400B 的模型，它其实同样也采用了「3 层 Gated DeltaNet 再配一层 Gated Attention」这样一种 3:1 的设计。那 K3 就进一步把这种「以 linear attention 为主、周期性地保留 global attention」的 hybrid attention 架构，直接 scale 到了接近 3T 这么一个相当大的级别。

这里其实值得一提的是，像 DeepSeek V4 走的是另一条路线：它没有去使用 linear attention，而是仍然在 softmax attention、就是正常 attention 的框架里面，通过 KV compression 以及 sparse attention 这样的 hybrid 来提升上下文的效率。这是不太一样的一条路线。

所以我觉得这次 K3 带给我、以及包括很多人的启发，可能就是：我们其实并不需要把 full attention 和 linear attention 理解成一个二选一的关系，hybrid attention 确实是一个很有前景的方向。

简单来说就是不同的 attention 承担不同功能：比如说大部分层我们追求效率，少部分层我们保留一个高容量的全局 attention、保留这种 global interaction。其实 K3 这次已经有效证明了，这套方案是完全可以 scale 到接近 3T 这样一个非常非常 frontier 的 scale 的。

曼祺

嗯，我想补充问一下：他现在 3:1 的这个混合比例——3 层线性注意力混一个全局注意力——是怎么决定的呀？

去年我和松琳聊线性注意力的时候，因为其实实际上大家用的线性注意力一般都是要混全局注意力的，她当时跟我说这个怎么混主要是靠经验、是实验出来的。那现在有了更多的理论方法、或者说总结出来的规律来指导怎么去混合吗？

曾致远

从公开的资料来看，这个比例的决定本质上应该还是靠 empirical，就是靠做实验。

之前 Kimi Linear 他们专门在一个 16 层的小模型上——就是上面提到的这个 48B 的模型——比较了不同的配比，他们当时的一个结论是 3:1 在验证集上面效果是最好的，就是那个 perplexity 指标它是最好的。1:1 的时候基本一样，但是 full attention 更多，推理成本也就越高。

所以 K3 基本上就沿用了这个 3:1 的比例，然后最后再去额外加一层 Gated MLA，保证我们整个模型结构的最后一层一定是一个 global 的 attention。

曼祺

你说 1:1 是一样的，就是说效果是一样好的？

曾致远

对对，效果更接近，但是因为 full attention 更多，所以相当于它效率就更低。

嗯，所以像 K3 的 report，他们其实也没有说在接近 3T 的规模上重新去扫描过各种比例——毕竟可以想象这肯定非常非常贵。

一般来说的话呢，在模型训练的团队里面，这种特别特别昂贵的 ablation study，尤其是 architecture ablation study，都会先在小模型上做，然后再沿着 scaling law 去验证整套的 architecture、包括这种 recipe 能不能稳定地放大。

K3 确实也做了一些整体的 scale out study，但是它主要验证的还是整套 K3 的 recipe，而不是说我们把每个细节拿出来。所以 3:1 到了 3T 它不一定说百分之百就是最优解，但是它目前作为整体设计的一部分，我们看结果，它已经很成功地 scale 了上去。

线性注意力下，百万上下文如何缓解遗忘

曼祺

接下来的一个问题就是说，因为 K3 是一个百万上下文的模型，上文非常长，它在这么长的上下文里面是怎么去解决以前线性注意力可能会有的「遗忘」问题的？

曾致远

这也是一个非常好的问题。我们先要把「遗忘」这一点说得更准确一点。

linear attention 的设计上，一般来说大家会认为是一个 trade-off：它会把任意长的历史压进一个固定大小的 recurrent state——比如说在 K3 里面对于 KDA 层来说。那这里好处就是说，cache 和每一步的计算不会随着上下文一直增长；代价呢就是说，不同的信息会在有限的状态里面互相干扰，就会导致特别早的、尤其是那些特别细节的信息可能会被覆盖掉。

所以问题的根源其实在于：这里的 compression 因为是固定 state 的，它本身就会存在容量瓶颈。

当然了，KDA 作为 linear attention 的一个 variant，它用的一些 technique 把这件事情做得更聪明了。比如说他们用的像 delta rule、像 channel-wise forget gate 这样的技术——简单来说，它每次可能先看 memory 已经预测出了什么，然后我们只去写它在预测时候的那个偏差；然后同时呢，不同的 channel 可以学到不同的保留时间。

除此以外，比如说 K3 他们还给每一步的 retention factor 加了一个 lower bound——这个其实在 tech report 的 Figure 3 那里有一些分析，感兴趣的朋友可以自己看看。简单来说，它直觉上也可以去限制过于激进的瞬时遗忘。

但我觉得，上面说了这么多 KDA 特别聪明的一些设计，我觉得它更多还是「更好地管理这种有限 memory」的手段，并不会从根本上消除上面说的容量瓶颈问题。说白了就是，你在计算的时候多步累积之下，信息还是会衰减。

所以我个人感觉，K3 解决百万上下文级别的遗忘问题，真正的答案还是因为做了这个 hybrid 的结构。

就像我们前面说那样，每 3 层 KDA 会加入一层 Gated MLA，最后一层也一定是一个 MLA。那 MLA 是这种 global attention，它会保留对所有历史 token 的 global interaction，所以模型其实并不需要 KDA 把这上百万级别的 token 每个细节都压在它的 recurrent state 里面——上面说的那其实也很困难。但是因为有这个 MLA、MLA 提供了这种全局的 attention 机制，所以我觉得它应该是缓解遗忘非常关键的一点。

曼祺

其实像比较早的时候，MiniMax 的 M1——那很早了，25 年年初的时候——他们也做了这种混合的方式，后来他们又换回了 full attention。就思路是一样的。

曾致远

然后效果不一样。

我个人觉得很多时候，做很多事情的关键主要还在 execution、就是在执行上。有东西能 work、不能 work，不代表这个技术路线本身 make sense 还是不 make sense——它可能就是具体实现的时候，比如数据不一样啊、Infra 不一样啊，做这个事情有很多小的细节不一样，最后可能就都很不一样。

线性注意力给推理系统带来的工程变化

曼祺

注意力结构的变化，它也会带来一些 Infra 上的变化。晨阳正好可以 call back——像我们上次在讨论 V4 的时候，也讨论了稀疏注意力和线性注意力这两种改进方式，你当时提到说你觉得线性注意力的理论优势可能要再等几代真实的大模型的验证。

那可以说 K3 现在其实已经验证了线性注意力的一些理论优势吗？包括这种新的注意力结构，它会给 Infra 带来的影响和变化是什么呀？

赵晨阳

我觉得我之前的判断还是很有道理的吧。我可以诚实地更新一下我的判断，也欢迎大家去听之前我们在晚点的 podcast 里面讨论 DeepSeek V4 的那期节目。

我当时提到的两件事情：第一，线性注意力的理论优势是需要几代真实的大模型来做验证的；第二，稀疏路线在工程上面更可控，和现有的 KV cache、prefix cache 这些基础设施的兼容性更好。

首先说 K3 对于线性注意力这个路线的验证。实际上每次有新的大模型发布，我的朋友圈都会围绕着「线性注意力还是稀疏注意力」吵成一片，甚至我觉得——

曼祺

非常的割裂。

赵晨阳

无论是做 Infra 还是做算法，都是这个感受吧。

K3 的话，毫无疑问是对线性注意力的一个有效证明：一个 2.8T 的主线模型，而且是百万 token，并且使用的是 NoPE。然后 K3 的 MLA 层完全不用加位置编码，位置信息就全靠 KDA 的递推门控还有衰减来提供。这样的话，它扩展到百万 token 的时候，不太需要重调类似于 RoPE 的这些频率、底座等等，也不太需要像 YaRN 一样专门去做插值，外推起来是非常自然流畅的。这个设计和效果当然是非常好的。

然后第二点，我说这个稀疏注意力在工程上面会轻松一些——这个看法也没错。

这段时间我们 SGLang 团队也花了很大的精力，去尝试把线性注意力需要的 recurrent state 也纳入到已有的 prefix cache 体系当中，就让 K3 这种 hybrid KDA + MLA 模型的前缀复用能够达到和全注意力模型一样的通用性。

长期来看，线性注意力和稀疏注意力的「兼容性差」这件事情，可以逐渐被工程弥补——当然代价就是我们的抽象会比以前更复杂一些，对吧？

另一个角度说，这个线性和稀疏也不是一个二分的问题。K3 选择一个 3:1 的混合，每个 block 三层 KDA 加上一层 Gated MLA，然后 overall 这个 backbone 最后还会有一层额外的 MLA：线性的部分是靠 KDA 来提供位置敏感的序列建模，全局的部分就是靠 MLA 来提供不受限的内容交互。这样体现出来的模型也非常强大。

然后异构的模型架构对于我们 SGLang 推理框架而言，需要持续性地同时维护好多种形态和生命周期的 attention 抽象架构，这是一个巨大的工程考验，这也是我们团队工程能力的体现。

不严谨来说：在同样的模型规模下，线性注意力为主的混合架构比起传统的全注意力架构，在 100 万 token 这个上下文量级，混合架构生成 token 的速度是全注意力架构的 6.3 倍。

6.3 倍是一个非常可观乃至令人惊讶的数字，我可以简单解释一下。

模型的 decode 阶段，每吐一个 token 都必须要把整个请求的全部历史上下文读一遍。

全注意力架构的「历史」是整个 KV cache，它是跟着上下文长度线性变长的——100 万 token 的 KV cache 长度近乎是 1 万个 token 的 100 倍；上下文越长，越靠后的 token 开销越大。

然后线性注意力则试图把请求的历史信息压缩到一个固定的 recurrent state 当中——100 万 token 和 1000 token，它们的线性注意力 recurrent state 几乎是一样大的。

69 层的 KDA 给一个请求分配的历史信息大小，基本就固定在 54 MB，不论长短。

然后这 24 层的 MLA 是全局注意力，它会为每一个 token 额外分配 27 KB——那么一个百万上下文长度的请求，在 MLA 上的开销大概就是 27 GB。

听上去是一个「54 MB 加上 27 GB」的组合。但是如果先前的 69 层也是全注意力，那就不是 54 MB 了，而是额外的几十 GB。

然后最后一个问题就是：什么情况下这个 6.3 倍的体现是最明显的？毫无疑问是长的 agentic coding。如果每一个 agentic coding 请求都消耗上百 GB 的 KV cache 的话，最强大的 HBM 缓存也撑不住几十个请求。

Attention Residuals：让深层模型选择性读取浅层信息

曼祺

除了 KDA 这个新的注意力机制之外，这次 K3 的另一个新东西是 Attention Residuals。这也是之前他们发的成果，是今年春天的时候发的，然后当时马斯克还转发过。我觉得它用到 K3 上的速度是非常快的。

这个我也可以补充一个我了解到的信息：其实在做 Attention Residuals 的时候，差不多就是 K3 定版的同期。所以当时「要不要直接把这个东西放到 K3 上，还是说再放到下一代的模型上」，其实他们内部是有一些讨论的，后来杨植麟也是拍板做了这个决策，就直接放到 K3 上了——它是很快就进到一个主线模型上的成果。

正好我们上次讨论 V4 的 mHC 的时候，也讨论到了 Kimi 的这个 Attention Residuals 是有一些异曲同工的作用，想追求的效果是一致的。想先请致远和大家简单介绍一下：Attention Residuals 是一个什么东西，它的作用是什么，它是在模型里的哪一个模块、或者哪一层发挥作用？

曾致远

我觉得 Attention Residuals 解决的主要是模型在深度方向、就是从浅到深方向的信息流。

最早的时候，最标准的 residual connection 在展开以后，当前 layer 看到的本质上是 embedding、以及之前所有比它浅的 layer 的 output 的直接相加，而且这里每一项的权重本质上就相当于都固定为 1、直接加起来。

那其实随着模型越来越深，这种 residual stream 的大小就会不断不断地增长。那导致什么问题呢？你每次新来一个 layer，新写进去的信息其实就会被逐渐稀释掉；而且同时，对于更深的 layer 来看，它没有一个直接的机制去说「我现在更需要前面哪一层、哪些层的 representation」。

那 Attention Residuals 这个 idea 非常非常直观：我们把正常的 attention 旋转 90 度。简单来说，正常的 attention 你是在 token 之间去算匹配的分数然后做选择；那 Attention Residuals 就是在 layer 之间做选择。

曼祺

层之间。

曾致远

对对对，就是会在层之间做选择。

每层各自会有一个可以学习的 query，这个 query 在所有 token 之间都会共享，然后这时候它会和当前 token 在不同深度的 representation 做一个匹配，再通过像 softmax 这样去决定应该从哪些更浅、就是更靠前的层里面去读取信息。

当然这里虽然 query 本身是固定的参数，但是不同 token 在各层的 representation 是不一样的，所以最后它的 attention 权重还是会随着 token 内容变化而变化。对，这主要就是 Attention Residuals 的原理。

曼祺

之前其实 V4 那期有聊到过，mHC 和 Attention Residuals 想追求的效果是相似的嘛——就是你最开始前面也提到了，K3 的整体思路也是把信息在不同方向的流动都做得更有效率，Attention Residuals 解决的就是你刚刚说的层之间的信息流动。

那回到这两种方法上，致远你觉得它有哪个潜力更高的这种区别吗？

曾致远

首先，他们这两种方法肯定还是想解决同一个大问题：就是上面也提到了，你标准的 residual connection 在深度方向的信息流太单一了。

当然这两种方法解决的思路就非常不一样。这里我可以大概说一下非常宏观的、很直接的一个 idea：

mHC 的做法，大概就是我们会维护多条并行的 residual stream（之前就一条），那每一层我们会先动态地把这些 stream 混合成这一层的输入，然后再把这一层的输出分发回不同的 stream。同时这里还有一些设计上的细节，比如说他们会对 residual mixing 加上一些约束，去保证信息、gradient 这样的东西在模型变深以后不会被无限制地放大。

然后 Attention Residuals 就像我们刚刚说的那样，它更像是——你可以说，更像是每一层我们去提供了一个「历史目录」的信息，这样的话它可以直接去找前面某个阶段产生的信息，然后选择性地把它挑回来使用。

我个人感觉呢：如果你只讨论架构的表达能力、只看理论上的上界的话，那可能说 Attention Residuals 的上限更高，这个是 make sense 的。

毕竟你想，mHC 刚刚说的这种原理，它最终说白了还是把所有的历史信息都递归地压缩在一个固定数量的 residual stream 里面；那 Attention Residuals 呢，它其实就有一点点像在每个 token 上，我们对于所有比自己更浅的那些层的输出，形成一个深度方向的下三角 attention map。

所以我做一个很不恰当、但是形象的比喻：它就有点像我们在层的深度方向上，一个是 recurrent model，一个是 softmax attention。那 mHC 的信息要通过固定大小的 state 一层层传递，有点像 linear attention，对吧；那 Attention Residuals 就可以直接去跨层读取。那从表达力的角度，那肯定是后者还会更高一点。

曼祺

你刚那个比喻的意思就是说，它在层的角度，一个是 RNN，对吧，一个是 Transformer。

曾致远

对对对对对。就是 linear attention 其实也是 RNN 的变体嘛。

但如果说我们想讨论最终的实际效果的话，那我觉得还是要看大家具体 situation 的细节。

比如说像 K3，它其实用的也不是刚刚说的那种完全 global、所有层之间都能互相有 attention 的结构，它做的其实是一种叫做 block attention 的 technique——它不是理论上表达能力最完整的那种 full attention。比如说它会先把层分成很多 block，先把每一个 block 里面的层的输出汇总，然后在 block 和 block 之间做 attention。

曼祺

我想到这个有点就像稀疏注意力了。

曾致远

Yeah, in some sense yes。

对。然后再比如说，Attention Residuals 其实需要保留更多的历史 representation，这里也会带来一些像显存和 communication 的成本；然后 mHC 其实也有一些自己 Infra 上的问题。所以我觉得最终的效果肯定要看其中的细节。

当然了，我觉得目前你可以确定的是：K3 和 V4 已经分别证明了这两种路线其实都可以 scale 到非常 frontier 的级别。所以未来到底哪一种路线会更有潜力、或者说能做到更好的效果，我觉得其实还是很拭目以待的。

曼祺

嗯，对。我觉得前面讨论很多东西，它是对比着来看的嘛，包括前面说线性和稀疏注意力这些。就你能看到有一个趋势好像是「条条大路通罗马」——大家本身会有不同的实现方式，但大家看到的问题是相似的，就是说行业里大家看到的瓶颈、或者要解决的东西是相似的。

Per-head Muon 与大规模训练稳定性

曼祺

下一个话题是优化器。和 V4 一样，这次 K3 里用的也是 Muon 优化器。而且 Muon 这个优化器之所以能被比较规模化地使用，其实本身也是 Kimi 自己更早时候的一个成果——MuonClip，然后他也把这个成果贡献给了业界，基本上是现在比较主流的一个优化器方法。

然后这次在 K3 里面，他们自己又有更进一步的改进，是提出了 Per-head Muon。这个想请致远可以再帮大家讲一讲：一个是说优化器为什么比较重要，它核心解决模型的什么问题；另一个就是 K3 这一次使用的 Per-head Muon，相比于之前 K2 已经在用的 Muon，具体的改进是什么。

曾致远

对。优化器相当于是模型训练——不止语言模型训练，就深度学习模型训练里面——非常重要的一个组件。

它解决的核心问题说白了就是：我们现在有个模型，在训练过程中我们的 batch 算出一个梯度之后，怎么把这些梯度转换成一次非常稳定、而且有效、而且从长远来看比较好的参数更新。

比如说我们在训练一个模型的时候，我们会涉及到 loss function，这说白了就是我们要优化的东西；然后梯度告诉你局部大概要往哪里走；那优化器就会决定最终要采用什么方向、走多大一步，然后我们怎么去利用一些历史的梯度去降低噪声、去处理不同方向的尺度差异、去处理不同方向的各种冲突等等这些信息。

那一个好的优化器，通常意味着在相同的训练计算量下，我们可以收敛得更快，最终的 loss 更低；而且还有一个很重要的就是稳定性——我们不希望在训练过程中出现太多不稳定的 loss spike。

Muon 本身的核心是说：我们拿 momentum（就是动量，是优化器里面根据梯度和历史梯度算出来的一些信息）去更新参数之前，先把它做一个近似的正交化。这样的好处就是，让更新不要只集中在少数几个比较 dominant 的方向上。

问题是，正常的那个 Muon——你考虑，以前我们的多头 attention 在存储上虽然是一个大的投影矩阵，但是在整个算法的计算逻辑上、就是对于模型架构来说，每个 head 是比较独立的。所以意味着，如果你现在把所有的 head 都放在一起正交化的话，那它们的 gradient、包括 momentum 这些信息，somehow 会有一些冲突：比如说有的 scale 更大的 head 可能就会主导整个矩阵的更新方向，而 scale 比较小的注意力头可能就没有办法被充分地 normalization。

所以 Per-head 的核心思想就是：对于每一个注意力头，我们都去单独做一次 normalization，这就意味着不同的注意力头在做更新的时候，它们的大小、它们的 scale 就更加均衡了。

所以 K3 报告里面也专门提了，他们发现 Per-head Muon 在他们的 setup 下可以让 training dynamics 更加平衡，能够很好地改善大规模训练的稳定性。

曼祺

嗯。相比 MuonClip、就是 Kimi 自己之前提的这个改进，新的这个 Per-head Muon 实现起来的难度会更大吗？我想知道它有可能在业界怎么扩散——因为 MuonClip 其实在业界还是有挺多扩散的，很多别的团队也会用。

曾致远

我觉得从实现难度角度说的话，Per-head Muon 算法上基本上就是我们直接去 reshape 成很多注意力头的 block，然后做一些并行处理，所以算法本身还是挺直接的。

我觉得实现的难点——一个难点可能是：我们在大规模的训练里面，像这些 QKV 经常被融合以及切分，这就导致优化器的 state 会分散在不同的 GPU rank 上。所以我们必须要保证每个注意力头在算法计算上的逻辑边界不会被打散，同时又能够非常高效地重建完整的 block；然后还要把大量的小矩阵合并执行、在一起做一些计算，避免带来非常大的通信开销，避免一些 kernel 上的问题。

嗯，所以我觉得像 K3 也在 tech report 里面提到说，他们为此也做了一些专门的处理，比如说把通信和正交化计算做了一些 pipeline。

曾致远

可以请致远分享一下：为什么他不直接联合训练一个，要先分后合？

曼祺

曾致远

曼祺

曾致远

这样的话，大家不需要为了方便最后的 joint training 就提前把所有的 recipe 和 Infra 都强行统一——那可能会导致你在做自己领域的时候非常束手束脚；然后我们也不需要在每次迭代的时候去同时协调所有的领域，这样你就能让迭代变得非常快；还有就是最后合版的时候，我们不需要花特别特别大的力气去协调各个方面。

曼祺

所以以前它也是分开训练的，现在也是分开的，只是「合」的方式不太一样：以前是一个更完整的合，就是你得带着各种训练设置一起来合；现在是每个专家训完之后，我最后只合那个结果，对吧？

曾致远

以前那样的 RL 训练还没有那么麻烦，对吧？比如说最早的时候我们不需要做 agent 的 RL，那也不需要——Infra 可能相对来说也比较统一，大家只需要把数据贡献出来，然后直接一合就可以了。

但现在各个方面、他们的 recipe，不同领域就会复杂很多，他们都有自己的 recipe，所以我们只合模型的话就会方便很多。

曼祺

嗯，它在直觉上好像给人一种跟预训练的趋势有些相反的特点。因为预训练其实你是在同一个模式里面吃了非常多元的数据，对吧，你就是放在一个过程里去训的；然后后训练，按你刚才的描述，其实是之前后训练要处理的下游任务比较单一或者简单的时候，大家其实是在一起训的。

那现在你能看到它是一个好像在走向分的过程，比如 K3 这次有 9 个分开的。它为什么是这样一个过程？以及你觉得更远来说，后训练这个阶段有必要又变成一个「合」的过程吗？那样的话它会潜力更高吗？

曾致远

「合起来」还是 MOPD 哪个潜力更高，这个不好说。

有很多的研究他们会说，可能做 MOPD 比直接做那种 joint 的 RL 效果要更好之类的。但是我觉得这种结果吧，你都要看它非常非常具体的实验 setup，才能说这个结果到底有多 generalize。

我觉得目前做 MOPD，主要还是说白了就是这样最方便：你不用像我刚刚说的那样，每个团队有一个自己的方案之后你还要去合方案；而我们是合最后的那个模型就行。就相当于说白了，合 recipe 很麻烦，但是合模型、用 MOPD 就很简单，然后大家就专心地把自己的模型做好就行。

蒸馏的纯技术定义、on-policy 蒸馏与 off-policy 蒸馏的区别

曼祺

然后 MOPD 里，它英文的最后一个 D 是代表 distillation，翻译过来就是蒸馏。我觉得正好也可以说下：本来「蒸馏」的意思是什么——因为现在关于蒸馏有很多讨论——那实际上它从技术上来说是怎么一回事呢？

曾致远

对。蒸馏从技术的最原始定义来说，它 always 都是去把教师模型的能力传递给一个学生模型。

它最经典的用法其实就是去压缩模型：比如说你先训练一个很大的教师模型，然后我们再把能力蒸馏到一个更小的学生模型，这样你可能用学生模型就更便宜一些，对吧？就比如说在知识蒸馏这一块，有的技术报告里面就说了，我们会做这种 strong-to-weak distillation——就是先去获得一个强大的模型，然后再用它们去帮助训练小模型。

所以从技术的角度，它 always 都是「教师模型去传递给学生模型能力」。但是我们更多要看它的目的是什么。

比如说在 MOPD 这里的目的不是说去压缩模型，而是我们刚刚说的「合版」：我们先从同一个 foundation 模型出发，训练出不同 domain、以及不同 reasoning effort 的教师模型，然后最后再把它们的能力传回一个统一的学生模型里面。这是目的这一方面。

然后另一方面，就是我们这个蒸馏具体怎么实现。从具体的算法角度：

on-policy distillation 做的事情是：让学生模型自己去生成一个轨迹，然后教师模型再对这个轨迹去打分，提供一种比较稠密的奖励信号，然后用这个奖励信号来提升学生。

然后另外一种也很常见、或者说更传统一点的蒸馏模式——也就是刚刚曼祺提到的，普通大众在社交媒体上讨论的那种蒸馏——一般是说我们这个老师先去预先生成一批固定的答案，然后学生就直接在这个固定的、离线的数据上直接去模仿学习，去学习老师模型在这个输入下的输出是什么。

曼祺

这里 MOPD 使用的是 on-policy 的蒸馏，和你说的、我们平时讨论的语境里面更常提到的那种蒸馏——它是 off-policy 的蒸馏。这个 on-policy 和 off-policy 的区别是什么样？

曾致远

更多指的还是算法层面的区别。

对对对。比如说 on-policy，学生是被训练的模型，训练过程中学生自己亲自去生成这个轨迹，所以我们说它是 on-policy 的。off-policy 指的是相对于学生来说，老师的这个轨迹是 off-policy 的——就是老师的轨迹不是学生自己生成的。

曼祺

哪一种它的学习效率会更高呀？

曾致远

这个其实也是不同的场景下有不同的经验性结果吧。

比如说在做合版的时候，肯定是 on-policy distillation 这种做法比 off-policy 更好。但如果只有教师模型的输出，你没法拿到它的权重、logits 这些的话，其实你没法做到「像教师模型去给学生模型细致地打分」，那你就只能去做 off-policy 的 distillation——相当于只能拿到它的最终输出。

曼祺

假如说比如 Anthropic 他自己有自己的模型权重，对吧？比如他自己蒸自己的话，从技术的效果上来说，你觉得他大概率是 on-policy 还是 off-policy？

曾致远

你说这里「自己蒸自己」的目的是啥呀？

曼祺

是为了变成一个更强的模型。就大家说的左脚踩右脚，然后自己原地飞升这种。

曾致远

这个感觉目前还是大家的愿景吧，就是还没有真的做到。

我个人理解，主要还是看这个 external、这种外在的监督信号它有没有。我觉得你很难在没有一个很本质、很 scalable 的外在监督信号的情况下去提升一个模型。也就可能是说，你最后用的这个技术里面它的名字可能带了个 distillation，但它肯定是找到了一种很 scalable 的方式，能够稳定地把外在的监督信号给打进来的这个过程。

KDA 结构下，投机采样回退机制的变化

曼祺

那最后在 Infra 的层面，想请晨阳来分享一下：你觉得 K3 做 Infra 改进的整体思路是什么？因为你们这次 K3 也是第一时间做了适配，你可以讲讲你们适配的时候有什么有意思的发现吗？

赵晨阳

具体来说的话，我可以分享一下 KDA 架构对于投机采样带来的挑战。

投机采样简单来说，就是我们会通过一个小的模型来快速猜测出一批 token，然后让真正采样的大模型来一口气验证这些 token 是否正确。验证完成后，这批被猜测出的 token 当中，可能只有前几个会被大模型接受。所以大模型在验证这批被猜测的 token 之前的状态是需要保留的——因为如果猜测不对的话，大模型要能够随时回退到猜测之前的那个状态。

这对于普通的 attention 而言问题不大，就像举的比方：你无非就是把书的后几页撕了，然后继续从笔记本靠后的页开始写，对吧？

但是 KDA 的架构设计需要能够对每个 token 的递推状态进行原地重写。为了能够回退到大模型验证之前的状态，我们必须要想办法对之前的递推状态进行存档。

一个比较朴素的存档方法，就是每走一步就把整个递推状态做一个快照——但是对整个 69 层 KDA 做完整存档保留的开销非常大。

我们最后的做法是：不存状态，只存每一步状态的极小投影，大概只有 1 KB 左右。要回退的时候，就从上一个 checkpoint 出发，照着这些输入，把接受的那几个 token 的存档重放一遍。

这很像我去看我小表弟学习象棋的过程：象棋玩家为了复盘棋局，会通过一些简单的记号来记录每一步棋子的移动，这样你就不用每一步都给整个棋盘来一次完整的快照。然后我们为了支持 KDA 的投机采样，其实也实现了类似的思路——记录棋子的移动，而不记录整个棋盘。

比较有趣的是，我们后来观察到 Kimi K3 的 tech report 也和我们独立地提出了类似的设计。当然我们其实并没有提前为了这一块的设计做过任何讨论，也可以很荣幸地说：顶尖的工程团队，大家在这些工程问题上的解法都有异曲同工之妙。

曼祺

这次 K3 还开源了他们的一个 agent 环境，它就是叫 AgentEnv。你前面也说到，一般权重只是一次训练的产物，而环境是能够反复复用、产生下一代权重的流水线，所以环境是更重要的护城河。你也可以讲讲，这次从 AgentEnv 里面看到的一些有意思的思路是什么？

赵晨阳

AgentEnv 是一个最朴实无华的名字，我觉得还是比较有新意。因为一般而言，我们研究者往往为了模型的安全性会去主动限制模型的能力——大多数情况下，我们会通过更好的隔离方案来尽可能地锁死模型，让它少做一些越狱之类的操作。

但是 K3 的训练团队选择通过更好的隔离方式，来尽可能放宽模型的能力边界——就是说模型可能受到的限制更小。我相信他们自己也比较 believe，以后模型应该拿到的系统权限是更高的，可能是这个样子的。

往往我们认为，agent 越强的话，它的探索会越激进。早期的时候，我记得大概是 Kimi K1 或者 K2 的时候，他们会选择用容器 runtime 来完成这种沙盒，但那种情况下很容易出现我们所谓的 OS 的 panic 和内存的死锁。

他们并没有选择让 agent 持续去跑容器、或者换用别的虚拟机，而是干脆换了别的技术路线，把这种隔离做得更好——用了 Firecracker 来跑这种 microVM。

这个其实比较工程化，但是我觉得一句话 take away 就是说：他们选择赋予模型更高的权限，并且为这个权限做出更好的技术隔离。

曼祺

这个技术隔离是隔离什么和什么？

赵晨阳

简单来说就是希望如果一个 agent 把一个沙盒弄崩溃了之后，不会影响其他沙盒的运行。

曼祺

这是安全的考虑，对吧？

赵晨阳

是的。可以说是沙盒做得更安全，那么模型的安全限制就可以放低。

然后第二点是持久化 rollout 和沙盒。这个其实解决的问题很经典，就是我们 agent 的长尾问题。我觉得这是 Kimi 一个很厉害的地方——在 agent RL 里面有个经久不衰的做法叫做 partial rollout。

简单来说就是：一条采样轨迹可能是上千次的工具调用，得到了上百万个 token。然后假设我一次采样 16 个 request，这 16 个 request 里面可能就会有那么一两条特别长的——比如说它调一个外卖的接口，但是外卖那个 mock 接口返回得比较不稳定，可能过了一分钟才返回。这种情况下会极大地阻塞这个 batch 的整个运行。

在 Kimi K1.5 的论文里面，他们就提出 partial rollout：不必等待所有的轨迹都结束，等到一定比例的轨迹完成了之后，就把结束的轨迹用作训练，然后没有完全结束的轨迹会缓存起来，在下一轮继续去完成它。

这个做法其实是有很深厚的统计学观察在里面的，就是说通过提高采样的总数、或者说只选择把不长尾的那部分 request 拿来使用，可以加速采样的过程。

这个也有一些强化学习理论上面的挑战。一方面从系统设计上面，模型的历史采样信息需要尽可能地保存，比如说模型上次采样的 KV cache——他们需要把这些 KV cache 写下来，避免下次重新采样的时候需要做一次特别长的 long prefill。

然后另外一个问题是强化学习侧的数据过时问题，用术语叫做 off-policy-ness：这样采样的轨迹会有一个问题——可能这个轨迹的前一个部分是上一个版本的 checkpoint 采样出来的，余下部分才是当前版本的 checkpoint 采样出来的，这样的话一条采样序列其实不是严格的 on-policy、或者说不是严格在线的。

K3 还是采用了 per-token 正则的方式，把我们所谓的策略更新约束在了一个局部邻域之内，来部分容忍这样的 off-policy-ness。这是一个很经典的用算法上的宽容来换取 Infra 上的自由，然后其实对 Infra 的提速是非常好的。

最后一点，我觉得体现出 Kimi 团队的一个设计哲学：让 RL 环境和推理时 agent 运行的环境尽可能一致。

K3 的训练管道把 agent 的 harness 表示成了一组可以配置、可以组合的模块——类似于工具接口、system prompt、上下文管理策略、skills 还有 memory，他们用各种复杂的策略去模拟组合出各种主流的 agent harness。

这种组合其实也避免了在模型训练过程当中 overfit 到某一个 harness 上。以至于比如说你训练在美团上面订外卖，最后发现用户想要用饿了么就用不了——这些对人类而言是非常愚蠢的，但是对模型而言，训练不佳很容易出现这样的问题。很显然他们这样的策略组合，能够很好地缓解这种「学会了美团就不会饿了么」的问题。

从 Infra 的角度上来讲，我其实很认同他们这个方向：环境正确，就是说我们对 harness 的要求会逐渐提高。更广地来说，我们希望 harness 能够自由地和各种 agent 的 workflow 做组合。这和我们在 serving 侧的想法也是一样的——不要为了每一个模型去做许多策略，要为了这些状态尽可能去组织成树状结构。

曼祺

嗯，所以他的整个思路就是说：我这个模型训出来之后，在上面一层、就这个 harness 这一层，不管是什么类型的 harness 他都能比较好地去调用，可以适配不同类型、更多的框架。

赵晨阳

理论上是这个样子，但是效果我觉得肯定不至于那么完美。但是我觉得现在随着对 harness 的使用越来越多，对 harness 泛化性的要求也必然是越来越强的。

曼祺

你觉得闭源模型有这个需要吗？比如说 Anthropic 或者 OpenAI，它可能自己训的模型就是在自己的 harness 框架里面被使用的。

赵晨阳

对，这个必然是需要的。

换句话来说，即便是 Claude Code 这样的平台，它其实能够接入的组件也是非常多的——类似 Claude Code 可以去接 Slack、可以接 Gmail，还可以接你的 calendar，这也是某种意义上的 harness。何况我刚刚提到美团和饿了么这个切换问题，可能对于 Anthropic 而言，他们换的就是用 Gmail 还是用 Outlook。这两个事情听上去也非常类似，但是不做精心的设计，模型的 overfitting 会非常令人尴尬。

Flash KDA、QAT 与训练—推理一致

曼祺

除了你刚才说的、你自己最在意的这个进展——AgentEnv，就是他们强化学习的环境——之外，其他的一些改进，包括这个 Flash KDA 还有它的量化感知训练，这些你也可以展开讲讲，就是它在 Infra 上带来的变化是什么？

赵晨阳

我们回到一下这两种 attention 的区别吧。

softmax attention 的 kernel 主要是在和带宽做斗争；然后线性注意力的 kernel，不严谨地来说，它会更多和串行依赖关系做斗争。

具体来说，KDA 是在 chunk 之内做并行、chunk 之间做串行，以此 recurrent state 得以一个 chunk 一个 chunk 地往前传导。所以这种情况下，最 naive 的写法就是每一个 chunk 你算一次、你就传一次状态，就会导致计算资源的大面积空转。

然后 Flash KDA 是 Kimi 团队基于 CUTLASS 写的一个 chunkwise 的 kernel，把 chunk 内的计算和跨 chunk 的状态传输尝试做重叠——术语来说叫 overlapping。这是 Flash KDA 的第一层。

然后如此一来的话，就带来一个差别：softmax attention 的 kernel 对于 KV cache 的关注其实不会特别强，因为 kernel 对于 KV cache 是只读不改的；但是 KDA 的这些 kernel，旧有状态可能会被覆盖，所以 kernel 的设计还需要考虑更全的生命周期——什么时候做持久化、写到哪一个 chunk slot 里面、怎么去保证其他 request 正在读的缓存不会被冲掉。

可以说 KDA 的 kernel 会难度更高一点，而且它也模糊了我们认为 kernel 和缓存管理之间的界限。

然后另外一个角度是 Kimi 的拿手技能，这个我们说的 QAT，就是 quantization-aware training。可以看到 K3 和 DeepSeek V4 同时都在采用 FP8 精度的训练。DeepSeek V4 的具体做法我们之前有讨论过，我们这里可以更多讲 K3。

K3 从 SFT 开始就做 QAT，这个直观的好处就是模型会有更多的时间去适应量化噪声。而且他们也着重强调了 RL 采样阶段和 training 阶段采用的是同一套量化方案，这样尽可能地减少训练和推理不一致带来的磨损。

这个也可以从 RL 的角度上来感受。我们刚才其实提到一个术语叫做 off-policy。直观来说，RL 策略梯度优化这整件事情能够成立是有一个前提的：我正在优化的，是那个产生了这些数据的策略。就是我们训练的时候会采集到许多序列，然后拿去优化模型——我们希望这些序列就是我们优化的那一个模型产生的：它不是 t−1 的 checkpoint、也不是 t−2 的 checkpoint，它最好就是 t−0 这个 checkpoint 产生的数据。

但是这个 t−0 或者 t−1、t−2，它有的时候不是你刻意造成的。就比如说我们说的这个训推不一致：训练的时候可能它的量化比如说是 BF16，那你推理时候采用 NVFP4，那么这就会导致其实这两个策略是有区别的，这也是一种 off-policy。

所以一旦训练和采样的过程对同一个 checkpoint 给出的精度不一致，它给出的 token 概率就是有细微区别的，这就是一个不严谨的梯度计算；而且这种不严谨的梯度计算对于 MoE 而言，可能会导致一个灾难性的崩溃。

OK，所以 K3 的训练哲学还是在贯彻 RL Infra 领域一贯的认识：为了让我们训到的模型就是我们要去优化的那个模型，一定要让训练和推理阶段尽可能契合，采用尽可能相似的配置。

曼祺

哎，这件事情它在实现上难吗？就说现在大家、其实主流的公司都能做到尽可能一样的配置，还是说这个还是需要挺多努力才能实现的？以及它其实也能去看一个公司大概 Infra 的水平。

赵晨阳

我可以说这个事情非常难，而且对于很多公司而言，需要单独去维护一个硕大的 Infra、甚至说是 kernel team，才能够把这个事情做好。这点上来说，我觉得 Kimi 的技术还是非常领先的。

曼祺

你之前说 DeepSeek 是 Infra 领域的巨鲸啊，那类比一下的话，你觉得 Kimi 是在什么段位？

赵晨阳

那我不希望有一个分出高下的。但是坦诚来说，我觉得国内公司的 Infra 真的强。不过正向来说，我们叫做「用 Infra 换算力」吧——真的是非常不容易。

曼祺

最后这一部分我有个想补充的问题。我看 K3 在技术报告里写到，K3 在优化测试里已经给——他的原文写的是 "a tolerant vendor"，有可能是个国内的芯片公司——给这个 vendor 的 GPGPU 写了 kernel。那是不是有可能用 K3 这个模型，也能加速 K3 自己向国产芯片的适配了？

赵晨阳

是的，我觉得这点应该是比较明确的。当然我们不确定最终 deliver 上生产的这些是不是 K3 写的，但是 K3 至少从性能和正确性上来说是非常能打了。

然后另外一个角度就是，这一次我们也见到，由于现在这个模型的生态真的扁平得非常厉害——以前有一段时间，国产芯片的同行想要在模型发布当天 support 这些新的 AI 模型，其实是有一定难度的；但是到了最近，我们也看到类似于摩尔线程，他们也通过 MUSA + SGLang 这样一个生态，在很快的时间之内（我不记得是不是当天，但一定是在极短的时间之内）就成功 support 上了 Kimi K3，而且也达到一个很好的效果。

我觉得可以想见，Kernel Development Agent 真的是一个非常伟大的事情，我觉得对于整个芯片产业是有很本质的推动的。

曼祺

你觉得这件事会怎么影响英伟达的统治地位吗？会到那个程度吗？

赵晨阳

这是一个我无法判断的事情。

曼祺

你这是无法判断还是不想说呀？

赵晨阳

我无法判断。

曼祺

这个我们可以讨论一下。就是理论上来说，因为 CUDA 这个生态就是建立在「你有比较丰富的 kernel」，这肯定是很重要的一部分，对吧？然后它的通用性比较好。

赵晨阳

嗯。我有很多好朋友在 AMD 做 AMD 版本的 CUTLASS，所以他们高强度地依赖这些 KDA（Kernel Development Agent）；而且我也有 NVIDIA 的好朋友，他们在 NVIDIA 写 next generation 的 DSL，也是大量依赖 KDA。

曼祺

那我觉得你这提供了一种视角：KDA 这个东西英伟达之外的厂商可以用，对吧？那英伟达自己他也可以用。

赵晨阳

对，因为英伟达自己也需要去更迭嘛。

然后我觉得很遗憾的是，现在这些模型的 KDA 还是——就是说优化 CUTLASS 可能很厉害，但是如果你优化，比如说举个例子，假设以后有 TC gen5（比如现在是 gen4），那 KDA 可能还得花一段时间来泛化上去。

曼祺

这也是个很好的问题。我们可以看看 KDA——这里指的是开发 kernel 的这种 agentic ——的发展之后，会怎么去影响芯片领域的一些竞争。

赵晨阳

我很难说 Kimi Delta Attention 和 Kernel Development Agent 哪一个更伟大，我觉得这两个事情都很牛。

下一个开源最强，以及开源能否超过闭源

曼祺

OK，都叫 KDA。我们最后可以来稍微延展讨论一下 K3 对业界的一些影响，有一些随便拍脑袋的问题。比如说：你们认为下一个「开源最强」什么时候会出现？可能来自哪个公司？

赵晨阳

嗯，首先我见到一个非常恐怖的事情：之前见到 Qwen 团队发布说，他们的模型在以日为单位智力更迭。

这个时代对智力前沿的加速度没有降低，反而我觉得是人类的想象力降低了——就是我们现在除了 coding 之外，我见不到下一个爆炸的点。

曼祺

对，就 Qwen3.8 preview、就预览版发的时候，说他们会一日更新。

下一个问题——其实前面稍微讨论过——就是你们觉得今年内、就剩下还有 5 个多月的时间里，我们有可能会见证开源超过闭源吗？

曾致远

我个人觉得这个是有一定难度的。

因为一般来说，大家会认为 OpenAI、Anthropic 他们内部最强的模型，是比他们现在放出来的模型还要再强半个 generation、半个甚至到一个 generation 的。

然后我们现在最强的开源模型，基本上目标是追平现在已经放出来的那个最强的闭源模型、或者说闭权重模型；但是他们之后能够放出来的，是他们现在内部已经有的、比现在闭权重模型还要更强半代甚至一代的模型。然后这个时候，可能确实开权重模型还需要一段时间去追。

所以我觉得至少未来 5 个月内，这个趋势应该不太会有很明显的变化。其实对于开源模型这边，基本上就是把目前最强的给放出来了。所以这里其实还是有一个代差在这里的——实际最强的，跟放出来的这个最强的。

曼祺

你的意思是说要找一个好的时机来放。

曾致远

对。

持续学习、评测与模型平台期

曼祺

最后一个问题是一个相对宏观趋势的问题。最近梁文锋说，下一代模型的标志是能持续学习。你们自己会怎么看下一代模型要实现什么能力呢？

赵晨阳

我对于持续学习的观点：我不是说希望这个模型的智力不断提升，我是说希望一个模型能够对任何系统都有很有效的优化——但这个「任何」应该就专指 KDA 吧。

比如说我现在说，你让 KDA 去优化现在的 CUTLASS，它可以优化得很好；但是等到 next generation 的 DSL 来了，KDA 能不能做得很好？目前来看是不太行的。

这其实反过来暴露现在模型的泛化性没有想象那么好——因为 kernel 绝对是一个最好验证的领域了，哪怕这样子，它的泛化度还需要一定的训练。那么从这点上来看，我觉得实现 RSI 还是有一些距离的。

曾致远

我不去评价「下一代模型的核心能力是不是必须要有持续学习能力」这个观点本身。

我觉得，如果我们假设这个观点是正确的话，现在有个很大的问题是：我们还没有一个很好的方式去评测、或者说去 measure 这个 progress——就是说我们去看现在的模型，它做持续学习的能力大概到了什么样的层次。因为它肯定不是一个 0 或者 1（就是「不会持续学习」或者「会持续学习」），它肯定是一个 0 到 1 之间的某一个状态。

对，我觉得现在还缺少这样一个衡量目前进展的很好的方式。所以我觉得如果认可这个观点的话，我们应该先把这样一个衡量进展的方式给明确地做出来——比如说通过各种比较完备的 evaluation、各种完备的评测，把这个问题给解决，然后再去讨论「我们现在的模型离达到我们想要的目标还剩多少」。

曼祺

那总体来说，你们觉得模型的进展接下来会是一路这样斜线上去、就可以这样进展了，还是它还是会有一个一个平台期出现？

曾致远

我个人猜测应该还是会有平台期的出现。

曼祺

就是有平台期也意味着有突破，对吧——你有一个突破，可能你就上一个台阶。

曾致远

对对。但这个突破不见得是大家会想象的那种特别巨大的范式性突破，我觉得可能更多是在修缮、在执行层面——把一些问题有些突破之后，这个平台期会有一个提升。

其实说实话，个人觉得最近半年都没有什么很本质的平台性突破，它只是在一个平台上做得更高一点这样。当然确实更高一点，带给普通用户的体验已经很不一样了。

一期是我们这次反复提到的第 163 期对 DeepSeek V4 的解读。其实这两期节目的结构挺相似的，这是因为现在开源大模型的技术报告的结构本身就有一定的共通性，会有几个绕不开的模块。

首先是架构层的注意力机制，这是大语言模型里非常关键的一部分。这次晨阳也说，attention 机制就是我们 AI 研究领域的忒修斯之船。这个词的本意是关于事物同一性的哲学比喻——如果一艘船的所有部件逐步被替换，直到没有原始材料被保留，那它还是原来的那艘船吗？其实我们现在对 Transformer 的改造、我们试遍所有配方的方式，就有点类似于边行船边换零部件；而这意味着，Transformer 这个大的方向继续往下，可能还有很多改进的空间。

另一个绕不开的是层与层之间的信息连接方式。在 V4 里，我们讨论了 mHC，它是怎么从字节最开始提的 HC 改进而来的；在 K3 里，我们讨论的是 Attention Residuals——Kimi 今年春天提出的这个方案本身也是受到了 mHC 的一些启发。

同时我也推荐过往多期节目里我们讨论过的注意力机制。

一是第 103 期「用 attention 串起大模型优化史」，这是在 25 年 2 月录制的。它特别好的一点是对非从业者相对友好：两位清华当时在读的博士生肖朝军和付天宇深入浅出地串讲了 attention 机制诞生的过程、原初版本的瓶颈、它的改进历史和背后的计算机与深度学习思维脉络。简单来说，注意力的改进一直是在服务于上下文的不断拓展——大家追求的是希望上下文越来越长时，计算和存储的开销不会爆炸，也就是一方面要提升效率、但同时又不降低性能。

然后是第 104 期，与当时 MiniMax 的高级研发总监钟怡然聊线性注意力方向的改进。这也是我们 K3 这一期提到的——MiniMax 在 M1（这是 25 年年初的一个模型）上就大胆地使用了线性注意力这件事，这也是业界第一个在这么大规模的模型上用线性注意力的尝试。

更近的一期是去年底发布的第 143 期节目，这次是和 DeltaNet 的核心作者杨松琳来聊线性注意力的优化。当时松琳是在博士的最后一年，现在已经加入了 TML。KDA 里的 D，就是 Delta 的意思。

那会儿的背景是 25 年的 9 月和 10 月，阿里和 Kimi 都发布了和 DeltaNet 相关的注意力改进成果。Kimi 当时那个用在 Kimi Linear 模型上的注意力改进，就是现在 K3 里用的 KDA——这期我们也聊到了：KDA 是从当初 Kimi Linear 这样一个 48B 的小模型，scale 到了现在 3T 的规模。这也是一个挺具体形象的例子，它展现了现在的模型研发中，是怎么一步步从小规模的实验再往上 scale 的历程。
