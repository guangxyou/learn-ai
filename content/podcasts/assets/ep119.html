研究主线：怎么走到线性注意力

杨松琳

大家好，我叫杨松琳，现在是 MIT 的 PhD 在读。我的主要研究方向是语言模型的架构，主要是比较高效的注意力机制之类的研究；更具体来说，是在研究这一类注意力模型——线性注意力。

张小珺

能不能给大家讲讲，你整个研究的主线是怎么递进的？你是怎么走向 linear attention 研究的？

杨松琳

最开始的时候，我看了很多斯坦福一个 research group 的东西，叫做 Hazy Research，就是 Albert Gu 他们在斯坦福的那个 lab。当时看了很多他们写的博客，觉得序列建模是一个非常有意思的问题，就决定来做序列建模的一些问题。

刚开始读博的时候，微软亚洲研究院有一篇工作叫做 RetNet。那个时候，最开始就是想办法提高 RetNet 的效率和 performance。之后就发现，提高效率的这一套硬件优化的算法可以扩展到很多其他类似的架构里面。

同时，之后的一些工作主要是想办法在能够硬件高效训练的同时，提高线性注意力的 performance。比方说从门控机制，到一个叫做 Delta Rule 的机制；后面就是把这两个东西 combine 在一起，让它合成一个统一的更新规则，同时又可以有一些硬件高效的算法来进行训练。

张小珺

我看上一次我们节目发了以后，很多人说你是「linear attention 之母」，这是为什么呀？

杨松琳

可能是在这个领域做了很多工作吧。尤其是还有一个开源库叫做 flash-linear-attention（FLA），这个领域里面很多人会用这个库，包括业界也有很多人用它来做一些 linear attention 的探索。加上我那几篇工作应该还是比较有影响力的，所以可能大家会这么叫我。

怎么通俗理解「线性」

张小珺

能不能更通俗地理解一下 linear？它中文是「线性」对吧，线性注意力机制。

杨松琳

线性主要的意思就是线性复杂度。它对应的是平方复杂度——我们平常的 self-attention 是平方复杂度。

大家都知道 self-attention 有三个矩阵，Q、K、V，就是 query、key、value。一般是 Q 和 K 先做一个矩阵相乘，得到一个 L×L 的矩阵，L 是序列长度；然后对这个 L×L 的矩阵做一个 masking，因为它基本上都是自回归的语言建模，所以要把未来的信息 mask 掉。这样我们得到一个下三角的 L×L 矩阵，再加一个 softmax，就得到一个注意力分数矩阵；最后用这个注意力分数矩阵和 value 矩阵相乘，得到 output。

这就是 Softmax Attention 在自回归建模里面一个比较粗略的介绍。因为它中间会有一个 L×L 的矩阵，所以它的复杂度是平方的。

线性注意力一般就是把 softmax 这个 operator 去掉。把这个非线性的 softmax 去掉之后，我们可以通过一些等式变换，把它写成一个类似于 RNN 的推理形式。这样它每一个 step 的 cost 就是 O(1)；处理长度为 L 的序列，整体复杂度就是 O(L)，跟长度呈线性关系。所以大家把它叫做线性注意力。

张小珺

如果把现在的大语言模型算法做一个框，让大家有一个背景的话，Linear Transformer 应该放在哪个地方？

杨松琳

我觉得现在都是在 Transformer 这个基础架构里面做一些魔改。

大语言模型的技术栈可能分成 pre-training、post-training 之类的，架构的研究肯定是在 pre-train 这一块里面。pre-train 还有很多其他类别的研究，比方说优化器、基础架构，还有 pre-train data 之类的东西。线性注意力应该算在基础架构这个研究里面。

现在基础架构整体的框架还是 Transformer 这种：有一个注意力机制，和一个前馈网络（feed-forward network），在这两个模块上反复叠加很多次，就得到我们那个最经典的 Transformer。一般大家就是在这个框架下面做一些修改。

最近几年，大家会把传统的 MLP 或者说 FFN 换成混合专家的模块，Mixture of Experts，MoE 的模块；而线性注意力，就是把传统的 Softmax Attention 换成线性复杂度的 attention。

当然，现在最火的是一类叫做 Hybrid 的架构：有一些层还是 Softmax Attention，另外大部分的层换成线性注意力的层。

Part 1 · Kimi Linear 与 KDA

为什么 Kimi 要重新设计注意力

张小珺

我们来聊聊你最近参与的一个新工作吧。你是怎么参与到 Kimi 的工作中的？这个工作应该是 10 月底刚发布。

杨松琳

这个工作他们应该是年初就想开始做。当时 flash-linear-attention 这个库的另外一个主要作者叫张宇，今年博士毕业——在国外读博，毕业之后正好就在 Kimi。Kimi 那时候正好想做混合注意力，张宇就在做这个项目。

因为张宇是 FLA 那个开源库的 collaborator，我们很熟，所以我会帮他们看一下：有哪些线性注意力的变种、那些变形的算法该怎么设计之类的。

张小珺

当时他们团队遇到的核心问题是什么？为什么决定要重新设计一下注意力机制？

杨松琳

年初的时候，大背景是 DeepSeek R1 和 Kimi k1.5 那个时候刚刚发。它们的核心是会做一些 RL，会得到一些非常长的思维链（CoT），然后用这个非常长的思维链来做 test-time scaling，来解一些比较复杂的问题。而这个思维链的长度，往往能到几万个 token。

Kimi 就觉得：如果我们每一层都是平方注意力的架构，它在 decoding 的时候就太贵了。首先每一层要存大量的 KV cache；另外它每一步是线性的时间复杂度，所以 decode L 个 token，时间复杂度也是平方的。

所以在这种长思维链生成的背景下面，Kimi 觉得需要投入资源来探索一下混合注意力，因为它能把 inference 的 cost 打低很多。这一点在长思维链的背景下，以及今年整体的 agent 背景下，是非常有用的。大概背景就是这样。

张小珺

你们魔改的核心目标是什么？

杨松琳

当时的核心目标——主要是张宇在那边做——他们的目标应该就是：跟之前的 Full Attention 相比，performance 不掉点，同时 inference 速度快很多倍。

张小珺

如果用 Full Attention，它的缺陷是什么？

杨松琳

如果用 Full Attention，做长文本 decoding 的时候就非常昂贵。

KDA：把粗粒度的衰减率换成细粒度

张小珺

能不能从你的视角给大家讲讲这篇论文，稍微画一下重点？

杨松琳

这篇文章里，线性注意力的模块他们最后选到的是一个叫做 KDA（Kimi Delta Attention）的模块。这个名字感觉也挺有梗的——他们应该是想对标 DeepSeek Sparse Attention，就特意取了一个 Kimi 开头的名字，非常对仗。

这个线性注意力模块，基本上是基于我去年的一个工作 Gated DeltaNet，在这个基础上做了一些改善，最后形成了 KDA。

总的来说，首先我们有一个叫做 Delta Rule 的东西，这个可以之后再具体讲。做 Gated DeltaNet 的时候，当时受限于 efficiency，我用到了一个像 Mamba2 一样的、scalar 形式的 gating——它的门控值，对于一个 attention head 来说，下面所有的维度全部共享同一个 decay（衰减率）。这样在计算上会带来一些简化。所以当时的考虑是：先在 Mamba2 的基础上加上 Delta Rule，让效率有保证。所以当时只用到了那种粒度比较粗的门控机制——这就是 Gated DeltaNet。

而张宇做的这个 KDA，是把粒度比较粗的衰减率换成了粒度比较细的衰减率。之前是一个 attention head 下面、不同维度共享同一个衰减率；现在是不同维度每个维度有自己的衰减率。这样每一个维度对应的那个 RNN 记忆的隐藏状态，就有自己独立的一套更新频率。直觉上来看，它能够更好地利用有限的 hidden state，从而提高 performance。

张小珺

你们的设计逻辑和灵感来源于什么？

杨松琳

我觉得 KDA 其实就是把我之前两个工作的 idea 合并在了一起。

我之前还有一个工作叫做 Gated Linear Attention（GLA），它就是有一个粒度比较细的衰减率。后面到 Gated DeltaNet 的时候，之所以没有用这种细粒度的衰减率，是因为当时算法本身和 kernel 优化都没有优化到一个比较好的状态，所以出于效率考虑，被迫只能用 Mamba2 那种粒度更粗的衰减率。

后面在算法层面和 kernel 优化层面都有了很多进步，到今年年初这个时间点，大家就觉得：是不是可以重新研究一下，能不能把这个细粒度的衰减率重新引回到 Gated DeltaNet 里面。

Scaling Ladder：像通关一样往上 scale

张小珺

你们设计完，最初的效果怎么样？

杨松琳

最初的效果——我记得张宇应该是先试了一大堆混合注意力的混法，最开始发现混 Gated DeltaNet 比混其他的要好。

后面因为 Kimi 内部有一个叫做 Scaling Ladder（规模阶梯）的东西：你在一个规模下面表现好，就要到下一个规模去继续 scale。有点像通关一样，有很多很多关卡，过了一关之后，到下一关继续去跟 Full Attention 比。

最开始可能发现，那种 hybrid Gated DeltaNet 在有些地方还是不如 Full Softmax Attention；后面他就试了一下，把那个 decay 换成更加细腻的 decay，发现在他的一些实验下面，提升还挺大的。

Part 2 · 各家在注意力上的不同押注

Kimi Linear vs DeepSeek Sparse Attention

张小珺

Kimi Linear Attention 和 DeepSeek Sparse Attention，你自己觉得它们的表现哪个更好？它们分别可能适合什么样的任务？

杨松琳

这两个 attention 其实想解决的是同一个问题：在长文本 decoding 下面，如何解决效率问题。

Kimi 走的是混合注意力的路线——其实千问也走的是这一条，现在主要在投入混合注意力这条路线。而 DeepSeek 主要喜欢走稀疏注意力的路线，他们最近这一版，包括之前发的 Native Sparse Attention，都是走的稀疏路线。他们觉得稀疏可能是一种更好的、降低 decoding cost 的方式。

DeepSeek Sparse Attention 应该是没有 Full Attention 层的，每一层都是 DeepSeek Sparse Attention。但它每一层都要把所有的 KV cache 全部存下来，只能从一个 checkpoint 经过一些蒸馏，得到那个叫做 index 的东西，来选那些 top-k 的 token。

而混合注意力这条路线，还是有一些全局注意力层的，比较快速的那些层是线性注意力层。它的好处是可以省很多 KV cache——因为绝大多数层都是类似于 RNN 的层——同时也能提高 decoding 的效率：因为减少了 KV cache 的 size，做 decoding 的时候就可以用更大的 batch size。之前可能放不下，现在 KV cache 被减少了很多，就可以加大 batch size。

DeepSeek Sparse Attention 是没有减少 KV cache 这个作用的，但它可以通过稀疏的激活，来减少每一个 token 生成的花费。

MiniMax 从 M1 到 M2，为什么退回 Full Attention

张小珺

还有一家 MiniMax，他们最近也做了一个算法的选择，对吧？他们上一版是 Linear。

杨松琳

对，MiniMax 应该算是混合线性与平方注意力的先驱——他们年初发的 M1 版本，是一个非常大规模的混合注意力实践。

然后他们前几天发了一个叫 M2 的模型，这个模型现在变成了 Full Attention：既不是混合注意力，也不用 Sparse Attention，干脆退回了 Full Attention。

张小珺

这是为什么呀？

杨松琳

我觉得他们的负责团队非常 open，分享了很多经验，这些经验都是很宝贵的。

比方说我记得他们说过：第一版的时候，他们监控的那些指标上，用到的 Lightning Attention 模块表现都很好，而这个 linear attention 效率又更高一点，所以最后就上了 Lightning Attention。后面他们发现，在一些叫做 multi-hop reasoning（多跳推理）的 task 上面，掉点会非常大。

当初之所以选那个方案，是因为他们最开始没有去检测多跳推理这个能力，主要只看 MMLU 之类的能力。而且就我来说，我觉得 Lightning Attention 其实是一个比较弱的线性注意力——最近两年线性注意力这个领域发展了很多，他们用到的那一个 linear attention，给人的感觉像是两年前的技术。所以很有可能是因为他们第一版做评价的 pipeline 不够详尽，就选了这么一套略显 naive 的方案。

最近他们可能是想做 agentic task、想做 coding，而多跳推理这个能力在这种场景下面变得非常重要。他们就发现 Linear Attention 跟 Full Attention 之间的 performance 差距还是挺大的，于是暂时退回了全部都是 Softmax Attention 的 Full Attention 架构。但他们说还在继续探索混合注意力的架构，说不定下一版 M3 又变成混合注意力架构了。

张小珺

你怎么看待大家在算法上的不同选择，或者说反复？

杨松琳

历史会螺旋上升嘛。一套技术方案肯定是要经过很多很多验证，才能最后定下来的。当时可能就是验证得不够充分，比较草率地上了，后面发现在多跳推理上面效果不好，就暂时退回来——这个也是很正常的。

张小珺

硅谷的公司现在对于混合注意力机制，探索方向是什么样的？各家公司有什么不一样？

杨松琳

这个我感觉我不能讲。

张小珺

哦，OpenAI 什么的可以讲吗？

杨松琳

OpenAI 的话，我只能讲有 paper 的方案，没有 paper 的方案我是不会讲的。

比方说 GPT-3，它在 technical report 里面就讲了：会用到一个全局注意力和一个 local sliding window attention 混合的方案。这个在 GPT-3 的报告里已经明确写出来了，所以这个是可以讲的。他们最近发出来的那个开源模型（gpt-oss）也用到了这套滑动注意力的方案，所以他们应该是一直在用这一套。

Part 3 · 线性注意力这几年的脉络

两次改进：衰减率变成输入相关、更新规则换成 Delta Rule

张小珺

你刚才说 linear attention 这两年发展也有很多，能给大家讲一下它的发展线索吗？

杨松琳

好呀。linear attention 最开始我觉得是非常不 work 的——就算在短文本下面它也不 work。最早的 linear attention 是 2020 年发明的，中间这几年在 language modeling（语言建模）上面一直都没有跑到很好的效果。

后面一个比较有代表性的工作是 RetNet。它通过加一个遗忘衰减的机制，就发现 linear attention scale 上去，在语言建模上面还是可以取得比较好的效果的。

RetNet 加的是一个输入无关的 decay：它的遗忘率跟输入没有关系。比方说遗忘率是 0.99，那每过一个 token，前面的 hidden state 就要乘上 0.99，相当于遗忘掉 1% 的东西，然后再把新的东西写进去。这就是输入无关的衰减，是 RetNet 用到的技术。

这种输入无关的遗忘，之后逐渐被替换成了输入相关的衰减。比方说我之前那个工作里加的门控机制，前面也提到了。

像 Mamba 和 Mamba2，其实跟线性注意力也有很多联系。尤其是 Mamba2，基本上可以看成是线性注意力加了一个衰减；它跟 RetNet 的区别就是：那个衰减是由输入来决定的，每一个 token 的衰减率可能不一样。

比方说它遇到有些 token，觉得前面的内容没有必要忘，就可以把衰减率设为 1，这样前面就完全不做衰减；如果遇到一些 token 让它觉得前面这些信息已经没用了，就可以在那个位置让衰减率等于 0——乘了一个 0 上去，前面的 state 就被完全忘掉了。这种输入相关的 decay 比较灵活，能够通过数据来动态地学：什么时候该遗忘、什么时候该记住前面这个 state。

这是第一个比较大的改进：把衰减从输入无关变成输入相关。

第二个改进是 DeltaNet 这一路线：把更新公式从最开始那个简单的形式，换掉。最开始 linear attention 用到的其实应该叫做 Hebbian rule——简单地把 key 和 value 的外积加到 hidden state 上面，这就是一个 Hebbian 的更新。

而 DeltaNet 这一套模型用到的是 Delta Rule。Delta Rule 是说：每一步的时候，先用这个 key 去记忆矩阵里面取，会返回一个值——这是这个 key 在记忆矩阵里本来对应的 value，我们管它叫旧 value；而这个 key 这一步又带来一个新的 value，我们把它叫做输入 value。

因为它有一个关联记忆的视角，每一个 key 我们想让它只对应一个 value。模型也不知道应该对应旧 value 还是输入 value，所以我们又有一个可以学习的系数叫做 β——可以看成一个值在 0 到 1 之间的系数，用来决定我们要用多少旧 value、多少输入 value，做一个线性组合，得到最后的新 value。然后把「key 和旧 value 的外积」从记忆矩阵里面减去，把「key 和新 value 的外积」加到记忆矩阵里面。这就是 DeltaNet 更新公式的 high-level idea。

相比于原来的 linear attention，它其实多了一个减法操作：加法可以想象成往记忆矩阵里面记东西，减法就可以理解成从记忆矩阵里面删掉一些东西。这样会更有针对性——之前那个 decay 可能是很多维度一起在做衰减，现在是只取某一个分量，有一些非常有目标性的删除操作在里面。

所以 Delta Rule 代表的这第二个改进，应该就是 linear attention 这个领域里最近的第二个改进了，像 DeltaNet、Gated DeltaNet 都用到了它。

每一次回头看 linear attention，都是因为撞到了 Context Wall

张小珺

为什么 linear attention 从一开始效果不好，到慢慢一步步改进，大家就相信它是 promising 的？

杨松琳

我觉得每一次大家关心 linear attention，肯定都是因为撞到了 Context Wall。

比方说 2020 年左右大家去研究 linear attention，是因为那个时候遇到了第一堵 context 的墙。如果想继续提高 context，就只能找一些复杂度小于平方的东西。当时像 BERT 那个年代，训练长度其实就是 512；在当时的视角，可能 2048、8192 就算一个长文本了，因为那个地方非常慢。

后面随着 FlashAttention 这个技术的诞生，就打破了这一堵墙。现在看来 8192 是一个非常短的文本，在这上面做训练没有一点压力。但在没有 FlashAttention 的时候，计算需要把平方的那个 attention 矩阵先实例化在 global memory 上面，再从 global memory 搬回 shared memory 里面，整体的读写开销非常大；同时因为这个 attention 矩阵会被实例化在 global memory 里，还可能带来 out of memory 的问题。这就是最开始大家研究 linear attention 的 motivation。

随着 FlashAttention 出来，大家发现这堵墙其实已经破了——既然我们能用精确的方式直接算 FlashAttention，那就没必要找一些 linear attention 去逼近它。所以 linear attention 的研究就开始没有那么受关注了。

直到最近，长文本的 decoding 又重新成了需求量非常大的东西：推理模型要吐很多很多 token、要做这种 decoding，这个花销就让人们不由自主地又重新审视这一套技术。

而这套技术本身在学界又有了这么久的发展。尤其是在 FlashAttention 之后，学界也意识到：linear attention 这一套模型如果想被大家接受，硬件上的效率是非常关键的。这也就是为什么我最开始搞了一个叫做 flash-linear-attention 的 project——把这些 linear attention 的变种用 Triton 写成一个库，写了很多 kernel，让它们能在当代硬件、主要是 GPU 上快速运行。

张小珺

所以它核心是效率更高、价格更低。

杨松琳

每当 softmax 的效率变成一个瓶颈的时候，大家就会回来看它。linear attention 的诞生大概就是这样一个历史。

纯线性是不 work 的，3:1 快成了共识

张小珺

那混合注意力现在是共识了吗？

杨松琳

我觉得现在的共识是：纯线性 attention 是不 work 的。它在长文本下面有一些比较 fundamental 的缺陷，现在大家一般都不会去尝试纯线性的模型。

而比较折中的方案——混合注意力——还是有很多很多线性注意力层，但同时保留一定数目的全局注意力层。这样模型的下限是有保证的，处理长文本也有一定保证。全线性的网络从理论上就没办法做长文本 task，因为 RNN 的状态数目是恒定的：随着 context 长度增加，早晚会存不下，早晚会损失很多精度。而混合注意力里面有全局注意力，还是可以通过这些全局注意力来完成长文本 task。

比方说 Kimi Linear 这篇 paper、之前的 Qwen3-Next，它们在长文本上——比如 RULER 之类的 task——表现没有掉点，所以在长文本上还是有一定能力的。混合注意力因此受到很多关注。

但我也不知道它算不算共识，因为不同的地方还是在尝试不同的方案，比方说 DeepSeek 就在尝试 sparse attention 那种方案。

张小珺

在 Kimi 的论文里面，你们提出的是每 3 层 KDA（Kimi Delta Attention，增量注意力机制）插入一层 Full Attention。这个比例是怎么确定的？这个比例重要吗？

杨松琳

我觉得 3:1 现在也快变成一个共识了。

MiniMax 之前是 7:1 的比例。7:1 的话，可能 Softmax Attention 的层数不够，长文本的保证没有那么好。

我记得之前字节也发了一篇 paper 研究这个 hybrid 架构——需要百分之多少的 Softmax Attention。他们做了很多 pre-train from scratch 的实验，改不同的线性注意力 module，也改混合的比例，结论大概是：3:1 这个比例是最好的，而且 Gated DeltaNet 这个模块比另外那些要好。后面 Qwen3-Next 也是用 3:1，换成 Gated DeltaNet 这个方案。这个方案应该是不同的厂商各自探索出来，都觉得这个比例更好。

MiniMax 最开始可能没有验证充分——前面也说了，他们最开始的评测还有一些不足——所以用到了一个更 aggressive 的方案，就是 7:1。现在基本上都回到 3:1 上面来了。我觉得 3:1 应该就是这个不共识的 hybrid 里面的一个共识了。

表达能力与效率的权衡

张小珺

是不是你们在算法设计的时候，始终要平衡表达能力和计算效率？这两者是它的核心，比如说北极星指标吗？

杨松琳

确实，我觉得还是有一些 trade-off 的。

全局注意力如果太少，像 reasoning task、长文本 task 肯定会受影响比较大。一些 short context 的 task 没什么影响，比方说 MMLU；但那些长文本和推理的 task，现象会比较明显。

但从另外一方面来说，也不是说 attention 层越多越好。大家训完之后会发现，绝大多数的 attention 层可能是没有用的，只有一些关键层的 attention 是有用的，不是每一层都有用——这个网络本身就有冗余在里面。这就给我们带来了机会：可以把一些层换成线性层。

所以混合架构不一定代表它比全 global 差，很有可能它是一个全面更好的替代方案。

像 MiniMax 之前也承认了一点，我觉得非常好：他们发现 hybrid linear attention、或者 hybrid 滑窗注意力，在长文本的 multi-hop（多跳）推理上会有缺陷。我觉得这应该是现在 hybrid 唯一的问题——就我所知，它在其他 task 上面基本上不会比全 Softmax Attention 差。

这个也比较好理解：多跳推理比较吃 token 和 token 之间的关系，所以比较吃 Softmax Attention 的层数。而非常吃全局注意力层数的任务不是很多，可能就只有多跳推理、长文本上做 reasoning 这类会稍微吃一点；其他很多 task 基本上不吃，那就完全不会受影响。

而多跳推理这个 task，如果我们去开发一些硬件高效、但表达能力更好的 RNN，这个 gap 是有可能被缩小、甚至反超的。比方说 Kimi 最近这个工作，张宇之前就发现：把粒度粗的 decay 换成粒度细的 decay 之后，在 reasoning、coding 和 math 这些 task 上面提升还是比较可观的。也就是说这些 task 上 hybrid 可以做得更好。

现在我觉得混合线性注意力只是一个开始，整体上还是很有可能做出更好的混合注意力机制的——可以去雕一下线性注意力那个模块。

我对这个工作的唯一贡献：一个 chunkwise 并行算法

张小珺

你在过程中给了 Kimi 什么算法建议？

杨松琳

张宇想做那个细粒度的 decay，我就帮他想了一个 chunkwise 并行算法。感觉这可能就是我对这个工作唯一的贡献了。因为基本上都是张宇在 Kimi 做了很多很多 ablation study，基本上都是他做的，所以 credit 基本都在他那里，不在我这里。

这个算法其实也是因为之前有一篇文章叫做 Comba，它设计了一个新算法，能够把求逆的次数减少一次。我看完那个算法之后就发现：那我可以把 GDN（Gated DeltaNet）的求逆也减少一次；紧接着我又推了一个适用于 KDA 的算法，然后把这个算法告诉张宇，张宇去写 kernel、实现这个算法，发现在 scalability 上还是比之前的算法要好一点。

Attention 到底应该怎么设计

张小珺

问一个很 general 的问题——这是一个研究员想问你的：attention 到底应该怎么设计？

杨松琳

我觉得现在可能就只有两条比较主流的路线：一种是 hybrid 线性，一种是 sparse。这两种其实都是非常 promising 的。

另外可能有一些比较非主流的 attention 设计。比方说我看上次 Meta 还放了一个论文，搞一个三次方的 attention——就是嫌平方复杂度还不够，还要搞一个三次方的。

还有一些比较有意思的平方复杂度的变种，比方说字节之前有个叫做 DeltaFormer 的工作，相当于把 Delta Rule 的思想引入到 Softmax Attention 里面，让它表达能力更强。这个工作我觉得也非常有意思。

改进注意力，要么是让它做得更好，要么就是做一些更加高效的变体，比方说 Sparse Attention、或者混合线性的 Attention。而这两种我觉得也是可以结合的，它们有各自的优点和缺点：Sparse Attention 做 retrieval 肯定要更强一点，但缺点是 KV cache 省不掉；线性可以省很多 KV cache。所以我之前写了一个知乎回答，就说：这两种方案为什么我们不能把它结合到一起呢？

我心中理想的方案：用 Sparse 换掉混合注意力里的全局层

杨松琳

比方说我们可以让 Sparse Attention 去取代混合注意力里面的那个全局注意力层。这样我们就不需要有一个全局注意力的复杂度了，虽然还是要存那部分 KV cache，但剩下很多层的 KV cache 可以通过线性注意力把 size 打下来。这可能就是我目前心中比较理想的高效架构了——就「高效且不掉点」而言。

张小珺

所以 Linear Attention 和 Sparse Attention 未来的关系，可能是融合到一个统一的框架里面，对吧？

杨松琳

对，我觉得线性 attention 和 sparse attention 其实没有什么竞争关系。我觉得线性 attention 的竞争对手更多的是 sliding window attention——比方说 GPT-3 论文里提到的那个「全局混 sliding window」，如果让线性去取代 sliding window、能够让它更好，那未尝不可。

张小珺

所以你觉得怎么把 linear attention 和 sparse attention 做更好的结合？现在有人在探索这件事吗？

杨松琳

工业界据我所知，应该还没有看到有人在同时结合 sparse attention 和线性注意力；但学界有一些工作还是有这方面的探索的——有些层用 sparse，有些层用 linear attention。

张小珺

所以 DeepSeek 选了 Sparse Attention、Kimi 选了 Linear Attention，这其实可能也是阶段性的，对吧？未来大家会探索一条新的路，把两者都结合，现在也不是非此即彼的关系。

杨松琳

对。混合注意力在 decoding 长度上去之后，问题是它还是会被全局注意力的效率绊住，后面那个瓶颈就主要在全局注意力的效率上面了。而全部都用 sparse 的话，瓶颈可能在 KV cache 的管理上面，因为它还是不省 KV cache，所以等长度上去了，可能要做很多各种各样的 KV cache 压缩工作。两者都还是有各自的问题的。

张小珺

它的结合，比如说可能是不同的层用不同的 attention 吗？

杨松琳

我觉得最好的结合，就是把混合注意力里面的全局注意力换成 sparse attention。理论上只要 sparse attention 能选得准，是完全可以取代 Full Attention 这一层的。但它现在的问题可能是选不准，这是一个很大的问题。

这也可能是为什么 DeepSeek 最近放的那个 DSA 要用蒸馏的方式，来尽可能让它的 indexer 选得准一点。

张小珺

OK，选得准选不准，核心的瓶颈在哪？

杨松琳

我觉得是学习难度。Sparse Attention 如果你从头开始训练，梯度可能不太准，学着学着就选不准那个 block 了——它学会选 block 还是挺难的，有各种稀疏梯度的问题，sparse 经常会有这种问题。

而蒸馏的方式，其实是让一个训好的、全部都是 softmax 的 teacher model 来蒸馏出 token 的选法，那就可以选得非常好，这从学习的角度来说也是 make sense 的。

Kimi Linear 相比 M1 进步在哪

张小珺

你觉得 Kimi 这个工作，相比年初 MiniMax M1 的工作，进步在哪里？

杨松琳

主要在于线性注意力那个模块好很多。就像我之前说的，Lightning Attention 给人的感觉像一个两年前的工作，还停留在 RetNet 那个版本。

而这两年线性注意力有很多发展，这些发展我觉得都是 work 的——千问和 Kimi 都发现这两年的一些进步是有用的，比方说那个门控、比方说 Delta Rule。把这些最新的进展融合进来肯定是更好的。Kimi 甚至在之前工作的基础上新开发了一个 KDA，让模型的能力更强。

另外可能还有其他不同，比方说 MoE：Kimi 用的应该是细粒度 MoE，而 M1 我记得那个 MoE 还比较粗，还没有用到这么细粒度的 MoE。所以有很多种可能性。

怎么做一个公平的比较

张小珺

如何做一个公平的比较——比较一下 Linear Attention 和 Sliding Window Attention？

杨松琳

我觉得可以有两种。一种是控制 state size：sliding window 有 KV cache，因为它是滑窗，所以 KV cache 的上限是被绑住的，我们可以把这个上限的 size 当成 sliding window attention 的 state size；而 RNN 有 RNN 的 state size，就是那个状态数。如果这两个东西大概在一个 level，我觉得就是一个公平的比较。

因为 decoding 的时候，sliding window 和 RNN 基本上都是一个 memory bound 的过程，所以只要 state size 差不多，decoding 的效率就不会差太多——memory bound 主要就是看它读多少 state，只要 state 差不多大，decoding 效率基本上就差不多。

Part 4 · 架构的演变与未来

算法演变的共同目标：同样的 FLOPs，更低的 loss

张小珺

说到算法的演进，从 Transformer 到 MoE，再到现在大家探索 Linear Attention 或者 Sparse Attention，这种渐进式的创新，你觉得它优化的最终目标可能是什么？最终可能形成的算法共识会是什么样？

杨松琳

我觉得这些优化基本上都体现在：给定相同的 FLOPs，你怎么更好地利用这些 FLOPs，取得更低的损失函数。

像 MoE 这个技术，前两年——比方说 2023 年的时候——都在传 GPT-4 用 MoE，但也有很多地方不太敢跟。现在 MoE 基本上已经变成显学了，每一家都会做这种细粒度的 MoE。

MoE 其实可以想象成一个更高效的 FFN 替代品：它可以更好地扩大 FFN 的参数量，同时保证 FLOPs 不变。这样付出相同的 FLOPs，在预训练里取得的训练 loss 就会更低。这是一个点。

我觉得 MoE 可能是近几年架构方面突破最大的一个方案，而下一个突破点可能就在 attention。因为 Transformer 就两个模块，一个 FFN，一个 attention；现在 FFN 基本上已经雕成了细粒度 MoE 这种形状，那 attention 我觉得大家也是可以来雕一下的——why not？这样在长文本下面，付出相同的 FLOPs，取得的 loss 也可能更低。

这两套思路是一样的，都是减少 FLOPs。FFN 减少 FLOPs，就可以用更大的参数量、更大规模的模型——总参数量可以堆高，因为 FFN 的算力减少了。大家都知道，在大规模训练下面 FFN 的计算是主导的，把它换成细粒度 MoE 能降低很多 cost。

而 attention scale 的主要不是参数量，是 context window size。如果 attention 的 FLOPs 在长文本下面能够打下来，那我们做长文本生成——比如你有很多 agent 去处理很多 workflow、喂很多 context 给它——也会 benefit from 更大的 context window。

如果把架构比作大脑

张小珺

如果把模型的架构比作大脑的结构，你觉得 MoE 和 attention 分别代表大脑的什么组件？能这样形象化地理解吗？

杨松琳

attention 应该就相当于 working memory（工作记忆）；而 FFN 有点像人脑存储信息的那个模块——可能就是海马体，用来存储过去的信息。

FFN 基本上会被看成是一个 key-value 的关联记忆网络，它可以记下很多很多 knowledge，像 world knowledge 都会被记到 FFN 里面。

而 attention 是：你在一个新的场景、遇到新的 scenario、读到新的 context，它会在这个 context window 里面动态地处理这些信息，很像我们人脑的工作记忆。

张小珺

对，它更偏即时性一些。

数据撞墙之后，算法重新变重要

张小珺

当现在数据遇到瓶颈比较明显的时候，是不是算法的创新变得更重要了？因为你要在有限的数据里面压缩更多的智能。

杨松琳

我觉得是的。之前如果数据一直能 scale，你谈 data efficiency 就没有什么特别大的用途——大家闭着眼睛加数据就行了，让模型继续 scale up、继续加数据，所以不需要去动算法，只需要买卡就行了。

现在如果有数据墙、还有算力墙，那最终还是要回到算法这种本质的东西上面来。我觉得这些东西都是缺一不可的：data、算法、算力，有点像三驾马车，来驱动整个人工智能的发展。

我记得之前 OpenAI 的 CTO 也说过，在这个节点上面，算法研究的重要性可能会被重新抬高。如果我没记错那个采访的话，他应该是这么说过的。

Transformer 的天花板：先把全局注意力干掉

张小珺

你觉得现在的 Transformer 架构，它的天花板是什么？

杨松琳

我觉得还是先把 efficiency 的问题解决掉吧，因为现在还没有解决掉。它处理一个很长的 context window 还是有局限性，所以大家会做很多上下文工程、做一些 RAG，通过其他方式来绕这些问题。但如果 context 的问题解决掉了，那 RAG 这一套技术都不需要了——直接把它放到 context 里面做 in-context 检索就行了。

所以天花板的话，第一点是先看看能不能把全局注意力干掉。它确实是阻止 context window 继续 scale up 的主要瓶颈，这个瓶颈我觉得早晚都要弄掉。

第二点可能就是 Continual Learning（持续学习）。现在这种架构还是没法做 Continual Learning。之后让 AI 自己学习，甚至——大家不都想把 pre-training 这个地方变成直接从 RL 开始，让模型直接从零开始学，不给它喂 pre-train data 吗？这种新的范式可能就是之后的探索。

怎么把 Linear Attention 的 Transformer 继续 scale up

张小珺

一个研究员问你：如何把 Linear Attention 的 Transformer scale up、继续扩展？

杨松琳

我觉得 scale up 应该没有什么特别大的问题。可能还有一点是：那些配套的基础设施还需要继续搭。

像 flash-linear-attention 只是提供了一些 Triton 的 kernel，基本上可以凑合用，但效率肯定不是最优的，因为它是 Triton 写的。所以如果有志向投入这个领域的公司，或许可以花一些精力去优化这些 kernel，这对继续 scale up 上去有好处。

而推理那边的支持已经在逐渐变多了。比方说半年前我参加 MiniMax 的一个圆桌讨论，当时主持人问我这个领域主要的瓶颈是什么，我说是 infra 的配套没有跟上，当时主持人还觉得挺意外的，以为我会回答一些别的东西。

但事实上就是这样。算法层面，像近两年的这些发展已经可以大规模来试了——比方说 Qwen3-Next 和 Kimi 这些都是可以大规模直接试的。后面 deploy 的瓶颈更多是在配套设施上。

因为这两家发了这两个模型，开源社区的支持力度也挺大。像之前 SGLang 都不支持 hybrid model 做 inference，现在就趁着这个机会，把 Qwen3-Next、MiniMax-M1 这些模型加上推理引擎的 support。我觉得这是一个正向流动、正向发展的过程：做基模的厂商做出一些比较 promising 的结果，把开源权重发出来，做推理引擎的人就会有很多动力来支持这些东西。

当这些配套更好的时候……之前别的公司可能觉得这个生态太差，就算做出来了，实际 deploy 的成本也很高；但现在只要生态做起来了，就会有一个正向循环的作用。

张小珺

Kimi Linear Attention 的效果跟 DeepSeek Sparse Attention 的效果比，哪个更强？

杨松琳

Kimi 最近这个 report 有一点是：它有一个跟 Full Attention 的 apple to apple 比较，但它没有跟 sparse attention 的 apple to apple 比较。要是有一个地方能做实验、apple to apple 比一下，让大家更清楚就更好了。但现在因为没有人在做这个比较，所以这个问题我也不知道哪个会更好。

杨松琳

论文里还值得关注的：RoPE 还是 NoPE

张小珺

你看那篇 Kimi Linear 的论文，觉得还有哪些是值得大家关注的？

前面说的是线性注意力那个模块。另外可能就是全局注意力里，用 RoPE 还是用 NoPE 的比较。

Kimi 选的是 NoPE，而 Qwen3-Next 选的是保留一部分 RoPE——25% 用 RoPE、75% 不用。我觉得在这种混合注意力里面，大家都在砍 RoPE，只是看砍多少：Qwen3-Next 砍了 75%，Kimi 砍了 100%。

从长度外推来看，现在看起来 RoPE 在这种 hybrid 架构里面可能会比较阻碍长度外推。但这个地方其实也没有共识，有些还是用 RoPE、有些用 NoPE，还有些地方用 partial RoPE。

因为之前对整个领域把握得非常通彻，所以我知道：如果其他人关心这个问题，我应该从什么角度去切入，也知道前面工作有什么问题——比方说 2021 年的 DeltaNet 没有硬件效率的保证。所以做完那个工作之后我就知道，DeltaNet 是一个很好的模型，它的缺点是大家还不能大规模用起来；如果我能开发出一个算法能把它 scale up，那就是一个非常有意义的工作。我大概就是这套逻辑链。然后可能也是运气好，正好能推出一个能够把它 scale up 的算法。

Part 6 · 考古：从 Transformer 开始的算法变种史

三个模块，各自的变种

张小珺

你刚才提到读博士前半年做了很多算法考古，能给大家讲讲算法是怎么一步步演进到今天的吗？

杨松琳

那我从 Transformer 开始讲吧。Transformer 大概三个主要模块：一个是注意力机制，一个是位置编码，最后是 FFN。

最开始那几年架构 research 非常多，有一些改进也确实被用到了今天。比方说相对位置编码、比方说 RoPE（旋转位置编码）——今天基本上都改成这种相对位置编码了。

像 MoE，我觉得可能也是从 2021 年左右就开始发展了。中间有段时间大家不怎么信 MoE，后面又发现——比方说 DeepSeek 把 MoE 做通了——大家又回来重新做 MoE，现在 MoE 应该是大家都会用的东西了。

而注意力的变种可能就更多了。前面说到 2020 年前后，attention 的变种非常非常多，其实也主要就是两种：第一种是线性注意力，第二种是稀疏注意力。

线性注意力那一批，会搞很多用 kernel method 去逼近 softmax attention 的做法。在今天来看，我觉得这是一个非常错误的方向——不应该去用 kernel method 估计 softmax attention。

好工作被埋在文献海里

杨松琳

有一些好工作可能因为没有 follow-up，就被埋没在文献海里面了。

比方说 DeltaNet 这个工作，前面也说了它 2021 年就有了，但 Delta Rule 那个东西后面几年根本没有人 take it seriously，没有什么 follow-up work。

从演化的时间线来说，有一些技术很多年前就有了。比方说这种细粒度的遗忘、细粒度的 decay，至少 2022 年就已经有一篇工作了；最早的话，我可以考古到 2016 年。但后面比方说 2023 年，反而用的是一个粒度更粗的 decay。所以我觉得可能是之前的技术没能更好地传承下来。

而我又比较喜欢把之前所有的技术全部重新审视一遍，然后选一些我觉得最 make sense 的技术来做。可能就比方说 Delta Rule 这个技术，又可以重现光芒吧。但如果没有我来 follow，可能就不好说了，这一套技术路线可能就会一直埋在文献海里面。

像 sparse attention，他们最早可能做一些 static 的 sparse attention，像 Nyströmformer、BigBird，会有各种各样的 sparse attention，后面好像就逐渐收敛到用 sliding window 了。近几年会有一些不一样的东西出来——早几年比较少、最近又比较多的，比方说动态稀疏：像 Kimi 的 MoBA、DeepSeek 的 Sparse Attention 都属于动态稀疏。

总的来说，整体还在不断演进，有些技术可能需要被 rethink 几次。多多少少，这个发展还是有点螺旋上升的味道在里面。

张小珺

其实历史中已经有很多工具，但今天我们要拿哪些工具来推动今天的算法演进，其实是一个很关键的事儿。

杨松琳

对。我觉得很多历史上的算法其实很先进，但当时的同行没有意识到这个工作的价值，那个工作就被埋没了；也有可能是那个工作的配套——比方说开源代码——做得太烂了，其他人想 follow 也没法 follow。

所以如果今天做工作，我就会把代码做好、让大家好用，这样这一套技术肯定能流传下去。而对于别人之前的工作，我会找一些我觉得 make sense 的，尽可能看看它的潜力有多大。

再说回架构里面的算法：算法的 variant 太多了，试架构肯定还是需要很多算力来试的；而且有很多算法可能只在小规模下面 work，到大规模就不 work 了，这非常常见。可能像今年国内公司又对开源重新有兴趣了，那今年大家见到的架构开源工作会更多一点，架构的变化相较去年可能会多很多。

Delta Rule 的灵感，与我看算法的方式

张小珺

你的 Delta Rule 是什么给你带来的灵感？

杨松琳

就是 2021 年那个工作，是他们提出来的。我想了一个并行算法，其实就挺类似于 FlashAttention 之于 Softmax Attention——就是一个能让它硬件高效实现的算法。如果没有 FlashAttention，self-attention 也走不到今天；没有那个并行算法，DeltaNet 肯定也不能走到今天，大概是这样一个关系。

我做研究比较喜欢从硬件亲和力的角度来看：我看一个算法有没有潜力，会分析它的并行潜力有多大、scalability 有多大。然后我会在历史的文献海里面，找出一些在 machine learning 上 make sense、同时我又能想办法把它并行化的算法来做。这是我做 research 的思路。

总的来说，还是要在 machine learning 上 make sense、同时又能有并行算法，这样的算法才能在这个年代被用起来——因为在大模型的年代，你肯定需要一些 scalable 的算法。如果一个算法本身就很 make sense，比方说 Delta Rule，同时 scalability 又比较好，那就完全有可能在今天这个时代带来一些不一样的架构。比方说 Qwen3-Next 和 Kimi Linear，就已经给这个新架构领域带来了一些新气象。

Transformer 是这一代硬件的天选架构

张小珺

我前几天做了一个论文的博客，就提到 Transformer 是这一代硬件的天选架构。

杨松琳

对，Transformer 肯定是天选的——它当时设计出来就是为了让它在硬件上快。

FFN 那不用说了，都是大矩阵乘法，肯定快。而 attention——在 attention 之前，大家是用 LSTM 这种不能并行的模块来做的，LSTM 的硬件加速更难搞；attention 就算它是平方复杂度、比 RNN 高了一个级别，但它可以通过矩阵乘法算出来，所以硬件亲和比 RNN 要好很多。大家宁愿用理论复杂度更高的 Transformer，也不用理论复杂度更低的 LSTM，因为它们的硬件亲和表现完全不一样。

我觉得算法整体的发展，就是要找到这些硬件亲和、同时又更好的算法。因为 Transformer 不但硬件更亲和，它确实也解决了一些长程依赖的问题，所以才会流行得这么开。

像今天线性注意力重新登上舞台，也离不开这一系列的发展：比方说把它分成 chunk 的那些并行算法、更强的那些设计，能让它从建模能力的角度更加 make sense——这些才是推动它发展的原动力。

所以我还是非常主张做一些非常 principled 的东西：从数学上是 make sense 的、mathematically grounded 的，比方说 Delta Rule；同时又是 hardware-aligned 的模型。

因为做模型肯定要结合当前的硬件。有些人会说：我设计一个算法足够好，硬件公司来帮我优化呀——那怎么可能呢？你这算法是金子做的还是银子做的，能让硬件公司天天帮你优化？那是不可能的。

你首先要让你的算法满足一些非常通用的原则。硬件有一些 principle，像 memory hierarchy、像矩阵乘法更快，这些东西你不论看哪种类型的 hardware，基本上都遵从——是一些 universal 的 principle。你可能没必要专门针对 H100 去优化，但我觉得做算法至少要满足这些硬件比较通用的原则；要不然在当今这个讲 scalability 的场景下面，做的算法基本上就没有什么实际价值，纯自娱自乐。

Kimi 的硬件优化，与 kernel 这个工种

张小珺

Kimi 这个对于硬件有做什么样的优化吗？

杨松琳

Kimi 的算法还是硬件亲和的。kernel 的话，现在应该还是张宇写的那个 Triton 的版本，凑合用。

我相信大家都没有那么多——优化是一个非常耗时的工种，非常需要时间，要慢慢磨，要老师傅慢慢来打磨。在快速迭代的时候，大家愿意用 Triton 写一下、凑合用就行了；如果验出来有用，后面再补一些 CUDA kernel 也是可以的。就我所知，他们现在应该还在用 Triton kernel 在训，我不知道后面会不会找人来写 CUDA kernel。

硬件与 Transformer 的协同演进

张小珺

从硬件亲和的角度，你觉得下一代的算法会怎么演进？

杨松琳

现在硬件的演进跟 Transformer 是有一点协同演进的——硬件会变成 Transformer 更喜欢的模样。所以对于一些 alternative 来说，其实是有一些不好的因素在里面的。

因为现在的硬件，大家会发现它就是为了优化矩阵乘、让矩阵乘越快越好——因为 Transformer 里面有大量的矩阵乘。比方说 Tensor Core、像 TMA 这种东西，还有最近的 Blackwell 上面，专门针对矩阵乘还有单独的一块 memory，这都是来优化矩阵乘的。所以大家会看到 FlashAttention 越来越快，FA4 在 Blackwell 上面会越来越快。

既然硬件是这么 evolve 的，那从设计算法的角度看，你就必须要设计一些能用上矩阵乘法的算法，要不然硬件效率肯定跟不上。像 linear attention 的 chunk 算法有个好处，就是它基本上都是一些矩阵乘；当然它还会有一些其他的 overhead，那可能就得克服一下。

它在 training 的时候可能还是不如 FlashAttention-4 在 Blackwell 上面高效。但其实也无所谓——很多地方不 care 训练效率，只 care inference 效率。所以我觉得只要训练时能以 reasonable 的速度来训、reasonable 的速度来 prefill，然后 decoding 快，这种架构其实也是有市场的。

另外，比方说细粒度 MoE、sparse attention 这种「降 FLOPs、又能用矩阵乘法」的，都属于这种类型：还是要用矩阵乘法，同时想办法通过算法创新把 FLOPs 打下去。一个算法里面基本上都是矩阵乘，那它在 hardware 上相对而言还是挺好优化的。

因为硬件就是奔着「矩阵乘法越来越快」的方向在走。甚至说，矩阵乘太快了，导致 softmax 里面那个 exponential 模块都变成瓶颈了——所以 FA4 会用一些 approximate 的方法来算 exp。这个也挺好笑的：就是矩阵乘太快了。

那我们现在还是要尽量去利用矩阵乘快速这个性质，去设计一些算法。

DeepSeek 的软硬协同

杨松琳

我觉得像 DeepSeek Sparse Attention，它就已经用到了这种性质。DeepSeek 是一个非常非常注重硬件和算法协同设计的公司。

像 DSA，它会有一个 indexer，用 FP8 来算那个分数。因为它不需要 softmax，只需要算 logits，再做 top-k 来选。所以首先它是 FP8，其次它又可以把那个昂贵的 exponential 操作去掉；这样基本上就是一大堆矩阵乘，所以那个 indexer 会非常快。

这样就有可能被用到他们下一代的架构里——我也不知道他们下一代架构是什么，但这些性质在那里，就有可能作为下一代架构的一个 candidate。

杨松琳

DeepSeek，absolutely。

张小珺

Kimi 没有把这个作为一个重要的优化目标，对吧？

杨松琳

不太确定。我觉得 Kimi 肯定还是会 scale up 硬件上面的东西，但没有 DeepSeek 那么追求。DeepSeek 我觉得他们非常追求这种——比方说这个算法能不能在 FP8 上面跑。

我觉得他们的 infra 在算法迭代过程中的话语权会比较高。这个都是因公司而异的：有些公司 infra 的话语权高一些，有些公司算法的话语权高一些——感觉算法就经常会搞一些让 infra 不爽的东西出来。
