杨松琳

嗯，哈喽大家好，我叫杨松琳，我现在是 MIT CSAIL 的一名 PhD 学生在读，然后我老板是 Yoon Kim。博士期间主要的研究方向就是注意力机制，然后主要是线性注意力这个方面。

一、注意力机制到底在做什么

曼祺

年初我们有两期节目讨论过注意力机制，因为这也是 Transformer 大语言模型里的一个核心机制。一期是 103 期，是和 InfLLM 的作者肖朝军、还有 MoBA 的作者付天宇一起聊稀疏注意力机制的改进；然后是 104 期，和当时在 MiniMax 的钟怡然聊线性注意力机制。

因为有一些听友可能对注意力机制还不是那么了解，所以松琳你可以先简单地从你的角度解释一下：注意力机制在大语言模型里面是一个什么作用，以及为什么很重要？

杨松琳

注意力机制的话，通俗来讲它就是一个上下文的处理机器。

就是你有一段话，你后面的话如果想用到前面这些话的信息的话，那你必须要有一些能够在句子这个维度上面做运算的操作；然后注意力机制就是一个非常典型的做这种运算的代表。

一般的话，我们可以管这种在序列上面做的 mixing 叫做 sequence mixing——就是我们会把不同位置的那些信息混合起来，得到当前的一个 representation 来预测下一个词，然后我们就想尽可能去 uncover 前面的那些信息。

然后注意力机制它就是一个非常直接的、通过建模两点之间 pairwise 的直接交互的这么一种机制。对，所以它是一个平方的机制。

嗯，注意力机制现在应该也可以泛指这一类在序列维度上面做信息聚合、或者信息交互的算子，比方说这种线性注意力——然后有一些可能就已经没有那种注意力的 interaction 了。

曼祺

对，你的意思就是说它最开始的那个版本是一个平方的关系，就相当于它要算每个词和每个词之间的相关性吧、或者说它的联系；但现在你说它也可以泛指一些只要有方法能去表达这个关系的东西，可能已经有很多不是……比如说线性的改进其实就是这个方向上的。

杨松琳

我觉得注意力不一定要用这种 pairwise、就是两两之间直接建模注意力的方式来做，但是我们肯定需要有一些在序列长度上面做信息聚合的操作。

对，所以我们可能可以提出很多各种各样的这种操作，但平方的话，它就是最直接、然后最被大家常用到的。

二、DeltaNet 的提出：用 delta rule 增强 in-context retrieval

曼祺

对，因为其实你的工作也是对这个领域的一个改进嘛，然后我们可以从最近的一些进展开始聊。

为什么这次我特别想找到你来聊这个注意力机制？也是因为有好几个新的动向都是和 DeltaNet 有关的：一个是 9 月 12 号的时候，阿里那边发布了 Qwen3-Next 开源模型；然后再就是 10 月底，月之暗面发布了他们的开源线性模型 Kimi Linear——这里面都用到了 DeltaNet 的一些成果吧。

比如说 Qwen3-Next 的技术报告里就提到了，他们是在注意力模块混合使用了 Gated DeltaNet attention 和 Gated attention；那 Kimi 开源的这个新的线性注意力机制，它就是叫 Kimi Delta Attention，包括我看 Kimi 也把这个新的机制简称为 KDA，也是放到了你在发起和维护的这个开源线性注意力小组 FLA 在 GitHub 上，这个大家也可以去看。

就是你可以给我们简单地介绍一下这些业界的新应用和 DeltaNet 之间的关系吗？

杨松琳

嗯，好呀。我可以大概简单讲一下 DeltaNet 是个什么东西。

最开始的话，比方说那种线性注意力，基本上就是把 softmax 那个操作扔掉，然后就变成线性注意力了。因为你把 softmax 扔掉，它本来就已经线性了，再通过一些数学变换，就可以把它写成一个 RNN 的形式——对，这个结论应该挺经典的。

然后后面几代的话，就是在研究怎么改善线性注意力这种机制。因为它这种机制虽然最开始的时候可以写成 RNN 做 inference，但是首先那个时候好像也没有搞明白要怎么高效地训它，然后那个年代也没有把这个东西在 language modeling 上面做得很 work。

然后后面有一系列的改进，常见的就是加 gating，或者加 delta rule。

像加 delta rule 这个思路的话，最早是 2021 年，就是 LSTM 的那个作者、他们那个团队，当时做的一篇 paper 应该叫做 《Linear Transformers Are Secretly Fast Weight Programmers》，这应该是一篇 ICML 2021 的 paper。

在这个里面，它就是把线性注意力用比较传统的 Fast Weight Programming 的视角来解释了一遍——这怎么翻译呢，「快速权重变换」。

然后他们就说：这个 fast weight 的更新可以用一些更强的 rule。像线性注意力用的是那个叫做 Hebbian 的 update rule，然后他们在那篇文章里就提出了 delta rule。

然后就相当于是用 delta rule 这个机制来增强整个模型的一种叫做 in-context retrieval 的能力。

in-context retrieval 的话就是：比方说在模型前面的 context 里放一些 key-value 的关联对，然后想让模型能够正确地通过这个 key 来找到它所关联的 value。

这就是 DeltaNet 当时诞生的背景。

但是我觉得 DeltaNet 在那个时候可能没有受到太多的重视。

一方面，像线性注意力，它近几年在网络架构层面有很多改进了，就是有很多东西如果没有这些改进就不 work 了。

比如有一个改进叫做 short convolution——short convolution 的话就是短卷积，它是当代线性注意力一个非常重要的模块。然后它可以看成 RWKV 之前那个 token shift 的一个 extension：它相当于每一个 token 有一个单向的卷积操作，每个 token 大概你可以理解成，它不仅可以看自己这个 token，还可以看前面三个 token 的信息，这是短卷积。

然后另外的话呢，还有比方说在输出的地方加上 output norm 或者 output gate，这两个东西对结果也挺重要的。对，这都是一些比较现代一点的网络架构改进，现在很多线性注意力都是会采用这些模块的。

所以 DeltaNet 在当时那个条件下没有火起来：一方面是它缺少一些必要的、当代的网络模块，能让这些线性注意力的模型表现得很好。

然后另外一方面呢，也是 DeltaNet 当时没有一个很好的实现。它作者提供的那个实现，其实是一个用 CUDA 写的循环的实现——虽然它是能用的，但是那个速度比较感人。

直到比方说我去年的时候发了一篇文章，叫做 《Parallelizing Linear Transformers with the Delta Rule over Sequence Length》，这一篇 NeurIPS 文章。这篇文章就是来探讨怎么去并行化 DeltaNet 的这个循环递归。

三、近年的改进主要在模型架构，而不在「更新规则」

曼祺

对，因为你刚讲的这些还是挺硬核的，有些可能要给不是做研究的人稍微解释一下。你说最开始是大家把 softmax 丢掉，然后直接到 RNN，对吧——就相当于回到之前那种循环神经网络的方式。这个大概是在什么阶段呀？比如哪一年有这个探索？

杨松琳

嗯，应该就是 2020 年吧，有一篇 paper 叫 《Transformers are RNNs》，就是最早提出「你可以把它看成这个概念」。

后面很多年——包括 DeltaNet，它也是 2021 年做的——这些工作其实都挺早的。但是在当时那个条件下，既没有硬件加速，又缺少一些当代的网络模块，比方说前面提到的短卷积，比方说前面提到的输出的 normalization 和输出的门控。这就导致这两个模型在当时既慢、效果又不是特别好，所以可能很长时间就被大家忽略掉了。

然后最近几年呢，现代的这种网络模块其实有很多发展，短卷积、输出的 normalization、门控基本都是标配了。这个时候的话，你就算是一个比较简单的 linear attention，你给它加一个 RoPE、再加一个简单的 decay，它就可以表现得挺好的了。

对，这其实就是有一篇工作叫做 RetNet，它是微软亚研院的一个工作，这就是那篇工作的核心 idea。像 MiniMax 他们做的那一些，也是在这个基础上面加了一个简单的 decay，他们管这个叫 Lightning Attention。

所以我觉得这些工作可能更多还是在网络架构的改进上，而不是在更新规则的改进上。当然这些工作肯定是为这种网络架构的改进做出了很多贡献。

像之前 Lightning Attention 之前叫 TransNormer，然后它更早之前就是把 output normalization 推出来的；然后后面 RetNet 又推用了 output gate、就是输出门这个模块；然后再往后面，Mamba 直接把短卷积这个模块带火了。

就是感觉前几年的进展主要是在网络的小模块上的进展，跟整体的这个 RNN 线性注意力的更新公式呢，是没有什么太大的、有点乏善可陈。对，包括像 Lightning Attention 那样，它的更新规则都是在最开始的基础上面加一些简单的 decay。

曼祺

那更新规则的大的改进是最近发生的什么？比如说你 24 年你们发的那个论文里，是有一些更新规则的改进。

杨松琳

像更新规则改进的话，我觉得我们也没有发明一些特别新的东西吧，我们就是发明一些新的算法，然后让一些比较老的技术能够让大家重新看到它的潜力。

就比方说像 delta rule 这一个机制，我前面应该也提到了，它 2021 年就有了，但是它后面几年都没有人用；然后我去年 NeurIPS 就是提出了一个并行的算法，能让它 scalable 地来训练。

然后紧接着呢，我去年在英伟达实习的一个工作就叫做 Gated DeltaNet，它其实就是在 DeltaNet 基础上面加上一些衰减的 decay 这些 term。Gated DeltaNet 其实可以看成是 DeltaNet 和 Mamba2 的一个结合。

然后 Gated DeltaNet 呢，就是它既继承了 RetNet、继承了 linear attention 这种比较当代的网络架构，又拥有最开始 DeltaNet 那些从理论上更新得更好的规则；然后再加上衰减——像衰减就是类似于遗忘门。

遗忘门在 RNN 里面就非常重要，因为 RNN 的 hidden state 大小就那么大，所以它肯定需要遗忘一些信息，要不然的话，它有限的这个空间如果把所有的都记下来的话，它就会撑爆。

然后所以就到了我们这个 Gated DeltaNet。这个架构在今年应该是被千问团队比较认真地试了一下，当时从他们那个博客我看到——他们跑了一些全注意力、混闪电注意力（Lightning Attention）、然后还混那个 Mamba2、然后再混那个 Gated DeltaNet，做了一些 apple-to-apple 的比较，然后他们就发现 Gated DeltaNet 应该是最好用的一个版本，所以他们就用到 Qwen3 的模型里面了。

像 Kimi 用到的那个 KDA 呢，它应该就是 Gated DeltaNet 的一个改进版本：DeltaNet 的那个部分是保持在那里没有变的，然后它把衰减的那个部分，从一个非常粗粒度的衰减变成了一个非常细粒度的衰减。

原来的话，比方说你 head dimension 是 128、你有 128 个 channel，那这 128 个 channel 需要去共享一个遗忘率；然后现在的话，就相当于给每一个 channel、每一个维度一个独立的遗忘率。这样的话，可能有一些维度它能忘得更快，然后有些维度就可以忘得更慢，用来记一些更长程的东西。

然后这种细粒度的 decay，它其实历史也挺多的。比方说像最近的，我 ICML 2024 发表了一个工作叫做 Gated Linear Attention，它其实就是用到了这种细粒度衰减的思想。

嗯，KDA 这个模块就是可以看成是 Gated Linear Attention 和 DeltaNet 的一个 combination；然后 Gated DeltaNet 就可以看成 DeltaNet 和 Mamba2 的一个 combination。它们的主要区别就类似于 GLA 和 Mamba2 的区别，就是在那个衰减的粒度上面。

曼祺

所以其实大家都是用了很多之前可能已经存在一段时间、但由于一些限制以前效果没有那么好的东西；但现在包括算力、硬件各方面更 ready 了，然后它的效果就体现出来了。

嗯，就是你刚刚说的 Qwen3 的那个成果，对吧，他们也做了一些比较——他们有混 Mamba 也有混 Gated DeltaNet，然后是觉得 Gated DeltaNet 效果是更好的，包括 KDA。

四、更新规则和模型架构改进的区别：更新规则是在算子层面「动刀」

曼祺

对。你可以给大家解释一下，这个「更新规则的改进」和「模型架构的改进」的区别是什么？

杨松琳

我觉得架构改进它分成两个模块吧，一个是网络的改进，然后一个是算子的改进。

像网络的改进呢，比方说像这种在输出上面加个门控——像这个思想，之前在 LSTM 里面就用到了很多；然后像千问最近有一篇工作叫做 Gated Attention，它也是在输出上面加了一个门控。

我觉得这一类的改进基本上都可以叫做是网络架构上的改进，它主要动的是网络架构。它真正做运算的那些算子——比方说像 Gated Attention 里面，它还是用 GQA 来作为最基本的算子，还是用 FlashAttention 去算。所以这个中间的算子，它可能就是更加算法层面的了。

然后更改更新规则的话，它就是在这个算子的层面上面来动刀；然后外面那些网络架构其实就都可以随便用——比方说最近那些大家都验完、效果好的那些架构，我们就跟着用。我们只需要把那个核心的、中间的那个算法（就是它定义如何在序列上面做 mixing 的这个操作）进行一些改善。

然后像这个更新规则，DeltaNet 的话，它直接反映在那个线性注意力所对应的 RNN 的转移矩阵上面。

还交代一个前提吧：线性注意力一般是可以写成一个一阶的线性递归。一般这种一阶线性递归会有比方说那种转移矩阵，然后它会有一些 input。

然后像 linear attention 的话，它的 input 一般就是一个外积，然后 linear attention 的转移矩阵其实是一个 identity 矩阵；之后像 GLA 呀、像 Mamba 呀，就把这个 identity 的转移矩阵换成了一些 diagonal 的转移矩阵；然后像 DeltaNet，它其实是把这个转移矩阵变成了一个 identity plus low rank——就是一个 identity 加上一个 low rank 这个形式。

然后像 Kimi 最近的这个工作，他就是把那个 identity 的部分又 relax 成 diagonal、对角的一个可以学的矩阵。像 RWKV-7 的话，它也是用到这种 DPLR 类型的转移矩阵——DPLR 的话就是 diagonal plus low rank。

曼祺

其实这些部分我都不太能听懂，但是我觉得到时候我们可以把这个内容保留下来，因为我觉得对做研究的人来说，这个信息肯定还是有价值的。

五之二、为什么现在都是混合架构

曼祺

然后我们可以回到 DeltaNet 相关的一些进展。因为刚才也说到 Qwen3-Next、还有 Kimi Linear 都有用到嘛，然后我也注意到他们都是一个混合的架构。

就是为什么现在大家会采用这种线性和之前的 full attention 混在一起的结构啊？他不能全部都用线性的原因是什么？

杨松琳

我觉得主要还是长文本吧。

因为线性的话，它的容量是有限的——它每一层有一个 RNN 的隐藏状态，那个大小是固定的；然后当你所有的层都固定住了，那么你整体的状态数量大小就是可以算出来的，它是一个常数。

然后就是，当你的序列长度变长的时候，你的整体容量并不会变。所以如果是这种纯线性的模型，它在短文本上面可能还可以应付，那到长文本下面的话，基本上表现就会非常烂——主要还是这种容量太小了，这个大家应该是有共识的。

然后像注意力机制的话，在传统的 softmax attention 里，他们有 KV cache——你可以把 KV cache 也看成隐藏状态。然后他们就是 token 越多，隐藏状态、就是这个 KV cache 就会线性地增加，一个 token 一个 KV cache；那这样的话，它长文本是根本不会被容量这个问题给绑住的，因为每个历史 token 都有一个属于它自己的 state。

嗯，然后 attention 所有 inference 的困难，其实也是来源于它这个 state 太多了。KV cache 线性增加到一段时间之后——因为推理它本身是一个 memory bound 的过程，就是它取决于你从 global memory 里面去读取多少的状态数——然后像 KV cache 就要读整个 KV cache，那这个就会很慢。

曼祺

所以 softmax 是解决长文本的这个问题，因为线性可能会遗忘之前的一些东西，对吧？那混这个线性的话，线性主要是解决的效率问题。

杨松琳

因为如果所有层都是 full attention 的话，那它做 inference 的时候——尤其是长文本做 inference——迟早会被 KV cache 这种 unbound 的增长把速度拖下来。

六、稀疏注意力 vs 线性注意力：潜力对比

曼祺

哎，从你自己的角度，你觉得稀疏注意力和线性注意力，它们未来的潜力或者说空间有什么区别？

杨松琳

嗯，我觉得就单看一层来看潜力的话，那肯定稀疏注意力更强。

因为像现在这些动态的稀疏注意力，它都是要把 KV cache 全部存下来——把这些 KV cache 存下来了，大家会有满满的安全感，这种 token 它不容易掉；然后理论上呢，这个模型有足够多的 KV cache，它能够把相关的那些 KV cache 找回来，这样的话就可以逼近 softmax attention。因为 softmax attention 大家写出来都发现，它那个 attention map 是相当稀疏的。

嗯，所以单看一层来说，sparse attention 当然更好了。

然后像线性注意力，它就是有一些理论上的缺陷——因为它那个 state size 固定死了。

但是这个东西我觉得是一把双刃剑：因为它既是理论上的缺陷，又是它做 inference 加速的动力——因为它 state size 更少，所以 inference 可以加速。

sparse attention 是通过减少激活的 KV cache 的读取来起到加速作用的；但是 sparse attention、就是这种动态 sparse attention 这条路径，它其实是没有省 KV cache 的——还是需要存这么多 KV cache，只是你每一次做运算的时候动态地选一些 KV cache 出来，你用得比较少。

对对对。但是 eventually，规模很大的时候、序列很长的时候，当这个 KV cache size 本身成为一个瓶颈的时候，这个稀疏注意力我觉得它就是爱莫能助的了，没有办法去减少 KV cache 的 size。

然后像 hybrid 这种线性的话，因为它一般是 75% 的层都被换成了 RNN，那这些在长文本推理的时候，这些 RNN 的 state 大小基本上可以忽略不计——这样的话，它们的 KV cache size 就基本上减了 3/4。

嗯，这样的话它们就可以去支持更大的 batch size 来做 inference。对，然后 batch size 更大的话，我们都知道 batch size 越大，做 inference 的效率肯定就越高——我们可以 batchify 很多操作，然后同时来 serve 很多 user 之类的。

七、即使算力无限，线性注意力仍有价值：瓶颈在数据

杨松琳

像这种 full attention，它这种 data efficiency 肯定是更差的，因为它没有那种 inductive bias，它是一个全局的注意力。然后如果当你的 data 比较固定的话，那你全局注意力学它，可能就会变得比较慢。

这时候的话，我觉得可能 full attention 反而是一个劣势吧——因为它的 inductive bias 太差。虽然你喂它足够多的数据它也能学出来，但是如果数据变成一个 bound 的话，那这个东西反而会变成一个劣势。

曼祺

杨松琳

曼祺

杨松琳

嗯，那肯定要带一些先验嘛，inductive bias 它就是先验。

然后甚至比方说像 post-training、像 RL 这些场景下面，它的 data 是更加被绑住的，它不像 pretrain 那样有非常多的 data。所以说不定像 hybrid 这种线性的架构，它的优势就会在这种 post-training 上面体现出来。

八、线性注意力在状态追踪上的效果优势，而状态追踪对 Agentic 很重要

十二、发现 Householder 累乘和 DeltaNet 关联的过程

曼祺

它的难点的话，就像一个线性的 recurrent，如果我们想要并行的话，那肯定就把它展开；然后展开完之后，我们就有一个转移矩阵——那个转移矩阵一展开，它就会有一个累乘的项在那个地方。

然后后面突然发现这个 Householder 的累乘，它其实是有一个算法叫做 WY 算法——然后这个算法它就相当于把一个累乘变成一个累加。然后我一看到累加，我想：哎，这不就是线性注意力它的形式吗？

然后我就意识到，它 Householder 的累乘和线性注意力的 chunkwise 算法，可能就有一些能够兼容的部分。然后我后面推了一段时间，我终于推出来一个这样子的算法，然后还挺开心的——就推到一个这么一个比较好玩的算法，然后可以把 DeltaNet 这个工作把它 scale up。

杨松琳

我觉得做 research 你肯定就是突然你就想通了，可能。

对，就比方说突然盯着那个形式看，然后盯了一会，然后想：哎，这玩意——它这个 transition matrix 不就应该是一个 Householder 的矩阵吗？

然后我就想，那我是不是可以把它 reduce 成一个 Householder 累乘的算法，然后去搜相关的 literature；然后就发现可以搜到一些 numerical linear algebra 里面一些比较经典的算法。然后我又发现这些算法它就可以跟线性注意力的算法完美地融成一体——对，我觉得这个就有点吓一跳。

然后这个 SuPar 呢，我感觉他是维护得相当好的：他会有一些非常 clean 的并行实现，然后效率都挺好的。然后当时我觉得所有的 parsing researcher 都会来用这个库来做相应的 research，然后当时觉得这个库非常的酷。

然后当时想做 FLA 的时候，我第一时间就想到赶紧把张宇拉过来，因为他做库很有水平嘛——对，他之前就有维护开源库的经验，然后我感觉他是一个写这种并行算法、写 kernel 的苗子。虽然他当时应该还没有大规模地写这个，但他之前就喜欢写这种东西嘛；然后我觉得把他拉过来，他兴趣上面也会比较感兴趣，然后我就把他拉过来一起来做这个开源库了。

然后你要是翻 FLA 的 commit 记录，无论是 in terms of 贡献的行数还是总体的 commit 数，他都是最多的——对，他是这个库里写得最多的。我觉得他写代码写得非常厉害。

然后后面也是 Kimi 想做这种 hybrid 的理念，那可能就来找 FLA 这个库的作者嘛。像我在美国，他们肯定也不能把我弄过去，那他就把张宇弄到 Kimi 去来做这种研究。

曼祺

哦，所以张宇是先和你一起在做 FLA，然后他才去的 Kimi？你们刚开始、就去年的时候，他那会儿还不在 Kimi？

嗯，我看到他的头像是个二次元啊，一个少女，一个少女拿着一个什么实验仪器吗？还是什么东西？

杨松琳

经典 stereotype 了，就是二次元头像的人，搞 coding 的——这个非常刻板印象。

曼祺

所以相当于 Kimi 他们有关注到这个方向，然后也定向地找了一些这个方向做得比较好的人。

杨松琳

杨松琳

我听说好像是 Tim 来判的，对，就是周昕宇。对，但是其实我也不太了解——对，因为我毕竟也不是在他们那里上班，对吧？

曼祺

对。我觉得 Kimi 的模型上的产出还是挺强的，其实他 K1.5 的时候就挺强的，只不过当时 DeepSeek R1 肯定是最吸引关注的。

杨松琳

嗯，对啊。感觉他就经常喜欢对着 DeepSeek 干——对，DeepSeek 出一个 NSA，他出一个 MoBA，都来做 sparse attention；然后现在起名也要对着干了，DeepSeek 出一个 DeepSeek Sparse Attention，他要来一个对仗的名字，所以就有 Kimi Delta Attention 的诞生了。

十四、稀疏注意力的改进：DeepSeek 年初 NSA 到最近 DSA 的变化

曼祺

你觉得再往下的话，整个注意力的演进趋势可能是什么样？可以分线性注意力和稀疏注意力都聊一下，如果稀疏注意力那边你也有一些了解的话。

杨松琳

嗯，我觉得稀疏注意力的话，我本身还是挺熟这一块领域的，对。因为我觉得做架构的一般都会关心不同 subarea 的进展。

然后像稀疏注意力的话，它主要就是想做一些动态的稀疏，因为之前那些比较静态的稀疏可能就是效果不太好。然后动态稀疏的话，就是一个 token 它动态来决定哪些东西要跟它有关联，对吧。

对。然后我觉得稀疏注意力那边可能还是也是卡在「你这个实现要怎么硬件高效」。

像 NSA 的话，它也是搞了一些东西能让它硬件高效。就比方说，它有一个 block 的 selection——就是你一次要选一个 block，这样的话你就可以把它连续地读进来，然后一次来做一个运算。

对，然后最近的话，像 DeepSeek Sparse Attention，它好像就把这个东西又扔掉了，它又改回那种完全 unstructured 的 sparse attention 了。

曼祺

它是改成静态的了吗？

杨松琳

它还是动态的，但是它把那个「按 block 来选择」（去掉了）——对，因为按 block 来选择还是一个 constraint。

对，你如果你要选 512 个 token，你是选 512 个单独的 token 好呢，还是按照 block size 32、你选 512 除以 32 个 block 好呢，对吗？那肯定就是从直觉来看，选 512 个单独的 token 要更好嘛。

然后像 DeepSeek Sparse Attention，它就改成这种更灵活的方式了；相对应的，他们可能就会加一些其他的新的改动了。

曼祺

哎，相当于就是它选的这个范围颗粒度变得更细了是吗？它之前是选一块一块，现在可能是选到跟它更相关的单个的、就是你刚刚说直觉上更好的单个 token。

杨松琳

嗯，对对对，它就是变得更加灵活了。

曼祺

但这个就是更难实现的。

杨松琳

对，这东西肯定会有些难度的。

然后像 DSA 处理的那个方法，就是说它会用一个非常非常轻量的、平方复杂度的算子来做一个整体的注意力，然后会得到一个 L² 的矩阵。

因为它这个东西会比较轻量，它这个算子是可以在 FP8 下面做的——因为它这个东西如果选 top-k 的话，它不需要做 online softmax，它不需要做那种 exponential 这种非常吃精度的算法，它其实就是一个矩阵乘法，那它就可以用 FP8 的矩阵乘法来加速。

另外的话，它这个模块本身就比较轻量，所以比方说它那个维度比较小、然后算起来比较快。所以它会有一个比较轻量的这个——他们管这玩意叫 indexer。

然后 indexer 的话，它求出一个整体的注意力，然后它就求 top-k，然后每个 token 就是来找它前面 top-k 个注意力最强的那些 token。

曼祺

嗯，你可以继续说，这是稀疏注意力上的一些演进。

杨松琳

对，这大概就是最近这两个工作的思想。

然后我觉得它想要解决的问题应该还是「如何去把那个 token 选得更准一点」。像那个 block sparsity 的话，我觉得如果你那个 block 没选中，就容易把重要的信息给漏掉；所以研究怎么去把这个 block 选准，我觉得这是一个非常有价值的问题。

然后另外一方面，比方说像 DeepSeek 一样走这种 token level 的 sparsity，那它其实训练起来的话，它没有从预训练开始就开始做——它其实是从 mid-training 开始的。

嗯，它会先跑一个蒸馏：它会把最开始的 V3.1 转成一个 MQA，然后把 attention 的那个 distribution 拿来蒸馏这个 indexer，然后来得到一个初始化。

嗯，对。然后有一些——因为这种稀疏，我觉得好像是有一些梯度传递的问题；然后可能 sparse attention 它 block 之所以选不准，可能也跟这种梯度传得准不准挺相关的。然后就是无论什么时候如果有 sparse 的话，那你肯定要想一下这个梯度要怎么更好。

然后大概可能就这样子。然后最后的话，我觉得 sparse attention 也可以想一下：有没有可能稍微丢一下这种 KV cache 呢？

因为现在 sparse attention 它完全不丢 KV cache，那它跟 full attention 一样嘛；所以我前面也讲到，它最后可能还是会被 KV cache 的 size 给 dominate 了。

曼祺

所以就是相比于 full attention，sparse attention 它的推理效率是更高的，但是它存储的负担上还是很大，如果文本越来越长的话。

杨松琳

对啊，因为它还是存全局的 KV cache。

曼祺

那这个方向是有人在探索吗？就是在稀疏注意力的基础上，然后我去掉一些 KV cache，也是有人在做这个方向？

杨松琳

不太确定哎。

十五、线性注意力的改进：从线性混全注意力，到线性混稀疏注意力

曼祺

那你可以讲讲线性注意力机制的改进这一块，再往下你觉得会怎么去演进啊？可能会有些什么趋势？

杨松琳

像线性注意力，我觉得就是——前面也讲了嘛，它主要是两个方面的改进：一个是网络架构上面的，一个是更新规则上面的。

然后像网络架构，我觉得大家可能已经验得差不多了；然后像更新规则的话，可能可以想一下：除了 delta rule 这一种，还有什么更新规则能够更好地并行、同时它又看起来更加 expressive。

然后另外的话，我觉得像 DeltaNet 这一系列沿着这条线走已经有很多 work 了：

就比包括把它加 decay，然后加 fine-grained decay；因为 DeltaNet 它还有一个梯度下降的视角嘛——从 test-time training 的角度来看，它有梯度下降的视角，然后也有一些工作就是每一个 step 它不做一次梯度下降了，它做很多次梯度下降，然后有个工作叫 DeltaProduct。

呃，然后还有一些动态扩容的方法。比方说像那种把 state 看成 MLP 的 weight matrix 的做法——既然 MoE 可以在 weight matrix 上面做 MoE，那我为什么不能在 RNN 的 state 上面来做一个 MoE 呢？所以也有些工作这么做的。

然后最近还有一些，比方说把 sliding window 和线性注意力做一个结合。比方说有个工作叫 Native Hybrid Attention，它相当于就是说它还是保留了 sliding window attention，然后它把 RNN 的那种 state 就可以看成很多个 token；嗯，然后可能外面的就用那种 RNN 来 compress，然后相近的就直接保留那种 sliding window 的形式。

曼祺

就是滑动窗口加线性注意力的结合是吧？

杨松琳

对啊对啊。就是临近 token 就是 sliding window，外面的话就用那种线性。

曼祺

你觉得当前的注意力机制离你理想中所设想的那个状态，它还差什么呀？或者说离大家理想中所设想的状态还差什么？

杨松琳

呃，我先不说理想吧。我觉得我下一波最想看到的，就是有个地方把 sparse attention 加线性注意力把它做通。

因为像 hybrid attention 的话，其实现在还是有全局的 full attention 嘛；有全局 full attention 的话，那其实你在长文本 decode 的时候，你还是会或多或少被这些 global attention 的层影响到。

然后可能可以把这些 full attention 全部换成这种 sparse attention，然后沿着这个路子把它做通。就比方说，你搞一个 DSA 混那个 KDA——对，你搞一个这样子的混法。

对，DeepSeek 和你搞的这种 hybrid，我觉得也挺好的呀。对，你至少可以把长文本的这个问题暂时先彻底搞定嘛，这样的话你 KV cache 的 size 也掉下来了呀，然后你这个 inference 的速度也降下来很多；然后你可能就可以 build 更多的这种 application，然后能做很多长文本的应用，然后可能可以做更多的 agent 的 task。对，我觉得长文本问题还是那种开销还是要来处理一下的。

曼祺

现在大家在混的时候都是混线性注意力和 full attention，而不是直接用线性注意力混稀疏注意力，原因是什么样？就它没有这么容易混起来吗，在现阶段的难点是什么？

杨松琳

啊，我觉得架构 research 它是一个缓慢的过程，它不可能一步子迈这么大，它可能都是慢慢地来嘛。

就是你先保留一些 full attention 来验这个⟨听不清⟩，然后先验完这种 hybrid 的——你 hybrid 先验出来，你再验这个 sparse 也不迟嘛。

然后现在 hybrid，先等那些更大 scale 的旗舰模型验出来了，然后再来验这种 sparse attention 嘛。那肯定不能急嘛，不可以直接最开始就直接来一个非常 crazy 的改动。

然后我觉得架构 research 还是要扎实：就是你一次动一点点，然后你来把这个东西验得非常充分，之后再去动下一个，这样子才能有一些比较实在的进步吧。

曼祺

嗯。所以接下来其实就是我们看这种混合的线性注意力和 full attention 的表现好不好。可能接下来一个比较明显的观察指标就是 K3.5 还有 K3，对吧？它肯定是比较大规模的模型了。如果他们真的用这个 KDA 的话，可以看一看是一个什么效果。

杨松琳

对啊对啊对啊，我觉得这就是一个非常好的观测指标。如果他们最后要上到那个 scale，然后大家可以让子弹再飞一会儿，到时候回来再看一下也不迟嘛。

十六、更广泛来说，关注何种模型演进：持续学习

曼祺

就更广泛来说的话，你现在比较关注大语言模型、或者说这个「预训练加强化学习」再往下走的什么演进趋势啊？

因为业界上有一种讨论，就是会觉得预训练加强化学习已经到了一个比较强的阶段，那可能需要一些新的方法或者说范式吧。有几个讨论得比较热门的方向，包括什么在线学习、持续学习、自主学习等等。

杨松琳

我觉得持续学习应该是大家一个非常关心的问题吧。

这个领域有很多 open question，持续学习到底要怎么搞，大家也没有什么定论；然后感觉大家搞的持续学习，效果好像也没有看到怎么样。

曼祺

但就是说是一个很新的、觉得有前景、然后很早期的状态，路径还很不清楚的状态。

杨松琳

持续学习我觉得它肯定是一个非常重要的东西。

就比方说你 AI 如果能持续学一些外界的东西，这样你可能就不需要隔一段时间重新训一遍了。

然后另外，它有很多商业上的价值：比方说做 personalization——你这个用户不停地交互，然后这个模型就要有这些记忆，然后它能够更好地来记住用户的喜好或者历史的一些事情之类的。

曼祺

现在的模型的记忆，比如说 ChatGPT 它有这个记忆的能力，但它并不是内化在模型里面，它是靠一些工程或者外挂的方式记住你的一些东西，是吗？

杨松琳

嗯，对啊。

像 pretrain 的话，它就是把东西压到 FFN 的那个 weight 里面；然后另外一种就是比如说上下文工程，你就是把那些东西放在 context 上，然后通过这种注意力机制、或者其他东西来 in-context 地学——这是现在主要的两种。当然也有很多那种搞一些 memory 外挂，然后把它加进来。

曼祺

所以如果模型能自己持续学习的话，理论上这个模型就可以变得越来越懂你，或者说它懂某一个场景或者任务。

杨松琳

对，可以这么理解。

曼祺

那这样的话，岂不是上下文工程的空间就变少了？当然这还没实现啊，只是设想一下。

杨松琳

其实这也是一个 open question：就是有一些信息，它到底是存在 weight matrix 里面好呢，还是存在上下文做 KV cache 更好呢？对，我觉得这东西也是没有定论的。

啊，然后其实我觉得这两个是一个 duality（对偶）的问题——梯度下降嘛，你也可以想象成，比方说你上下文学习，你也可以想象成一个梯度下降的问题。

像最近比较流行的这种 test-time training 的这套框架，就相当于你每一个 token 都相当于是一个训练的样本，然后把训练样本喂进去，然后它过一遍 gradient descent 来优化一个目标函数，然后更新它的那个 weight matrix。

然后这边的 weight 就是快速变化的，所以我们也可以把它叫 fast weight；然后 fast weight 在 RNN 里面，它就可以看成是 RNN 的一个隐状态。

然后既然它有这么一个 duality 的问题，那其实我觉得像「FFN 怎么学这种知识」这个东西，其实也是一个很好的、来启发大家解决长文本的东西。

像 FFN 肯定记了⟨数量级听不清⟩的 token，嗯，对，然后它很多还记得还挺牢的。

嗯，你要是比方说你有一个长上下文的问题，那你其实可以把它转换成——你看能不能用类似的这种技术，把它存在一些 weight matrix 里面，这么来动态地做一些 test-time training，然后可能可以实现一些比较好的持续学习的路径吧。我觉得这个路径还是挺看好的。

因为像现在的话，这些 weight matrix 它都是一些 slow weight——就是说它在做 inference 的时候是不更新 weight 的，所以它无法从新的 token 里面学到新的信息。

像 test-time training 或者像 Fast Weight Programmers，它这个 weight matrix 在处理完新的 token 之后是会更新它自己的 weight 的，对，它有一套更新的规则；然后 weight 更新其实跟 RNN 的更新规则也是一个 duality 的关系。

嗯，然后如果我们能把这一套做通的话：首先长文本的问题可以解决——我们可以把它转换成用一个更加 compact 的 matrix 来存很多东西；然后另外，我觉得这个也可以顺便解决一下持续学习这个东西。
