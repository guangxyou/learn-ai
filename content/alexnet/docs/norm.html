六种归一化，差别只在「跟谁一起算统计量」

形式全都是「减掉一个均值、除以一个标准差、再乘个可学习的 γ 加个 β」。 真正的分歧只有一个：那个均值和标准差，是在哪一堆数上算的。

把一个卷积层的输出想成四维张量 N × C × H × W（样本数 × 通道数 × 高 × 宽）。 上图里每一格是一个样本的一个通道，也就是一整张 H×W 的特征图。选中的格子就是「一起算统计量」的那一堆。

每一种解决的是什么问题

Local Response Normalization（本文，2012）

要解决的怎么解决代价
ReLU 无上界，某个神经元可以一路涨上去，主导后面所有层 同一像素位置上，拿相邻 5 个通道的响应平方和当分母，把自己除小 k、n、α、β 四个超参全靠验证集手调，一个可学习参数都没有

只除不减，所以作者自己说叫 brightness normalization 更准确。 换来 top-1 降 1.4%、top-5 降 1.2%。

为什么被否掉：VGG（2014）实测它在 ILSVRC 上没有提升，反而多占显存多花时间。 更根本的问题是「相邻通道」这个前提站不住 —— 卷积核的编号是随机初始化决定的， 第 37 号和第 38 号核之间没有任何理由该互相压制。作者自己在论文里也写了 the ordering of the kernel maps is of course arbitrary。

BatchNorm（2015）

要解决的怎么解决代价
前面的层一更新，后面的层收到的输入分布就变了，学习率被迫压得很低 对每个通道，在整个 batch 和空间位置上算均值方差归一化，再用可学习的 γ、β 把表达力还回去 依赖 batch 大小；训练和推理用两套统计量；序列长度可变时没法用

它是这一串里收益最大的一个：学习率能开大一个量级，初始化不再敏感， 还自带正则化（每个样本的归一化结果取决于同批次的其他样本，相当于注入噪声）， 所以 ResNet 干脆不用 dropout 了。

但它有一个结构性的麻烦：统计量来自「同一批的其他样本」， 这意味着一个样本的输出取决于它跟谁一起进的网络。

推理时没有 batch，只能拿训练期间攒的滑动平均顶上。训练和推理走的是两条路。 batch 小的时候统计量本身就不准，batch = 1 时彻底失效，检测和分割这类大分辨率任务首当其冲。

LayerNorm（2016）

要解决的怎么解决代价
BatchNorm 依赖 batch，循环网络和变长序列上用不了 统计量只在一个样本自己的全部特征维度上算，和 batch 里其他样本无关 卷积网络上通常打不过 BatchNorm，因为它把所有通道混在一起算，抹掉了通道之间的差异

关键性质是「样本独立」：batch 多大都一样，batch = 1 也一样，训练和推理完全一致。 代价是它假设一个样本内的各个特征维度可以放在一起统计，这在视觉里不太成立，在语言里反而合适。

InstanceNorm（2016）与 GroupNorm（2018）

统计范围为什么这么切
InstanceNorm一个样本的一个通道 风格迁移里，一张图的整体对比度和色调本身就是「风格」，逐图逐通道归一化正好把它洗掉
GroupNorm一个样本的一组通道 在 LayerNorm（全部通道一组）和 InstanceNorm（每通道一组）之间取中间值， 默认 32 组。目标是在小 batch 的检测分割任务上顶替 BatchNorm

这两个和 LayerNorm 一样都不看 batch。GroupNorm 的实验结论是： batch 大的时候略输 BatchNorm，batch 降到 2 时大幅胜出（ResNet-50 在 ImageNet 上错误率低 10.6 个百分点），因为它的精度根本不随 batch 变化。

RMSNorm（2019）

要解决的怎么解决代价
LayerNorm 每层都要算一遍均值再做减法，大模型上这部分开销不小 干脆不减均值，分母直接用全部特征维度的均方根，只保留可学习的 γ 丢掉了对平移的稳健性，理论保证比 LayerNorm 弱
这里有个绕回来的地方。RMSNorm 的论证是：LayerNorm 的收益主要来自对缩放的稳健性， 不是对平移的稳健性，所以减均值那一步可以省。形式上它回到了本文 Local Response Normalization 的「只除不减」。 区别在于 RMSNorm 的分母是全部特征维度的均方根、且带可学习的 γ；本文的分母是编号相邻的 5 个核，一个可学习参数都没有。 同样是只除不减，一个是想清楚了才砍掉，一个是当年碰上的。今天 LLaMA、Mistral、Qwen 用的都是 RMSNorm。

Transformer 为什么用 LayerNorm 而不是 BatchNorm

答案不在「哪个更好」这一层。BatchNorm 有几个前提，放到序列生成这个场景里全都不成立。逐条看。

一、序列是变长的，同一位置上的样本数不一样

BatchNorm 要在「同一通道、跨全部样本」上算统计量。搬到序列上， 所谓通道是特征维 d，所谓样本是 batch 里的每个序列。 但一个 batch 里句子长短不齐，短的要 padding。第 5 个位置可能有 32 个真实 token，第 300 个位置只有 2 个。 在这些位置上算出来的均值方差，可靠程度天差地别，而且大量统计量是在 padding 上算的，本身就是噪声。

LayerNorm 完全不碰这个问题：它只在一个 token 自己的 d 个维度上算， 跟这个 batch 里有没有别的句子、有多长，没有任何关系。

二、推理时的行为必须和训练时一致

语言模型是自回归的，一次生成一个 token，实际部署里 batch 大小完全不可控， 可能是 1，可能是几百，还会随着请求动态拼批。 BatchNorm 的输出会随着「同一批里还有谁」而变，这在生成任务里是不能接受的： 同一个 prompt，跟别人一起跑和单独跑，结果不一样。

而且 BatchNorm 推理时要换用滑动平均统计量，训练和推理是两套行为。 LayerNorm 两个阶段是同一个式子。

三、Transformer 的隐藏维度天然适合逐样本统计

dmodel 通常是 512 到 8192。单个 token 的向量里就有几千个数，够算出稳定的均值和方差， 不需要借别的样本来凑样本量。反观卷积网络，LayerNorm 要把所有通道混在一起算， 而不同通道检测的是完全不同的东西（边缘、颜色、纹理），混在一起统计会抹掉这种差异， 这也是 LayerNorm 在视觉上一直打不过 BatchNorm 的原因。同一个设计，在两个领域里的处境正好相反。

四、训练一个模型的成本决定了不能冒险

大模型训练是一次性的长跑，中途发散代价极高。 BatchNorm 引入的「跨样本耦合」会让梯度里混进同批次其他样本的信息， 在数据并行、梯度累积、流水线并行这些切分方式下，还得额外做跨设备的统计量同步（SyncBatchNorm）， 通信开销和实现复杂度都上来了。LayerNorm 是逐样本的，怎么切都不用同步。

BatchNorm 的统计量借自同批次的其他样本。在图像分类里这笔买卖很划算：batch 大、样本等长、 训练推理都能接受滑动平均。搬到序列生成上，同一笔交易只剩负担：变长、batch 不可控、还要求逐样本确定性。 Transformer 要的是「样本独立」这个性质，LayerNorm 只是当时手边最现成的实现。 后来换成 RMSNorm 也没什么阻力，因为真正被依赖的那条性质没变。

后来还动过两次

Pre-LN 取代 Post-LN。原始 Transformer 把 LayerNorm 放在残差相加之后（Post-LN）， 深了之后需要 warmup 才能训起来。后来普遍改成放在子层之前（Pre-LN）， 残差通路上就没有归一化挡着了，warmup 可以去掉，几十上百层也能稳定训。

LayerNorm 换成 RMSNorm。见上一节，省掉减均值那一步。今天主流开源大模型基本都是 Pre-RMSNorm 这个组合。
