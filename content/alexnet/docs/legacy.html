先分清两种贡献

首创是「这个东西第一次出现」，首次做实是「东西早就有，第一次在大规模真实任务上证明它管用」。

这篇论文的分量几乎全在后者。严格意义上的首创只有三条，而且都不算大：

真正的贡献不在创新列表里

它证明了特征也可以学。

在此之前，视觉识别的流水线里只有最后的分类器是学出来的， SIFT、LBP、Fisher 向量全是人写的公式。本文把这二十年的手工积累整体换成了 6000 万个参数。

第 6.1 节的图 3 是这个论点最硬的证据：网络自己学出了方向选择性的边缘检测器和色块检测器， 而这些正是当年由人手编码的东西。这张图后来被引用了无数次，原因就在这里。

这篇论文的性质是一次配方的集成，不是某个单点突破。 ReLU 解决优化速度、GPU 解决算力、dropout 和数据增强解决过拟合、ImageNet 提供数据。 四件事任缺一件都做不成，而它们在 2012 年恰好同时可用。

十二项做法，今天各自的境遇

活下来的四条有个共同点

它们解决的是普适问题，而不是 2012 年的具体困难。

  • ReLU　梯度不衰减是任何深网络都要面对的事。后来的 GELU、SwiGLU 只是在修它的负半轴，整流这个形式没被推翻。
  • 端到端学特征　这条已经不再被当成一个「做法」，它成了默认前提。今天没人会问要不要手工设计特征。
  • 随机裁剪 + 水平翻转　便宜、无害、对齐了图像真实存在的不变性。RandomResizedCrop 只是把它做得更强。
  • SGD + momentum 0.9 + weight decay　三个数字二十年基本没动过。

被否决的两条也有共同点

它们解决的是那一年的具体困难，而且解决得不干净。

  • 局部响应归一化　机制本身站不住：相邻核是随机排的，作者自己写了 the ordering of the kernel maps is of course arbitrary。 收益大概率来自正则化的副作用，而正则化后来有了更好的手段。VGG 实测无效，BatchNorm 全面取代。
  • 巨大的全连接头　fc6 一层占全网 62% 的参数，只为了把 6×6×256 压成 4096。 GoogLeNet 用 global average pooling 直接取消它，参数量从 6000 万降到几百万，精度反而更好。

中间那一档最有意思

它们大多没有消失，而是被搬到了别处。

双 GPU 拆分变成了分组卷积。本来是为绕开 3GB 显存想出的临时方案， ResNeXt 把分组数做成和深度、宽度并列的设计维度，MobileNet 的 depthwise separable 卷积是它的极端情况 （分组数等于通道数），ShuffleNet 又在分组之间加了 channel shuffle 补回被切断的信息流。 一个显存妥协，五年后成了轻量化网络的标准组件。

Dropout 在 CNN 里被 BatchNorm 挤掉，却在 Transformer 里成了标配。 attention dropout、residual dropout 都还在用。不过现在的大模型预训练常常把它设为 0， 因为在万亿 token 上训一两个 epoch 时，模型见到的数据远超它能背下来的量，过拟合不再是主要矛盾。

10-crop 测试变成了 TTA 这个门类。比赛和刷榜里还在用，线上服务基本不用， 十倍推理算力换一个多百分点不划算。

局限：三类

一、三处同源的数值错误

3.5 节写的 224 应该是 227，否则 11×11 / stride 4 得不到 55×55。 Caffe 用 227 裁剪、conv1 不补边；torchvision 用 224 加 padding=2，靠 floor 也落到 55
图 2 图注253,440 对不上 55×55×96 = 290,400。我没能反推出这个数，也没找到权威解释
4.1 节2048 倍应该是 2178，位置数是 (256−224+1)² × 2，每个轴少数了 1

前两处同源：脚注 4 明说图 2 的 224 来自裁剪尺寸，而 150,528 = 224² × 3 说明图注确实按 224 在算。 一个裁剪尺寸写错，牵连了三处数字。另外全篇没有一处提到 padding， 而离了它 conv2 到 conv5 的维度全都对不上。

二、做得不干净的地方

  • 所有消融都是单次测量。1.7% / 1.4% / 0.4% 这些 delta 没有多种子重复、没有方差。 以今天的标准，这些量级的差异需要重复实验才能区分真实效果和运行间波动。 当然，一次训练五六天，做不起，这是时代条件不是作者含糊。
  • 偏置初始化成 1 只用在 conv2 / conv4 / conv5 和全连接隐层，为什么是这几层没有解释。
  • 学习率下降的时点没有记录，这一段严格说不可复现。
  • 连接模式靠交叉验证试出来（a problem for cross-validation），没有原则。
  • 论文不是精确规范，作者自己把这件事推给了 cuda-convnet 的代码。

三、结构上的天花板

这一类才是后续三年真正要解决的。

局限被谁解决
八层就到顶，再深会退化ResNet（2015）的残差连接，做到 152 层
11×11 的大核浪费参数，感受野增长太快VGG 证明堆 3×3 更好；ZFNet 先把 conv1 改小
没有归一化层，靠 weight decay 和初始化硬撑BatchNorm（2015）
参数 96% 堆在全连接头global average pooling（NIN / GoogLeNet）
手写 CUDA kernel，别人复现不了cuDNN（2014）与深度学习框架
只能做分类，不能定位、分割R-CNN 系列、FCN，都是拿它当骨干网改的
这些局限没有一条是「思路错了」，全是「还没做到」。 这也是这篇论文和它同期竞争者的区别：它指出的方向在之后十年里一直是对的， 只是每一处细节都被换掉了。第 7 节最后那句关于视频的设想 （very large and deep convolutional nets on video sequences）后来也兑现了， 只是兑现的形式不是卷积网络。
