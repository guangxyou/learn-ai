### 图 2 到底改了什么（v1 → v2）

- **v1**：`Linear` →（往上）`Split` → `Scaled Dot-Product Attention`，头数标注为大写 **H**。
  画法的含义是：**先做一次线性投影，再切成 h 份**。
- **v2 起**：`Split` 那一行**整排删掉**，`Linear` 变成**层叠的 h 份**（图上能看到堆叠阴影），头数标注改成小写 **h**（和正文式子里的 h 对齐）。
  画法的含义变成：**h 组各自独立的投影** W_i^Q / W_i^K / W_i^V。

改的原因很清楚：v1 的画法和 §3.2.2 的公式不一致 —— 公式写的是 h 组独立投影矩阵。

**但这里有个值得讲的反转**：几乎所有真实实现（含官方 tensor2tensor、nanoGPT、HuggingFace）**做的其实是 v1 那张图** —— 一次大的 Linear 投到 d_model，再 reshape/split 成 h 个头。因为两者数学上完全等价（把 h 个 d_model×d_k 的矩阵横着拼起来就是一个 d_model×d_model 的矩阵），而单次大矩阵乘法快得多。
**所以：论文为了对齐公式把图改"对"了，工程上大家仍按被改掉的那版画法写代码。** 这是「架构图」模块最好的一个注脚。

### v1 → v2 其他值得一提的改动

- 摘要里 WMT En-Fr 的成绩一路在变：**v1 是 41.0 / 训练 3.5 天** → **v2 是 41.2 / 训练 4.5 天** → **v5 定稿 41.8 / 3.5 天**。
- §3.2.1 里 v1 写成「except for the scaling factor of **√d_k**」，是个笔误（应为 1/√d_k），v2 改成 **1/√d_k**。
- **脚注 4 是 v2 加的**：解释为什么要除 √d_k —— 若 q、k 各分量独立、均值 0 方差 1，则 q·k 的均值为 0、**方差为 d_k**。v1 只说了「点积会变大」，没给这个方差论证。
- v2 补了 Illia Polosukhin 的「Work performed while at Google Research」脚注和 tensor2tensor 代码链接，残差连接补了引用 [11]。
- 「∗ Equal contribution. Listing order is random.」这条署名脚注**从 v1 就有**，不是后来补的。

https://bbycroft.net/llm ✅ 200

https://catherinesyeh.github.io/attn-docs/ ✅ 200

https://github.com/jessevig/bertviz ✅ 200

## 自己做的交互，我的建议清单

按实现成本从低到高：

1. **点句子看注意力**：给一句固定的英译德例句，预计算好各层各头的权重，前端只做 SVG 热力图 + 连线。零推理成本，纯静态，和 learn-ai「构建期生成、运行时零进程」的架构完全一致。
2. **Q·K/√d_k 的手算器**：给 2~3 个词、d_k=4 的玩具例子，让读者拖动向量分量，实时看点积、缩放、softmax 的数值变化。**这是「公式图」和「交互」的结合点，也是最能体现「读懂了」的东西。**
3. **mask 开关**：一个 6×6 的矩阵，切换 encoder self / decoder masked / cross 三种模式，看掩码怎么变。三行代码的交互，但解决了读论文时最常见的困惑。
4. **位置编码波形**：滑动 position 和 dimension，看正弦曲线和热力图，再叠一个 RoPE 的旋转演示做对比。
5. **Table 1 复杂度对比**：拖 n（序列长度）和 d（维度），看 self-attention 的 O(n²·d) 什么时候开始输给 recurrent 的 O(n·d²) —— 论文里那句「when n < d」就有画面了。

# 五、现代 LLM 中的架构（2017 → 2026）

这一块是整个条目最有价值的部分，因为大部分讲 Transformer 的材料停在 2017。

### 核心参考：Sebastian Raschka

- 《The Big LLM Architecture Comparison》 https://magazine.sebastianraschka.com/p/the-big-llm-architecture-comparison ✅ 200
  逐个拆 DeepSeek V3、OLMo 2、Gemma 3、Mistral Small 3.1、Llama 4、Qwen3、SmolLM3、Kimi 2、gpt-oss、Grok 2.5，全部对照原始 GPT 架构画图。
- 《LLM Architecture Gallery》 https://sebastianraschka.com/llm-architecture-gallery/ ✅ 200
  上文的架构图合集 + 每个模型的 fact sheet，**是「现代 LLM 架构」模块最好的图表参照**。
- 《The State of LLMs 2025》 https://magazine.sebastianraschka.com/p/state-of-llms-2025

### 这个模块要讲清的「换了什么」

原论文 → 2026 事实标准，逐项对照（这个表可以直接做成页面上的对照组件）：

| 原论文（2017） | 现在（2025–2026） | 换的原因 |
| --- | --- | --- |
| Encoder-Decoder | Decoder-only 为绝对主流 | 生成式任务统一，训练更简单 |
| Post-LN（残差后归一化） | **Pre-LN / Pre-RMSNorm**（OLMo 2 等还在试 Post-Norm 回潮） | 深层训练稳定性 |
| LayerNorm | **RMSNorm** | 去掉均值中心化，更省 |
| 正弦绝对位置编码 | **RoPE**（旋转位置编码） | 相对位置、可外推 |
| ReLU FFN | **SwiGLU**（门控） | 同算力下效果更好 |
| Multi-Head Attention | **GQA**（分组共享 KV）/ **MLA**（DeepSeek 的潜在压缩）/ 滑动窗口 | KV cache 显存是推理瓶颈 |
| 全部有 bias 项 | **无 bias** | 无损、更稳 |
| 稠密 FFN | **MoE 稀疏专家** | 「参数量装大、算力花小」 |
| — | **FlashAttention** | 不改数学，改访存 |

一句话概括：**RoPE + RMSNorm + Pre-Norm + SwiGLU + GQA/MLA + MoE + FlashAttention 是当下的默认配方**，而 attention 本身的公式 —— 论文里的式(1) —— 一个字没改。这句话就是这个模块的收尾。

### 延伸：机制可解释性（如果想再深一层）

# 八、对 learn-ai 条目结构的建议

按现有 `content/<条目>/` 的模块化设计（`entry.json` 决定拼哪些模块），这条建议这样拆：

```
content/transformer-paper/
├── entry.json        模块清单：引子 / 正文 / 公式 / 架构图 / 交互 / 现代架构 / 索引
├── article.md        正文（对照论文逐节，段首带 §3.2.1 这类锚点而不是时间码）
├── index.md          资料索引（本文件核过的链接，按 论文/文章/视频/交互/课程 分）
├── figures/          自己重画的 SVG：Figure 1、Figure 2、位置编码热力图、mask 矩阵
└── interactive/      注意力热力图 / QK 手算器 / mask 开关 / PE 波形 / 复杂度对比
```

和第一条（播客）的关键差别：**没有时间码，所以「可跳播时间线」要换成「论文小节 ↔ 正文段落 ↔ 图 ↔ 交互」的四向锚点**。构建期的交叉校验可以照搬现有思路：每个交互都必须挂在某个论文小节上，每个公式都要能追到论文式号，挂不上就让构建失败。

注意力权重数据建议**构建期预计算成 JSON**（跑一次 HF 模型，导出固定例句的各层各头权重），运行时前端只画图 —— 这样能保住「静态站、运行时零进程」。
